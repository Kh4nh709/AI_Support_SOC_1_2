# React UI v1.0 Implementation Plan (phase P10)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this project each task is one **card** (`P10-Txx`), built by one Coder (Sonnet 5.5, xhigh) in its own worktree and checked by one separate Reviewer (DEC-151). The Director merges.

- **Goal:** Replace the Jinja Tier-1/Tier-2 pages with a separate React service `ui` that calls the backend's JSON API. The service shows alert information and AI analysis in separate columns, updates the queue in real time, and ships in v1.0 by 07/10 12:00.
- **Architecture:**
  - A Vite + React 19 + TypeScript SPA in `frontend/`.
  - Built into `nginx:alpine`, which serves the SPA and reverse-proxies `/api` and `/api/ws` to `app:8000` on the same origin.
  - Authentication is the JWT from `POST /api/auth/login`, sent as `Authorization: Bearer`.
  - The backend gains five additive pieces (`/api/auth/me`, queue filters and counts, the ② investigation view API, case page fields, and a WebSocket fed by a Postgres NOTIFY trigger). `eval/ops_export.py` gains the pilot metrics.
  - The Jinja Tier-1/Tier-2 pages are removed at the end.
- **Tech stack:**
  - Backend: FastAPI and psycopg 3 (sync, plus async for LISTEN), and `websockets` for uvicorn's WebSocket support.
  - Frontend: Node 22, Vite, React 19, TypeScript, React Router, TanStack Query v5, Tailwind CSS v4.
  - Tests: Vitest, React Testing Library, MSW, axe-core, Playwright. Nginx serves the build.
- **Spec:** `docs/superpowers/specs/2026-09-30-react-ui-v1-design.md`. Decisions: DEC-157, DEC-161, DEC-162, DEC-163. Canvas: `https://claude.ai/artifact/MyBdt1oRM9jXUpM1ZLnBNy`, with the artboards `Main`, `Queue`, `Login`, `Case` and `AiStates`.

## Global Constraints

Every card's requirements include these, copied from the spec and the project rules.

**Scope**
- v1.0 covers the Tier-1 and Tier-2 flows only. The assistant (DEC-160) and the admin console (DEC-159) are v1.1: build none of them.

**Serving and network**
- The `ui` service binds `127.0.0.1:8080:80` only.
- The same origin serves the SPA and proxies `/api`, so there is no CORS.
- CSP, verbatim: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`. Also `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`.
- Fonts come from bundled `@fontsource/ibm-plex-sans` and `@fontsource/ibm-plex-mono`. No request goes to Google Fonts or any third-party script host.
- Target: desktop, 1280 px and wider, current Chromium and Firefox.

**Authentication and the token**
- The token travels as `Authorization: Bearer <token>`.
- It is held in memory, mirrored to `sessionStorage` key `soc.session`, and shared across tabs over `BroadcastChannel('soc-session')`.
- It is **never** written to `localStorage` and **never** put in a URL.
- On the WebSocket, the token is the first message: `{type:"auth", token}`.

**Rendering and security**
- Alert, log and model text is rendered as React text only.
- `dangerouslySetInnerHTML`, `eval` and `new Function` appear nowhere in `frontend/src`. A test counts them at 0.

**The blind arm (DEC-101) is server-side only**
- The UI shows the "ẩn — nhánh mù" state when the suggestion keys are absent and `suggestion_visible === false` on an undecided alert.
- It never fetches, infers or caches a suggestion any other way.
- WebSocket messages carry ids only.

**Copy and dates**
- All user-facing copy is Vietnamese, in `frontend/src/strings.ts`.
- Dates display in `Asia/Ho_Chi_Minh` (`DISPLAY_TZ`) whatever the browser's zone.

**Values the UI depends on**
- Queue "Mức" is `risk_band` (`critical|high|medium|low`), not `severity`.
- Case conclusions are exactly `concluded_fp` "Dương tính giả", `concluded_policy_violation` "Vi phạm chính sách" and `confirmed_incident` "Xác nhận sự cố".
- Tier-1 decisions are `false_positive` "Đóng — dương tính giả" and `benign` "Đóng — lành tính", plus escalate and reopen. Decide and escalate are enabled only when the alert is `tier1_active` and acknowledged by the current user.

## Review Focus

These are the five inputs or conditions the spec implies but does not test directly. Each is pinned by a test in the task named.

1. **Hostile text in logs and model output.** Examples: `<img src=x onerror=alert(1)>`, `</script>`, the RTL override U+202E, ANSI escapes, 200 KB lines. They must render as inert text and must not freeze the page. Pinned in P10-T10 (`renders hostile raw_log as text`, `renders a 200 KB raw_log without a new element`).
2. **A burst of queue changes.** A pull of 500 alerts arrives as many NOTIFYs. The UI must refetch the queue about once per burst, not once per alert. Pinned in P10-T05 (server coalescing) and P10-T09 (client: 50 messages give at most 2 queue fetches).
3. **The browser's time zone differs from `Asia/Ho_Chi_Minh`.** Times must still show in +07. Pinned in P10-T08 (`formatTime under TZ=UTC`).
4. **The token expires while a decision reason is being typed.** The typed reason must survive re-login, and nothing is posted twice. Pinned in P10-T10 (`keeps the reason draft across a 401`).
5. **Server values the UI has no label for.** An unknown status, category, `stopped_by` or conclusion is shown as its raw code, never a crash or a blank. Pinned in P10-T10 and P10-T11 (`unknown enum renders raw code`).
