## 1. Built

**`backend/app/tier1/labels.py`** (imports `domain`, `kb`, `audit`, `tier1.visibility` and nothing else)
- `REPO_ROOT`, `CANDIDATES_PATH`, `G1_CLUSTERS_PATH`, `FREEZE_MARKER`, `LABEL_ORDER_SEED = 20260904`. The seed is a separate literal equal to `eval/build_gold.py`'s `EVAL_SEED`. A test checks that the two agree.
- `load_candidates(*, path) -> list[Candidate]`. It drops `source`, `stratum`, `agent_name` and `rule_id`, and `Candidate` has no `source` field. A missing file gives `[]`.
- `load_g1_clusters(*, path) -> list[G1Cluster]`. A missing file gives `[]`.
- `labeler_order(candidates, labeler_id, *, seed=LABEL_ORDER_SEED) -> list[str]`. The shuffle is seeded with `sha256(f"{seed}:{labeler_id}")`.
- `next_unlabelled(conn, order, labeler_id) -> NextResult(cluster_id, done, total)`. It reads only this labeller's `gold_offline` rows.
- `cluster_view(conn, candidate, *, g1_clusters) -> dict`. The dict holds exactly `VIEW_KEYS`, the 19 keys of note 3. There is one explicit-column `SELECT` on `alerts`. `occurrence_count`, `first_seen` and `last_seen` come from the file. `raw_log` is cut at 32,768 bytes for display, with a flag. The playbook falls back to *"No playbook covers this category."* The result then goes through `visibility.strip(..., mode="labeling")`.
- **`g1_correlation(g1_clusters: Sequence[G1Cluster], head: G1Cluster, window_hours: int = 2) -> list[CorrelationView]`**, public for P7. It uses the same three-way OR as phase-4 P4-2 and counts a cluster when its span intersects `[head.first_seen ± window]`. The head itself is excluded. Rows are grouped by `(rule_id, category)`, sorted by `alert_count` descending, at most 20. `correlated_g1_clusters(...)` returns the same clusters ungrouped, which the page uses for its samples.
- `CorrelationView(rule_id, category, cluster_count, alert_count, first_seen, last_seen)`. It has no `status` field. G2 goes through `domain.correlation.summarize_for_prompt`: `status` is dropped from every row and sample, and the rows are **re-grouped** by `(rule_id, category)`.
- `clean_note(note)`, `submit_label(conn, *, labeler_id, cluster_id, label, confidence, note, candidates_path) -> SubmitResult` and `undo_last(conn, labeler_id, *, freeze_marker) -> str | None`. Refusals are typed: `InvalidSubmission` (422), `UnknownCluster` (404), `AlreadyLabelled` (409), `Frozen` (409).

**`backend/app/web/routers/labels.py`** (found by the router discovery in `web/main.py`, which I did not edit)
- `GET /api/admin/labels/next?labeler=` returns `{cluster_id, done, total, cluster}`.
- `POST /api/admin/labels` returns `201 {cluster_id, done, total, next}`.
- `GET /admin/labels` and `POST /admin/labels` (redirects 303 to the page), and `POST /admin/labels/undo`.
- Every route depends on `require_role("admin")`. The pages also depend on `page_user`. `labeler` must equal `Claims.user_id`, otherwise the route answers `403 {"detail": "labeler must be the current user"}`.

**`backend/app/web/templates/labels.html`** extends `base.html` and renders with autoescape; nothing uses `|safe`. It has 20 `data-field` lines, one `<form id="label-form">`, and the undo form only while `FREEZE_MARKER` is absent and the labeller has at least one label.

## 3. Deviations

1. **The playbook is exempt from the forbidden-substring check.** Nine of the ten playbooks, including `ssh_brute_force.md` for the canonical 40112, name `ioc_context`, `asset_context`, `identity_context` and `lookup_status` as things to check. The card requires the playbook to be shown, and it also lists those four strings as forbidden with no exemption. Both cannot hold. The playbook is static KB text, the same for every alert in its category, and holds no data from any alert. So both substring tests remove the `playbook` value, or the `<pre data-field="playbook">` element, before checking, and each asserts that `ioc_context` really is inside the playbook, so the exemption is actually used. `raw_log` and `description` are **not** exempt from these substrings. Only the `replay|wazuh|lab` token check exempts them, as the card says.
2. **Red case (a) is caught by P4's filter first.** The card expected the allowlist and source-token tests to go red when `source` is added. They stay green, because P4's `labeling` filter removes it. That is the two layers working. To show that my allowlist also holds on its own, I added `test_allowlist_holds_without_p4_filter`, which replaces `visibility.strip` with an identity function. It is the test that goes red under (a); the API-level tests go red once the filter is bypassed as well (a2).
3. **Template red case, acceptance 3.** `{{ view.source }}` is caught by the grep, but it renders an empty string: the view has no `source` key and P4's Jinja environment is not `StrictUndefined`. So the HTML tests cannot see it. The grep is the guard for that case.
4. **G2 correlation rows are re-grouped** after `status` is dropped. `summarize_for_prompt` groups by `(rule_id, category, status)`. Leaving two rows side by side would still tell the labeller that two sets of clusters were decided differently. The counts are summed and the spans are min/max. `src_ip_count` cannot be merged exactly and is not part of `CorrelationView` anyway.
5. **G1 samples:** these are up to 5 correlated clusters from the file, taking the file's numbers and `first_seen` as `alert_time`. `description` and `raw_log` come from `alerts` by the explicit-column query, or are `null` when that head is not in `alerts`. The sample keys are the same as G2's minus `status`, so the template has one loop.
6. **P4 names:** they all matched the amended card: `deps.require_role("admin")`, `deps.current_user`, `pages.page_user`, `visibility.strip(..., mode="labeling")` and `templating.render`. One detail: `strip` requires `status=` and `suggestion_visible=`, which labeling mode ignores. Neither column is selected, so I pass `status=""` and `suggestion_visible=False`, the fail-closed values.
7. **Tests use the shared `db` fixture, not a scratch DB.** `get_conn` is overridden to yield `db` without committing, so everything rolls back. I did not add a test for a non-admin being refused. `require_role` commits its `authz.denied` row, which would also commit the `db` fixture's transaction; P4-T01's tests already cover that path.
8. **TDD order:** the module and the tests went into the same first commit, rather than tests first. The DEC-025 red cases above are the evidence that each test checks what it claims.
9. The card's acceptance 3 still names `backend/app/web/labels.py`, which the 19/09 amendment voids. I ran the grep on `backend/app/web/routers/labels.py`.
