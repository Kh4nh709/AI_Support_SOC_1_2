## 3. Deviations

1. **`gold_candidates.csv`'s first line is its header, not a "G1 only" statement** (note 4: "say so in their first line"). P6-T02's loader reads the file with `csv.DictReader` and P6-T03's dependency check is `head -1 eval/gold_candidates.csv`; a comment line would break both. The run mode is the first line of `gold_coverage.md` (`# Gold coverage — G1 only` / `— G1 + G2`) and the `gold_set` column carries it per row.
2. **`allocate` may return fewer than `min(target, len(pool))` rows** when the `unknown` cap binds *and* the classified pool is exhausted (note 3 says "exactly"). The alternative is to breach the cap to fill up, which the same note forbids the code to decide; the table prints `sample short: <n> of <T>` and `main` reports the floor. It never returns more (§2 item 2's size-contract test; see item 5).
3. **The category-floor top-up never pushes a donor below its own floor** — that is what makes "repeat until … nothing can be moved" terminate; a category that cannot be lifted is named in the table (`category floor 25: <c> stays at <n> of <wanted> -- nothing can be moved`). Today's pool lifts `suspicious_login` 21 → 25 from `ssh_brute_force` 107 → 103, as the card computes.
4. **Classified medium/low is allocated by category first, then split within the category** (proportional to the category's medium/low pool, largest remainder), rather than per `(category, severity)` stratum and re-split. Both orders give the card's 107 / 21 / 9 → 103 / 25 / 9 → 95+8 · 25 · 1+8 today; the by-category order is what the card's within-category split step describes.
5. **Two defects found and fixed after the card's acceptances were green** (commit `6bfebcc`), by an internal adversarial review run before this report: (i) with the take-all rule on, the cap's remainder was drawn without regard to the room left under the target, so a high cap over-filled the sample silently (`--g1-target 160 --unknown-cap-pct 100` on the real archive returned 203 rows, exit 0); now `min(remainder, target − crit_high)` with `test_allocate_never_exceeds_the_target_when_take_all_fills_the_room` and a 40-case size-contract test — 160 → 160. The defaults (300 @ 40 %) were never affected: the committed files' sha256 are unchanged. (ii) A `--dsn` libpq cannot parse raised `psycopg.ProgrammingError` through `main` (traceback, exit 1 — the code note 7 reserves for a floor miss); `DsnUnreadable` now maps every connect failure to exit 2 with `DSN unreadable: <type>` and no DSN text (`test_malformed_dsn_exits_2_without_printing_it`). Also strengthened: the floor test now has a two-donor case that tells "largest allocation" from "first in PRIORITY order".
6. **Extra public names beyond the card's list** (`coverage_document`, `grid_table`, `read_manifest_ids`, `check_db`, `AllocParams`, `G2Result`, `LabWindow`, `lab_tag_command`, `read_lab_windows`) and two extra keyword arguments on `coverage_table` (`extra_pool_lines`, `extra_sample_lines`) so the G1-only lines (loopback exclusion, `DESKTOP-MIRSO17`) and the G2-only lines (windows, zero categories, the benign reminder) live in the document builder. The card's listed functions exist with the card's signatures.

No merge forward (none of those changes touch this card's files; the Director merges). `STATE.md`'s P6-T01 row is edited on this base — it will need the usual row-level reconciliation at merge.
