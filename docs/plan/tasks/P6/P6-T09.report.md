# P6-T09 report — `label_export.py`: disagreements vs window truth, committed scenario-exclusion at freeze, report freed of G1 wording

Branch `task/P6-T09` on the director branch (P6-T07 merged). Files changed: `eval/label_export.py`,
`backend/tests/test_label_export.py` (+ this report and the STATE row). Not merged to `main`.

## Built

**A (must) — `disagreements` against the window truth.** New `AdjRow` dataclass and pure
`build_adjudication_rows(candidates, pairs, labeler_a, labeler_b)`. A candidate carrying a window
`truth_label` yields one **window**-basis row per labeller whose label differs from that truth (0, 1
or 2 rows); a candidate with no truth yields the original **peer**-basis row only when both humans
labelled it and disagree. `ADJUDICATION_COLUMNS` gains four trailing columns `basis`, `truth_label`,
`labeler`, `labeler_label` (trailing, so `read_adjudication` and every existing reader are
unaffected). `write_adjudication_csv` now takes `list[AdjRow]`. `cmd_disagreements` builds the rows
and prints `disagreements: N (W vs-window, P vs-peer)`. No `triage_labels(source='disagreement')`
row is written for a window-basis disagreement — the window is not an adjudicator (DEC-111).

**B (must) — `freeze` honours a committed `eval/excluded_scenarios.csv`.** New pure
`read_excluded_scenarios(path)` (ordered, de-duplicated `scenario_id`s; `[]` when absent) and
`apply_scenario_exclusions(candidates, excluded_ids) -> ExclusionResult(kept, dropped, matched,
unmatched)`. New `freeze` flag `--excluded-scenarios` (default `eval/excluded_scenarios.csv`). Before
resolving labellers or building gold rows, `cmd_freeze` drops every candidate whose `scenario_id` is
listed and prints `excluded <n> candidates from <m> scenarios: <ids>`; a listed id matching no
candidate is a `warning:` on stderr, not an error; an absent or empty file changes nothing. The file
is the record (DEC-117) — no flag types an exclusion at freeze time. `eval/excluded_scenarios.csv`
is **not** created by this card.

**C (should) — `report` drops G1 wording, prints `vs_truth`.** `render_report` no longer prints the
`G1 rows >= 300` gate; the G2-rows gate floor is now `>= 100` (DEC-111). Section 4 gains a "Human
baseline vs window truth (DEC-111)" block printing each labeller's `accuracy` and `by_category` from
`kappa_v1.json`'s `vs_truth`, and `(not available -- kappa_v1.json carries no vs_truth)` when the
key is absent (never a zero). The section-5 limitation "`web_attack` and `policy_violation` are
zero-cluster categories in G1 today" is reworded to "... are absent categories".

## Open questions / follow-ups

- A **window** row and a **peer** row never share a `cluster_id` (a cluster either has a truth or
  does not), so no cluster appears under both bases — noted for the adjudication-meeting tooling.
- The adjudication file can now carry window rows with empty `final_label`; `_adjudication_in_progress`
  keys on a non-empty `final_label`, so window rows never block a re-run — intended.
