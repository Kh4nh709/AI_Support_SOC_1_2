- **Design notes:**

  **1 · CLI.** `python3 eval/label_export.py <kappa|disagreements|freeze|report> [options]`, run as `PYTHONPATH=backend python3 eval/label_export.py …` from the repository root. Common options: `--candidates eval/gold_candidates.csv`, `--dsn DSN` or `--env-file .env` (the DSN is `--dsn` if given, else `config.load(env_file=…).DATABASE_URL`; never printed), `--labeler-a UUID --labeler-b UUID` (optional: when absent, the two `labeler_id`s with the most `gold_offline` rows over the candidate ids are used and printed; any count of distinct labellers other than 2 among those rows → exit 1 naming them — the protocol is two people). Exit codes: **0** done; **1** a refusal the text explains (see each subcommand); **2** a file or the DSN is unreadable. `report` is the only subcommand that does not need the database.

  **2 · κ — the 3 × 3 formula, written once, ten lines (`prompts/P6.md:31`; no `sklearn`).** Over the candidate ids labelled by **both** labellers: `n` pairs; `p_o` = agreements / n; `p_e = Σ_k (rowmarginal_k / n) × (colmarginal_k / n)` over the three labels; `κ = (p_o − p_e) / (1 − p_e)`; when `1 − p_e == 0` (both labellers used one label throughout) κ is `null` with `"reason": "p_e = 1"`. `cohen_kappa(pairs: list[tuple[str, str]]) -> KappaResult(n, p_o, p_e, kappa, confusion)` is a pure function; `confusion` is the 3 × 3 dict keyed by the fixed label order `false_positive, benign, escalate`. `kappa_v1.json`: `{"candidates": N, "labelled_by_both": n, "labeler_a": …, "labeler_b": …, "overall": KappaResult, "by_gold_set": {"G1": …, "G2": …}, "by_category": {…} (should), "disagreements": d, "disagreement_rate": d/n, "computed_at": ISO}`. The known-value test: 50 pairs — 20 both `escalate`, 5 (`escalate`,`benign`), 10 (`benign`,`escalate`), 15 both `benign` → `p_o = 0.70`, `p_e = 0.50`, **κ = 0.40**; a test pins that to 1e-9.

  **3 · `disagreements`.** For every candidate labelled by both with `label_a != label_b`, one row of `eval/adjudication_v1.csv`: `cluster_id,gold_set,category,severity,label_a,confidence_a,note_a,label_b,confidence_b,note_b,final_label,final_note` — the last two **empty**; sorted by `cluster_id`. Candidates not yet labelled by both are counted and printed (`not yet labelled by both: <n>`), never written. `--out` defaults to `eval/adjudication_v1.csv`; refuse to overwrite an existing file whose `final_label` column has any non-empty value (exit 1: *"adjudication in progress — refusing to overwrite; pass --out another path"*) — the meeting's work is never clobbered by a re-run.

  **4 · `freeze` (planning decision 12).** Inputs: the candidates, the labels, `--adjudication eval/adjudication_v1.csv`, `--out-dir eval`, `--adjudicator-id UUID` (the `users` row that records `source='disagreement'`; when absent, the disagreement rows are still frozen into the CSV but no DB row is written, and the report says so). Rules: (i) a candidate labelled by both with agreement → `label`, `adjudicated = false`, `note` = `note_a` if non-empty else `note_b`; (ii) a disagreement → the adjudication row's `final_label` (`false_positive|benign|escalate`, else exit 1 naming the `cluster_id`), `adjudicated = true`, `note = final_note`; a disagreement with an **empty** `final_label` → exit 1 listing every such `cluster_id` and writing nothing; (iii) a candidate with fewer than two labels → exit 1 with the count, unless `--allow-partial`, in which case it is dropped and the count goes into the JSON sidecar `eval/gold_v1.freeze.json` (`{"candidates", "frozen", "dropped_unlabelled", "adjudicated", "sha256", "frozen_at", "adjudicator_id"}`). Output `eval/gold_v1.csv` — columns exactly `cluster_id,gold_set,alert_id,category,severity,source,label,adjudicated,note,confidence_a,confidence_b,occurrence_count,first_seen,last_seen` (`source` copied from the candidates: `replay|lab`, for scripts only), rows sorted by `cluster_id`, `csv.QUOTE_MINIMAL`, `\n`; then `eval/gold_v1.sha256` = `f"{sha256(bytes of gold_v1.csv)}  eval/gold_v1.csv\n"` (the `sha256sum -c`-compatible form). **Version-by-existence:** if `eval/gold_v1.csv` exists, write `gold_v2.csv`, `gold_v2.sha256`, `gold_v2.freeze.json` and `eval/gold_v1_to_v2.diff` (`difflib.unified_diff` of the two files' lines, with `fromfile`/`tofile` set to the paths) and **never open v1 for writing**; if `gold_v2.csv` also exists, `v3`, and so on — the next free version number. There is no `--force`. With `--adjudicator-id`, every adjudicated cluster also gets `INSERT INTO triage_labels (alert_id, labeler_id, source, label, confidence, note) VALUES (%s, %s, 'disagreement', %s, NULL, %s) ON CONFLICT DO NOTHING` — the value the CHECK set reserves for exactly this, and `ON CONFLICT DO NOTHING` because a re-freeze after a v2 must not fail on the rows v1 wrote.

  **5 · `report` → `docs/gold-v1-report.md` (planning decision 6 — the brief's T06).** Inputs: `--gold eval/gold_v1.csv` (or the highest version present), its `.sha256` and `.freeze.json`, `--kappa eval/kappa_v1.json`, `--adjudication`, `--coverage eval/gold_coverage.md` (P6-T01's; its **G1 pool grid, G1 sample grid, G2 grids and the "enriched by design" line are copied in verbatim** — find them by their section headings), `--out docs/gold-v1-report.md`.
