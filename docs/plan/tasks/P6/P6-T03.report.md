## 1. Built

**`eval/label_export.py`** (written from a one-line docstring stub; stdlib only — `argparse`, `csv`,
`difflib`, `hashlib`, `json`, `re`, `subprocess`; `psycopg` for the three DB-touching subcommands;
`from app.infra import config` for `DATABASE_URL`)

- `cohen_kappa(pairs) -> KappaResult` — the 3 x 3 formula over the fixed label order `LABELS =
  (false_positive, benign, escalate)`, ten executable lines; `KappaResult(n, p_o, p_e, kappa,
  confusion, reason)`, `kappa=None, reason="p_e = 1"` when `1 - p_e == 0`. `group_kappa(pairs_by_cluster,
  key_by_cluster) -> dict` — the same formula computed independently per group (`gold_set` or
  `category`), pure, no I/O — this is what makes `by_gold_set`/`by_category` and the `should`
  per-category breakdown testable without a database.
- `Candidate`, `LabelPair` (`.both_labelled`, `.disagrees`), `AdjudicationRow`, `GoldRow` — frozen
  dataclasses carrying exactly the CSV columns each subcommand reads or writes.
- `resolve_labelers(conn, candidate_ids, labeler_a, labeler_b) -> (str, str)` — explicit pair if both
  given (never touches `conn`); else the `labeler_id`s of every `gold_offline` row over the candidate
  ids, grouped and counted; anything other than exactly two distinct labellers raises
  `TwoLabelerProtocolViolation`, caught by every subcommand's `main()` path and printed with each
  labeller's row count, exit 1.
- `fetch_label_pairs(conn, candidate_ids, labeler_a, labeler_b) -> dict[str, LabelPair]` — one
  explicit-column-list query, pivoted in Python; a candidate with zero, one or two labels all produce
  a `LabelPair`, never a `KeyError`.
- `cmd_kappa` → `eval/kappa_v1.json`: `candidates`, `labelled_by_both`, `labeler_a/b`, `overall`,
  `by_gold_set`, `by_category`, `disagreements`, `disagreement_rate`, `computed_at`
  (`datetime.now(timezone.utc).isoformat()`).
- `_adjudication_in_progress(path)`, `read_adjudication`, `write_adjudication_csv`; `cmd_disagreements`
  → `eval/adjudication_v1.csv`, one row per both-labelled disagreement sorted by `cluster_id`, empty
  `final_label`/`final_note`; the clobber guard runs **before** any DSN is resolved, so refusing never
  touches the database.
- `build_gold_rows(candidates, pairs, adjudication, *, allow_partial) -> FreezeResult` — the pure rule
  engine (rules i–iii): raises `PartialLabelled` (candidates with fewer than two labels, unless
  `allow_partial`) or `MissingFinalLabel` (a disagreement whose adjudication row has no valid
  `final_label`) instead of writing anything; otherwise returns the frozen `GoldRow`s plus the dropped
  count. Tested entirely on hand-built in-memory objects, no database.
- `write_gold_csv`, `write_sha_file(csv_path, sha_path, *, label=None)` (label defaults to `csv_path`
  as given; `sha256sum -c`-compatible), `write_version_diff` (`difflib.unified_diff`, `fromfile`/
  `tofile` set to the two paths), `next_free_version`, `write_freeze_outputs` (version-by-existence:
  the CSV, the sha file, the diff for v2+, the `gold_vN.freeze.json` sidecar). `cmd_freeze` wires these
  to the database: resolves labellers, fetches pairs, calls `build_gold_rows`, calls
  `write_freeze_outputs`, and — only with `--adjudicator-id` — `INSERT ... ON CONFLICT DO NOTHING` one
  `triage_labels(source='disagreement')` row per adjudicated cluster, committed once at the end (the
  script's only write; every other path never commits).
- `read_gold_csv`, `_default_gold_path` (highest `gold_vN.csv` present, or `gold_v1.csv`),
  `_git_log_line`, `_band_sentence`, `_extract_section`/`_extract_line`/`_crit_high_ratio` (parse
  `eval/gold_coverage.md`'s own bullet lines rather than re-deriving their numbers), `render_report` —
  a pure function of its inputs (no clock, no subprocess call inside it) producing the five sections:
  Freeze, Counts (by `gold_set` x `label`, by `category` x `label`, the three floor gates, G3),
  Coverage (P6-T01's pool/sample grids copied verbatim by heading, which carries the "enriched by
  design" line for free), Agreement (kappa overall/by-set/by-category, confusion, disagreement rate,
  the protocol sentence), Limitations for P8 (the `unknown` stratum, B1's escalate-recall ceiling
  re-derived on **this fold's own numbers** for both the pool and the sample, the loopback exclusion,
  `DESKTOP-MIRSO17`, `web_attack`/`policy_violation` at zero, the three author-written-rule categories
  with their G2 counts, author-as-labeller with the kappa just reported, the lab-host/time-window
  sentence, G2's readable dates, the severity-enrichment sentence). `cmd_report` is the only subcommand
  that never touches a DSN.
- `main(argv) -> int` — four subparsers, exit codes `EXIT_OK=0`, `EXIT_REFUSED=1`,
  `EXIT_UNREADABLE=2`; `_resolve_dsn` prints `dsn: from --dsn (redacted)` / `dsn: from .env (redacted)`,
  never the DSN itself.

## 3. Deviations

**Implementation before tests, not strict red-green-red TDD.** The freeze rules, the sha/version
mechanics and the report renderer all needed to be split into pure functions (`build_gold_rows`,
`write_freeze_outputs`, `render_report`, `group_kappa`) specifically so that ten of the sixteen named
acceptance tests could run without a database at all — design note 6 names several of these tests
without a `(db)` tag, which only makes sense if the function under test never opens a connection. That
split is the architecture, not an afterthought, so I designed it first, then wrote the module and its
tests together rather than watching every test fail on a stub first. Every acceptance test does have a
demonstrated failing case (§2, item 1 and item 2's red steps) — the DEC-025 discipline was applied
after the fact rather than before, which is the actual deviation. None of the sixteen named tests or
their failing cases needed to change once written.

**One test's fixture alerts use a direct `INSERT` instead of `domain.transitions.open_alert`.**
`test_freeze_writes_v1_sha_and_disagreement_rows` is the only test whose `main()` call commits (it
passes `--adjudicator-id`, the single write this script makes). `open_alert` writes an append-only
`audit_events` row on every call; a commit in that test would persist it for the rest of a
`make test-db` run and could desync another file's exact-count assertions on that table — the same
failure mode `test_lab_tag.py`'s own docstring already documents and fixes the same way. All four
`p6t03c-`-prefixed rows this one test commits (two alerts, two users) are swept by an autouse fixture
ordered, via `request.getfixturevalue("db")` before `yield`, to run before `db`'s own rollback+close.
Every other database test never commits and needs no such cleanup.

**Design note 5's DSN clause read literally.** "`report` is the only subcommand that does not need the
database" is implemented exactly: `cmd_report` never calls `_resolve_dsn` or opens a connection.
`kappa`, `disagreements` and `freeze` all resolve a DSN unconditionally (even `disagreements --out
<clobbered-file>`, which still refuses before touching it — the DSN resolution simply never runs on
that path because the guard returns first).

No other deviation from the card. `label` in `write_sha_file` is a keyword-only default exactly as
specified ("`label` defaults to the csv path as given, and `freeze` passes `eval/gold_v1.csv`") —
`freeze` constructs it as `str(out_dir / f"gold_v{version}.csv")`, which equals the literal
`"eval/gold_v1.csv"` under the documented default `--out-dir eval`.

## 4. Open questions / follow-ups

None blocking. One judgement call worth flagging for the Reviewer: the "quote every number with its
denominator" limitation sentences in `report`'s §5 are built by parsing `eval/gold_coverage.md`'s own
bullet lines (regex on text P6-T01 already wrote and tests) rather than re-implementing the
pool/crit-high/unknown arithmetic a second time in this file — deliberate, so the two scripts can never
disagree about the same number, but it does mean `report`'s limitations section goes empty-with-a-note
if `gold_coverage.md`'s wording ever changes shape. `render_report` degrades to "not found" /
"not found -- limitations cannot be re-derived" rather than crashing in that case, and
`test_report_handles_missing_inputs_gracefully` pins that.
