## Built

- **`eval/report.py`** (was a one-line stub). One read-only command turns a frozen gold sha's
  `eval_runs` rows (each carrying the `metrics.metrics_json` document, P7-T03) plus the local
  `eval/results/<eval_run_id>.json` files (P7-T04 note 7) into three markdown files and one CSV
  under `--out-dir`. It computes no metric: it imports P7-T03's pinned names
  (`Prediction, OUTCOMES, TRUTH_CLASSES, correct, human_predictions, mcnemar_exact, outcome,
  paired_delta_ci, score`) and the DEC-111 caveat sentence (`DEC111_SENTENCE`) from `build_gold`
  (imported, never retyped).
  - **`render_*` are pure over their inputs** (a `Run` = the run identity + its `metrics` document
    + its per-cluster `Prediction`s + the raw rows) and are tested without a database. The CLI does
    all I/O.
  - **`ablation.md`**: the two caveat lines first; the run table (config, thinking, prompt_version,
    model_id, n, eval_run_id[:8]); the G2 headline with **deferral(escalate) [CI] immediately after
    recall(escalate) strict [CI]**, precision(close) [CI], deferral(close), error rate, evidence-
    verified (✓/✗ vs 0.90, B2–B4 only), cost/alert, billed, p50/p95; the 2×4 truth×outcome table
    per G2 run; the human baseline (`human_predictions` + the kappa file's strict `vs_truth`
    accuracy, labelled "a second result, not the gold (DEC-111)", or `(not available — run_configs.py
    human)`); B4 vs B1 (`paired_delta_ci` for macro-F1 and recall(escalate), `mcnemar_exact`); the
    paired thinking ablation (DEC-042: B4 disabled vs enabled, each run's recorded `llm_thinking`
    printed from its metrics, deltas [CI], McNemar, cost and p50/p95 for both); the prompt-v1.1 line
    (three states); the charts note.
  - **`per_category.md`**: caveat; `by_category_expected` (primary), `by_kind`, `by_severity`
    (band as written, never re-banded), `by_category` (secondary); the dropped-category list
    (lab categories with no gold cluster, plus `web_attack`/`policy_violation` named with
    DEC-055/DEC-057).
  - **`adversarial.md`**: caveat; the G3 ASR block (n, successes, ASR, error rate) for B3/B4,
    `by_vector`, `by_pattern_family`; the architecture expectation printed **as an expectation, not
    a result** (`expected: B3 > 0, B4 ≈ 0`); `(no G3 run selected — nothing to report)` when none.
  - **`predictions_<gold12>.csv`**: the exact 20-column header, one row per (run, cluster), sorted
    by (gold_set, config, llm_thinking, prompt_version, cluster_id), UTF-8 with `\n`. **No free-text
    column**; `error` is the exception class name only; `outcome` is the decision class from
    `metrics.outcome(verdict)`; `correct_strict` is `n/a` where truth is `None` (G3).
  - **Determinism**: no clock/hostname/absolute path; rates 3 decimals, USD 4, ms integer, `None`→
    `n/a`, fixed order. Rendering twice is byte-identical.
  - **DB**: `select_runs` uses `metrics->>'gold_sha256'` and `DISTINCT ON (gold_set, config,
    metrics->>'llm_thinking', prompt_version) … ORDER BY … created_at DESC` for latest-per-key, or
    exactly `--run-ids`. The CLI connection is `SET TRANSACTION READ ONLY`. A missing results file
    or a `metrics.gold_sha256` ≠ `--gold-sha` exits 3.
  - **Charts** (`should`): `_get_pyplot()` returns pyplot or `None`; charts render only when
    matplotlib imports (it is not in this venv), else the markdown says
    `(charts not rendered: matplotlib not installed)`. No dependency added.
- **`backend/tests/test_eval_report.py`**: 12 pure tests + 1 `@pytest.mark.db`. Fixtures are
  hand-built `Prediction` lists passed through `metrics.metrics_json` and results dicts in P7-T04's
  shape.

## Deviations

1. **`git diff main` is non-empty; `git merge main` is a no-op.** `main` (`5c312f2`) is an ancestor
   of the base (`HEAD..main` count = 0), so `git merge main` changes nothing and was not run as a
   mutating op (the session is isolated in another worktree). Because P7-T03's `eval/metrics.py`
   was merged into the base but not into `main`, `git diff main` for the acceptance-3 paths shows
   that one added file. It is not my change: `git diff HEAD` for those paths and
   `git diff -- eval/metrics.py` are both empty. Same situation P7-T03/T04 recorded.
2. **Headline identity columns.** The card lists the headline's metric columns; I prepend `config`
   and `thinking` so the two B4 rows (disabled/enabled) are distinguishable. `deferral(escalate)`
   is still the column immediately after `recall(escalate) strict` (design note 2, tested).
3. **T06/T07 JSON shapes assumed.** Those cards are not built (T07 is likely never built, DEC-116).
   The prompt-v1.1 renderer reads `--gate-decision` as `{"decision", "reason"}` and
   `--fewshot-decision` as `{"reason"}`; the reader is defensive (`.get`). See Open questions.
4. **CSV `outcome` semantics.** P7-T04 note 7 lists an `outcome` field per results row (the
   evaluation's processing outcome). The CSV `outcome` column is instead the **decision class**
   (`metrics.outcome(verdict)` ∈ escalate/close/review/error), so it sits on the same scale as
   `truth`; `error` (the exception class name) is a separate column, read from the row.
