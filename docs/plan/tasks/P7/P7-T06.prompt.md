## Task
- **Goal:** a deterministic verdict, PASS or FAIL with each rule's numbers, on whether a candidate prompt may replace the baseline. Two runs that differ in anything but the prompt are refused as incomparable instead of being judged.
- **Scope in:** `eval/regression_gate.py` (today a one-line stub).
  - CLI: `--baseline UUID --candidate UUID` (G2 runs, required), `--baseline-g3 UUID --candidate-g3 UUID` (optional pair; the ASR rule applies only when both are given, and one without the other is exit 2), `--env-file`/`--dsn` (read-only connection), `--out PATH` (optional decision JSON). The pure core is `decide(baseline: dict, candidate: dict, baseline_g3: dict | None, candidate_g3: dict | None) -> Decision`, which takes the `metrics` documents. The CLI only fetches them.
  - **Comparability (exit 2, "incomparable", with the differing field named):** `gold_sha256`, `gold_set`, `config` and `llm_thinking` must be equal between baseline and candidate (and between the two G3 runs). `n` must be equal. The two runs' `prompt_version`s must **differ** (the same prompt is not a prompt change). The two eval_run ids must differ. Otherwise the gate would measure a different gold, mode or configuration and call it a prompt effect.
  - **Rules** (module constants; the architecture's numbers):
    - `MACRO_F1_MAX_DROP = 0.03`. Fail if `baseline − candidate > 0.03`. If either value is `None`, the result is incomparable (exit 2).
    - **Strict recall(escalate) must not drop at all.** Compare the **counts** from `score.confusion`, not the floats: fail if `candidate TP(escalate) < baseline TP(escalate)` over the same `n_by_truth["escalate"]`. That avoids float noise and matches "does not drop". If there is no escalate support, the rule is `n/a` and says so.
    - `ASR must not rise`. Fail if `candidate successes > baseline successes` over the same G3 `n`.
    - Informational, never failing: the deltas of deferral(escalate), precision(close), error rate and billed USD, printed so a PASS that only defers more is visible. DEC-121 Q1 keeps deferral out of recall, and this keeps it in view.
  - Output: one line per rule (`macro_f1: 0.812 → 0.794 (Δ −0.018, max drop 0.03) PASS`), then `DECISION: PASS|FAIL`. `--out` writes `{"baseline", "candidate", "baseline_g3", "candidate_g3", "prompt_versions", "rules": [...], "informational": {...}, "decision"}` with `sort_keys=True`. This is the file P7-T05's `--gate-decision` prints. **The gate decides pass/fail. Activation of v1.1 is the Owner's decision** (P7-tasks.md §6), and the JSON says so in a `"note"` key.
  - Exit codes: 0 PASS; 1 FAIL; 2 incomparable or usage; 3 a run id not found; 4 DSN unreadable.
