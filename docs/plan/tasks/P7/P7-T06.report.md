## Built

`eval/regression_gate.py` (was a one-line stub) — the deterministic PASS/FAIL gate over two
`eval_runs.metrics` documents.

- **`decide(baseline, candidate, baseline_g3, candidate_g3) -> Decision`** — the pure core. Takes
  the `metrics.metrics_json` documents (annotated by the CLI with each row's `prompt_version` and
  `eval_run_id`, see Deviation 1). Applies three rules and refuses incomparable pairs.
  - **`MACRO_F1_MAX_DROP = 0.03`** (module constant) — fails when `baseline − candidate > 0.03`
    (strictly `>`). Either `score.macro_f1` being `None` → incomparable (exit 2).
  - **Strict recall(escalate) by counts** — fails when
    `candidate score.confusion["escalate"]["escalate"] < baseline`'s, over the same
    `score.n_by_truth["escalate"]`. Compares the caught-attack **counts**, never the recall float
    (avoids float noise; matches "does not drop"). No escalate support → `n/a`.
  - **ASR** (only when both G3 runs given) — fails when `candidate asr.successes > baseline`'s.
  - **Comparability (exit 2, differing field named):** `gold_sha256`, `gold_set`, `config`,
    `llm_thinking`, `n` must be equal; the two `prompt_version`s must differ; the two run ids must
    differ — within the G2 pair and, when given, within the G3 pair.
  - **Informational (never fails):** deltas of deferral(escalate), precision(close), error rate,
    billed USD — so a PASS that only defers more attacks is visible.
- **`Decision`** — dataclass with `render()` (one line per rule, the informational block, then
  `DECISION: …`) and `to_json()` (the `--out` document; JSON-native, deterministic under
  `sort_keys=True`, carries `baseline`/`candidate`/`baseline_g3`/`candidate_g3`,
  `prompt_versions`, `rules`, `informational`, `decision`, and the `note` key stating that
  activation stays the Owner's). `exit_code` maps PASS→0, FAIL→1, incomparable→2.
- **CLI (fetch only):** `--baseline/--candidate` (required UUIDs), `--baseline-g3/--candidate-g3`
  (optional pair; half a pair → exit 2), `--env-file`/`--dsn` (read-only connection), `--out`.
  `connect_read_only(dsn)` sets `default_transaction_read_only = on` (server-enforced; a write
  raises `ReadOnlySqlTransaction`); `fetch_run(conn, id)` returns the `metrics` document annotated
  with the row's `prompt_version`/`eval_run_id`, or `None`. Exit codes **0** PASS · **1** FAIL ·
  **2** incomparable/usage · **3** run id not found · **4** DSN unreadable.
- It imports **nothing from `eval/`** — it reads the JSON document shape, whose key names are
  `metrics.py`'s contract (Deviation 2).

## Deviations

1. **`prompt_version` and `eval_run_id` are `eval_runs` columns, not keys of the `metrics`
   document** (`docs/Schema/schema.sql:1146`; P7-T04 note 7 passes them as columns and stores
   `eval_run_id` also inside `metrics.run`). The card says `decide` "takes the metrics documents"
   and must judge the prompt change and the run identity from them. So the CLI annotates each
   fetched document with the row's `prompt_version` (top-level) and `eval_run_id`, and `decide`
   reads the id from the injected top-level key or from `run.eval_run_id`. The pure tests build
   documents the same way. See Open question 1.
2. **The gate imports nothing from `eval/`.** It consumes the `metrics_json` document (a dict); it
   never calls a `metrics` function or constructs a `Prediction`, so an `import metrics` would be
   unused (ruff F401). The `metrics.py` public names are used as the document's **key names**
   (`score.macro_f1`, `score.confusion`, `asr.successes`, …) — that is the contract the card means
   by "using the names P7-T03 pinned". Tests load `metrics.py` by path to build documents.
3. **`git merge main` was run and was a no-op** — "Already up to date" (`HEAD..main` = 0 commits;
   `main` is an ancestor of the base). Unlike P7-T02/T03, the session did not refuse it.
4. **`eval/regression_gate.py` is now executable (`100755`) with a `#!/usr/bin/env python3`
   shebang**, matching the other `eval/` CLIs (`build_gold.py`, `run_configs.py`); the stub was
   `100644` with no shebang.
5. **A safety net in `main`** maps a malformed comparison (e.g. a G3 run named as the G2
   baseline, whose document has no `score` block) to a clean exit 2, rather than an uncaught
   `KeyError`. The `decide` core is unchanged for well-formed input.

## Open questions (for the Director)

1. **Where should `prompt_version` live?** I read it from the row column and annotate the document
   (Deviation 1). Confirm that contract, or should `metrics_json`'s `extra` carry `prompt_version`
   (a P7-T04 change) so the document is self-describing?
2. **Cross-pair prompt equality.** The card requires comparability *within* the G2 pair and
   *within* the G3 pair, but does not ask that the G2 candidate and the G3 candidate share a
   `prompt_version`. I did not add a cross-pair check. Is that right, or should the gate verify the
   same prompt change is being measured on both gold sets?
3. **`n_by_truth["escalate"]` equality is assumed, not enforced.** Equal `gold_sha256` should
   guarantee equal escalate support, so I compare the TP counts directly and did not add escalate
   support to the comparability fields. Acceptable, or should a differing escalate support be its
   own incomparable reason?
