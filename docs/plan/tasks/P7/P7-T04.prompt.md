- **Design notes:**

  **1 · The frozen-gold check comes first, before any connection.** `gold_sha(gold_path, sha_file)` requires four things. (a) `sha_file` exists. (b) Its hex equals `sha256` of the gold file's bytes. (c) Both files are tracked (`git ls-files --error-unmatch`). (d) Both are unmodified against `HEAD` (`git diff --quiet HEAD -- <both>`). Any failure exits **3** with the reason: this is the brief's stop condition. `gold12 = sha[:12]` names every output. Every `Prediction`, results file and `eval_runs.metrics` carries the full `gold_sha256`.

  **2 · Loading the gold.** Read the rows with `label_export.read_gold_csv` (reuse it, do not re-parse). Join `category_expected` from `eval/lab_windows.csv` by `scenario_id`. A gold row whose `scenario_id` has no window exits 3. A label outside `{escalate, benign}` exits 3 (DEC-115; `metrics.truth_class` would raise later anyway). `Prediction.category` is the alert's own `alerts.category`, read from the DB: that is the secondary view (planning decision 5). `severity` is the gold row's.

  **3 · G3.** `--gold-set G3` takes its targets from the manifest's `alert_id`s, with `truth=None`. Before anything runs, each target must exist in `alerts` with `is_synthetic` true. If any is missing, exit 3 and print `eval/adversarial/load.py` as the fix. `--config` must be `B3` or `B4` for G3 (the brief); anything else exits 2. The G3 sha check still runs against `gold_v1` (G3 is evaluated only after the freeze, planning decision 8), and `metrics.run.manifest_sha256` records the manifest's sha.

  **4 · B0 and B1: deterministic, no adapter constructed.** B0: `verdict = metrics.B0_MAP[row.severity]`. B1: `facts = b1_facts(conn, alert_id, cfg)`, then `table = get_decision_table(category)`; if the table is `None` or no rule matches, the verdict is `needs_review` (the brief), and otherwise it is `apply_table(...)[0]`. **`b1_facts` must produce the same facts ① sees.** Build it from the same helpers `evaluate_alert` uses (`_load`, the correlation call, `llm.triage.build_facts`), importing them from `tier1.triage` (`eval → everything` is allowed, context pack import rules). `test_b1_facts_equal_evaluate_alert_facts` pins equality with `evaluate_alert(..., adapter=FakeLLM(...)).facts` on the same row. That test is the guard against the two drifting. If equality cannot hold without editing `backend/`, stop and report. Do not edit `backend/`. B0: `model_id='none'`, `prompt_version='severity_for'`. B1: `model_id='none'`, `prompt_version='kb:'+sha256(concatenated kb/decision_tables/*.yaml bytes, name order)[:12]` (planning decision 9).

  **5 · B2, B3, B4: one code path.** B2 is `EvalSwitches(include_context=False, include_correlation=False, gate_mode="steps_1_3")` (the brief: ① without the enrichment and correlation blocks, gate steps 1–3). B3 is `EvalSwitches(gate_mode="steps_1_3")`. B4 is `DEPLOYED`, or `dataclasses.replace(DEPLOYED, proposer_template=Path(args.template))` when `--template` is given. `--template` with any other config exits 2. The adapter is `CachingAdapter(DeepSeekAdapter(cfg_run, spent_usd=…), cache_dir=…, thinking=args.thinking, spend=guard)`, where `cfg_run` is the loaded `Config` with `LLM_THINKING` set to `args.thinking` (`dataclasses.replace`). **The thinking mode that reaches the request and the one in the cache key are the same value, by construction.** A test asserts it. Each alert is evaluated with `run_bounded(..., max_workers=args.max_workers)`. **Each worker thread opens its own connection**, because psycopg connections are not shared across threads, and runs `SET TRANSACTION READ ONLY` first. `evaluate_alert` writes nothing (P7-T01), and a read-only transaction makes that a server-enforced fact during the evaluation. Map each `TriageEvaluation` to a `Prediction`: `verdict = final_verdict if outcome == "ok" else None`, plus `reasons_kept`/`reasons_dropped`, `cost_usd`, `latency_ms`, `cached` and `billed_usd` (0.0 for a hit). A per-item exception captured by `run_bounded` becomes `verdict=None` with the exception's class name in the results file.

  **6 · Money (brief design note; DEC-121 Q5).** Before the first live call, `month_spend = llm_runs.month_spend_usd(conn) + Σ metrics.run.billed_usd over this calendar month's eval_runs rows`. The evaluation writes no `llm_runs`, so without the second term, repeated evaluation runs would be invisible to the cap. The estimate is `estimate_cost(n, calls_per_alert, usd_per_call) × 1.10`, where `calls_per_alert` is 1 for B2/B3 and 2 for B4, and `usd_per_call` is 0.00028 (`disabled`) or 0.00415 (`enabled`), module constants citing P7-tasks.md §4. Print one line: `estimate: <config> <gold_set> thinking=<m> n=<n> calls≈<c> usd≈<e> month_spend=<s> cap=<cap>`. Then `refuse_if_over(e, s, cfg.LLM_MONTHLY_USD_CAP)`. **If `e > 5.00` and `--approved-usd` is absent or below `e`, exit 5** and print the approval command. `--estimate-only` prints the line and exits 0. The estimate is an upper bound: cache hits make it smaller, never larger. `SpendGuard` stops the run mid-way if the cap is reached. Remaining items then become `error` predictions, the run is recorded with `metrics.run.stopped_by_cap = true`, and the exit code is 6.

  **7 · Outputs.** `eval_run_id = uuid4()`. `eval/results/<eval_run_id>.json` holds `{"eval_run_id", "gold_sha256", "gold_set", "config", "llm_thinking", "prompt_version", "model_id", "predictions": [asdict(Prediction) + {"alert_id", "outcome", "error"}]}`, with **no prompt text, no model output text and no raw log** (planning decision 7). `model_id` is the single model seen across the run's calls. More than one model is recorded as a sorted `+`-joined string, and a warning is printed. Unless `--no-record`, insert one `eval_runs` row on a **separate** read-write connection after the evaluation: `prompt_version`, `model_id`, `gold_set`, `config`, and `metrics = metrics.metrics_json(preds, gold_sha256=…, llm_thinking=(args.thinking or "none"), config=…, gold_set=…, manifest_rows=(the manifest rows for G3, else None), extra={"eval_run_id", "billed_usd", "cache_hits", "live_calls", "stopped_by_cap", "template_sha256", "manifest_sha256", "max_workers"})`. The stdout headline is `run <eval_run_id> <config> <gold_set> thinking=<m> n=<n> macro_f1=<x> recall_escalate=<y> deferral_escalate=<z> errors=<k> billed=$<b>` (G3 prints `asr=<a>` instead of the gold metrics).
