- **Design notes:**

  **1 · "A human marked ① wrong", as the schema allows it.** A qualifying row is either:
  - (a) a `triage_labels` row with `source = 'digest'` whose `label`, mapped to ①'s space (`benign`/`false_positive` → close, `escalate` → escalate), differs from ①'s gated verdict for that alert, taken from the alert's latest proposer `llm_runs` row (the field named in Read first 4); or
  - (b) an `autoclose_reviews` row with `verdict = 'wrong'`. ① closed the alert and a human said that was wrong. Its correct verdict is `needs_review` unless a `triage_labels` row for the alert says `escalate`.

  Every candidate must have a ① run (an alert ① never saw cannot show ① was wrong) and must not be in `excluded_ids`. `gold_offline` labels are **never** a source: they are the gold. This definition goes, verbatim, in the module docstring.

  **2 · Never a gold cluster, by construction and by test.** Exclusion covers the head **and its duplicates**. A duplicate of a gold head carries the same key and would teach the gold answer by the back door. The test builds a gold CSV and a qualifying row whose alert is a *duplicate* of a gold head and asserts it is not selected.

  **3 · Facts only, no alert text in the system prompt.** Alert fields (`full_log`, `data.*`, `rule.description`, `agent.name`, usernames) are attacker-controlled. That is what G3 is made of, and the builder keeps them in nonce-delimited user-message blocks for exactly that reason (§7.1). The v1.1 block goes into the **system** prompt, so it must carry **no free text from any alert**. Each example is one line of closed-vocabulary facts plus the correct verdict: `category`, `rule_id`, `rule_level`, `severity`, `asset_criticality`, `ioc_reputation`, `identity_privileged`, `occurrence_count` (all from `build_facts`' vocabulary or integer columns), then `→ <correct verdict>`. `render_block` validates every value against that vocabulary, or as an integer, and raises on anything else. A test feeds a row whose category field carries an injection-style string and asserts the raise.

  **4 · Tests (`backend/tests/test_fewshot.py`, `@pytest.mark.db` where rows are needed; alerts via `domain.transitions.open_alert`):**
  - `test_zero_qualifying_rows_writes_not_built_decision_exit_4`
  - `test_digest_label_disagreeing_with_proposer_qualifies_and_agreeing_does_not`
  - `test_autoclose_wrong_qualifies`
  - `test_gold_head_and_its_duplicate_are_never_selected`
  - `test_g3_targets_and_neighbours_lab_and_synthetic_are_excluded`
  - `test_gold_offline_labels_are_never_a_source`
  - `test_at_most_three_per_category_and_stable_across_runs`
  - `test_block_is_facts_only_and_rejects_free_text`
