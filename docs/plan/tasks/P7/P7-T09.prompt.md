# Hotfix card — P7-T09 · ① reads a JSON boolean `identity_privileged` as its string

> **Card, 29/09/2026 (Director, DEC-150).** `must`, ≈ 30 min. P7-T08 stopped because of a defect, as its stop conditions require. The Director implemented the fix solo (the Owner's standing preference), and a separate reviewer session reviewed it.

## The defect (found by P7-T08, pre-existing in production)
- **What happened in P7-T08.** The first live run, B2 on G2 (`4c02f4f8`), finished with `errors=11` of 56. That is 19.6 %, above the card's 5 % stop line. Every error is `outcome=schema`: 10 `ssh_brute_force` clusters and 1 `suspicious_login`.
- **It predates the run and the signing.** Production `llm_runs` hold 121 proposer schema failures up to 29/09. Before the tables were signed, `ssh_brute_force` failed 72 of 131 runs and `suspicious_login` 24 of 88. All 121 carry exactly one message: `structured_basis.identity_privileged: expected one of true|false|unknown`.
- **Cause.**
  - `schemas.render()` shows the enum vocabulary as `identity_privileged: true|false|unknown`.
  - The model reads `true`/`false` as JSON literals and answers `true`, not `"true"`.
  - The repair round quotes the same vocabulary, so it fails the same way.
  - The alert ends with no proposal: `triage_status=unavailable` in production, an error row in evaluation.
  - It hits exactly the clusters whose identity is privileged or not (root, service accounts), which is most of `ssh_brute_force`.

## The fix
- `backend/app/llm/schemas.py` gains `normalise(name, obj)`, a new object that does not mutate its input. At an enum leaf whose vocabulary contains the spelling `true`/`false`, a JSON boolean becomes that string. In `output_schemas.json` the only such leaf is `triage_v2.structured_basis.identity_privileged`.
- `backend/app/llm/triage.py` `_parse()` calls `normalise` before `validate`.
- Nothing else changes:
  - the accepted values are the same;
  - every other mismatch still reaches `validate` and the repair round;
  - `render()` and the templates are untouched, so the template hash inside `prompt_version` and the evaluation cache keys do not change. The git-rev half of `prompt_version` moves with the fix commit, so the pre-fix B2 row is never paired with a post-fix run in `regression_gate.py`;
  - `Proposal.content` stays the raw model text.

## Tests (additions only)
- `test_schemas.py`:
  - `True`/`False` normalise to `"true"`/`"false"` and then validate clean, and the input is not mutated;
  - every other mismatch is left alone: a boolean at another enum, at an integer, or at an extra key;
  - `normalise` is the identity on all five valid fake payloads.
- `test_llm_triage.py`: a proposer answering `identity_privileged: true` is accepted on the first call, with no repair and the parsed value `"true"`.
