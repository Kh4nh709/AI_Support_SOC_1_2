## Built

TDD: the test file was written first and failed at collection (`FileNotFoundError: eval/llm_cache.py`).
Then came the module. Stdlib + `app.*` + the sibling `smoke_test`. No database, no network, no model call.

- **`fold_nonce(text)`** reads the build's nonce from the `nonce="<16 hex>"` attribute of the
  message's `<untrusted_data …>` / `</untrusted_data …>` boundary tags. It replaces every occurrence
  of that value with `NONCE` through **`smoke_test.stable_user`**. Zero nonces → text unchanged.
  Two or more distinct values → **`NonceAmbiguous`** (a `ValueError`). The error message gives how
  many nonces, never which ones, and never the text.
- **`CachingAdapter(inner, *, cache_dir, thinking, spend=None)`**:
  - `complete(*, system, user, response_format=None, timeout_s=None, model=None)` has
    `DeepSeekAdapter`'s keyword-only signature.
  - **Key** = `smoke_test.cache_key(request_model, system, fold_nonce(user), thinking)`: imported,
    not re-typed.
  - **Read** by `smoke_test.load_cached(cache_dir, key)`, the smoke test's `<key>.json` layout.
  - **Written atomically**: `tempfile.mkstemp` in the same directory → `json.dump` → flush + fsync
    → `os.replace`. The temporary file is removed on any failure.
  - `thinking` is keyword-only with **no default**. A value outside `("enabled", "disabled")` (the
    smoke test's own `THINKING_MODES`) raises `ValueError`.
  - A hit returns the recorded result and never calls `inner`.
  - A miss runs spend check → `inner.complete(..., model=request_model)` → spend record → atomic
    write → return.
  - A message with two nonces raises before anything is sent or written.
- **Where `cached` is: both.**
  1. **Attribute:** every result is a `CachedResult`, a frozen subclass of `app.llm.adapter.LLMResult`
     that adds `cached: bool` and `key: str`.
  2. **Side record:** `CachingAdapter.results` holds every returned `CachedResult` in call order.

  The harness needs (2): `llm.triage._call` copies the result into a `Proposal`, which drops the
  attribute. For per-item records under `run_bounded`, build one `CachingAdapter` per work item.
  That is cheap: they share the directory, the key locks and the `SpendGuard`.
- **An entry is a measurement** (design note 3). It holds:
  - `format`, `key`;
  - `request {model, thinking, system_sha256, user_sha256}`, where the user digest is of the folded
    message;
  - `called_at` (UTC, ms, taken just before the live call);
  - `content`, `model` (the response's), `usage`, `latency_ms`.

  No prompt text and no nonce. A hit reports the recorded usage and latency. An entry is served
  only if its `format`, `key` and whole `request` match and its fields have the right types.
  Otherwise it is a miss and is replaced whole (`load_cached`'s rule already made an unreadable
  file a miss).
- **Request model:** `model or cfg.LLM_MODEL_PROPOSER`, exactly as `DeepSeekAdapter` resolves it,
  when the inner adapter carries a real `Config` as `_cfg`. Otherwise `model=` is required
  (`ValueError`, nothing sent); `propose`/`verify` always pass it. The key uses the request model,
  never the response's `LLMResult.model`. The resolved model is forwarded, so the key and the
  request always name the same model.
- **Mode cross-check:** if the inner adapter's `Config.LLM_THINKING` differs from `thinking`,
  construction raises `ValueError`. Every entry would otherwise be filed under the wrong mode
  (DEC-042).
- **One lock per key:** concurrent misses on one key make one live call; the others are served the
  entry it wrote. So a run and its re-run give every item the same answer.
- **`SpendGuard(month_spend_usd, cap_usd, cfg)`**:
  - `check()` raises `LLMBudgetExceeded` when `month + live >= cap`. It also raises when
    `month_spend_usd()` is not finite.
  - `record(usage)` adds `adapter.cost_usd(usage, cfg)`.
  - `live_spent_usd`, and `total_usd()`, which can be handed to `DeepSeekAdapter` as `spent_usd`.
  - Hits are never checked and never recorded. Thread-safe.
- **`estimate_cost(n_alerts, calls_per_alert, usd_per_call)`** is the product of the three. A
  negative or non-finite input raises `ValueError`.
- **`refuse_if_over(estimate, month_spend, cap)`** raises **`CostRefused`** when
  `estimate > cap − month_spend`. The message names the estimate, the month spend, the cap and what
  is left, to 5 decimals. An estimate equal to what is left is allowed.
- **`run_bounded(items, fn, *, max_workers=4) -> list[Outcome]`** runs on a `ThreadPoolExecutor`.
  Outcomes come back in input order. `Outcome(index, item, value, error)` has `.ok`, and an
  exception is captured on its own item. `max_workers` outside 1..4 → `ValueError`; a non-int →
  `TypeError`.

     `git diff main --stat -- eval/smoke_test.py backend/app` literally.
2. **Nonce discovery reads only boundary tags**, not every bare `nonce="…"`.
   - The card says "attributes", and an attribute belongs to a tag.
   - `security/wrap.py` escapes block content with `quote=False`, so an attacker's own `nonce="…"`
     text survives verbatim inside a block. Matching the bare attribute would turn every such alert
     into a `NonceAmbiguous` refusal, and a G3 alert would get no verdict (a bias in ASR).
   - A real boundary cannot be forged inside a block, because `<` is always escaped. The linter
     recognises boundaries the same way.
   - Today's G3 payloads forge only a nonce-less `</untrusted_data>`, so no current case changes.
     Red (e) shows the difference.
3. **Additions beyond the card.** None of them changes the card's interface:
   - `key_for()`, the `results` side record, `CachedResult.key`.
   - `SpendGuard.record` / `live_spent_usd` / `total_usd`, and `Outcome`.
   - The per-key lock.
   - Model resolution and the mode cross-check through the inner adapter's `_cfg`. That is
     `DeepSeekAdapter`'s private attribute; a test pins it, so a rename fails loudly, and only a real
     `Config` is read, never a mock's auto-attribute.
   - Failing closed on a non-finite month spend.
   - The "foreign or malformed entry is a miss" rule.
   - `ValueError` on negative or non-finite amounts.
   - `TypeError` for a non-int `max_workers`, which ruff's TRY004 asked for.
4. **`called_at` comes from Python's clock (UTC)**, not the database. It annotates a measurement.
   Context pack §9's "time from the DB" rule is about control timestamps.

## Open questions

1. **The `_cfg` read.** Is reading `DeepSeekAdapter._cfg` acceptable, or should P7-T04 always pass
   `model=` and build `thinking` from the same `cfg`? A public `cfg` property would be cleaner, but it
   means modifying `backend/app`, which is outside this card.
2. **`response_format` and `timeout_s` are not in the key.** The card's formula is exactly model,
   system, user and thinking. `propose`/`verify` never pass `response_format` (the adapter defaults
   to `json_object`). A future caller that varied it would be served one entry for both.
3. **Wiring notes for P7-T04:**
   - Build `DeepSeekAdapter(cfg_mode, spent_usd=guard.total_usd)`, so the adapter's own cap check
     also sees the evaluation's live spend.
   - Build one `CachingAdapter` per work item.
   - `month_spend_usd` must not include this run's live calls. Summing the month's `llm_runs` is
     right, because the evaluation writes none.
   - Concurrency overshoot: the check comes before the call and the cost is known only after it. So
     a run can end past the cap by what the calls in flight at the last passing check cost: at most
     4 calls at concurrency 4 (at most 1 on a single worker, the same as `DeepSeekAdapter`'s own
     check). At the §4 prices that is below $0.02.
4. **`refuse_if_over` with a month already over the cap.** A zero estimate is still refused, because
   0 is more than a negative remainder. So a fully cached re-run in such a month would be refused by
   the estimate even though it spends nothing. I kept the literal rule. The harness can skip the
   estimate when every key is already cached.
