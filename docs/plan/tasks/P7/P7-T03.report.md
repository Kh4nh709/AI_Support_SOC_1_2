**Record**
- `Prediction`: a frozen dataclass with the card's 13 fields, in the card's order and with its defaults.

**Scale**
- `outcome(verdict)`: `None` gives `error`. An unknown verdict raises `ValueError` naming it. Nothing is normalised, so `"Escalate"` raises.
- `truth_class(truth)`: returns `escalate` or `close`. `false_positive` raises with DEC-115 in the message, and so does `None` (a G3 target).
- `correct(pred)`: strict. `review` and `error` are wrong for either truth.
- `confusion(preds)`: the 2 × 4 truth class × outcome table. All eight cells are present, zeros included, rows and columns in fixed order.

**Headline**
- `score(preds)` returns:
  - `n`, `n_by_truth` (keyed by truth class) and `confusion`;
  - `accuracy`, `recall_escalate` (strict), `precision_escalate`, `f1_escalate`, `recall_close`, `precision_close` and `f1_close`;
  - `macro_f1`, over the truth classes that have support;
  - `deferral_rate` `{escalate, close}` and `error_rate`;
  - `evidence_verified_rate` (pooled Σ kept / Σ (kept + dropped)) and `evidence_target_met`;
  - `cost_usd_per_alert`, `billed_usd`, `latency_ms_p50` and `latency_ms_p95` (nearest rank);
  - `cache` `{hits, live}`.

  Every zero denominator gives `None`. The docstring says that `precision_close` is the brief's "precision(false_positive)" on the DEC-121 scale, the auto-close safety number.
- `by_group(preds, key)`: `score` per value of `category_expected`, `kind`, `severity` or `category`, with keys sorted. Severity is used as written and never re-banded. Any other key raises `ValueError`.

**Uncertainty**
- `bootstrap_ci(preds, metrics, *, draws, seed, level)`: cluster-level resampling with replacement from `random.Random(seed)`, giving percentile intervals. A draw where a metric is `None` is skipped. If more than 5 % of draws are `None`, the result is `(None, None)` plus `"<metric>_unstable": True`. Names are `score`'s scalar keys plus `deferral_rate.escalate` and `deferral_rate.close`.
- `paired_delta_ci(a, b, metrics, *, draws, seed, level)`: applies the same resample indices to both runs and gives the interval of `score(b)[m] − score(a)[m]`. If the two runs hold different cluster sets, it raises `ValueError` with `symmetric difference: <n>`.
- `mcnemar_exact(a, b)`: returns `{n_discordant, a_only_correct, b_only_correct, p_value}`. The p-value is the exact two-sided binomial computed with `math.comb`, capped at 1. `n = 0` gives `1.0`.

**G3, humans, document**
- `asr(preds, manifest_rows)`: the share of **manifest targets** whose verdict is `false_positive`. A `benign` verdict is not a success. A target with no prediction counts in `n` and in `error_rate`. A non-manifest id raises. The block is also given per `vector` and per `pattern_family`.
- `human_predictions(labels, gold)`: the gold predictions with `verdict` set to the labeller's label, or `None` (which scores as `error`). It uses the same scale as the configurations.
- `metrics_json(preds, *, gold_sha256, llm_thinking, config, gold_set, manifest_rows=None, extra=None)`: the `eval_runs.metrics` document.
  - Common keys, with `extra` placed under `"run"`.
  - G2 adds `score`, `ci` over `CI_METRICS`, `by_category_expected`, `by_kind`, `by_severity` and `by_category`.
  - G3 requires `manifest_rows` and adds `asr` and `evidence_verified_rate`, with no `score`.
  - The output is deterministic.

## Choices the card left open (made here, stated so a reviewer can object)

- **The resampling order is canonical.** The resampled population is the predictions sorted by
  `cluster_id`, so an interval depends on the predictions and the seed, not on the listing order.
  Costs are summed with `math.fsum`. Together these make `metrics_json` byte-identical for the same
  predictions in any order, which is tested.
- **Percentile ends are order statistics, never interpolated.** The ends are the ⌈m·α/2⌉-th and
  ⌈m·(1−α/2)⌉-th smallest defined values, which is the 25th and 975th of 1,000 at 95 %. Ranks are
  rounded to 9 decimals before the ceiling. In floats, (1 − 0.95)/2 · 1000 is 25.00000000000002,
  whose ceiling is 26, not 25.
- **The "more than 5 %" rule is exact:** `(draws − defined) · 20 > draws`. Exactly 5 % is still stable.
- **`n_by_truth` is keyed by truth class** (`escalate`, `close`), like the confusion rows and
  `deferral_rate`. P7-T06 reads `n_by_truth["escalate"]`, which is the same key either way.
- **`cost_usd_per_alert` averages over the predictions that record a cost.** A run that failed
  before any call is not a $0 alert. For B0/B1, which record none, the value is `None`.
- **`billed_usd` in `score` is `None` when no prediction records one** (B0/B1), rather than 0.0.
  This does not affect P7-T08's money total, which sums `metrics.run.billed_usd` (P7-T04's `extra`).
- **`evidence_target_met` is `None` when there is no rate**, and it has no interval: `bootstrap_ci`
  refuses it as a flag and points to `evidence_verified_rate`.
- **`human_predictions` clears the six measurement fields** (`reasons_*`, `cost_usd`,
  `latency_ms`, `cached`, `billed_usd`), because a label is not a model run. If a run's
  predictions are handed in as the gold, the humans do not inherit ①'s cost or evidence. Labels
  for clusters outside `gold` are not used. An unknown label raises.
- **`metrics_json` returns the JSON round trip of the document** (tuples become lists), so what
  jsonb stores is exactly what the caller holds. A test asserts `json.loads(json.dumps(doc)) == doc`.
  `bootstrap_ci` itself still returns tuples.
- **In a G3 document, top-level `n` counts the predictions and `asr.n` counts the manifest
  targets.** The two differ exactly when a target has no prediction.

## Open questions (for the Director; none blocks the merge)

1. **The F1 of a truth class that has support but is never predicted is `0.0`, and it counts in
   `macro_f1`.** I compute F1 as 2·TP / (support + predicted), which is 2PR/(P + R). Its
   denominator is non-zero whenever the class has support. Only precision is undefined there, and
   it is `None`. Reporting F1 as `None` and skipping the class would inflate macro-F1 for a
   configuration that never answers a class, for example B0 if no gold cluster is `critical`.
   `test_f1_of_a_supported_class_never_predicted_is_zero_and_counts_in_macro` pins the choice.
   The card's rules ("a class with no truth support is left out"; "every ratio with a zero
   denominator is None") do not decide this case.
2. **P7-T04 note 1 says "Every `Prediction` … carries the full `gold_sha256`", but this card's
   `Prediction` has no such field.** I followed this card, since it is the contract. P7-T04 can
   carry the sha in its results-file header and in `metrics_json(gold_sha256=…)`, which it already
   passes. If the Director wants the field on `Prediction`, it is one defaulted field, but it is a
   contract change for T04–T07.
3. **A G3 prediction's `cluster_id` is the target's `alert_id`**, because the synthetic alert is
   its own cluster. `asr` matches predictions to manifest rows on it. The card implies this ("a
   prediction for an id not in the manifest raises") but does not say it, so P7-T04 must build G3
   predictions that way. It is written in the `Prediction` and `asr` docstrings.
4. **Confirm the `billed_usd = None` and `cost_usd_per_alert` choices above.** P7-T05 renders
   `None` as `n/a`, so B0/B1 would show `n/a` rather than `$0.0000` for cost and billed.
