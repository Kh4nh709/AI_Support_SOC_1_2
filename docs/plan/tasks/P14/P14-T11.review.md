### Issues
#### Critical (Must Fix)
- None.

#### Important (Should Fix)
1. **Only the RAG-on arm sees the decision history, which can carry same-run analyst decisions; the report neither flags nor counts it.**
   - **How it gets in:** `prompt_material` renders the stored history whenever `history.total > 0` (rag/lookup.py:661). It lands in ①'s learned section and ②'s block 10 (dossier.py:1305-1306, 1420); RAG off reads no lookup.
   - **What it counts:** analysts' decisions on earlier heads sharing the subject's key, starting with the SOAR case key, including a concluded case's status (rag/history.py:7-19). For a case, any head match counts (:29-30).
   - **Why same-run rows get in:** self-exclusion removes only the subject, its case and that case's alerts (:32-33). Earlier alerts and cases of the **same test run** are counted.
   - **Effect in the lab:** the history is stored at lookup time, so it is time-correct. But when analysts escalate and conclude as the attack unfolds, a later subject's RAG-on prompt can read e.g. `escalated_open 3` or `confirmed_incident 1` for the same attack.
   - **Why it matters:** the correlation exposure already ruled on reaches both arms; this one lifts only RAG on, so it inflates exactly the RAG-on − RAG-off difference the thesis reports. `leak_flags` (lab_measure.py:338-363) looks only at `Seen.matches`, and `Seen` (:193-212) drops the history, so the report can't even say which subjects had one.
   - **Fix:**
     - keep `history.total`, `last_seen` and `examples` (alert ids, rag/history.py:325-326) in `Seen`;
     - flag e.g. `history_same_run` when an example lies in the subject's run(s) or `last_seen` ≥ the run's `starts_at`;
     - count per tier the RAG-on prompts that carried a history;
     - add it to the correlation caveat the next round adds.

#### Minor (Nice to Have)
1. **Test gap on the boundary the measurement uses on every case** (test_lab_measure.py:349-350, :1195).
   - The strict `<` of `_PREVIOUS_RUN_BEFORE_SQL` (dossier.py:532-539) at exactly `as_of` is never tested. The unit test puts its runs at cut ± 5 min. The lab test asserts only that `PREVIOUS-RUN-AFTER-AS-OF` is absent, while `FIRST-RUN-OF-C1` sits exactly at `as_of` (:885) and is never asserted.
   - A `<=` in that one statement passes the whole file. Because `as_of` is always the first run's own `created_at`, that would put the product's first ② answer into both arms.
   - The report's "strictness" mutation only turned tests red through the notes and events at the cut.
   - Fix: assert `"FIRST-RUN-OF-C1" not in prompt` at :1195, and add a run at `cut` in the unit test.
2. **Coverage, mean best match and leak flags describe the stored lookup, not the prompt** (lab_measure.py:540-551).
   - The prompt can carry less than the stored lookup:
     - `prompt_material` drops matches whose entry is inactive or whose hash changed (rag/lookup.py:653-659);
     - the budget can drop the whole section (`learned_used`);
     - a lookup read that hits a database error is silently treated as no lookup (investigate.py:537-556).
   - A subject whose material never reached the prompt is still reported as covered. Rare with 40k/60k budgets, but real if an entry is merged or retired before measuring.
   - Fix: decide "applied" from the evaluation (`rag_lookup_id` on both evaluation types, `rag_not_applied` on ②), and count matches after the same active/hash filter. This also removes `seen_of_case`'s second copy of the "newest decides" rule.
3. **Exit 6 and the cap message count only `cap`** (lab_measure.py:1211-1222).
   - ①'s `verifier_cap` (tier1/triage.py:452-463) is also a guard refusal. A run whose cap falls on its last verifier call exits 0, and the message undercounts.
   - A run where every call is `unavailable` (a 402) also exits 0 with nothing answered.
   - Fix: count both outcomes; consider a non-zero exit when nothing was answered.
4. **A paid run can end with no report** (lab_measure.py:664-679, :1201-1202).
   - A `psycopg.Error` mid-run ends the command before `build_measure_report`.
   - An unwritable `--out` fails only after the last call.
   - Ctrl-C loses everything.
   - In each case the spend is recorded nowhere.
   - Fix: check `--out` before the gate, and write the rows gathered so far, marked partial.
5. **The report header shows the current thresholds, not the ones the lookups used** (lab_measure.py:869-874). It prints the thresholds and `RAG_RERANK_MODEL` from this `--env-file`, but the RAG-on lookups were filtered and levelled with the values in force when they ran. Label the header accordingly.
6. **Unpaired arms** (lab_measure.py:259-291, :623).
   - Each arm's rates are over its own `answered` set, so off and on can be scored on different subjects. A paired line over subjects answered in both arms would make the comparison exact.
   - ①'s `verifier_*` outcomes carry `proposed_verdict` but are left unscored. They are visible in `no_answer`; worth one sentence in the report.
7. **Duplicated `held_by` rule.**
   - `_held_by` (investigate.py:617-625) re-implements `investigation_view.held_by` (investigation_view.py:286-299).
   - The equality test (test_lab_measure.py:258-316) skips `high_severity_injection_finding`.
   - Fix: keep one implementation and add a high-injection case.
8. **Nits.**
   - investigate.py:877 has an `assert` in the job's control flow; under `-O` it is stripped and the code reaches `raise None`.
   - :840 builds a new `UnknownCase` just to get its text, and drops the old `from exc` chain.
9. **Unplaceable entries pass silently** (lab_measure.py:352-354). A matched entry the database lacks, or one with a NULL `approved_at`, skips `after_cutoff` without a trace; count such matches as "unplaceable".
10. **File size.** eval/lab_measure.py is 1,466 lines and holds two commands that share only the plumbing. `calibrate` (:1228-1402) would stand alone as `eval/lab_calibrate.py`. Its siblings are 1,171 and 1,282 lines, so this is not blocking.
