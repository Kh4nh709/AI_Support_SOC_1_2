#### Important (Should Fix)
1. **The run page can show a label and counter the server does not hold** (LabRunPage.tsx:71-77; contradicts the claim at LabAlertRow.tsx:9-10).
   - **What's wrong:** `labelled` writes the label into the infinite query's cache with `setQueryData` but does not cancel a fetch of the same key that is already out.
   - **Triggers are ordinary:** every background refetch re-reads all loaded pages:
     - on mount of a cached run, i.e. going back into a run within the cache lifetime;
     - on window focus;
     - on reconnect.

     All three are on, because `api/queryClient.ts:12` sets only `retry` and `staleTime` is 0.
   - **Effect:** if a PUT or DELETE succeeds while such a refetch is out, and the refetch read the alert's page before the write, the refetch lands afterwards with the pre-write snapshot.
     - The row and "Đã gán x/y" revert to their state before the write.
     - Later labels then move the counter from the wrong starting count.
     - It corrects itself only at the next refetch.
   - **Confirmed by a focused test** on an export of d89c3d0: two pages loaded, a focus refetch with page 2 held, then a label on row 2, then release.
     - After a TP: the server holds `true_positive`, the row shows "chưa gán", the counter shows "Đã gán 1/3" (expected TP, 2/3).
     - After "Bỏ nhãn": the server holds no label, the row shows "TP", the counter shows "Đã gán 1/3" (expected chưa gán, 0/3).
   - **Why it matters:** this is the named failure ("the UI showing a label the server does not hold") by a different route than a double click. It is not Critical because the server always keeps the admin's latest write.
   - **Fix:** in `labelled`, call `await client.cancelQueries({ queryKey: key })` before `setQueryData` (TanStack's documented pattern). Alternatively, when `client.isFetching({ queryKey: key }) > 0`, follow the cache write with `invalidateQueries({ queryKey: key })` so the read that lands is served after the write.
   - **Regression test:** the test I ran can be adapted: /tmp/claude-1001/-project-project-AI-Support-SOC-1-2/0bb456f5-e8e1-406d-8ede-1e60a8cc5f36/scratchpad/t10-review/tree/frontend/src/features/admin/LabRunRace.test.tsx
   - **Also consider** `refetchOnWindowFocus: false` on this query: every focus re-reads every loaded page (up to 100 alerts with 32 KB raw logs each per page), which is the reload the design avoids on a label.
