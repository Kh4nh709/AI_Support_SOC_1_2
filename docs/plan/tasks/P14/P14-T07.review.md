#### Important (Should Fix)
- **`backend/tests/test_queue_rag.py:365`: the blind-arm DB test fails without any leak about one run in twenty.**
  - **What's wrong.** `assert "87" not in text.replace("-", "")` searches the whole dumped view for the digits "87".
    - The blind view keeps `first_seen_at`/`last_seen_at` (queue.py:634-635), which are set by `DEFAULT now()` (schema.sql:210-211). Inside the `db` fixture's transaction they share one random microsecond value, and `json.dumps(..., default=str)` writes all six digits. I computed that 49,401 of 1,000,000 microsecond values (4.94%) contain "87".
    - The alert id is `p4t02-{n}`, from the module-level `itertools.count()` in tests/test_queue.py:104, which this file imports (test_queue_rag.py:30). After `replace("-", "")` it reads `p4t02{n}`. 20 of every 1,000 counter values (87, 187, …, 870-879) put "87" in it, so adding or removing any earlier test can make it fail every time.
  - **Why it matters.** `make test-db` is every task's gate, with only the 2 libxml failures allowed. This test would report a blind-arm leak that isn't there.
  - **Fix.** Drop the substring line and assert on keys instead, e.g. `{"rag", "best_pct", "not_applied"}.isdisjoint(_walk_keys(view))`, keeping the existing `"rag_not_applied"`/`'"auth"'` checks.
