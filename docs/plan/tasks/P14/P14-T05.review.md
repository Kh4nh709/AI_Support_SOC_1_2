### Issues
#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. **vector_index.py:192-196: a malformed `DATABASE_URL` prints its password.**
   - **What's wrong:** only `psycopg.OperationalError` is caught around `infra_db.connect()`. A malformed `DATABASE_URL` (an unescaped `%` or `@` in the password, or a mistyped scheme) raises `psycopg.ProgrammingError` instead.
   - **Check I ran:** with the venv's psycopg, both `postgresql://app:s3cretPW%zz@db:5432/soc` and `postgresql//app:s3cretPW@db:5432/soc` raise `ProgrammingError`, not `OperationalError`, and `str(exc)` contains `s3cretPW`.
   - **Why it matters:** that exception is neither `ConfigError` nor `RagUnavailable`, so it escapes `main()` and the interpreter prints the traceback with the password on stderr.
   - **Context:**
     - `vector_store.connect` already gets this right (vector_store.py:118).
     - The project fixed the same pattern in INT-T03 ("any psycopg.Error is one generic line", 662e446).
     - The trigger is a misconfiguration, and the documented `exec rag-worker` route needs that container up, so in practice the exposure is low.
   - **Fix:** catch `psycopg.Error` there, ideally once in `main()` with one generic line and exit 1. Add a `ProgrammingError` case to test_rag_vector_index.py:446.

#### Minor (Nice to Have)
1. **embed.py:104-137: a retirement can still be lost after the re-look.**
   - **What's wrong:** the worker runs the handler and `finish_job(succeeded)` in one transaction (worker.py:105-107), and `enqueue` is single-flight over pending and running jobs (jobs.py:92). The job's last read of the entry takes no lock: `entry_by_id` on the unchanged path (:104, :113), `_state` after the call (:120, SQL at :92).
   - **Effect:** a `retire_published` that commits after that read and before `finish_job` gets `DO NOTHING` from its enqueue. The job then upserts, or keeps, the vector of a now-retired entry, and no job is left to delete it; only `--rebuild` does.
   - **Why only Minor:** T06's re-check bounds the cost to a wasted candidate.
   - **Fix:** read with `SELECT ... FOR SHARE` in `_state`, and call it on the unchanged path too. `retire_published` locks the same row `FOR UPDATE` (publish.py:586), so it either commits before the re-read (seen, so Reschedule) or waits for the job's commit, after which its own enqueue succeeds.
2. **vector_index.py:126: `rebuild` reads in the unsafe order.** It reads the active entries before the stored rows; `check` reads them the other way (:108-111).
   - An approval whose job upserts between the two reads becomes an "orphan" and is deleted (:127-129). The result is an active entry with no vector and no pending job.
   - A retirement whose job deletes between the two reads is re-embedded.
   - **Fix:** read `stored` first, as `check` does. Both cases then become harmless.
3. **Two tests assert nothing on pgvector.** test_rag_embed_job.py:194 and test_rag_vector_index.py:308 assert only in their memory variants, and those check a call count, not the "before the first read" order their names claim. Nothing shows that the job itself creates a missing table on real pgvector (deviation 2). Add a job test that drops `entry_vectors` first, like test_rag_vector_index.py:354 does for the CLI.
4. **The "changed during the call" tests use the job's own transaction.** test_rag_embed_job.py:453 and :479 make the change on the job's connection, so they cannot catch a regression in how a concurrent commit becomes visible (db.py:48 is a plain `BEGIN`). A two-connection variant would pin it.
5. **voyage.py:167 and :198: a bare `str` is accepted.** A `str` passes as `texts` or `documents` because it is a `Sequence[str]`, so `list("abc")` sends one input per character. Guard with `isinstance(texts, str)` before T06 adds callers.
6. **embed.py:113: `stored(vconn)` scans the whole table for one id.** The report flags this itself. A one-row reader would do.
7. **embed.py:65-73 is a third copy of the `SET LOCAL idle_in_transaction_session_timeout` statement.** The others are rag/lookup.py:131-135 and rag/draft.py:765-769. Fold them into one helper when T06 opens lookup.py.
8. **Shared test doubles are imported from other test modules.** test_rag_embed_job.py:42-43 and test_rag_vector_index.py:35 import from `tests.test_rag_publish` (with `# noqa: F401`/`F811`) and `tests.test_rag_voyage`. Move them to a helper module (`tests/rag_data.py`, `tests/vector_data.py`).
9. **test_rag_worker.py:117: misleading name.** The name says the rag worker has a timeout-table entry for `knowledge_embed`, but it has none (`embed.py` declares no `STATEMENT_TIMEOUT`) and the test asserts nothing about rag timeouts.
10. **infra/worker.py:61: stale docstring.** It still says the rag-worker passes `[["rag_lookup"], ["knowledge_draft"]]`. This file is outside the card's list, so it is for the docs card.
