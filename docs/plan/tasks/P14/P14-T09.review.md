1. **`backend/tests/test_admin_lab_api.py:52-53,73-74`: any failing test in this file prints the full DSN, password included.**
   - `World(str(scratch_dsn), ...)` turns the `conftest.Dsn` into a plain `str`. That type's `__repr__` is redacted precisely because "pytest prints a failing test's arguments with repr()" (`conftest.py:70-71`), and every test in the file takes `world`.
   - Check I ran: a scratch pytest in my scratchpad with the same NamedTuple. On failure it printed `World(dsn='postgresql://soc:FAKE-PASSWORD-123@…')`. Keeping the `Dsn` type printed `soc:***` instead.
   - **Impact:** this breaks "No DSN is ever printed" on any host whose `TEST_DATABASE_URL` carries a password.
   - **Fix:** `World(scratch_dsn, ...)` with `dsn: conftest.Dsn`.
   - The pattern was copied from `backend/tests/test_admin_labels_api.py:103`, which leaks the same way. That one is pre-existing and takes the same fix.

#### Minor (Nice to Have)
3. **`backend/app/lab/runs.py:126-146`: `create_run` is atomic with its event only when the caller already has a transaction open.**
   - In psycopg 3.3.4, `Transaction._push_savepoint` (`transaction.py:215`) turns `with conn.transaction()` on an IDLE connection into the outer BEGIN/COMMIT. The run is then committed before `write_event` runs (`:139`).
   - That contradicts `runs.py:10` ("commits nothing") and `admin_lab.py:43` ("land together or not at all").
   - **Production is safe:** `deps.current_user` calls `auth.verify`, which SELECTs on the same `Conn` first (`deps.py:110`, `infra/auth.py:214`).
   - **The tests do not model this:** they override `current_user` (`test_admin_lab_api.py:91`), so POST runs on an IDLE connection. A POST copy of the PUT failure-injection test at `:618` would fail under this harness, and none exists.
   - `tier1/labels.py:537` has the same shape.
   - **Fix:** move `write_event` inside the `with` block, and add the POST twin of the `:618` test.
4. **`admin_lab.py:125-137` and `runs.py:98-103`: some valid ISO instants give a 500 instead of a 422.**
   - Instants such as `0001-01-01T00:00:00+14:00` and `9999-12-31T23:00:00-14:00` pass validation. Postgres stores them, then psycopg's loader raises `DataError` on `RETURNING` (`psycopg/types/datetime.py:691-694`: BC, or after year 10K).
   - Check I ran: `.astimezone(UTC)` on both raises `OverflowError`.
   - The savepoint rolls back, so no row is left behind.
   - **Fix:** in `_instant` and `_check_time`, normalise to UTC and map `OverflowError` to `invalid`.
5. **`backend/app/lab/labels.py:96-122`: `set_label` accepts a duplicate alert, not just a queue head.**
