### New Breakage in the Fix Diff
1. **Minor: the M3 refocus takes the focus from wherever the admin put it** (LabRunPage.tsx:79-86, 172-175).
   - **Cause:** any press of "Tải thêm" sets `refocus`. When the read ends, `loadMore.current?.focus()` runs unconditionally, with no `preventScroll`.
   - **Scratch test B:** press "Tải thêm", then focus a row's button while the page loads. When the page lands, the focus is on "Tải thêm", and `focus()` was called with `[]`. On the round-0 page files the focus stays on the row's button, so this is new.
   - **Scratch test A:** a TP that cancels an in-flight "Tải thêm" moves the focus off that TP button to "Tải thêm" at once. This is the very flow the report's Concerns describe.
   - **In a browser:** without `preventScroll`, the browser scrolls to the button whenever the focus moves there. The code's own premise is that a disabled button drops its focus, so the focus does move. After an appended page the button sits below the rows just loaded, so the view jumps past them.
   - **Untested:** the covering test, LabRunPage.test.tsx:905 ("gives the focus back"), still passes with the `focus()` call deleted (`Tests  1 passed | 74 skipped (75)`). jsdom keeps the focus on a button that becomes disabled.
   - **Fix:** refocus only when `document.activeElement` is `body` or null, and pass `{ preventScroll: true }`. Alternatively, keep the button `aria-disabled` with a guard in `onClick`, so it never loses focus.
2. **Minor: trade-off of the ruled pattern.** A label during a mount or reconnect refetch throws away that read's news from elsewhere (LabRunPage.tsx:74, 94).
   - The revert keeps this page's own labels, but restores the cached snapshot. That snapshot can be as old as the cache lifetime.
   - What is lost: labels set since by another admin or tab, and alerts that arrived in an open window.
   - With focus refetch off, nothing reads again until a reload. Reopening the run is the same mount refetch, and a quick label cancels it again.
   - A row changed elsewhere then shows a label the server does not hold. Labelling it moves the counter by a delta the server did not apply.
   - The report's Concerns cover this only in part.
   - **Fix:** when the cancelled read was a full refetch (not a "Tải thêm"), follow `setQueryData` with `invalidateQueries({ queryKey: key })`.
3. **Minor (nit): labModel.test.ts:375 asserts the two names are absent** from both the sources and the strings.
   - A future `fieldReason.invalid` that a page really reads would fail this test.
   - The `it.each` at labModel.test.ts:370 already catches a string nobody reads.
