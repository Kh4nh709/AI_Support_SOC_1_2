## 1 · Built

- `backend/app/tier1/queue.py`
  - `list_queue(conn, *, page, page_size, band=None, category=None, agent=None,
    status="queued", actor_id=None) -> QueuePage`. The filters are ANDed.
    - `status="queued"` is `a.status = 'queued_tier1'` (today's behaviour, and the default).
    - `status="mine"` is `a.status = 'tier1_active' AND a.acknowledged_by = %(actor_id)s`.
    - `NOT a.is_synthetic` stays in every variant.
  - `_QUEUE_SQL` now uses named parameters (`%(retriage_factor)s`, `%(limit)s`, ...) and a
    `WHERE {where}` slot. `_filters(...)` builds the `WHERE` from a fixed list of fragments
    (`_STATUS_WHERE`, `_band_sql`) and a params dict. No user value is formatted into SQL. The
    only `str.format` inputs are those fixed fragments.
  - The band: `BAND_CODES = ("low", "medium", "high", "critical")`, in `_BANDS` order.
    `_band_bounds(band)` derives the inclusive score bounds from `_BANDS` (the constant
    `risk_band` itself reads), open on the outer side of the end bands, because `risk_band`
    clamps. An unknown band raises `ValueError`. There are no literal thresholds.
  - `counts_by_band` is one grouped query,
    `SELECT <CASE over _BANDS> , count(*) ... WHERE <filters without band> GROUP BY 1`. The CASE
    is built once at import from `_BANDS`/`BAND_CODES`, and its bounds and codes travel as
    parameters. A NULL-score head groups under NULL and lands in no band. All four keys are
    always present (zero-filled), ordered critical, high, medium, low.
  - `QueuePage.counts_by_band: dict[str, int]`, with a zero-filled default so callers that build
    a page by hand (`test_pages_alerts.py:331`) are unchanged.
  - The blind-arm strip is unchanged: every row passes `visibility.strip(mode="analyst")` on
    every filtered path.
  - `ValueError` for: an unknown band or status, `status="mine"` without an `actor_id`, a NUL byte
    in `category` or `agent`.
- `backend/app/web/routers/tier1.py` `get_queue`: new query params `band`, `category`, `agent`,
  `status` (default `queued`); `del claims` is gone, the route passes `actor_id=claims.user_id`;
  `ValueError` becomes `HTTPException(422, str(exc))`; the response gains `counts_by_band`.
- `backend/tests/test_queue_filters.py` (new): 25 tests, all `db`.

## 4 · Deviations

1. **Two band vocabularies, kept apart.** The row's `risk_band` stays the Vietnamese label
   `queue.risk_band` returns today (`Thấp/Vừa/Cao/Rất cao`), because "unfiltered = exactly today's
   rows" and `test_queue.py` pins it. The filter and `counts_by_band` speak the four codes the plan
   names, `low|medium|high|critical`, mapped by position in `BAND_CODES` (`Thấp`=low, `Vừa`=medium,
   `Cao`=high, `Rất cao`=critical). The test file pins that mapping with a literal table. **P10-T08/T09
   must map a row's Vietnamese `risk_band` to a code (or keep showing the label) when a chip is
   selected.** A third, unrelated `risk_band` exists in `llm/builder.py` (`low|medium|high|very_high`);
   it is not used here, because `queue.risk_band` is the one that produces the row's field.
2. `QueuePage.counts_by_band` has a zero-filled default (the brief gives none). Without it,
   `test_pages_alerts.py:331` (`QueuePage(rows=..., total=..., page=..., page_size=...)`) would
   break, and that file must stay unchanged.
3. `status="mine"` with no `actor_id` raises `ValueError` (the brief is silent; the alternative,
   `acknowledged_by = NULL`, would silently return nothing). The route always passes `claims.user_id`.
4. Extra guard: a NUL byte in `category` or `agent` raises `ValueError`, so the route answers 422
   instead of a driver-level 500.
5. The route types `status` as `str` (not `Literal`) so an unknown value takes the same
   `ValueError` to 422 path as an unknown band, with a `{"detail": "<message>"}` body as the brief
   says. The call carries a one-line `# type: ignore[arg-type]`.
6. `alerts_pages.py` (the Jinja queue) calls `list_queue(conn, page=page)`, so it now also runs the
   grouped counts query and discards it: one cheap extra query per Jinja queue render, until T13
   retires the page.
7. The brief names the test helper `_insert_alert`. `test_queue.py`'s equivalent is `_queued`; it is
   copied under the brief's name, with `first_seen_at` set to an ever-later instant (deterministic
   ties) and an optional `acknowledged_by`.
8. `test_synthetic_rows_never_listed` was written up front (the brief allowed adding it first), so
   red step 1 shows it red directly.

Not deviations, but a limit worth knowing: an empty `band=` or `status=` in the query string is
"unknown" and gets a 422, so the client must omit an unset filter rather than send it empty.
