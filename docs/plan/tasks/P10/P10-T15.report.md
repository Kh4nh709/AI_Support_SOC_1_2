## 1. Built

**The key.** `Config.DEDUP_ENABLED: bool = True`, read by a new `_parse_bool`/`as_bool` in the style of `_parse_enum`: `true|false`,
`1|0`, `yes|no`, `on|off` (any case, spaces trimmed); an empty value is unset (the module's rule) and gives the default; anything
else is a `ConfigError` naming the key, never a silent default (a typo such as `flase` must not leave grouping in a state nobody
chose; `web/worker.py` fails fast on a bad config, so it stops the worker at start). It is registered where the key set is pinned:
context pack §6.3 (the single source, `scripts/gen_env_example.py::keys_from_pack()`), which makes it a 57th contract key, and the
generated block of `.env.example` (`DEDUP_ENABLED=true`, with a comment). `make lint` checks the two against each other.

**The switch.** In `soar/pipeline.py::_process` the advisory lock, the head lookup, the bump and the `duplicate` branch are now under
`if config.load().DEDUP_ENABLED:`. With the flag off none of the three `dedup` calls runs, and the alert falls through to the
non-duplicate path that already existed: `open_alert(kind="received")`, `start_enrichment`, `finish_enrichment` (its own enrichment,
`risk_score` and `triage` job), or `open_alert(kind="auto_closed")` when an auto-close rule matches. `config.load()` is called per
alert, the pattern `_suggestion_visible` already follows for `EVAL_BLIND_FRACTION`. With the flag on the code path is the same code,
in the same order: nothing else moved. Receipt-level idempotency is upstream (`intake`'s `ON CONFLICT (manager_id,
source_alert_id) DO NOTHING`, then `Duplicate`, then a 409) and was not touched.

**The queue.** `tier1/queue.py`: `alert_user` and `srcip` are in `_QUEUE_COLUMNS` and in the SELECT (after `agent_name`). The order,
the filters, `total`, `counts_by_band`, R17 and the DEC-164 sort (`QUEUE_ORDER_BY`) are untouched. Neither field is derived from ①
(R12), so `visibility.strip` needed no change and both stay on a blind, undecided row while the `ANALYST_HIDE` keys still go.
`alert_user` is nullable and `srcip` is `TEXT NOT NULL DEFAULT ''`; the API passes both through raw.

**The page.** `QueuePage.tsx` has two new columns right after Agent, "User" and "IP nguồn" (`S.queue.col.user`, `S.queue.col.srcip`
in `strings.ts`), neither sortable, and the ① column is still the last. A null user, an empty or missing source IP shows
`S.common.missing` ("—"), on blind and visible rows alike. `QueueRow` gained `alert_user?: string | null` and
`srcip?: string | null` (optional, so a page that meets an older server shows a dash). No `dangerouslySetInnerHTML`, no
`localStorage`; the value is rendered as text.

**The runbook.** A new `### Grouping switch (DEC-165)` after the Environment keys table and before `## Alarms`, self-contained: what
the key does, the Owner's command (`DEDUP_ENABLED=false` in `.env`, then `docker compose up -d --force-recreate app worker`, and
`docker compose exec -T worker printenv DEDUP_ENABLED` to confirm), why `restart` is not enough, what to expect, that the switch is
**forward-only** in both directions, that receipt idempotency is unchanged, that ① then runs once per alert (watch the spend row
against `LLM_MONTHLY_USD_CAP`), and a check to run an hour later. Nothing else in the file was edited.
