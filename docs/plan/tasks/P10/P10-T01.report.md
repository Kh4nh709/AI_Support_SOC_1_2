## Deviations

- **R4 is applied, but it does not decide the no-token test.** `deps.current_user` returns 401
  ("not authenticated") for a request with no token *before* it calls `auth.verify`, so with
  `config.Config()` defaults the no-token case is already 401, not 503. Only a request that carries a
  token reaches `verify`, where an empty `JWT_SECRET` raises `AuthDisabled` (503). I applied R4's
  `dataclasses.replace(config.Config(), JWT_SECRET="test-secret")` in the fixture as directed, and added a
  fourth test, `test_me_with_a_bad_token_is_401`, so the fixture has a test that fails without it
  (the R4 red step above). The brief said "3 passed"; it is 4.
- **`backend/tests/test_auth.py` edited (not in the card's file list).**
  `test_routers_are_discovered_sorted_and_auth_routes_exist` pins the exact set of routes on the auth
  router, `{"/api/auth/login", "/api/auth/logout"}`, so adding the route turned it red in `make test`.
  It now expects `/api/auth/me` too, and asserts the OpenAPI method set for `/api/auth/me` is `{"get"}`.
  This is the "frozen routes change where the plan says so" case: the plan adds this route.
- **`make test-db` was not run through `make`.** The harness for this worktree refuses `make` with a
  runtime-computed `TEST_DATABASE_URL` and refuses `eval "$(dsn_env.py ...)"`, and the brief forbids
  creating a `.env` here. I ran the target's own pytest command instead —
  `-m "db and not live" -rs backend/tests` with `TEST_DATABASE_URL` and `PGHOST/PGPORT/PGUSER/PGPASSWORD`
  set as plain environment prefixes (the same variables `dsn_env.py` exports), so the tests that build
  scratch databases with a bare `createdb` reached the same cluster. `pgrep -fc` showed no other
  concurrent pytest run. Nothing in the result depends on `make` itself.
- `test_auth_me.py` is the brief's file with three differences: `import dataclasses`, the R4 fixture
  line, and the added fourth test. The route is the brief's code verbatim.
