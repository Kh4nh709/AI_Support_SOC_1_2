## 1. Built

**`backend/app/web/routers/pages.py`.** `GET /` is `home()`: no session → `303 /login` (`page_user`); admin → `303
/admin/rules`; tier1 and tier2 → the page `new_ui.html`, h1 "Dùng giao diện mới tại cổng 8080". `POST /login` and `GET /login`
(signed in) answer `303 /` and let `/` decide. The link is `new_ui_url(host_header)`: the request's own `Host` with the port
swapped for `NEW_UI_PORT = 8080` (`127.0.0.1:8000` gives `http://127.0.0.1:8080/`; a LAN address likewise); never a hard-coded
address. The header is checked with one strict `fullmatch` (DNS labels or IPv4, or a bracketed IPv6 checked by `ipaddress`,
at most one `:port` ≤ 65535); a header that carries a path, query, fragment, userinfo, a second port, whitespace, control or
non-ASCII characters is refused as a whole — the page then has no link and echoes nothing of the header, only names the port.
`X-Forwarded-Host` is deliberately not read (the app is reached directly on 8000). The URL goes into the template through
autoescape. `NEW_UI_PORT` is tied to `docker-compose.yml`'s `127.0.0.1:8080:80` by a test.
