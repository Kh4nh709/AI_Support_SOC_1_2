### Findings
1. **Important (outside the card's diff): ⟳ leaked "① ran" on blind rows.**
   - ① is the only first-time writer of `alerts.triaged_count`. `needs_retriage` is `triaged_count > 0 AND occurrence_count >= 10 × triaged_count …`, and the queue sorts by it first.
   - So on a blind head with 12 occurrences, ① finishing turned ⟳ on and moved the row to the top of the queue. That is the side channel R12 closed for NOTIFY.
   - The Jinja queue leaked the same way.
2. **Minor.** Each flush called `invalidateQueries` with the default `cancelRefetch: true`. Under a steady stream with slow answers, every fetch was aborted and the list froze. Reproduced: 9 answers, 0 applied.
3. **Minor.** Axe did not cover the empty state or `LiveIndicator`.
4. **Minor.** A page load cost two fetches (the mount plus the resync), and `failures` reset on `ready`, so a server closing right after `ready` got about one reconnect a second.
5. **Minor (docs).** The blind arm was called "per person"; it is per alert (a sha256 of `alert_id`, `soar/pipeline.py`). The report named the wrong branch. The ⟳ glyph was a literal.

**Cross-card note for P10-T10.** `QueryClient.clear()` empties both the query cache and the mutation cache when the token ends. The reason draft must live outside both.
