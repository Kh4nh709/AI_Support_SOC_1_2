### Verified

**Token storage**
- The token lives only in memory and in `sessionStorage["soc.session"]`.
- Non-test source contains no `localStorage`, `console.`, `token=` or `innerHTML` (R5).
- `ApiError`'s message is the status code only.

**Cross-tab sharing**
- A `session` answer is accepted only while this tab is asking.
- `parseSession` validates the token, role and expiry.
- `/me` then confirms, and a 401 clears.
- Logout is broadcast. Receivers forget without rebroadcasting, and a 401 is not broadcast.

**Expiry and routing**
- An expired entry is dropped on load, and a timer clears the session at `expiresAt`.
- `RequireRole` waits for `ready` (that is, for `/me`).
- `Authorization` is added only to the path-absolute `/api` + path URL.

**Test quality**

**Red steps reproduced**
- `localStorage` in `saveSession`: 9 red.
- The 401 hook removed: 5 red.
- The `//` return-path guard removed: 1 red. With the guard, `from=//evil.example/x` lands on `/queue`.

### Findings (all Minor)
1. **Logout hangs on a stalled backend.** It waits for `POST /auth/logout` before clearing locally. The user can walk away believing they are signed out.
2. **The return-path check accepts `"/\t/evil.example"`.** react-router 8.4 refuses the external navigation, so there is no open redirect, but the app blanks. Only the `//` case is tested.
3. **`expires_at` from login and `/me` is not validated.** When missing, it gives a `setTimeout(NaN)` loop and the session never expires client-side. This is hypothetical; the backend always sends it.
4. **The stored role is shown in the header before `/me` confirms.** A non-401 `/me` failure keeps it, but the API enforces every role, so this is display only.

## Follow-up under R14 (`954848f..d37ef98`), merged after `eb8b591`

All three Minors were fixed, each with a test and a red step:
1. **Logout order.** Logout now clears locally, broadcasts to the other tabs and navigates first. It then POSTs with the old token, aborting after 5 s.
2. **Return path.** `isLocalPath` rejects:
   - control characters;
   - any backslash;
   - `//`;
   - anything the URL parser would resolve off-origin or to a scheme other than http(s).
3. **Expiry.** `parseSession` is exported and applied to the results of both `/me` and login. A missing, null, non-date or past expiry now gives no session and no NaN timer.

Tests: 222 in total, 39 new.

**Scoped re-review: all ADDRESSED, no new breakage.** The Reviewer re-probed three things:
- A hung logout: 1.5 s later the page is on `/login`, storage is empty, the other tabs have logged out, and the POST still carried the Bearer.
- `from=/\t/evil.example/x`: it now lands on `/queue` instead of blanking the app.

**Accepted trade-off, which fails closed.** The backend's logout sets `sessions_invalid_before = now()`. So if a slow logout POST reaches the server after the user has already logged in again in the same window, the new token is killed and the user is sent to `/login` once. This goes in `docs/limitations.md`.
