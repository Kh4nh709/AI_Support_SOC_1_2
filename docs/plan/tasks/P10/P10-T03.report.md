## Deviations

- **Credentials by a temporary `PGPASSFILE`, not `PG*` variables with a password.** The harness refuses
  `eval "$(dsn_env.py ...)"` and `make` with a run-time-computed DSN, and the brief forbids `.env` here
  and forbids printing the password. A `pgpass` file under `/tmp/p10t03-pg/` (written without printing it)
  with `PGPASSFILE`, `PGHOST`, `PGPORT`, `PGUSER` and a password-less `TEST_DATABASE_URL` reached the
  same cluster. The directory is removed at the end.
- **The one failing db test, `test_the_cron_line_itself_writes_a_dump`.** `_cron_env` in
  `test_backup_restore.py` takes the password from the DSN only, and my DSN carries none, so the `psql` it
  starts in a clean environment has no password. It is an artefact of this credential method, not of the
  change: the test reads nothing this card touches. I did not work around it, because the only fix is to put
  the password in the DSN. Expect it green on a run that has one.
- **`_render_state` in `case_analyze_pages.py` now takes the whole `body` dict** instead of the separate
  investigation pieces, and renders `investigation=` all of it but `current` and `current=` beside it,
  the context the template always had. On a POST success the router passes a synthetic running body
  (`{"state": "running", "run_id": ..., "minutes": None, "run": None, "current": None}`) so that path
  still makes no extra database read, as before.
- **More tests than the brief's nine**: 25, listed under Built. The extras are the edge cases the moved
  code has (stall bound, hint, malformed id, no snapshot, no conclusion, `forced_by`, `case_open` for
  every status).
- **`run_id` is `null` on a `done` state.** The moved `derive_view` never set it there (it sets it for
  `running` and `stalled` only; a done state carries the run under `run`). Kept verbatim, and
  `test_done_run_has_evidence_marks_and_labels` asserts it (`body["run_id"] is None`).
- **A malformed `run_id` on the JSON route is a 422** (FastAPI's `uuid.UUID` parameter), where the Jinja
  page treats it as absent (`_parse_uuid`). The two routes differ only there.
- **`test_a_result_without_a_conclusion_is_labelled_unknown` replaces an "unknown code" test.**
  `ck_llm_runs_suggested_conclusion` only stores the four conclusions, so a raw unknown code cannot be
  seeded; a result with no `suggested_conclusion` key can.
- `test_json_and_html_agree` computes `evidence_check` (with `original_conclusion`) before inserting the
  run, because `llm_runs` is append-only and cannot be updated afterwards.
- One test imports `REJECT_TEXT` lazily from `app.tier2.investigation_view` so a change to
  `MIN_QUOTE_CHARS` is followed rather than hard-coded.
