## Fix round 1 (`768de8a..e2ccce7`)
**Secrets and cleanup:**
- Trace and video are off.
- Every request-context call and every password fill goes through a guard that rethrows only the method, path and failure class.
- `make ui-e2e` runs `scripts/ui_e2e_run.sh`, which scans `test-results/`, `playwright-report/` and the captured stdout for the run's secrets, `postgresql://`, JWT and Bearer. A hit fails the target; only file names are printed.
- A watchdog (stdin EOF, or the parent gone) runs the cleanup.

**Isolation and inputs:**
- The DB name must be exactly `soc_ui_e2e_test`.
- A `flock` stops concurrent runs.
- The ready line names the backend dir, and the Makefile ignores an inherited `E2E_BACKEND_DIR`.
- `e2e-t2b` is seeded for the concurrent conclude.
- Children get their environment from a mode-600 env file, so no secret is in any argv (strace: 0 of 303 execs).
- `blind.spec` fails on any unknown answer shape that carries the head.

**Coder's results.** 3 runs in a row, 8 passed each. Realtime took 863–977 ms against the 2 s budget.

**Deviation accepted.** The scan lives in the wrapper, so a direct `npm run e2e` has no scan. Only `make ui-e2e` is named anywhere.

**Scoped re-review: all ADDRESSED. Verdict: APPROVE.**
- A probe sent a fake secret as `X-API-Key` and Bearer to a closed port: 0 hits.
- A timed-out `fillSecret` printed nothing secret, even with `PLAYWRIGHT_LIST_PRINT_STEPS=1`.
- SIGKILL of the runner left everything clean within 0.49 s, and still clean at 15 s.
- The DB-name, `flock` and `E2E_BACKEND_DIR` checks each behave as specified.
- The concurrent 409 names `e2e-t2`, and `concluded_by` is t2's id.
- A `/proc` poll every 2 ms over 4 runs found 0 argv hits.
- Across `test-results/`, stdout and `dist/`, the forced-failure runs gave 0 hits.
- **Parked Minors, for the final fix batch.** The values belong to a scratch stack that is gone by then.
  1. The scan does not decode the base64 zip embedded in the HTML report. With `PW_ARGS=--reporter=html`, a `Fill "<value>"` step title is stored there. Fix: decode it, or refuse `--reporter` in `PW_ARGS`.
  2. A failed e2e login leaves the password in Playwright's `error-context.md` page snapshot. The scan catches it and fails the target, but the file stays. Fix: clear the field when `loginAs` fails.
- **Observation outside this card, for the Owner.** Other sessions' `perl`, `psql` and `python` processes on this host carried the database password in their argv. `/proc/*/cmdline` is readable by every local user.
