## 1. Built

All paths are under `frontend/src/`.

**`features/tier1/aiState.ts`.** The one place the ① state is decided; `AiCell.tsx` only words it, and P10-T10 reuses it.
`DECIDED` (`closed_fp, closed_benign, closed_confirmed, escalated_tier2, auto_closed`, the same as `visibility.SHOW_STATES`).
- `aiStateOfRow(row)`: **hidden** (no `suggested_action` key, `suggestion_visible === false`, status not in `DECIDED`) → **ready**
  (a string action; `forced = gate_forced === true`) → **unavailable** (`triage_status === "unavailable"`) → **pending**.
  The blind arm is never `pending`: a blind row carries `suggestion_visible: false` and no keys, and is `hidden`.
- `aiStateOfView(view)`: **decided** (status in `DECIDED`) → **hidden** (no `suggestion` key, not visible) → **ready** →
  **unavailable** → **pending**.

**`api/tier1.ts`.** `QueueRow` (the ① keys optional: the server strips them, they are absent and not null), `QueueResponse`,
`QueueFilters`, `QUEUE_PAGE_SIZE = 50`, `queuePath` (an unset filter is left out: an empty `band=` or `status=` is a 422),
`fetchQueue(filters, page, signal)`, and a minimal `AlertView` for `aiStateOfView` (P10-T10 completes it).

**Band table (rulings R8, R13).** `strings.ts` `S.band` is code → label (`critical` "Rất cao", `high` "Cao", `medium` "Vừa",
`low` "Thấp") and `bandCodeOfLabel(label)` is its inverse: the one table. Chips and the filter speak codes; a row's `risk_band`
is the server's label and its badge colour is looked up label → code. An unknown label is shown raw in a neutral badge, no
score is "—". `api/types.ts` has `BAND_CODES`, `BandCode`, `isBandCode`.

**`live/socket.ts`.** `connectLive({token, onChange, onStatus, onUnauthorized?, url?}) → disconnect`, over the global
`WebSocket`. The URL is `ws(s)://<host>/api/ws` with no query, ever. The token is read when the socket opens and sent as the
first frame `{"type":"auth","token"}`; `ready` makes the status `live`; `alerts.changed` is honoured only after `ready`
(`ids` of strings, or `many: true`). A drop is `offline` and reconnects with a doubling backoff (1 s → 30 s, reset on `ready`).
Close **4401** calls `onUnauthorized(sentToken)` and stops; **4403** stops (no reconnect); **1011** and anything else back off
and reconnect. A constructor that throws schedules a reconnect. No token → offline, no socket. Disconnect is idempotent.

**`live/invalidate.ts`.** `createInvalidator(client, windowMs = 500)`: a leading-and-trailing throttle. The first change flushes
at once and opens a 500 ms window; changes inside it are folded (`many` wins) and flushed once when it closes, which opens the
next window. A flush invalidates `["queue"]` plus `["alert", id]` per id (`["alert"]` for `many`). So a burst costs two flushes.

**`live/LiveProvider.tsx`.** One socket per token (opened for `useAuth().session?.token`, closed with it). `useLiveStatus()`
is `"live" | "offline"`; it is offline with no provider, so a page rendered alone polls. The status is kept together with the
token it was reported for, so the socket of an ended session never speaks for the next one. Every transition to `live` runs
one `many` invalidation (changes before `ready`, or while down, were not heard). The query cache is cleared when the token
changes or ends (one session's rows, blind or visible per person, are not shown to the next). `live/LiveIndicator.tsx` is the
header's `Trực tiếp` / `Mất kết nối` (`role="status"`, the word and not only the colour).

**`api/client.ts`.** Additive `reportUnauthorized(sentToken)`: calls the 401 hook only if that token is still the current one,
the same rule as a 401 answer. **`api/queryClient.ts`** `createQueryClient()`: no retry for a 4xx `ApiError`, at most two for
the rest.

**`features/tier1/QueuePage.tsx`** (with `queueParams.ts`, `QueueFilterBar.tsx`, `QueuePagination.tsx`, `AiCell.tsx`).
- View in the URL: `?band=&category=&agent=&status=mine&page=`; only non-defaults are written, only understood values are read
  (a band that is not one of the four codes, a status other than `mine`, a page that is not a whole number ≥ 1 are dropped,
  so the server never sees them). A filter change goes back to page 1.
- `useQuery({queryKey: ["queue", filters, page], queryFn: fetchQueue, placeholderData: keepPreviousData,
  refetchInterval: live === "offline" ? 30_000 : false})`.
- Band chips (`role="group"`, buttons with `aria-pressed`, most serious first) show `counts_by_band`; a chip sets the `band`
  filter and pressing it again clears it. A band select, a status select (Chờ xử lý / Của tôi), category and agent text
  inputs (applied on submit) and "Lọc" / "Xoá bộ lọc".
- `DataTable` columns: Mức (`BandBadge`), Mô tả (a link to `/alerts/:id`, `rule N`, a "⟳" mark for `needs_retriage`),
  Category, Agent, Số lần, Lần cuối (`formatTime`, +07), ① (`AiCell` from `aiStateOfRow`).
- ① wording: hidden "ẩn — nhánh mù" (never "chưa có"), pending "chưa có", unavailable "Không có gợi ý ①", ready the action label
  with `(độ tin cậy)` and the `⚑` mark (with an accessible name) when the gate forced it; an unknown action shows as its code.
- Pagination (`nav`, numbered links with gaps, previous and next as real links), a count line, an error alert with "Thử lại",
  and the empty states (`empty`, `emptyMine`, `noMatch`, `pageEmpty`).
- The page fetches only `/api/tier1/queue`. The blind arm is the server's: it does not look anywhere else for a suggestion.

`routes.tsx`: `/queue` renders `QueuePage` under the same `RequireRole`; the Shell header gets `<LiveIndicator />`.
`app.tsx`: `BrowserRouter > AuthProvider > QueryClientProvider > LiveProvider > AppRoutes`.

## 4. Deviations

1. **`connectLive` has an optional `onUnauthorized(sentToken)`** beyond the brief's signature, and `api/client.ts` gained the
   additive `reportUnauthorized(sentToken)`. Reason: the brief's rulings make 4401 "like a 401" (clear the session, no
   reconnect), and the 401 hook lives in the client, so the socket needs a way to reach it. `AuthState` is unchanged.
2. **The cache is cleared when the token changes or ends** (`LiveProvider`), and **every transition to `live` runs one resync**
   (`many`). Neither is in the brief; the first keeps one session's rows from showing to the next, the second covers changes
   missed before `ready` or while down. The burst test settles that resync first and then counts.
3. **Category and agent are text inputs, not selects**: there is no facet endpoint to list them (the spec only fixes the
   filter names). They apply on submit; the band and status selects apply on change.
4. **`S.ai1.action` and `S.confidence` labels were added** (`false_positive` "Dương tính giả", `needs_review` "Cần xem xét",
   `escalate` "Chuyển tier 2"; `thấp/trung bình/cao`), read through `labelOf`, so an unknown value shows as its code.
5. **`S.band` labels were changed** from the scaffold's `Nghiêm trọng / Cao / Trung bình / Thấp` to the server's own
   `Rất cao / Cao / Vừa / Thấp` (rulings R8 and R13: the row's `risk_band` label and the chip are the same word), with
   `satisfies Record<BandCode, string>` and `bandCodeOfLabel` as its inverse. P10-T11 changes the same lines in parallel, so
   expect a trivial merge there.
6. **The fake socket is a `FakeSocket extends EventTarget` installed with `vi.stubGlobal("WebSocket", …)`** in `socket.test.ts`,
   which is how the brief's "fake WebSocket class injected" is met without a second parameter; the `QueuePage` and
   `LiveProvider` tests mock `connectLive` itself.
7. **`routes.test.tsx` stubs `QueuePage`** (`vi.mock`) because `AppRoutes` there has no `QueryClientProvider`; the page has its
   own test file.
8. **Prettier was run on files committed earlier in this card** (`aiState*`, `socket.test.ts`, `strings.test.ts`), since
   `make ui-lint` runs `prettier --check`.
