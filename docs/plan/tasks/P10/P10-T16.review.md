### Findings
1. **Important.** R22 was keyed on the switch *at evaluation time*.
   - `evaluate_alert` is also the B2–B4 path of the evaluation harness, and `eval/run_configs.py` builds its config from `--env-file`, `.env` by default.
   - Once the Owner sets the switch to false, a B1–B4 run on the pre-switch gold set would feed B2–B4 a burst count reaching up to the day of the run, while B1 keeps the row's count.
   - That breaks the pinned invariant "B1 facts == `evaluate_alert` facts". It also changes the prompt, so the LLM-cache keys miss and the run pays again.
   - This goes against DEC-165 item 5.
2. **Minor.** The runbook row's "who sets it" said `default`, but the live value is the Owner's.
3. **Minor, parked.** The burst query's cost grows with the key's whole history, because the `first_seen_at` bound is in no index. It measured 16.6 ms worst case on 200k rows.
