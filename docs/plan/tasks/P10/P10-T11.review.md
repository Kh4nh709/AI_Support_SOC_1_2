### Verified
- **Polling.** The ② column polls every 3 s only while `running`, sending the `run_id` kept from the 202. It stops on done, failed, stalled, an error and unmount.
- **Evidence.** Each evidence mark comes from the server's `verified === true`. `reason_text` and the empty counter-evidence warning are shown.
- **Conclusions.** The three labels are exact, with the scope note beside "Xác nhận sự cố" only.
- **Times** show in +07 under `TZ=UTC`.
- **Roles.** `RequireRole` (tier2 and admin) wraps both routes.
- **Strings and safety.** Every string is in `strings.ts`. There is no `innerHTML`, no `localStorage`, and no token in a URL.
- **Errors.** A 404, a 422, or a done view with `run_id: null` never crashes.
- **Deviations accepted, 12 in all.** They include:
  - `S.ai2.failed`;
  - evidence split into two lists, because the output schema does not link them;
  - model, tokens, cost and quota not shown, because the ② query does not carry them;
  - no add-note form on a concluded case;
  - the timeline taken from the case detail;
  - "Sau" enabled only on a full page, because the list route returns no total.
- **Red steps reproduced:**
  - polling continued on `done` → red (24 requests where 4 were expected);
  - every evidence item forced to verified → 2 red;
  - `raw_log` rendered through `dangerouslySetInnerHTML` → the guard and hostile-log tests red.

### Findings
1. **Important.** Reads went through a local `useLoad` hook, not TanStack Query (spec §3.2: "TanStack Query owns every read"). This was not disclosed.
2. **Minor.** The stale-response guard was correct but unpinned: with it removed, every test stayed green.
3. **Minor.** "Thử lại" after a poll error read without the `run_id`, so the view showed `idle`, and "Đang phân tích…" stayed on screen while nothing polled.
4. **Minor.** A failed run hid the earlier run's result and stop reason.
5. **Minor.** `playbook_used` was not shown.
6. **Minor.** Past the last page, the pager said "Chưa có case nào.".
7. **Minor.** A 422 offered a retry that can never succeed.

## Fix round 3 (`ae00f19..e2c8aca`)
- A transition from `running` to done, failed or stalled invalidates `["case", id]` and `["cases"]` once, from inside the ② read's `queryFn`.
- A page opened on a finished run reads the case exactly once.
- 3 new tests. Red: the invalidation removed → the done and failed tests red.

**Scoped re-review: ADDRESSED. Verdict: APPROVE.**
- The side effect in `queryFn` is sound. It is bound to its own key's case id, and StrictMode does not repeat it.
- A cancelled poll can fire it twice, which costs one harmless extra GET. That path is unreachable while a job runs.
- **Parked Minor, for the final-review fix batch.** A stalled job that later finishes does not re-read the case: the trigger requires the previous state to be `running`, so stalled → "Kiểm tra lại" → done leaves the old summary. A reload recovers it.
