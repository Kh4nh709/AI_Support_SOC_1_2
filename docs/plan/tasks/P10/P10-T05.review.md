### Findings

1. **Important: a DEC-101 side channel.** The trigger watched `triage_status`, and ① writes only that column (plus `triaged_count`). Each time ① finished on a **blind, undecided** alert, every socket got `alerts.changed [id]`. The refetched row showed nothing new, but the analyst learned "① ran on X, now". `visibility.py` forbids this: "a blind row must not even say ① ran".
2. **Minor.** The role test could not fail, because both of its roles are allowed.
3. **Minor.** "Subscribe before `ready`" was not pinned by any test.
4. **Minor.** The 8192-character first-frame cap applied only after uvicorn had buffered up to its default 16 MiB `ws_max_size`.
5. **Minor.** The JWT was checked only after a DB connection was opened, with no `connect_timeout`.
6. **Minor.** `Hub` did not take keyword-only arguments.

## Director ruling R12

The trigger function returns without notifying when all of these hold:
- the operation is an UPDATE;
- `NOT NEW.suggestion_visible`;
- `NEW.status` is not in `visibility.SHOW_STATES`;
- every watched column except `triage_status` is unchanged.

The visible arm keeps its real-time ① update. A blind alert still notifies on any other change. The SQL status list is pinned to `SHOW_STATES` by a parity test. `018` is edited in place, which is safe because it is not yet applied live.
