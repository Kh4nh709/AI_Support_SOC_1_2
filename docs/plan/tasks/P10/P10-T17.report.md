### 14.1 Race in the held-by-other exclusion (DEC-166 item 3), `24ac3df`

`correlated_cluster_ids` is a plain SELECT; analyst B could acknowledge a `queued_tier1` sibling and commit before `transitions.escalate`'s
UPDATE, which re-checked only `case_id IS NULL`, so A's case swept an alert B held and B's next decide got a 409.

Change (`backend/app/domain/transitions.py`): the UPDATE of ③a also requires
`AND (alert_id = %s OR status = 'queued_tier1' OR (status = 'tier1_active' AND acknowledged_by = %s::uuid))`, the escalating actor bound.
A sibling that is now another analyst's (or no longer open) fails the WHERE, the existing `touched.rowcount != len(head_ids)` check raises
`StaleState`, and `decide.escalate`'s savepoint undoes the case. Two deliberate differences from the one-line suggestion: the **trigger is
exempt** (`alert_id = %s`; it is locked `FOR UPDATE` and the API accepts `tier1_active` for it with no holder check, so applying the
held-by-me test to it would change what escalate does today), and `tier1_active` is spelled out rather than `acknowledged_by = %s` alone, so
the clause says what `cluster_ids_query` says. Under READ COMMITTED the WHERE is re-evaluated against the newest committed row, also when
the UPDATE had to wait for B's lock.

Route: `decide.escalate` turns `StaleState` into `_conflict(..., kind="already_in_case")`, `tier1.py` answers `409` with that flat body after
`conn.rollback()`. Nothing to change there, and a retry succeeds without the alert (asserted).

Test (`backend/tests/test_decide.py::test_escalate_sibling_acknowledged_by_another_after_the_select_is_conflict_not_swept`): a scratch
database (`tests/scratch_db.py`), two real connections, committed data; `correlation.correlated_cluster_ids` is wrapped so that right after
the real SELECT returns the sibling, connection B acknowledges it as another user and commits. Then A's `escalate` must raise
`DecisionConflict(already_in_case)`; after the rollback the sibling is `tier1_active`, held by B, `case_id` NULL, no `cases` / `case_alerts`
row; the retry returns `head_count == 1`, the case holds the trigger only, the sibling is unchanged.
