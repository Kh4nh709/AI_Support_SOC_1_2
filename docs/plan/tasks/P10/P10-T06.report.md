  - CLI. `--pilot-start ISO8601`; `--pilot-end ISO8601` (default: the database's `now()`, never
    printed). `--pilot-end` without `--pilot-start` and an unparsable or inverted pilot window exit 2
    before any connection. The pilot window is its own half-open `[start, end)` on
    `audit_events.created_at`, separate from `--since/--until`. `PilotWindow` is a frozen dataclass whose
    text prints the end as a fixed phrase when it was left out, so the output stays byte-identical.
  - Without `--pilot-start` the section prints `not measured: pilot start not given`, cites no pilot
    query, and no pilot query runs.
  - Four queries, one per figure, each a module-level `Query`, run once by `_Runner.run` and printed

    `%(pilot_end)s`:
    - **Q29** decisions by type (`false_positive`, `benign`, `escalated`) with `n`, per arm and per
      source (`wazuh`, `lab`, `all` via `ROLLUP` with `GROUPING()`). A source that is neither (for example
      `replay`) gets its own row after `lab`, so `all` still reconciles.
    - **Q30** median acknowledge → decide, in minutes, with `n`: `percentile_cont(0.5)` over the interval
      between the alert's latest `alert.acknowledged` (at or after the pilot start and not after the
      decision) and the decision, both `audit_events.created_at`, i.e. the database clock. A decision
      with no such acknowledge is counted in `decisions` and not timed.
    - **Q31** (① rule superseded by Fix round 1, F1: ① is the suggestion as it was at the decision)
      ①'s agreement with the human, **blind arm only** (`WHERE d.arm = 'blind'`), as a fraction
      with `n` and the denominator. ① is the latest `pipeline='triage' AND role='proposer'` `llm_runs` row's
      `result->>'suggested_action'` (the queue's own rule; `tier1.escalated` carries no suggestion in its
      payload). `escalate` agrees with a human escalation, `false_positive` with a human
      `false_positive`; any other pair is a disagreement. `needs_review` is "no verdict": out of the
      denominator, counted in its own column. A decision with no ① result is counted in its own column.
    - **Q32** per person (`audit_events.actor_id`, a uuid, no name), arm and source: decisions by type
      and the median. Not in the card text; spec §5.6 asks for per-person figures.
  - Decisions are `tier1.decided` with payload `decision` `closed_fp` (false_positive) or `closed_benign`
    (benign), and `tier1.escalated` (escalated); synthetic alerts are excluded. The arm is
    `alerts.suggestion_visible` (blind is `false`, DEC-101) and the source is `alerts.source`.
  - Stale reasons replaced in section 6: the ② row is "built and run, no rating control in v1.0

### F1 (Important): ① is the suggestion as it was when the human decided

- **Cause.** Q31 took the latest proposer row with no time bound. The triage job still runs on
  `escalated_tier2` (`backend/app/tier1/triage.py:71`), so a run created after the decision could count as
  "agreed"; and a time bound alone does not fix `tier1.decided`, because a job in flight has a `created_at`
  (its transaction's start) before the decision although the analyst's console never had its row.
- **Change** (`eval/ops_export.py`, new `_PILOT_VERDICT` fragment shared by Q31 and Q33; `d` also selects
  `payload->>'llm_suggestion'` as `recorded_suggestion`):
  - `tier1.decided`: ① is the event's own `llm_suggestion`, which `transitions.decide` wrote from
    `queue.latest_suggestion` (`transitions.py:427-436`). A null one (no `llm_run_id`) is `no_result`,
    whatever run exists now.
  - `tier1.escalated` (payload `llm_suggestion: None`, `transitions.py:550`): the latest proposer row with
    `created_at <= decided_at` (a correlated scalar subquery in a `CASE`, so it runs for escalations only). A
    latest row whose `result` is NULL is `no_result`, as `latest_suggestion` returns None for it.
  - Section 6a prints the caveat line `escalations: ① taken as the latest run created at or before the
    decision; a run in flight at that moment may be included` in the agreement block, and the ① bullets say
    which source is read for which event.
