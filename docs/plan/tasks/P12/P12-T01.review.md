# P12-T01 review — round 2 (fix round 1)

Reviewer: independent subagent, own worktree, detached at `task/P12-T01` = `41c3248`. I reviewed `git diff 3d1ba5e..41c3248`. The reviewed tree was not edited (`git status` clean).

**Findings:**
1. **Minor** · `docs/runbook.md:207`, "every one that is not closed gets a ① run". This is wrong. Under D8, an auto-closed alert also gets a ① run (`transitions.py:295`) and lands in the next 08:00 digest. Only an alert grouped as a duplicate gets no ① run. So with auto-close back on, the catch-up costs a ① run on every non-duplicate alert and also floods the digest. The paragraph understates both. Fix: "every one that is not grouped as a duplicate gets a ① run, the auto-closed ones included (D8), and those also fill the next digest". The test only asserts "① run", so the test is unaffected.
2. **Minor** · `docs/runbook.md:207`, "Those SOAR already posted are dropped by the intake key". This is true only if SOAR's body keeps the Wazuh `id` and `manager.name`. The SOAR payload schema is not delivered yet (P12-T02 is blocked), so this is not established. If SOAR rewrites either field, every alert it already posted is pulled again as new and gets a second ① run. Fix: state the condition and add a check before re-enabling, for example compare `manager_id` on recent `via='webhook'` rows with the indexer's manager name.
3. **Nit** · `docs/runbook.md:207`, "`last_sort - PULL_OVERLAP_S`". This mixes units: the same sentence says `last_sort` is in milliseconds, while the overlap is in seconds (`puller.py:263` multiplies by 1000). Fix: write `last_sort - PULL_OVERLAP_S × 1000` and update the literal in `test_runbook_env_keys.py`.
4. **Nit** · `docs/runbook.md:207`, "reads `f|t`". This holds only if the last pull before the switch succeeded. If it ended on an error, `last_error` is kept and the row reads `f|f`. Fix: say "`f|…` (first column false)", or name both cases.
