## Built

`_windows_fields(data)` returns `None` unless `data.win` is a dict, which is the case of every Linux alert. Otherwise it returns
already-filtered values:

- **srcip**: `eventdata.ipAddress`, else `eventdata.sourceIp`. **dstip**: `eventdata.destinationIp`.
- **ports**: `eventdata.ipPort`, else `eventdata.sourcePort`; `eventdata.destinationPort`; read by the existing `_safe_int`.
- **user**: `eventdata.targetUserName`, else `eventdata.subjectUserName`, else the part after the last `\` of Sysmon's
  `eventdata.user`.
- **Empty**: `-`, `""`, `127.0.0.1`, `::1`, `0.0.0.0` for addresses; `-`, `""` for ports; `-`, `""` and any name ending in `$`
  for users. Values are stripped first. A non-string value counts as absent, never raised on (R2).
- **raw_log**: `system.message` if it is a non-blank string, else `json.dumps(data["win"], sort_keys=True, ensure_ascii=False)`.

In `parse_wazuh_alert` the Linux lines are untouched. After them, each of srcip, dstip, src_port, dst_port and alert_user takes
the Windows value **only if the Linux value is empty** (`srcip = srcip or windows.srcip`, …). `full_log` takes `windows.raw_log`
only when it is empty. Both go through the existing `_truncate_raw_log`. There is no new `Alert` field:
`eventID`/`status`/`subStatus`/`logonType`/`image`/`targetFilename`/`queryName` stay in `raw_payload` and reach ① through
`raw_log`.

## Deviations

1. **`mapping_version` is compared with the live constant, not the snapshot.** It labels the category tables rather than
   being parsed from the document, and §4 item 1 bumps it to `v3.3`. Every other field is compared with the base, including
   category, categories and resolved_by. `test_snapshot_is_the_base_parser_at_mapping_version_v3_2` pins the snapshot's
   `v3.2`. So the test did not need editing in P9-T02.
2. **Small totality additions the card does not spell out.**
   - Windows values are stripped before the empty check.
   - `-`/`""` also count as empty for ports, so an empty `ipPort` falls back to `sourcePort`.
   - The JSON fallback passes `default=str` and returns `""` on `TypeError`/`ValueError`/`RecursionError`. None of these can
     occur with a mapping decoded from JSON; they keep `parse_wazuh_alert` total (R2) for a hand-built mapping.
3. **The synthetic fixtures' rule blocks are illustrative.**
   - Rule ids and MITRE ids follow stock Wazuh where the reading below confirmed them: 60122 `T1531`, 60204 `T1110`,
     60106 `T1078`.
   - They are plausible for the rest: 60115, the Sysmon rules and 62123.
   - Each synthetic Sysmon/Defender rule's description says "(synthetic fixture)".

## Open questions

1. **Real fixtures (§1 item 4, §3 acceptance 3) — pending P9-O1.** A read-only count on the dev DB (`intake` rows whose
   `raw_payload` has `data.win` or `_source.data.win`) found **405** real Windows alerts. They come from one Windows agent,
   26–28/09, decoder `windows_eventchannel`; `alerts` held 1,171 Windows rows by the P9-T02 proof run, so the agent is still
   sending.
   - **Event ids present:** 4624, 4625, 4634, 4672, 5038, 7040, 7045, 104 and application-channel events.
   - **Logon events, by aggregate count at the end of the session:**
     - 4624 has logon types 2, 3, 7 and 11; 164 of the type-3 logons carry a real source address, and none is type 10;
     - all 10 4625s are local (type 2 ×9, type 11 ×1, loopback address);
     - no 4740, 4771, 4776 or 4648 exists.
   - **Not present at all:** Sysmon 1/3/11/22 and Defender 1116.
   - **Today's parser.** All 405 had `srcip = ''`, `alert_user` NULL and `raw_log = ''` as parsed by the base parser, which
     is the card's "Today".
   - **Field names confirmed.** Reading field *names* and rule metadata confirmed the card's camelCase keys (`ipAddress`,
     `ipPort`, `targetUserName`, `subjectUserName`, `logonType`, `status`, `subStatus`), no `full_log`, and a non-empty
     `system.message`.
   - **Why none were copied.** Copying real rows from `intake.raw_text` into fixtures was **refused by this session's
     permission check (PII handling)**; it was not retried by any other route. The synthetic fixtures use invented
     identifiers only (`WIN-LAB-01`, `labuser`, documentation and lab-range addresses).
   - **Decision needed.** Whether real rows (redacted or not) become fixtures is the Owner's call, as is which Windows agent
     counts as "the Owner's" for §1 item 4.
2. **Closed by the P9-T02 follow-up (Director 1, 29/09): a `windows_eventchannel` alert no longer reaches tier 5.** Kept for
   the record: **Sysmon 3's `destinationPort` now reaches the port tier.**
   - `resolve()` takes the alert's `dst_port`. For a Windows alert whose rule has no mapped MITRE id or group, tier 5
     now sees Sysmon 3's destination port: 80/443 → `web_attack`, 22 → `ssh_brute_force`. At `ba7b070` the port was always
     0 for a Windows alert.
   - I kept `category = resolve(stored columns)` rather than resolving on the Linux-only port, so a later re-classification
     from the stored columns agrees with the stored category.
   - No Sysmon alert exists yet. Whether Windows alerts should skip tier 5 is a Director decision; P9-T02's Windows tier
     does not cover it.
3. **Addresses are not normalised.** An IPv4-mapped IPv6 address (`::ffff:10.0.0.5`) passes through as is, and
   `::ffff:127.0.0.1` is not treated as loopback.
4. **User sources are exactly the card's.** Defender 1116's `detection User` and 7045's `accountName` are not read. Service
   and system names (`SYSTEM`, `LOCAL SERVICE`, `ANONYMOUS LOGON`, `DWM-n`, `UMFD-n`) are not filtered; only `NAME$` is.
