## Built

1. **Resolver.** `_is_windows(decoder)` checks whether `windows_eventchannel` is a substring of the decoder name (case- and
   whitespace-insensitive, like tier 4's keys). For such an alert, three Windows tiers run in front of tier 1, and tier 5
   never runs.

   | Tier | Signal | Table | `resolved_by` |
   |---|---|---|---|
   | W1 | exact MITRE technique id | `WINDOWS_TECHNIQUE_TO_CATEGORY` | `mitre` |
   | W2 | parent technique id (the part before the first `.`), only when no id matched W1 | `WINDOWS_TECHNIQUE_TO_CATEGORY` | `mitre_parent` |
   | W3 | `rule.groups` | `WINDOWS_GROUP_TO_CATEGORY` | `rule_groups` |
   | 1–4 | the shared tiers, unchanged | the four shared tables | as before |
   | ~~5~~ | not for Windows: a Windows host's destination port is not a category signal | | |

   A Windows alert that nothing matches is `unknown`/`none`.
   - `WINDOWS_TECHNIQUE_TO_CATEGORY`:
     - T1110, T1110.001, T1110.003 → `brute_force`;
     - T1490, T1485 → `ransomware`;
     - T1071.001, T1573 → `c2_beacon`;
     - T1048, T1567 → `data_exfiltration`;
     - T1059.001 → `malware`.
   - `WINDOWS_GROUP_TO_CATEGORY`: `authentication_failed`, `authentication_failures`, `invalid_login` → `brute_force`;
     `authentication_success` → `suspicious_login`.
   - **The Windows tiers run the same code as the shared ones.** `_tier_mitre_exact`, `_tier_mitre_parent` and
     `_tier_groups` take their table as an argument. The default is the shared table, and it is the only one any other
     decoder sees.
   - **Any other decoder is untouched.** It never enters W1–W3 and keeps tier 5, so its five tier calls are the v3.2 ones
     on the v3.2 tables. The four shared tables are not edited; they still hash to the `v3.2` digest `33ed2ec1…`. Every
     `resolved_by` stays inside `ck_alerts_resolved_by`.
2. **`PRIORITY`** is now 12 names, with `brute_force` directly after `ssh_brute_force`. **`MAPPING_VERSION = "v3.3"`**, kept at
   v3.3 when the group table joined, because v3.3 was never merged.
3. **`kb/decision_tables/brute_force.yaml`.**
   - `reviewed_by: null`, `reviewed_at: null`.
   - Six rules over the existing facts only: severity, rule_level, ioc_reputation, asset_criticality, identity_privileged
