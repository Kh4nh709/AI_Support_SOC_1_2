### Findings

**F1 — Minor.** `backend/app/tier1/labels.py:578` (unchanged by this diff; tests at `backend/tests/test_labels.py:1131-1473`).
- **Problem.** Undo's `source = 'gold_offline'` filter has no test.
  - The same admin can own a newer `digest` label (`tier1/digest.py:268`, verdict "correct") or a `disagreement` row (the adjudication written by `label_export freeze`).
  - With the filter dropped, undo deletes that row instead of the gold label, and no test fails.
  - It cannot be reached today, because the marker exists and undo answers 409. The code is correct.
- **Evidence.** On the scratch copy, the mutation `"  WHERE labeler_id = %s"` (filter removed) gives:
  - `test_labels.py` + `test_admin_labels_api.py`: **`67 passed, 5 deselected`**, so the mutation survives;
  - my probe `test_probe_undo_never_takes_the_callers_digest_label`: `AssertionError: assert '1788340536.1509017' == '1786903016.121311'` (`1 failed, 11 passed`).
- **Fix.** Add that test to `test_labels.py`:
  1. The caller's gold label is older than a `digest` label of the same caller.
  2. Undo answers 200 with the gold cluster.
  3. Only the `digest` row remains.
  4. The next undo is 404.

**F2 — Minor.** `backend/app/web/routers/labels.py:179-205`.
- **Problem.** No test sends a NUL or control character in the undo body. The behaviour is right (see the Security table above).
- **Fix.** Add a parametrized test with escaped NUL, raw NUL, C0/DEL, a NUL key and C1. It asserts 403 or 422 and that the label is intact.

**F3 — Minor.** `backend/tests/test_labels.py:1118-1129`.
- **Problem.** The Jinja undo's frozen path is checked for the label count only, not for "writes nothing".
- **Evidence.** My probe `test_probe_jinja_undo_while_frozen_writes_nothing` passes: the `audit_events` count and max id and the `triage_labels` rows are unchanged for `/admin/labels/undo` and `/api/admin/labels/undo`.
- **Fix.** Assert that `_undo_events(db, USER_A)` is unchanged after that 409.

**F4 — Minor (plan; the Director's).** `docs/superpowers/plans/2026-10-18-admin-console-v1-1.md:332` and P11-T16's row (line 417).
- **Problem.** Undo requires a JSON body, but the plan's interface line does not say so. `api/client.ts` sends no body and no content type unless `json` is given (lines 47-52), so a P11-T16 call without `json: {}` gets a 422. The Coder documented this in the router docstring and the report.
- **Fix.** Add "call undo with `json: {}`; 409 and 404 are `detail.reason`" to P11-T16's card. Its MSW handlers should return `{"detail":{"reason":"frozen"}}`.
