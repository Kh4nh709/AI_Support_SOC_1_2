### Deviations judged

1. **The labeller id comes from the JWT `sub`, not from `/api/auth/me`: ACCEPT, KEEP (class: accepted deviation).**
   - Sound. `_TOKEN_CLAIMS = ("sub","role","iat","exp")`, and the login signs `{"sub": claims.user_id, …}` with `claims.user_id = str(user_id)`, the canonical lower-case uuid. `_bind` compares `labeler != claims.user_id` to the server's own `str(uuid.UUID(sub))`, so the page's reading is exactly what the server compares. Reading is not trusting: the server verifies the signature on every request.
   - Expired token: the page still reads `sub`; the request answers 401, the client ends the session (`getToken() === token`), and `RequireRole` leaves the page. A 401 is not retried (`shouldRetry`). At worst one render shows "Máy chủ trả lỗi 401" before the redirect.
   - No `sub`, or an unreadable token: stops with `sessionUnreadable` (`role="alert"`, no retry), and asks for nothing. Tested.
   - A `sub` that is not the user id: only possible with a forged token, which the server rejects on signature. If the user id did differ, `labels/next` answers 403 `labeler_mismatch`. The page shows it as a page error with no retry, and the save and undo show it at the form. Tested.
