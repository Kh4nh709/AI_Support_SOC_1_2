## 3. Deviations

1. **Row 27 — the denominator is `sum(occurrence_count)` over heads, not over every row.** After M4 each duplicate is a row of its own (`occurrence_count` 1) and its head's count already includes it, so a sum over every row counts each duplicate twice (4 of 13 = 30.8 instead of 4 of 10 = 40.0; a test pins it). The numerator also gets `duplicate_of IS NULL`, so it is a part of the denominator and `pct` cannot pass 100.
   Something the Director should know: the phase-3 design note's own SQL has `count(*)` as the denominator, with "sum, not count" about the numerator. On production-shaped data (a head plus its duplicate rows, all in the window) the row count and the head sum are equal, so I could not build a production-shaped database where the old formula passes 100 %. The 4950 % and 500000 % come from seeds with a big head and no duplicate rows, which is every unit-test seed. The fix makes the formula self-consistent, and the two differ only at window edges. The live width figures should hardly move.
2. **Row 12 — the stored reason is now the stripped one**, as Tier 1 stores it; the cap counts the stripped text. Without the strip, a client could pad a short reason with a megabyte of spaces. The existing empty-reason message is kept; only the cap message is Tier-1's.

**Something the unanchored rule needed that the ruling did not say: the pattern must not be run with `search`.** Searched as it stands, the unanchored regex is quadratic: every start position rescans the run of scheme characters. I measured, on a 64 KiB string, `"a" * 65536`: 15.8 s; `"a" * 65000 + "://"`: 15.4 s; `"ab1." * 16000`: 7.6 s; `"x://" * 16000`: 2.2 s. So `URL_WITH_PASSWORD` stays the definition of the rule (and the pinned text), but `is_secret_value` does not search with it. A match contains no whitespace and no `@` before its own `@`, so it lies wholly between two such characters: the function takes each `@`, looks back to the previous `@` or whitespace, and checks that stretch alone (`_holds_url_password_before`: a `://` with a letter-led scheme run before it, a non-empty user up to `:`, a non-empty password up to the `@`). ### Deviations, and what I did not do

1. **`,\s*` as well as `\s*`, in the five multi-key anchors** (`"job_id": job_id, "status"`, `**row, "width_threshold_pct"`, `"code": code, "count"`, the two `"rule_id": rule_id, "name"…`). The row asks for `\s*` after the brace. `ruff format` never wraps after the brace alone: a dict that outgrows its line gets one pair per line, so `, "status"` would trip the very wrap the row is about. The wrap simulation does both, so those five needed both. It is test-only and the keys read are the same.
2. **`wrapDictLiterals` and the second comparison are new, beyond the row's text.** They are how the anchors' red step exists as a test and not only as a one-off probe, and they keep the guard after this round: an anchor written for today's layout fails in the suite before a wrap does. Drop them (and the `py()` switch in `adminTypes.test.ts`) if the Director wants the row as written; the `\s*` edits stand alone.
3. **A quote inside a single-quoted Python string is still not understood.** An odd one now throws `unterminated string after: <anchor>`; an even number inside one string could still pair up wrongly and read a wrong key. The row did not ask for more, and an apostrophe or a `#` comment in a pinned dict would need a real tokenizer.
4. **`LazyPage` and its failure boundary are beyond the row's text.** The row asked for `Suspense` with the skeleton; with `React.lazy` alone, a chunk that cannot be fetched is an error nothing catches and React unmounts the whole app. That is a real case here, not a theoretical one: `nginx.conf` answers a removed hashed chunk with a 404 on purpose ("a hashed chunk of an old build is gone after a redeploy") and `deploy.test.ts` pins it, so a tab opened before a redeploy fails on the next admin page it opens. It catches any error of the page's first render too, not only a failed fetch. Its `key` is the path, so a failure does not stay on the next route. Drop `LazyPage` for a bare `Suspense` if it is not wanted: `routesLazy.test.tsx`'s failure test and `LazyPage.test.tsx` go with it.
5. **The fallback is `<p role="status">{S.common.loading}</p>`**, the waiting line `RequireRole` shows while the session is restored, and not the animated `TableSkeleton` of `UsersPage`: that one is private to a page component that is not mine, and one page's table shape does not fit the other six.
