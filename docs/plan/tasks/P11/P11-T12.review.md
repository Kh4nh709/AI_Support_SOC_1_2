### Findings
- **I1 (Important): passwords stay in TanStack's MutationCache.**
  - Where: `frontend/src/features/admin/UserCreatePanel.tsx:185-202` and `frontend/src/features/admin/dialogs/UserDialogs.tsx:45-58`.
  - Evidence: a scratch probe (since removed) read `client.getMutationCache().getAll().map(m => m.state.variables)`. It printed `PROBE create cache: true` after a successful create (form already emptied) and `PROBE reset cache after close: true` after the reset dialog had closed. Mutations keep `variables` for the default `gcTime` (5 min); the create panel's mutation lives as long as the page. This breaks "never in the query cache" and the panel's comment "nothing here … keeps one".
  - Fix: `gcTime: 0` on both `useMutation` calls; `mutation.reset()` in the create panel's `onSettled`; a test that the mutation cache holds no password after create and after reset. Tried on a scratch edit (restored): both probes then print `false`.
- **m1 (Minor): focus is lost after Deactivate and after Kích hoạt lại.**
  - Where: `UsersPage.tsx:199-251`.
  - Evidence: after a successful deactivation `document.activeElement` is BODY. The "⋯" opener is removed when the row turns inactive, so `ConfirmDialog` has nothing to return to. Reactivation swaps the button the same way.
  - Fix: after `onDone`/reactivate success, move focus to the row's new main button (or to the table).
- **m2 (Minor): the reset dialog's live length hint is announced on every keystroke.**
  - Where: `dialogs/UserDialogs.tsx:206-209`.
  - Evidence: the hint "Cần tối thiểu 12 ký tự, đang có N" sits in `role="alert"` and changes with each key, so a screen reader announces it assertively every time.
  - Fix: `role="alert"` only for the server's answer; the live hint through `aria-describedby`, with at most `aria-live="polite"`.
- **m3 (Minor, Owner question): one-click reactivation.**
  - Where: `UsersPage.tsx:89-102, 205-221`.
  - Evidence: one click restores a deactivated account's login with its old password, admin rights included. Old tokens stay dead. The spec and canvas draw no dialog.
  - Fix: if the Owner wants one, a primary-tone `ConfirmDialog` ("Kích hoạt lại …? Tài khoản đăng nhập được ngay bằng mật khẩu hiện tại."); otherwise record the ruling.
