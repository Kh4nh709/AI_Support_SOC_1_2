## 2. Deviations

1. **The labeller's id is read from the token's `sub`, not from `GET /api/auth/me` (`useMe`).** The T10 report says the id is "the
   caller's own (`GET /api/auth/me`, `useMe`)", and the card says the page makes no `/api/` request but the three label routes and
   that the log test asserts exactly those paths. Both cannot hold: the session has no user id (`Session` is `{token, role, username,
   expiresAt}`), and `AuthProvider` calls `fetchMe` outside the query cache, so on `/admin/labels` nothing has asked `me` before the
   page. `labelerIdOf(token)` (`labelerId.ts`) decodes the JWT payload and returns `sub`; no request is made. The server still decides
   (`_bind` answers 403 to a labeller that is not the token's user), and `labelerId.test.ts` reads the backend to keep the reading
   true (`payload = {"sub": claims.user_id`, and `if labeler != claims.user_id`). If the token holds no readable `sub` the page stops
   with `L.sessionUnreadable` and asks for nothing. The alternative (`useMe`) is a one-line change in `LabelsPage.tsx`; the cost is a
   fourth path in the log.
2. **No `useSubmitLatch.ts` on this base**, so the latch is a ref in `LabelsPage.tsx`: set on the click, cleared in `onSettled`, shared
   by the save and the undo (one write at a time). When the shared hook lands it replaces `once()`; nothing else changes.
3. **Commit trailer.** The card's text names `Claude Opus 5.5`; I am Sonnet 5.5, so each commit ends with the harness's
   `Co-Authored-By: Claude Sonnet 5.5 …` and the `Claude-Session` line (as the P11-T10 Coder did).
4. **"Render `next` directly".** `next` in the save answer is a cluster id, and a cluster's fields only come from `labels/next`. So the
   page says the id in the toast ("Cụm tiếp: …", or "Bạn đã xong phần của mình." for `null`) and then reads `labels/next` through
   `invalidateAfter("postLabel")`.
5. **The raw-log notice is the page's own line**, "raw_log dài hơn 32 KB: đã cắt ở 32 KB khi hiển thị.", as the card and the canvas
   word it. `LogBlock`'s own `truncated` prop (its text is "[đã cắt]") is not used, so the cut is not said twice.
6. **A read that fails after a write replaces the screen with the page error**, with no stale cluster left. The cluster just labelled
   would otherwise stay on screen, with a form that can only be refused (`already_labelled`). The page does not read again on window
   focus or reconnect (`refetchOnWindowFocus: false`): a cluster being read must not change under the labeller. It is read on entry
   and after its own writes.
7. **The samples are plain `<pre>`s, not `LogBlock`s.** `LogBlock` is a `role="region"` with the fixed name "Log gốc"; several on one
   page repeat a landmark name (axe `landmark-unique`), and a copy button inside a collapsed sample has no use.
8. **The form panel is a `<section>` named "Nhãn cho cụm này", not an `<aside>`.** Chosen up front: an `aside` inside `main` is a
   complementary landmark inside another landmark. I did not run axe on the `aside` variant.
9. **`frozen` is checked before `candidates_present`** (the Jinja page did the reverse). The card says "while `frozen` is true, render
   the frozen state", and frozen is the more useful thing to say when both are true. A candidate file that is there but has no cluster
   (`total` 0) is the no-candidates state, not "finished 0 of 0".
10. **Errors of the writes are shown at the form when the form is on screen** (beside the buttons just pressed, in a sticky panel), and
    above the content on the other screens (frozen, finished, no candidates), so a refusal never disappears with the form it came from.
    A confirmation is a `Toast` at the top.
11. **Wording against the canvas.** The subtitle drops "bộ gold_v2 · dữ liệu minh hoạ" (a design annotation). The canvas's bold
    "146 lần" is plain text (one string). The severity chip shows the raw code like the canvas, in the band colour when the code is one
    of the four bands. `alert_id` (an allowed key) is not shown: `gold_cluster_id` is the same text and is what the Jinja page showed.
    The frozen card's heading names `gold_v1` as the canvas does, and the count in its sentence is the answer's `total`, not a literal 56.
12. **No dialog.** The canvas and spec give the undo no confirmation, so there are no dialog confirm/cancel tests.
13. **The error screen's only link** is the shared `PageError`'s "Hàng đợi" (`/queue`). It is not on any state of the labelling flow.
14. **`strings.ts`:** `S.admin.labelsPage` is appended after `S.admin.verdict`, the last key of `S.admin`; it adds no import to the
    file's header (the choice and confidence types are checked where they are used).
