**I-2 · Important · `frontend/e2e/admin.spec.ts:185-186, 200-210, 221-240` · scenario 2 leaves the run's new-user password typed in a form, and line 210 prints it on failure.**
- `fillCreateForm` types `newUserPassword()` into the password and repeat fields. Nothing clears them on failure, as `clearingOnFailure` does for the login form (`frontend/e2e/loginFailure.ts`). After a refused duplicate at 221-223 both fields stay filled through line 240, because the panel empties only on success (`UserCreatePanel.tsx`: `onSuccess` calls `setValues(EMPTY)`, `onError` does not).
- Line 210, `expect(panel.getByLabel(C.password, {exact: true})).toHaveValue("")`, prints the received value when it fails.
- Evidence on a scratch Playwright project (a `type="password"` input filled with the marker `MARKER-pw-0123456789abcdef`):
  - `toHaveValue("")` failed with `Expected: ""` and `Received: "MARKER-pw-0123456789abcdef"` in the console. That marker is in `error-context.md` four times.
  - A failure elsewhere, with the field still filled, put `- textbox "Mat khau": MARKER-pw-0123456789abcdef` in the page snapshot of `error-context.md`.
- Evidence on the real stack (M10, the create route made to answer 500): scenario 2 went red at line 202, with the password fields still filled. The scan said `ui_e2e_scan: secret found in .../test-results/admin-scenario-2-.../error-context.md`, then `ui_e2e_run: the run left a secret behind: the target fails`.
- The scan catches it, so no secret goes unseen, and the account is a throwaway of a scratch database. But the password is written to `test-results/` and, via line 210, to the terminal and any CI log. The project already decided that must not happen (`loginFailure.ts`, `src/e2eLoginFailure.test.ts`).
- Fix:
  - Replace line 210 with `expect((await panel.getByLabel(C.password, {exact: true}).inputValue()).length).toBe(0);`, which can only print a number.
  - Wrap the create section in a helper that empties both password fields on failure (`field.fill("", {timeout: 2000})` in a try/catch, as `clearingOnFailure` does), and empty them explicitly after the refused duplicate at 223.

**M-1 · Minor · `frontend/e2e/adminFixtures.ts:139-160` · `holdAdminLocks` has no `child.stdin.on("error", ...)`.** If psql dies early, `child.stdin.write` (161, 156) emits an unhandled `EPIPE`, which crashes the worker with a stack instead of the poll's clear message.
