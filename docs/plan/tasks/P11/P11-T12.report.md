## 2. Deviations

1. **Commit trailer.** The brief names `Claude Opus 5.5`; I am Sonnet 5.5 and the session's attribution lines say so, so each commit ends with
   `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` then `Claude-Session: …` (as P11-T10 did).
2. **"Row menu" is a disclosure button, not a floating menu** (spec §4.2: "a row menu also offers Vô hiệu hoá"). `RowMenu` is a "⋯"
   button with `aria-expanded` and `aria-controls` that shows "Vô hiệu hoá" in place, under the row's main button. A floating panel
   would be clipped by the table's `overflow-x-auto`, and an ARIA `menu` would need an arrow-key model for one item. Esc and a press
   elsewhere close it; choosing the action returns the focus to the "⋯" button first, so the dialog gives it back there. An inactive
   account has no "⋯" (it has nothing to offer).
3. **A refusal is a card in the dialog, for all four reasons.** The canvas draws `last_active_admin` as a dialog with only "Đóng", but
   `self_change` as a bare alert. A bare alert has nothing to belong to once the dialog is the place the action was asked, so
   `self_change`, `forbidden` and `not_found` get the same card: title, alert, "Đóng". `last_active_admin` and `not_found` also read the
   list again (it may be out of date); that refetch is `client.invalidateQueries({queryKey: adminKeys.users})`, not `invalidateAfter`,
   because nothing was written.
4. **"Kích hoạt lại" has no confirmation dialog.** The brief lists four dialogs, the canvas draws none for it, and it is undone by
   deactivating. A refusal shows as an alert on the page.
5. **The caller's own row is told by the session's username**, not by `GET /api/auth/me`'s `user_id`. The login looks a username up
   exactly and it cannot be renamed, so it identifies the row without a second request and without a window in which the page does not
   know. The server still refuses a self change with `409 self_change`, and the page shows that.
6. **Layout.** The canvas is 1440 wide, list and matrix on the left and the create panel beside them. At 1280 (the app's minimum) the
   panel would leave the table 580 px, so below 1440 px the panel sits under the table (a CSS grid, `min-[1440px]:`). At 1440 the layout
   is the canvas's.
7. **Copy.** The canvas subtitle's "· dữ liệu minh hoạ" is a note about the canvas and is not on the page. The brief's phrase "phiên cũ sẽ bị
   đăng xuất" is in the canvas as two sentences: the matrix note ("phiên cũ của người đó bị đăng xuất") and the role dialog ("Mọi phiên đang
   mở của lan.t1 bị đăng xuất; …"); both are on the page. The server's `invalid` on the username, the display name and the password has
   plainer words than "Giá trị không hợp lệ" (`S.admin.usersPage.create.usernameInvalid`, `…displayNameInvalid`,
   `S.admin.usersPage.password.invalid`); the other reasons use `S.admin.reason.*` through `adminReasonText`.
8. **The page does not pre-check Cf/Zl/Zp in a display name.** The server's Unicode tables are the rule (a different JS and Python table could
   refuse differently), so it posts and shows the `422 invalid` at the field. It does check blank and more than 100 characters.
9. **The toast has no timer** (the canvas says it hides after 5 s). The shared `Toast` is the house one: no timer, dismissed with "Đóng".
10. **Edits outside the page's own files**, each small: `strings.ts` (the `usersPage` sub-object only); `adminStrings.test.ts` (item above);
    `AdminLayout.test.tsx` (`BUILT = ["UsersPage"]` and `PLACEHOLDERS`, because the built page needs a query client, a session and an API
    that the placeholder tests do not give; **the other page tasks will each add their name to `BUILT`**, which is the one line where the
    four branches will conflict); `routes.test.tsx` (`vi.mock` of `UsersPage`, as it does for the queue and alert pages).
