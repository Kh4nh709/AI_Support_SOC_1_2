### Findings

**Minor 1. `pct` reads 100.0 below the cap.** `backend/app/web/routers/admin_llm.py:382`
- Evidence, probe P3 (cap 30, one run at 29.99):
  ```
  P3 month_spend_usd: 29.99 cap: 30
  P3 adapter would stop (spent >= cap): False
  P3 page: {'spent_usd': 29.99, 'cap_usd': 30, 'pct': 100.0, 'projected_usd': 53.7045}
  ```
- Consequence: P11-T13's rule "≥ 100 % red stopped notice" would claim a stop while the model still runs, for any spend from 99.95 % up to the cap.
- Fix, either of:
  - floor `pct` (`ROUND_DOWN`), so that `pct >= 100` exactly when `spent >= cap`, the adapter's comparison. `test_month_pct_and_projection_on_a_frozen_now` then expects 41.6 (mutation m9 shows that test pins half up);
  - or keep `pct` and tell P11-T13 to drive the red notice from `spent_usd >= cap_usd`.

**Minor 2. The `stopped` map echoes `stopped_by` with no length limit.** `backend/app/web/routers/admin_llm.py:254-256`
- Evidence, probe P2 (one run whose `stopped_by` is a marker plus 500 characters):
  ```
  P2 stopped keys lengths: [538]
  P2 recent outcome: None
  P2 marker in response: True
  ```
  `outcome` limits the stop reason to 32 characters; `by_pipeline_role.stopped` does not.
- Severity: not model-reachable. The only writers are code constants (`cap`, `schema`, `transient`, `linter`, `permanent`), and the column has no CHECK (migration 016).
- Fix: in the `stopped` CTE, group by `CASE WHEN length(stopped_by) <= 32 THEN stopped_by ELSE 'other' END`, plus one test.

**Minor 3. The one-hour floor still multiplies day-1 spend by up to 744.** `backend/app/web/routers/admin_llm.py:245, 337`
- Evidence, probe P7: $0.05 at 00:05 on 1 October projects $37.20, 124 % of a $30 cap. $1.00 at 12:00 on day 1 projects $62.00.
- The page labels it a linear projection, but a five-minute sample drives it.
- Fix, either of (both leave every value from day 2 on unchanged):
  - floor at one day, `max(elapsed_s, 86400)`, which matches the "elapsed days" reading of §5.3;
  - or return the elapsed time so P11-T13 can hide the projection during day 1.

**Minor 4. Three mutations survive: test gaps.** `backend/tests/test_admin_llm_usage.py` (no such tests)
- Evidence, the runner in the scratch copy:
  ```

  ```
- No seeded row tells `result IS NOT NULL` apart from `stopped_by IS NULL`.
- Nothing seeds more than 200 quota users.
- Deviation 5's degrade path is never exercised.
- Fix, three tests:
  - one row with both a result and `stopped_by`, and one with neither; expect `with_result` 1 of 2 (probe P10 shows the code is right: `P10 2 1 {'cap': 1}`);
  - 201 users with one `case.analyzed` each; expect 200 listed;
  - monkeypatch `admin_llm.limits_out` to raise `psycopg.errors.QueryCanceled`; expect a 200 with `limits: null` and `limits_error: "limits_unavailable"`.

**Minor 5. The calendar-month test depends on the day of the month.** `backend/tests/test_admin_llm_usage.py:566-576`, by reasoning, not run.
- The only seed before the month is at `month_start - 1 day`. That is inside a rolling 30-day window only up to about day 29.
- On days 30–31 the Coder's red step (e), "month as a rolling 30 days", would survive. The same holds for `[month]` of the range test from day 21 on.
- Fix: also seed at `date_trunc('month', now()) + interval '1 second'` and assert the set the `month` row holds. From day 30 on, that seed falls outside the rolling window, so the two readings differ on every day.
