### Findings

**m1 · Minor · `frontend/src/features/admin/AuditPage.tsx:359-364`, `:406-410`, `:466-471`. The stack of cursors is not dropped on a filter change.**
- Evidence: `paging` is `{key, cursors}` and `cursors` is read as `paging.key === key ? paging.cursors : NO_CURSORS`. A view is ignored while the URL differs but is not dropped, so it returns when the same URL does. The comment at `:357-358` and the report ("dropped when a filter changes") say otherwise.
- A probe on a 120-row log (probe, deleted):
  - Page 2 of the default view, then group `users`, then the group set back to "Tất cả" and "Lọc": the page shows "51–100 trong 120 sự kiện" with Trước on, not page 1.
  - "Xoá lọc" from a filtered view lands on the page the unfiltered view was left on.
  - Back from `users` shows page 2 with URL `/admin/audit`, while a reload shows page 1.
  - A 503 on page 3 shows no pager, only "Lọc", "Xoá lọc" and "Thử lại". "Lọc" with unchanged filters refetches page 3, and the way out is to narrow a filter or reload.
- Rows, range and total always agree; the cursors stay valid. The test "starts again at the first page when a filter changes" covers A to B only.
- Fix: reset on key change during render, `if (paging.key !== key) setPaging({ key, cursors: NO_CURSORS })`, as `FilterForm` does for its draft. In `apply` and `clear` also set the stack to `NO_CURSORS` for the new key. Add tests: A (page 2) to B to A (typed) shows 1–50; "Xoá lọc" from page 2 shows 1–50. Optionally show Trước in the error region when `page > 0`.

**m2 · Minor · `AuditPage.tsx:382-385`. The `placeholderData` guard is untested (mutation M9 survived).**
- Evidence: replacing the guard with `placeholderData: previous` made all 87 tests of `AuditPage.test.tsx` pass. Without the guard, view A's rows stay on screen, greyed and `aria-busy`, under view B's filters and URL until B answers (up to the 3 s timeout), with the old offset in the range text.
- Fix: one test that gates B's answer, changes the filter, and asserts that A's rows are gone and the skeleton shows.

**n1 · Nit · `AuditPage.tsx:313` (`QueryFailure`), `AuditPage.test.tsx` "says a failed query in its own words too".** `503 query_failed` is a state `admin_audit.py` never sends (only `timeout`, `:337-340`). I accept it (deviation 7), but nothing in the code says so. Fix: a one-line comment at `QueryFailure` and at the test that this route does not send it, so a later reader does not think it can.

**n2 · Nit · `frontend/src/features/admin/auditSummary.ts:22-42`. The `visible()` deny-list has gaps.**
- A probe passed these through unescaped: the Tag characters U+E0001 and U+E0020–E007F (they are surrogate pairs, so a regex without the `u` flag cannot match them), U+034F, the Hangul fillers U+115F, U+1160, U+3164 and U+FFA0, U+2800, and U+FE00–FE0F.
- A literal text `‮` typed into a subject, actor or summary shows the same as an escaped U+202E (in JSON a literal backslash is doubled, so the payload is not ambiguous).
- Impact is low: no execution, and the bidi controls that matter for name spoofing are covered.
- Fix: add the astral ranges with the `u` flag and the missing BMP ones; optionally escape a backslash before `u` plus four hex digits in non-JSON text.

**n3 · Nit · `AuditPage.tsx:438-444` (the range text), `components/LogBlock.tsx` (the copy button).** The range text "51–100 trong …" is not in a live region, so a screen-reader user pressing "Sau" is not told the page changed (focus stays on the button).
