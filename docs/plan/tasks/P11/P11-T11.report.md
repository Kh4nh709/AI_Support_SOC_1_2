## 3. Deviations from the card, the plan, the spec or the canvas

1. **The LLM card is a second read.** The overview answer has no LLM cost (`admin_overview.py`'s nine sections), so the card reads
   `GET /api/admin/llm/usage?range=month` (`adminKeys.llmUsage("month")`, the key the LLM page will use, so a limit change refreshes it).
   It waits and fails alone (its own "Không tải được" and retry). That read is heavier than one number needs (`by_pipeline_role`, the
   quota, the last 20 runs); a `llm_month` section of the overview would be cheaper. It is a backend change my row does not name, so it is
   left as a follow-up for the Director.
2. **The reload result is in the inventory block, not in the dialog.** The card says "the reload dialog shows the result counts and the
   warnings". Spec §4.1 says "the result shows" and the canvas (`AdminStates`, "KẾT QUẢ NẠP KIỂM KÊ") draws the result and the 422 as cards
   outside the dialog, which is only the confirmation. So both answers close the dialog and the block keeps the result (dismissible), where the
   warnings can be read after the dialog is gone. Every other failure stays in the dialog. If the Director wants the result inside the dialog
   instead, it is a small change in `InventoryBlock.tsx`.
3. **`not_failed` and `not_found` use `S.admin.reason`'s text, without the job id.** The canvas says "Job 100412 không còn ở trạng thái
   lỗi…"; the notice sits in the failed-jobs block, right under the row the admin clicked, and the shell's text (pinned by its tests) is the
   single source. The 404 text ("…hãy tải lại trang") says to reload the page although the list has been reloaded already.
4. **Health labels.** The canvas shows sentence labels for four healthy checks and mono codes for failing ones; the API sends ten checks with
   English `detail`s. All ten are listed with a Vietnamese label (`S.admin.overviewPage.health.check`, pinned to the ten names of
   `infra/health.py`); a failing one also shows its code (the name `health.alarm` carries in the audit log); a name with no label is shown as it
   is; `detail` is the server's own text.
5. **Open cases sub-line** is "đang được điều tra", not the canvas's "1 đang được AI ② phân tích": the API has no such count.
6. **Toast.** The shell's `Toast` has no timer and a Đóng button; the canvas says it hides after 5 s. I used it as it is (bottom right, fixed),
   and made the two notices of the blocks (a stale list, a reload result) dismissible the same way.
7. **Chart.** Bars are SVG shapes with their size as attributes (the canvas uses inline heights, which the CSP forbids). With more than 12
   days the total over each bar is left out (the bar's title and the `sr-only` table still carry it), and for 31 days only every 4th label is
   drawn, counted back from the last one.
8. **Top agents** has a header row ("Agent", "Alert"), which the canvas lacks, because `DataTable` always has a `thead`.
9. **Extras the canvas does not draw:** the skeleton, a notice for a refresh that failed over data on screen (a silent stale dashboard is the
   worse failure), and a "Thử lại" on each card and block that failed. The page error is `PageError` as it is: its link goes to the queue, and
   the canvas's hint "xem Tổng quan → Sức khoẻ hệ thống" is left out, since this is the overview.
10. **The days of the range are counted from the browser's clock at the time the answer arrived** (`dataUpdatedAt`): the overview answer has
    no server time. A day the API sent is never dropped (a clock that is off stretches the series), and a clock years off returns the API's own
    days unfilled instead of building thousands of points.
11. **The range is component state**, not in the URL: spec §3 keeps only the digest day and the audit filters there.
12. **Shared files.** `strings.ts` (+142 lines, `S.admin.overviewPage`, inserted after `S.admin.building`, not at the end of `S.admin`, so
    it does not touch the lines the other page tasks append to), `AdminLayout.test.tsx` (the `OverviewPage` import, its row of `PAGES`, and
    its title in the expected list: 3 lines removed) and `routes.test.tsx` (a `vi.mock` of `OverviewPage`, +5 lines: the route test looks for
    the place and the title, as it does for the queue and alert pages). `api/admin.ts`, `adminKeys.ts`, `routes.tsx` and `format.ts` are not
    touched.
13. **Commit trailers.** Each message ends with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and the session line, as the
    harness's attribution notice gives for this session (the card's text says Opus 5.5; I am Sonnet 5.5, and P11-T10 did the same).
