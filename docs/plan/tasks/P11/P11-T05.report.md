**`GET /api/admin/overview?range=24h|7d|30d`** (default `24h`, anything else is 422; `Literal`, alias `range`).
- Eight sections, each `_run_section(conn, name, compute, errors)`: `with conn.transaction():` (a SAVEPOINT inside the request's
  transaction), then `SET LOCAL statement_timeout = <SECTION_TIMEOUT>` (`'3s'`, a module constant read at call time), then the
  section's reads. A `psycopg.Error` rolls the savepoint back; the section is `null` and `{section, error}` is appended.
  `QueryCanceled` (the timeout) gives `error: "timeout"`, any other `psycopg.Error` gives `"query_failed"`: never the driver's
  message (it can quote SQL) and never a DSN; the log line carries only the class and SQLSTATE. A non-`psycopg` exception is a bug
  and stays a 500. `infra/db.transaction()` is not used (it issues its own `BEGIN`/`COMMIT`).
- The sections are called through lambdas that look the function up by name when the request runs, so a test replaces
  `admin_overview._top_agents` (etc.) to make one section fail.
- `alerts_by_day`: `(received_at AT TIME ZONE %(tz)s)::date`, `tz = cfg.DISPLAY_TZ` as a bound parameter; total, heads
  (`duplicate_of IS NULL`) and duplicates (`IS NOT NULL`); ascending; a day with no alert is absent.
- `by_source`: `{rows: [{source, alerts, heads}], rejected}` (rows by alerts desc, then source; `rejected` over `rejected_alerts` in
  the range). `top_agents`: at most 5, count desc, then name. `funnel`: `by_status` over heads (statuses present only),
  `triage` `{ready, unavailable, pending, none}` always four ints. `cases_open`: int, `status = 'investigating'`. `health`: the
  newest `system_health` row `{checked_at, ok, checks}` or `null`. `failed_jobs`: `status='failed'`, `created_at DESC, job_id DESC`,
  `LIMIT 50`, `left(last_error, 200)` in SQL. `inventory`: active assets, identities and iocs, `loaded_at` the `GREATEST` of the
  three tables' newest active `loaded_at` (`GREATEST` skips a NULL).

**`POST /api/admin/jobs/{job_id}/retry`** (`job_id: int`, `Path(ge=1, le=2**63-1)`, `jobs.job_id` is a `bigint`).
- One request transaction: `SELECT ... FOR UPDATE` on the job (404 `not_found`), `status <> 'failed'` is 409 `not_failed`,
  `_has_live_sibling` is 409 `already_queued`, then `UPDATE ... status='pending', attempts=0, scheduled_at=now(), locked_at=NULL`
  inside a savepoint that catches `UniqueViolation` of `ux_jobs_mot_job_song_moi_subject` (the race where `enqueue` inserts the
  sibling after the check) and answers the same 409 instead of a 500; any other unique violation is re-raised. `last_error` is kept.
  Then `write_event("admin.job_retried", str(job_id), "admin", actor_id=claims.user_id, payload={job_id, job_type, subject_id,
  attempts_before, last_error[:200]})` in the same transaction, then `200 {job_id, status: "pending"}`.
- The worker really claims it again: `claim_job` takes `status='pending' AND scheduled_at <= now() AND job_type = ANY(...)` and
  sets `attempts = attempts + 1`; the retry satisfies all of that, and `reclaim_stale` only touches `running` rows. A test claims the
  retried job with `jobs.claim_job` and gets `attempts == 1`.
- Both routes take `claims: Admin` (`Admin = Annotated[Claims, Depends(require_admin)]`, `require_admin = require_role("admin")` is a
  module name so a test can assert the dependency is on each route).

## 4. Deviations

1. **Savepoint, not `infra/db.transaction()`** (the Director's instruction; the spec §2 and plan text at `a530b6d` still say
   `db.transaction(...)`, and `17e7135` amends them). Each section uses `conn.transaction()` plus `SET LOCAL statement_timeout`.
2. **Error bodies are `{"detail": {"reason": ...}}`**, not the bare `{"reason": ...}` of the card text: spec §3 says "a 409 whose
   `detail` is an object carries a machine-readable `reason`" and `api/client.ts` reads `detail`. The 404 uses the same shape.
   If the Director wants the flat body (`JSONResponse`, like `tier1.py`'s 409), it is a two-line change in `_refuse`.
3. **`inventory.loaded_at` is over active rows only** ("Active rows only" read as covering the whole object). A load stamps every
   row it keeps with `loaded_at = now()` and `active = true`, so the two readings differ only when the newest load kept nothing.
4. **`NOT is_synthetic` is applied to every alert section** (`by_source`, `top_agents`, `funnel` too), not only `alerts_by_day`, as
   the queue, the digest and the health checks do. `top_agents` counts all non-synthetic alerts of the range (heads and duplicates),
   the same base as `alerts_by_day.total`; `by_source` carries `heads` beside `alerts`; `funnel` is heads only.
5. **Shape choices the card left open**: `alerts_by_day` lists only days that have alerts (the UI can zero-fill); `funnel.by_status`
   lists only statuses that occur; `triage` always has its four keys (`none` counts NULL, which `ck_alerts_triage_status` and the
   NOT NULL column make 0 today); `failed_jobs` is ordered `created_at DESC, job_id DESC` ("newest" is the job's creation;
   `locked_at` is the last claim and may be NULL).
6. **`job_id` is bounded to 1..2^63-1**, because it is a `bigint`: a plain `int` path parameter would let `99999999999999999999`
   reach the driver as a `DataError` 500. Outside the bounds it is a 422, the largest bigint is a plain 404.
7. **The `error` texts are `timeout` and `query_failed`** (two short codes). The brief said "a short generic text".
8. **Tests use a module scratch database**, not the shared `db` fixture (reasons in section 2), and three tests go beyond the card:
   `test_an_unknown_display_tz_fails_only_that_section`, the two concurrency tests, and the `FOR UPDATE` red step.
9. **Suite counts.** `make test` is 2173 passed here against the 2168 of the brief. This branch adds exactly one non-db test; the
   other four are already in the tip: `git archive a530b6d` collects 2172 non-db tests (measured in the scratchpad, not run
   green there for lack of untracked files), so the stated baseline looks four short. The DB suite is the baseline's 1371 plus
   this task's 57, 1428, which is exact.

    plus this report, no shared file, so the merge should be clean.
