**The route.** `GET /api/admin/audit?range=&group=&actor=&subject=&cursor=&limit=`, `claims: Admin`
(`Admin = Annotated[Claims, Depends(require_admin)]`, `require_admin = require_role("admin")` is a module name so a test can assert the
dependency is on the route). Answer `{events: [{audit_id, created_at, event_type, actor_role, actor_username, subject_id, payload}],
next_cursor, total}`, `audit_id DESC`.

- **Parameters.** `range` is a `Literal["24h","7d","30d"]`, default `7d`. `group` is `Literal[tuple(GROUPS)]` (an enum in the OpenAPI
  schema). `limit` is `Query(ge=1, le=100)`, default 50. `cursor` is `Query(ge=1, le=2**63-1)`. `actor` and `subject` are
  `min_length=1` strings that may not hold a NUL byte. Each bad value is a 422 from the framework, before any SQL (the role check answers
  first: a tier1 user with `?limit=abc` is still a 403).
- **Filters.** `_filters()` returns a list of fixed `sql.SQL` fragments and a parameter dict; a request value only ever reaches the dict.
  `range`: `a.created_at >= now() - %(window)s`. `group`: `a.event_type = ANY(%(types)s)`. `actor`: `system` or `llm` is
  `a.actor_role = %(actor_role)s`, anything else `a.actor_id = (SELECT user_id FROM users WHERE username = %(actor)s)` (an unknown name
  makes the subquery NULL: no rows, no error). `subject`: `a.subject_id = %(subject)s`. The page adds `a.audit_id < %(cursor)s`.
- **`actor_username`** is a LEFT JOIN on `users`: `null` for `system`, `llm`, and for an actor with no `users` row
  (`audit_events.actor_id` has no FK).
- **`next_cursor`** is the last row's `audit_id` when the page is full, else `null`. **`total`** is `count(*)` of the same filter
  without the cursor.
- **Timeouts.** `_fetch_page` runs in `conn.transaction()` (a savepoint inside the request's transaction) after
  `SET LOCAL statement_timeout = QUERY_TIMEOUT` (`"3s"`); `QueryCanceled` is `503 {"detail": {"reason": "timeout"}}` (spec §3: a
  `detail` object carries the `reason`). `_total` is its own savepoint under `TOTAL_TIMEOUT` (`"1s"`) and answers `None` on any
  `psycopg.Error`. Both constants are read when a request runs. `infra/db.transaction()` is not used.
- **`GROUPS`** is the spec §5.8 table, five keys (`users`, `configuration`, `alerts_cases`, `model`, `system`), every name written out
  (13 + 3 + 5 + 4 + 3 = 28 = `len(EVENT_TYPES)`).
- **Payloads.** The size is decided in SQL: `CASE WHEN octet_length(a.payload::text) > 65536 THEN NULL ELSE a.payload::text END`, so
  a payload over 64 KiB never leaves the database and the row carries `{"truncated": true, "size": <bytes>}`. The rest is parsed
  (`json.loads`) and `redact()`ed: a dict key whose lower-cased name is in `REDACT_KEYS` has its value replaced by `"[đã ẩn]"` at any
  depth, through lists and dicts; nothing else is changed (no stringifying). `payload` is `null` for a SQL NULL.

## 4. Deviations

1. **Savepoint, not `infra/db.transaction()`, and the 503 body is `{"detail": {"reason": "timeout"}}`** (the Director's instruction, and
   the shape of `admin_overview`; the card text says the bare `{reason: "timeout"}`).
2. **The 64 KiB is measured in the database**, as `octet_length(payload::text)` (jsonb's own text, in UTF-8 bytes), not as a Python
   serialisation. Reason: a payload over the limit never reaches this process (a 1 MB string costs nothing), and the number in
   `{"truncated": true, "size": n}` is the stored size. jsonb's text has a space after `:` and `,`, so it can differ from a compact
   `json.dumps` by a few percent; a multibyte string is counted in bytes. The cut is `> 65536`.
3. **A depth cap the card does not name: more than 32 nested dicts and lists is cut the same way** (`{"truncated": true, "size": n}`),
   and so is a payload the JSON parser itself cannot read (`RecursionError`, from about 9,000 levels). Why: measured here,
   PostgreSQL stores `[[[...]]]` to about 15,000 levels (`stack depth limit exceeded` at 20,000), under 64 KB; FastAPI 0.141's
   serialiser raises at about 250 levels (a 500, and the same 500 on every page that row falls on, so one row would kill the audit
   page). No event the system writes nests past a handful. 32 is a judgement; it is `MAX_PAYLOAD_DEPTH`. "Never truncated except as
   below" is therefore read as "except for size or depth". A cut payload never leaks a secret: it is not sent.
4. **`actor` and `subject`: an empty value or one holding a NUL byte is a 422.** The card is silent. A NUL cannot be sent to
   PostgreSQL (the driver raises: a 500). An empty `?actor=` is refused rather than read as "absent", so a UI must leave an unset filter
   out of the URL (P11-T17's job).
5. **`actor` details the card leaves open.** `system` and `llm` are roles even if a user has that username (the role wins). A username
   is matched exactly and case-sensitively, as `auth.login` matches it. A deleted user's rows (an `actor_id` with no `users` row) are in
   the unfiltered list with `actor_username: null` and are matched by no username.
6. **`total` excludes the cursor and is always counted** (so it is the same on every page). It is not skipped on a short page.
7. **`next_cursor` "when the page is full"** means a full last page still carries a cursor and the next page is empty with `null`
   (tested, as the card words it). It does not fetch `limit + 1`.
8. **`cursor` is `>= 1`** (an identity starts at 1; `0` and negatives are 422) and at most `2**63 - 1`. `1e3`, `1.5` and the like are 422.
9. **A database error on the page other than a timeout stays a 500** (the card names only the timeout), e.g. a lost connection.
10. **Redaction matches the exact lower-cased key name, as the card says**: `apiKey`, `api-key`, `access_token` and `client_secret` are
    not redacted. Pinned in a test (`passwords`, `token_count`, `api-key`, `apikey` stay visible). The first layer, DEC-159 item 6
    (nothing writes them), is what covers those.
11. **`_WINDOWS` is a copy** of `admin_overview`'s three lines, not an import of a private name from a sibling router.
12. **Tests use two scratch databases** (reasons in section 2) instead of the shared `db` fixture, and the main-query timeout is a
    real lock-induced cancel, while the count's is a monkeypatched `pg_sleep` inside `_count_matching` (both queries read the same
    table, so a lock stops the page too and "page served, `total` null" could not be built that way). The lock holder releases itself
    after 8 s (section 3, last paragraph).
13. **Query cost, measured, not required:** 600,000 `audit_events` rows on the scratch server (`ANALYZE`d), no new index: the page took
    0.6 ms to 99 ms (`default 7d` 95 ms, `group model` 99 ms, an unknown username 30 ms; a `subject` filter 1.3 ms) and `total` 25 ms to
    60 ms (`count(*)` over all 600,000: 44 ms), all far under 3 s and 1 s.
14. **Baseline.** Measured before the first change at `3779371`: `make lint` exit 0; `make test` **2175 passed**, 20 skipped, 1433
    deselected, 2 xfailed (the brief said about 2173); DB **1430 passed** + the 2 known `test_backup_restore.py` XML failures.

Not done: nothing from the card is left out. `strings.ts` (the mirror of `GROUPS`) and the page are P11-T10 and T17.
