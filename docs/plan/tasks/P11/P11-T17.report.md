## 4. Deviations

1. **Commit trailer.** The brief says `Co-Authored-By: Claude Opus 5.5`; the session's own attribution line (the system reminder of this
   run) says `Claude Sonnet 5.5`, which is the model I am. I used the session's line on every commit (the first commit was amended to it
   before anything else was built on it).
2. **`components/LogBlock.tsx`, a shared component, is changed** (`aaa35de`). It gains an optional `label` (default `S.alert.rawLog`,
   the text it had), used as the `aria-label` of the `<pre>`. Nothing else changes. It is needed: two payloads open at once would
   both be the region "Log gốc", and a screen reader could not tell them apart. Its only other user is `tier1/AlertSections.tsx`, which
   passes no label; `AlertPage.test.tsx` and `CasePage.test.tsx` (the two that read the raw log) pass unchanged.
3. **Not the shared `DataTable`.** `AuditTable.tsx` is its own table: `DataTable` has one `<tr>` for each row and the canvas draws the
   payload as a full-width row of its own beneath its event. It uses the same classes and the same caption and `scope="col"` rules.
4. **One more column.** The canvas has five columns; the table has a narrow first one for the toggle button (`aria-label` "Xem payload: …",
   `aria-expanded`), whose header is read by a screen reader only.
5. **Subject links go to alerts and cases only** (the brief). The canvas also links a rule, a user, a limit and a job to their admin
   pages; here those are text. `job.exhausted` has no link either: its subject is an alert, a case or a day depending on the job, and
   the event does not say which.
6. **A "Thử lại" button on a 503.** The canvas's timeout card has the alert and the note and no button. The page still does not retry by
   itself (`retry: false` on the query, a test with the app's own retry rule); the button asks again, because pressing "Lọc" with the
   same filters would otherwise be the only way, and it is not obvious.
7. **The 503 `query_failed` is shown although this handler never sends it** (`admin_audit.py` answers `503` only for `timeout`; any other
   database error is a 500, which is the page's error). The shell's reason table has the code and the brief names it, so it has its
   own text and a test; it costs nothing.
8. **The default range is 7 days.** The canvas's select lists 24 hours first, but the handler's default and the canvas's own "no match"
   card both say 7 days. The URL leaves the default out.
9. **The form sends on "Lọc"** (the canvas draws a submit button), all four filters at once; Enter in a text filter sends too; sending the
   filters the page already has reads again. "Xoá lọc" clears the form, including what was typed and not sent, and the URL.
10. **The cursor is not in the URL.** The API pages forward only, so "Trước" needs the cursors already seen, which are page state; a reload
    gives the first page of the same filters.
11. **No match or empty log.** "No match" is shown when a group, an actor or a subject is set or the range is narrower than the default;
    otherwise an empty answer is "Nhật ký chưa có sự kiện nào" with the range named.
12. **The payload note is reworded.** The canvas says a payload "không bao giờ chứa mật khẩu, hash, DSN hay key"; the server only redacts
    (a second layer, spec §5.8), so the note says the value of a sensitive key was replaced by "[đã ẩn]". The canvas's "dữ liệu minh hoạ"
    is dropped from the subtitle.
13. **More than the brief: invisible characters are written out.** JSON escapes control characters below U+0020 but not DEL, the C1
    controls, a right-to-left override or a zero-width mark. `visible()` (in `auditSummary.ts`) writes each of those as its `\uXXXX`
    escape in the payload, the summary, the subject, the actor and the event type, so a subject such as a request path with an override in
    it (`authz.denied` stores the path) cannot make one name read as another. A test per code point.
14. **A summary of an `admin.user_updated` is read from the difference** of `before` and `after`, not from `after` alone (found by the
    canvas's own sample, which lists `is_active` in both).
15. **The summaries are my wording** for the 18 event types the canvas gives no line for (it gives nine); each is a clause in
    `S.admin.auditPage.summary`, with a fallback sentence when the payload lacks its keys. The `S.admin.auditPage` object is one block,
    placed after `eventType`, to keep the merge with the other pages small.
16. **Bundle size.** `make ui-build` is exit 0 but the main chunk is 506.64 kB (477.78 kB at `fba1bd8`, built the same way), which crosses
    Vite's 500 kB advice (a warning, not an error). This page adds about 29 kB; the other pages in flight will add more. Code-splitting the
    admin console is not part of this card.
17. **Tooling, for whoever reads the files.** The tool that wrote my files turned a `\uXXXX` escape of U+00AD or above into the raw
    character (so a regex with `\u2028` ended at a line separator). I found it with a scan, rewrote those places, and now build the
    pattern from a table of code point ranges, so no file of mine holds a raw invisible character (a scan of the eleven source files this card touches and of this report: none).
