### The pin

`ruleFields.ts` keeps each field on one line (`name: { type: "…", ops: […] },`). `test_rules_whitelist_pin.py` strips the comments,
reads `RULE_WHITELIST`, `RULE_OPS` and `OP_VALUE_KIND` as text and asserts: every field → operators pair equals `autoclose._WHITELIST`; every scalar type
equals what `_scalar_ok` accepts (found by probing the function with `"x"`, `443` and `True`: exactly one must pass); the operator vocabulary is the union of the
whitelist's; the value shape of each operator (`eq` one scalar, `in` a non-empty list, `cidr` a network and a bare IP, `prefix` any string and the empty one, `lte` an integer
and not a boolean, a string or a float) equals `_value_ok`'s; and the server side of "whole JSON numbers" (`"443"`, `443.0`, `443.5`, `True` are refused). The last two go beyond the brief.

## 4. Deviations

1. **Commit trailer.** The brief names `Co-Authored-By: Claude Opus 5.5`; each commit says `Claude Sonnet 5.5`, which is the model that wrote it (the harness's own attribution line, and what P11-T10's commits carry).
   The `Claude-Session:` line is as given.
2. **One "Tạo rule" button, not two.** The canvas has "Tạo rule" (left, disabled) and "Tạo rule với điều kiện này" (right). Two buttons for one gate would need two hints and two accessible names; the page has the left one, with its
   reason in a hint tied to it by `aria-describedby`, and the right panel carries the stale notice.
3. **The width footnote says "alert", not "cụm".** The canvas says "tỉ lệ cụm của 7 ngày qua"; `rule_width_report` divides the sum of `occurrence_count` closed by the sum over all clusters, i.e. a share of occurrences (alerts, copies included).
4. **Chips quote every string**, `srcip cidr "10.10.5.0/28"`, where the canvas shows the CIDR bare: one rule for every string value, so an empty or spaced value is visible.
5. **A failed list replaces the h1 with `PageError`** (its title is the page's only h1) and keeps the hard blocks and the create flow, instead of replacing the whole page. `PageError`'s extra link to the queue is the shared component's.
6. **Beyond the canvas, from the brief's notes:** the hard-block hint beside a condition that can never close; the hint for an empty `eq` or `prefix` value; the "no condition matches everything" note; the stale notice; `aria-live="polite"` on the preview panel; focus to the first bad value box.
7. **`in` is comma-separated.** A string value that contains a comma can therefore only be given with `eq`. A blank list or a blank item is refused at the box (the server also refuses an empty list). `asset_criticality` and `ioc_reputation` are free text boxes (the server takes free strings), not selects.
8. **Name and reason are required and trimmed** before the create (the Jinja form had `required`; the server accepts empty strings).
9. **Samples are cut to 20** on the page (`SAMPLE_LIMIT`), as the spec says, whatever the server sends. `simulateRule` invalidates nothing: it writes nothing; both writes (`createRule`, `toggleRule`) go through `invalidateAfter`.
10. **A `<header>` is not used inside the page**: the shell's tests count `banner`s, and `aria-query` reads any `<header>` as one. The title block is a `div`.
11. **Shared test files.**
    - `AdminLayout.test.tsx`: the `RulesPage` import and its row of `PAGES` are gone (it is not a placeholder, and it needs a query client those renders lack), and `S.admin.title.rules` leaves the expected titles list; one comment says why.
