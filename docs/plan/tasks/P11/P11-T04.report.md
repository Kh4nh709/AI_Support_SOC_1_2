How each part is built (the module docstring of `admin_llm.py` says the same):

- **`month`**
  - `spent_usd` is `audit.llm_runs.month_spend_usd(conn)` itself, not a copy of its query, so the page and the adapter's cap check cannot disagree. It is the calendar month whatever the range.
  - `cap_usd` is `limits.cap_usd`, `null` when the limits are unreadable.
  - `pct` = spent / cap x 100 to one decimal, `null` without a cap (or a cap <= 0).
  - `projected_usd` = spent / elapsed_days x days_in_month. `elapsed_days` = max(seconds since `date_trunc('month', now())`, 3600) / 86400, so day 1 at 00:05 uses one hour. `days_in_month` = the length of this month in days of 86400 s. Both come from one statement on the database's `now()` and session time zone, as `month_spend_usd` reads it. In code it is the pure function `_projected_usd(spent, elapsed_s, month_s)`, with its own unit test.
- **Money.**
  - `numeric` arrives from psycopg as `Decimal`. `_round(value, places)` quantizes it half up (`ROUND_HALF_UP`) to 4 places (1 for `pct`) and converts it to `float`.
  - The JSON number is that float's shortest repr, so it has at most four decimals and is a number, not a string.
  - `cost_usd` is `numeric(10,5)`, so the fifth decimal is the one dropped.
- **`by_pipeline_role`**: one statement, so the counts and the `stopped` map share a snapshot.
  - A CTE `win` over `llm_runs`, from `now() - interval` for the rolling ranges and from `date_trunc('month', now())` for `month`.
  - A second CTE counts `stopped_by` with `jsonb_object_agg`, non-null only.
  - The group by `(pipeline, role)` gives `count(*)`, `count(*) FILTER (WHERE result IS NOT NULL)`, token sums, `percentile_cont(0.5|0.95)` rounded (numeric, half up) to `int`, and the cost sum, ordered `pipeline, role NULLS LAST`.
  - A `NULL` role (v1 rows have no role) is a row with `role: null`.
- **`quota`**: `case.analyzed` rows grouped by actor, joined to `users`, over `tier2_runs.ANALYZE_QUOTA_WHERE`. Most used first, then username, `LIMIT 200`. `remaining = max(0, limit - used)`.
- **`recent`**: the last 20 by `(created_at DESC, run_id DESC)`.
  - `result` and every text column of the run are NOT in the select list, so nothing in Python can leak them.
  - `outcome` is computed in SQL from the row's one verdict key, only when that value is a JSON string of at most 40 characters. Any other value is `null`.
  - A row with no verdict and a short `stopped_by` is `stopped:<stopped_by>`.
- **Blocks.**
  - `_block(conn, name, compute)` runs each of `month`, `by_pipeline_role`, `quota` and `recent` in `conn.transaction()` after `SET LOCAL statement_timeout = BLOCK_TIMEOUT` (`5s`). `infra/db.transaction()` is not used.
  - `QueryCanceled` gives 503 `{"detail": {"reason": "timeout"}}`. Any other `psycopg.Error` gives 503 `{"reason": "query_failed"}`. The driver's message is never sent.
  - `_limits_block` is the one that degrades: `limits: null`, `limits_error: "limits_unavailable"`, and the rest is served.
- No request reads one of the three limit keys from `cfg`, and `from_config` is not called: the P11-T03 grep and AST guard in `test_settings.py` stays green.

## 4. Deviations

1. **`tier2_runs.py` is edited.** The card's Files line names only `admin_llm.py`, but the card also asks to "reuse or share the counting rule with `tier2_runs.py`". The rule is now the public constant `ANALYZE_QUOTA_WHERE`, and `_analyze_quota_count` builds its query from it. Its behaviour and its SQL are unchanged (the test of the analyze route still passes). The usage query is built from the same constant.
2. **The verifier's outcome.** The card says triage gives `result->>'suggested_action'`. A ① verifier row's `result` is `{agree, structured_only_verdict, reason}` (`llm/templates/output_schemas.json`) and never has `suggested_action`, so under the card every verifier row would show `null` unless stopped. I read the verdict from `structured_only_verdict` for `pipeline='triage'` with `role='verifier'`, under the same string and 40-character rule. If the Director wants the card to the letter, it is one `WHEN` in the `LATERAL` of `_RECENT_SQL` and the verifier cases of `test_outcome` and of the 41-character test.
3. **The `outcome` decision table**, where the card's wording ("otherwise, or when `result` is null and `stopped_by` is set") can be read two ways:
   - `result` is null: `stopped:<stopped_by>` if set (and the whole outcome is at most 40 characters, so a `stopped_by` over 32 characters is `null`), else `null`.
   - `result` is not null and the verdict key is present: the value if it is a string of at most 40 characters, else `null`. A hostile value is not rescued into `stopped:`.
   - `result` is not null and the key is absent (or `result` is not an object): `stopped:<stopped_by>` if set, else `null`.
4. **The scratch database, and the rename.** The tests use a per-module scratch database, as `test_admin_overview.py` does, not the shared `db` fixture, so totals are exact. The unreadable-limits test renames `settings` inside the test's own transaction, rolled back with it, rather than a committed rename restored in `finally` on a fresh connection. The route runs on the test's own connection, so a committed rename is not needed, and a crash cannot leave the table renamed (`test_admin_llm_limits.py` does the same with `DROP TABLE settings`). The card names the committed variant; the cost of the transactional one is that it would not catch a route that opened its own connection, and this one cannot.
5. **A failing `limits_out` read also degrades.** `limits_out` reads `users` for the names. If that read fails, `limits` is `null` with `limits_error: "limits_unavailable"` too (and then `cap_usd` and `quota.limit` are `null`), instead of a 503. The page then shows the read-only fail-closed panel, which is the conservative choice.
6. **Two CHECKs are dropped inside the hostile-verdict tests.** `ck_llm_runs_suggested_action` and `ck_llm_runs_suggested_conclusion` refuse any triage or investigate verdict outside the closed set, so a long or non-string one cannot be seeded under them. The route must not rely on that, so the tests drop both CHECKs for their own transaction (rolled back). The verifier key `structured_only_verdict` has no CHECK and is tested without that.
7. **The red steps ran on a scratch copy**, not in place (harness refusal, see section 3), and three more were added, (e) to (g).
8. **The quota list is capped at 200 users** (spec §6: "a row cap"). The card did not name a number.

Observations for the Director, not changes:

- `llm_runs` has no index on `created_at`, so `by_pipeline_role` and `recent` scan the table. That is fine at the lab's volumes and the 5 s statement timeout bounds it, but a later growth would want `(created_at DESC)`.
- Money at four decimals drops the fifth: a single call under $0.00005 shows `0.0` in `recent`. It is what the card asks for. Sums over many calls are exact to the rounding.
- The month's boundaries follow the database session's time zone, as `month_spend_usd` does. If the server's zone is not `DISPLAY_TZ`, the page's month starts at the server's midnight. This is the adapter's rule too, so the page and the cap agree.
- In a zone with daylight saving, `days_in_month` is 30.04 or 30.96 days for the month containing the change; the projection's ratio stays consistent.
