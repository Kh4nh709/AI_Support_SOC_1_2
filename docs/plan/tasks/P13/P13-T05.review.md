## Findings

### M1. The new runbook rows give a restart command that does not apply an `.env` change
- **Where:** `docs/runbook.md:237` (`rag_budget`) and `:235` (`knowledge_queue`).
- **What they say:** `docker compose restart rag-worker`, or no recreate step at all.
- **Why that is wrong:** `.env` is read when a container is created, so a restart keeps the old values. The check also runs in `worker`, and `rag-worker` is added only by T09.
- **Fix:** `docker compose up -d --force-recreate worker rag-worker`.

### M2. A retire that races a lookup can raise a false 24-hour `knowledge_integrity` alarm
- **Where:** `health.py:338-360`, with `publish.py:543-562`.
- **Why `--rebuild` does not clear it:** it skips retired entries.
- **Optional fix:** count only events whose entry is still active, or note the race in the runbook.

### N1. `rebuild` trusts any in-root `file_path`, and stops at the first `OSError`
- **Where:** `publish.py:596-606`.
- **Fix:** require the canonical path; skip and warn per entry.

### N2. `approve` builds the fingerprint twice, in two reads
- **Where:** `publish.py:389-405`.
- **Fix:** take both from `_build_source`.

### N3. A case draft whose `source_id` is not a UUID gives a 500
- **Where:** `admin_knowledge.py:333-349`.
- Only the job writes drafts, and it validates the id.

### N4. A crash before the rename leaves a `.tmp` file behind
- **Where:** `publish.py:244-255`.
- Harmless.
