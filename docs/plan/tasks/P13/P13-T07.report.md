## 1. Built

### `domain/transitions.py`
`_enqueue_triage` is called from `finish_enrichment` and from the `auto_closed` branch of `open_alert`.
- **Switch off:** exactly `enqueue(conn, "triage", alert_id)`.
- **Switch on:** `enqueue("rag_lookup", f"alert:{id}")`, then `triage` with `scheduled_at = now() + RAG_TRIAGE_DELAY_S * interval '1 second'`. The time comes from the database clock.

### `llm/triage.py`
- `build_proposer_prompt(..., learned: LearnedLike | None = None)`; `BuiltTriagePrompt.learned_used: bool = False`; `MAX_LEARNED_ENTRIES = 3`.
- **`LearnedLike`** is a Protocol with two members, `history_text: str | None` and `entries: Sequence[tuple[KbLearnedLevel, str]]`. `rag.lookup.PromptMaterial` satisfies it.
- **The section** comes after the playbook and before the request:
  1. `HEADING_LEARNED`;
  2. a `decision_history` block;
  3. one `kb_learned_level: <level>` fact line per entry;
  4. one `kb_learned` block, with the entries numbered `[1]`, `[2]`;
  5. `SENTENCE_LEARNED_IS_REFERENCE`.

  When nothing is found, the section is only `HEADING_LEARNED` and `SENTENCE_NO_LEARNED`. `learned=None` gives byte-identical output, and the system template is untouched.
- **Budget:** two new cut steps run before `raw_log_cut_to_8192`: `learned_entries_dropped`, then `learned_history_dropped`. If everything is cut, the section is omitted.
