## 1. Built

### `api/admin.ts`
- Eight functions, with types that mirror T05's JSON. `adminTypes.test.ts` pins them against `admin_knowledge.py` and `rag/draft.py`.
- `approveKnowledgeDraft` sends `{}` or `{edited}`, and only the 6 model fields.
- `knowledgeErrorOf` handles: 422 faults, 422 field/reason, 409, 503 `publish_failed`, 404.
- `KNOWLEDGE_LIMITS` is pinned to the backend.

### `strings.ts`
- `S.admin.knowledgePage`, plus `knowledgeFaultText` and `knowledgeWarningText`.
- A test reads `FAULT_VOCABULARY` and `WARNING_*` from the backend.

### `KnowledgePage.tsx`
- 5 ARIA tabs (arrow, Home and End keys); only the tab on screen is read.
- Rows keep the route's order, with a conflict badge, a count line, empty states and a note when the 200-row default is reached.
- A row opens the draft or entry view in place of the tabs. The tabs stay mounted, so the write's invalidation refreshes them. A toast follows each write.

### `KnowledgeDraftView.tsx`
**Left column, read-only:**
- the Tier-1 alert sections and `AiColumn`, or the case Summary, Heads, Timeline and `RunResult`;
- the decision, the notes, the SOAR block and the conflict entry, as text;
- "không còn dữ liệu" for null parts.

**Right column:**
- **Fields:** the six model fields; a tag picker (a tag outside the vocabulary stays ticked and is marked); the closed fields read-only; the warnings.
- **Duyệt** is disabled while the form is edited. **Sửa rồi duyệt** sends only the changed fields. **Từ chối** needs a reason. All three go through `ConfirmDialog`, latched against a double click.
- **Responses:**
  - 422 faults are shown on their field (`aria-invalid`, `aria-describedby`); a fault with no field goes above the form;
  - 409 shows "bản nháp đã được xử lý" and refetches;
  - 503 keeps the dialog open;
  - a 422 on the reason shows on the reason input.
- A retired conflict entry gets the badge "Mâu thuẫn với mục đã gỡ".

### `KnowledgeEntryView.tsx`
- All fields, the evidence, and `integrity.content_ok` / `file_ok` in words, on active and retired entries.
- Markdown is shown as text.
- **Gỡ** asks for a reason; a 409 `not_active` gets the entry's own sentence.
- An evidence row links only when its id matches `[A-Za-z0-9._-]`.

### Wiring
- A lazy route, the nav item "Tri thức" before the audit log, and the h1 "Tri thức học được".
- A "Mở trang duyệt" link on the overview block.
- LLM labels for `rag_lookup` / `retriever` and `knowledge_draft` / `drafter`.

### e2e (`admin-knowledge.spec.ts`, 3 tests, seeded by `e2e/knowledgeFixtures.ts`)
1. A real alert is closed by Tier 1, and a pending draft is inserted by SQL. An admin edits and approves it, sees it under Đã duyệt, then retires it. The test checks:
   - the exact body `{edited:{title}}`;
   - the file under `kb_learned/entries/…`, then moved to `retired/`;
   - the two audit events.
2. A literal IPv4 in the summary is refused with nothing stored; the draft is then rejected with a reason.
3. Every tab answers, and a `tier1` user is turned away.
