## Important

**I1. ①'s suggestion and gate result never reach the left column** (`KnowledgeDraftView.tsx:528`).
- **Why:** for a decided alert, `AiColumn` shows only `Decided`: ①'s action, its confidence and the agreement line. The gate (forced, `forced_by`, the steps, the verifier) and ①'s reasons are never shown, although `get_alert_view` sends them (`queue.py:636`).
- **The spec:** §7.5 asks for them, and DEC-206 allows the admin to see them.
- **Why the tests missed it:** the fixture has `gate: null, reasons: []`.
- **Fix:**
  - export `GateSteps`, `Reasons` and the gate line from `AiColumn.tsx`;
  - render them in `AlertWork` when a suggestion exists;
  - test with a forced gate, `forced_by`, and reasons that carry hostile text.

## Minor
- **M1.** While the tag vocabulary is loading or has failed, every tag is marked "ngoài danh sách" (`:813-815`). Compute it only once `vocabulary.data` is defined.
- **M2.** For a 409 `source_changed` or `unpublishable`, the draft stays pending, so the admin can retry into the same 409 forever (`:188-193`). Add the clause "chỉ có thể từ chối".
- **M3.** A 404 on approve leaves the actions enabled on stale data (`:194-199`). Hide them, or go back.
- **M4.** Focus is lost when a view opens or closes (`KnowledgePage.tsx:88,132-137`).
- **M5.** An edited form is lost without warning on in-app navigation or Back. Use `?draft=<id>` in the URL, or a blocker.
- **M6.** Source ids that fail `SAFE_ID` disappear (`KnowledgeEntryView.tsx:268-269`). Render them as plain text.

## Nit
- `v1_tags:unknown_tag` is shown above the form rather than at the picker.
- The reason counter uses UTF-16 `length`, while Python counts code points.
- The decision payload shows raw English keys.
- The conflict badge's hint is only in a `title` attribute.
- The tag descriptions have no `aria-describedby`.
- The e2e seed's `ON CONFLICT` is incomplete; this is harmless.
