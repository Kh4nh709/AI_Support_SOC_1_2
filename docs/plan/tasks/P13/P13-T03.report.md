## 1. Built

- **`llm/schemas.py`:** gains `validate_against(schema, obj)`. `validate(name, obj)` now calls it.
- **`rag/schemas.json`:** holds `rag_match_v1`.
  - The max-160 and max-3 limits cannot be written in the §6.2 notation; the 160 is only a note string.
  - Both limits are enforced in `rag.match` (`clean_reason`, `validate_matches`).
- **`rag/templates/match_system.txt`:** contains the word JSON and describes the schema in prose. A test pins its field names.
- **`rag/agent.py`:**
  - `AgentResult` has the five fields.
  - `call_json` lints the user message first, then makes one call and at most one repair. The repair message is linted too, and `model=` is passed on every call.
  - The repair vocabulary is generated from any schema in `schemas.json`.
  - `rag_model(cfg)` returns `RAG_MODEL or LLM_MODEL_PROPOSER`.
  - `Tape` wraps an adapter and remembers what was sent and what was paid for, even when a call raises. The job needs it for the run row; T04 can reuse it.
  - `is_transient` is tier2's classification.
- **`rag/match.py`:**
  - **`Match`** has three fields and never a reason.
  - **`build_user`** renders a `context` block for the fingerprint, then a `kb_learned` block per candidate (attribute `entry_id`), both through `wrap.untrusted_block`. Only the request sentence is outside a block.
  - **`validate_matches`** implements V-R1's membership (the id is a candidate and active) and V-R2 (the level is one of three, at most 3 matches, no duplicates).
    - Fault names are `unknown_entry_id`, `not_a_candidate`, `not_active`, `bad_level`, `duplicate`, `over_limit`, `not_an_object`, `matches: not_a_list`, each written `matches[i]: name`. None echoes the model's text.
    - A `Match` is built from the candidate, never from the model's text.
  - **`rank`** returns `(matches, notes, result)`.
    - `notes` maps `entry_id → reason`, cleaned to one printable line of at most 160 characters.
    - A schema failure after the repair returns `parsed=None` and no matches.
    - No candidates means no call.
  - **`injection_findings`** runs the detector over the same blocks.
- **`rag/budget.py`:** `rag_spent_usd`, `global_exhausted`, `rag_limits`, as in the brief.
- **`rag/runs.py`:** `write_rag_run`.
  - It checks that the pipeline and the role belong together.
  - It cleans NUL and lone surrogates out of everything that goes into jsonb. Without this, one `\u0000` in a model reason would fail the INSERT, and the job would fail on every retry.
- **`rag/lookup.py`:** `run_lookup_job`, `LookupResult`, `latest_lookup`, `PromptMaterial`, `prompt_material`.
  - **The job, in order:**
    1. Raise the idle timeout.
    2. Skip if no model is set.
    3. Parse the subject (`PermanentError` for anything other than `alert:<id>` / `case:<uuid>`).
    4. Build the fingerprint, the self-exclusion and the history.
    5. **Budget:** if the global cap or the RAG cap is reached, write a `budget` row and keep the history.
    6. **Candidates:** none gives `ok` if the history has data, else `empty`.
    7. `rank`, then `validate_matches` for the fault list, then `file_matches` per kept match. A mismatch drops the match and writes `rag.integrity_failed {"entry_id"}`.
    8. Write the run row and the `rag_results` row in one transaction.
  - **The run row's `gate_result`** is `{"faults": [...], "integrity_failed": [...]}`, plus `schema_errors` when the answer was unusable.
  - **The final status** is `ok` with a kept match or a history, else `empty`.
  - **Failures:**
    - A transient error before the last attempt writes the run row, commits and re-raises.
    - A transient error on the last attempt writes the run row, a `failed` row and `rag.lookup_failed {"lookup_id"}`, and the job returns.
    - `LLMPermanent` and a linter `PermanentError` give `failed` plus the event.
    - `LLMBudgetExceeded` mid-job gives a `budget` row and a run with `stopped_by="cap"`.
    - A bug is re-raised.
  - **`prompt_material`:**
    - It returns `None` for no row, `failed` or `budget`.
    - It returns an empty `PromptMaterial` for `empty`, and for an `ok` whose matches all fail the re-check and that has no history.
    - It re-checks from the database alone, because the main `worker` does not mount `kb_learned`. A match is kept only when the entry is active and `sha256(content) == content_sha256 ==` the stored hash. At most 3.
    - Stored JSON is read defensively: a malformed match is skipped.
- **`web/rag_handlers/{__init__,lookup}.py` and `web/rag_worker.py`:**
  - Discovery is `web.handlers`' contract over its own package.
  - `rag_lookup` declares `STATEMENT_TIMEOUT = "10s"`.
  - `main` runs `run_forever` with the RAG handlers only, after `config.load()`, and seeds nothing.
  - `wrap.untrusted_block` takes `**attrs: str`, so `entry_id` is an attribute; no text header was needed.

## 4. Deviations

1. **`write_rag_run` has an extra optional keyword**, `rag_lookup_id: uuid.UUID | None = None`. Migration 020 says the lookup's run row and its `rag_results` row point at each other. A non-final transient attempt carries `None`.
2. **`tests/fakes/llm.py` is unchanged.** `FakeLLM.complete` has no `model` parameter, so a local `RagFake(FakeLLM)` subclass records it.
3. **Extra public names:**
   - in `agent`: `Tape`, `is_transient`, `rag_model`, `schema_node`, `load_schemas`, `repair_constants`;
   - in `match`: `build_user`, `injection_findings`, `system_prompt`, `clean_reason`, plus constants.
   - `rank` returns validated matches. The job calls the pure `validate_matches` again, only to record the faults.
4. **`web/rag_handlers/__init__.py` duplicates the discovery code** of `web/handlers/__init__.py`, because that file reads its own `__path__`.
5. **`rag_lookup` declares `STATEMENT_TIMEOUT = "10s"`**, for up to six history aggregate queries.
6. **Judgement calls:**
   - An answer the schema refuses after the repair is `failed` plus `rag.lookup_failed` (`stopped_by="schema"`).
   - A linter `PermanentError` gives `failed` plus the event, with no `llm_runs` row (nothing was sent).
   - With no model configured, the job returns silently (the G7 pattern) with a one-line log.
7. **Audit `subject_id`:** `rag.lookup_failed` uses the alert or case id; `rag.integrity_failed` uses the entry id. The payloads are exactly as specified.

## 5. Concerns

1. **The shared fake lacks `model`.** Any later test passing the stock `FakeLLM` to `call_json`, `rank` or `run_lookup_job` fails with a `TypeError`. Suggestion: add `model=None` to `FakeLLM.complete`.
2. **The timing of the global cap.** The adapter's per-attempt check uses the RAG cap only; the global cap is checked once, at job start, so a cap crossed mid-job lets that one lookup (and its repair) through.
3. **`budget` hides the history.** `prompt_material` returns `None` for `budget`, as the brief says, so ① and ② lose the AI-free history too.
4. **`rag_lookup_id` has two meanings:** the lookup a ① or ② run used, and, on the lookup's own run, itself.
5. **The mount point.** `KB_LEARNED_ROOT` is `/srv/kb_learned`. T09 must mount it read-only on `rag-worker`, and `worker` must not mount it.
6. **Duplicate integrity events.** A tampered entry matched by many alerts writes one `rag.integrity_failed` per lookup. T05's health check should aggregate them.
7. **`latest_lookup` tie-break.** Two rows with identical `created_at` are ordered by `lookup_id`, which is arbitrary.
8. **Docs.** Context pack §6.2 does not list `rag_match_v1` (T09).
