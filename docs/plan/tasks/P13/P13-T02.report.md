## 4. Deviations

1. **Extra test files.** The brief lists four test files, and the pure parts (subject, tags, entries) had no home in them. Added: `test_rag_subject.py`, `test_rag_tags.py`, `test_rag_entries.py`, and `backend/tests/rag_data.py` (the row helper that the history, candidate and entry tests share, like `soar_payloads.py`). No existing file changed.
2. **`placeholderise` has one more keyword**, `users: Iterable[str] = ()`: bare user names become `<USER>`. The fingerprint uses it for the alert's own `alert_user`. The brief's positional signature is unchanged. Without it, a log line "Failed password for hr01" would keep the account.
3. **Full text searches the rule ids and rule descriptions, not the whole fingerprint.**
   - `plainto_tsquery` joins every word with AND, and a log carries a month and counters, so the whole text would match no entry written on another day.
   - The phrases are `Fingerprint.rule_ids` and the `rule:` lines (`fingerprint.search_phrases`), each through `plainto_tsquery('simple', …)`, ORed together.
   - A fingerprint not built by this module (no `rule:` lines, no rule ids) is searched by its whole text.
   - This list catches the entry about the same rule whose category, MITRE ids or scenario no longer match.
4. **The merge order is a choice the brief left open.**
   - Entries on both lists come first, in overlap order. Then the overlap-only and full-text-only lists take turns, so a long list of same-category entries cannot push every full-text hit out of the cap of 20.
   - The overlap list is ordered by how many of category, MITRE id and scenario are shared, then by newest approval.
5. **`History.total` counts decisions, not alerts.** An alert with no decision (queued, being worked, `auto_closed`, escalated with no case) is not counted. A level whose alerts are all undecided has no data, so the next level is tried.
6. **For a case subject, a level's key is the keys of its heads.** An earlier alert counts once if it matches any head. The brief does not say how a case maps to a key.
7. **`Entry` leaves out `fingerprint_tsv`**, a generated index value. Every other column is there.
8. **`Subject.__post_init__` checks only the kind and a non-empty id.** The strict shapes are in `parse_subject`, so a test that builds a `Subject` by hand with an odd id is not refused.
9. **Closed values are checked against their shape before they enter the fingerprint.**
   - A rule id, decoder and category must be a token. A scenario must be a JSON string shaped like an id. A MITRE id must match `T\d{4}(.\d{3})?`.
