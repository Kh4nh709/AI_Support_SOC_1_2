**The job, in order:**
0. Idempotency check, with `ON CONFLICT (source_kind, source_id) DO NOTHING` as the backstop.
1. The source record.
2. Candidates, with an empty exclusion. Each is checked (sha256 and published file) before it is sent, and a failure writes `rag.integrity_failed` as the lookup does.
3. Rank.
4. The merge rule.
5. The draft call, validated, with one retry whose message names the faults by name.
6. Store.

**Merge and storage:**
- **Precedence:** an agreeing `rat_giong` entry wins over a conflicting one. Otherwise the first `rat_giong` entry with another conclusion becomes `conflict_with_entry`.
- **The merge is one guarded `UPDATE`.** It appends `{subject, at}` (database clock) to the entry's evidence, and the alert id (for a case: the case id plus the head alert ids) to the entry's source arrays. `content` is left untouched. It is skipped if the entry is no longer active or already holds the subject.
- **Events:** `knowledge.drafted {"draft_id"}` and `knowledge.merged {"draft_id","entry_id"}`, exactly. The event's `subject_id` is the source alert or case id.
- **The stored draft** holds the model's six fields, tidied to one printable line each, plus the source's six closed fields. The schema refuses closed keys coming from the model.
- **With no model configured,** nothing is done (as for the lookup, G7).

## 4. Deviations

- **Subject spelling in `transitions.py`:** `f"alert:{id}"` / `f"case:{str(id).lower()}"`, because `domain` may not import `rag`. A test pins it to `Subject(...).key` and `parse_subject`.
- **`FakeLLM` records `model`** in `.models` and in `calls[i]["model"]`. A pinned dict in `test_fakes_llm.py` was updated, and `RagFake` was removed from two files.
- **Two `llm_runs` rows when a ranking call happens:** a `rank` row and a `draft` row, both `knowledge_draft` / `drafter`, told apart by `gate_result.stage`.
  - `knowledge_drafts.llm_run_id` points at the draft row, or at the rank row for a merge or a budget stop.
  - This way each row holds exactly one prompt, and the sub-cap counts the ranking spend.
- **Extra warnings:** `llm_permanent`, `llm_transient`, `linter` and `rank_unavailable`.
  - `rank_unavailable` can sit on a draft that otherwise passed; it says the duplicate check did not run.
  - On the last attempt, a transient failure stores an empty pending draft. Earlier attempts write the run row, commit and re-raise.
- **V1 and V5 extensions:** a control character or a lone surrogate is `v1_schema:<field>`, and a blank title or summary is `v5_empty:<field>`. V3 and V4 read at most 10,000 characters of a field (`MAX_SCAN_CHARS`).
- **V4 adds two checks** beside `detector.scan`: `<untrusted_data` after NFKC, and a token shaped like a 16-hex nonce.
- **The facts block** is the generalised fingerprint plus `kind`, `conclusion`, and the `occurrences` / `alerts` counts.
- **`rag/__init__.py` was not touched.** Its docstring does not mention `draft`.

## 5. Concerns

- **The JSON-escaped leading form** `\\FPT\\administrator` is caught by neither `_ACCOUNT` nor `_LEADING_ACCOUNT`.
- **Stored draft keys come back in jsonb order,** not `DRAFT_FIELDS` order. T05 must not rely on the order.
- **`KNOWLEDGE_QUEUE_MAX` is not applied;** the card did not ask for it.
- **Inventory names in rule descriptions.** A rule description word can be an inventory hostname, and V3 forbids those words in free text, as spec §7.4 says. So a common word that is also a hostname fails V3.
- **Older case notes.** `source_record` for a case reads `conclusion_reason` plus the newest 30 `case_notes`; older notes are not shown to the model.
