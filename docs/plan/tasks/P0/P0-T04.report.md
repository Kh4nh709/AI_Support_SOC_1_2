### TDD record (working rule 2)

Fixtures and tests were written first and watched fail, twice, for two different reasons:

```
# 1 — no script yet
E   FileNotFoundError: [Errno 2] No such file or directory:
    '/…/eval/indexer_probe.py'

# 2 — script written, loader wrong
E   AttributeError: 'NoneType' object has no attribute '__dict__'
    eval/indexer_probe.py:82: in <module>  @dataclass(frozen=True, repr=False)
```

The second failure is worth passing on: with `from __future__ import annotations`, a
dataclass resolves its field types through `sys.modules[cls.__module__]` at class-creation
time, which is `None` for a module loaded by path but not registered. The fix is one line in
the test — `sys.modules[_spec.name] = probe` **before** `exec_module` — and every later task
that loads an `eval/` script by path will need it.

## 4. Open questions / follow-ups

1. **For P2 — the sort field is an assumption, and the puller inherits it.** This script pages
   on `timestamp`: `"sort": [{"timestamp": "asc"}]` and `"range": {"timestamp": {"gte": …}}`.
   The evidence is the canonical §8 document, whose `sort` value `1786903016130` is exactly
   the epoch-millis of `fields.timestamp[0]` (`2026-08-16T17:56:56.130Z`, re-derived here),
   and `source_cursor.last_sort` is a `bigint`, which holds it. **It has never been confirmed
   against the live index.** The field is printed in the header line of every run for exactly
   this reason. P2's puller must re-check it on the first real pull: if the index maps a
   different field, or maps `timestamp` as something other than a date, `search_after` will
   page wrongly and silently. The cheapest check is to compare the `sort` value of the first
   returned hit against the epoch-millis of its own `fields.timestamp[0]` — one assertion, and
   it belongs in the puller, not here.
2. **For the Owner — the retention numbers in this report are fixture values, not facts.**
   `269` documents since `2026-08-01` and an earliest index date of `2026-07-30` are invented
   for the fixtures. The real numbers arrive with the first live run and are the answer to the
   open Owner action "Xác nhận retention `wazuh-alerts-*`". Do not size G1 from this report.
3. **`--save-samples` has never written a file the indexer produced.** The path is tested
   end to end against recorded hits, so the mechanics are proven, but the five committed
   sample documents the P0 deliverable asks for can only exist after `soc_ro` does.
4. **`INDEXER_CA` relative paths resolve against the repository root**, not the current
   directory, so the shipped `INDEXER_CA=conf/root-ca.pem` works from anywhere. If P2's
   `infra/config.py` reads the same key it should resolve it the same way, or the two will
   disagree when the worker runs with a different working directory.
