  **`backend/app/enrichment/inventory.py`** — `validate()` and helpers, nothing else. Public surface:
  ```python
  def validate(paths: Sequence[str | Path] | None = None) -> list[str]:
      """Return human-readable problems, one per line; an empty list means the files are usable.

      paths defaults to INVENTORY_PATHS from the environment, else the three conf/ defaults.

      DEC-007: INVENTORY_PATHS is stored as a JSON array (context pack §6.3 and
      .env.example both write it that way), so parse it with json.loads and require
      a list of str. Anything else -- bad JSON, or JSON that is not a list of str --
      is a configuration error naming INVENTORY_PATHS, never a silent fallback to
      the conf/ defaults. Only an unset or empty variable falls back. This parses an
      existing §6.3 value; the key name and its value are unchanged.
      """
  def validate_assets(doc: object, source: str) -> list[str]: ...
  def validate_identities(doc: object, source: str) -> list[str]: ...
  def validate_iocs(rows: Iterable[Mapping[str, str]], source: str) -> list[str]: ...
  ```

  **DEC-007 — how `validate()` routes a path to the right checker.** By **content**, never by
  position and never by basename: a `.csv` file goes to `validate_iocs`; a YAML file goes to
  `validate_assets` or `validate_identities` according to its top-level key (`assets` /
  `identities`). A file that matches none of the three returns one problem naming the path and
  the keys it looked for. Position would silently mis-validate the moment someone reorders
  `INVENTORY_PATHS`, and basenames break when the Owner renames a file — both are real, and
  content-routing costs three lines.

  Rules — every message names the file, the index or key, and what was expected:
  - the file exists and parses (`yaml.safe_load`, `csv.DictReader`); a parse error is one message, not a traceback;
  - top level is a mapping with `version: 1` and the expected list key (`assets` / `identities`);
  - `hostname` / `username` / `value` present, non-empty, `str`, and **unique** within the file (duplicate primary keys are the failure the Owner will actually make);
  - `criticality` ∈ `{high, medium, low, unknown}` (DEC-004) — and reject `crown_jewel` and `normal` with a message naming DEC-004, because that is exactly what a copy from an older document will contain; `reputation` ∈ the DB set; `is_privileged` is a real bool, not the string `"false"` (a classic YAML trap — test it); <!-- superseded-ok: DEC-004 the validator must reject this value by name -->
  - `expires_at` parses as ISO-8601 and carries a timezone; a row that has already expired is a **warning-shaped message** but still an entry in the returned list, prefixed `warning:` — the Owner needs to see it, and `validate()` returning non-empty is what `make`-style checks key on. Say in the docstring that callers may filter on the `warning:` prefix.
  - `owner` / `role`: optional, `str`, ≤ 200 characters (nullable columns as of DEC-004).
  - unknown keys are reported (they are almost always a typo of a real one).
  **Constraints:** `enrichment/` may import `infra/` only (§4) — and `validate()` must run before any database exists, so it imports **no** database module at all: standard library plus `yaml`. No `print`; return the list. No I/O beyond reading the given paths.
