Public surface of `enrichment/inventory.py`, one line each:

- `validate(paths: Sequence[str | Path] | None = None) -> list[str]` — problems, one per line; `[]` means usable. `paths` defaults to `INVENTORY_PATHS`, else the three `conf/` defaults; entries prefixed `warning: ` are filterable by callers.
- `validate_assets(doc, source) -> list[str]` — envelope (`version: 1`, `assets` list), then per entry: unknown keys, `hostname` present/non-empty/`str`/unique, `criticality` ∈ `high|medium|low|unknown` with the two retired v1 values rejected **by name and naming DEC-004**, `owner`/`role` optional `str` ≤ 200.
- `validate_identities(doc, source) -> list[str]` — same envelope over `identities`; `username` present/non-empty/`str`/unique; `is_privileged` must be a real boolean (the quoted `"false"` trap).
- `validate_iocs(rows, source) -> list[str]` — per row: unknown columns (once per column), `value` present/non-empty/unique, `reputation` ∈ the DB set, `expires_at` ISO-8601 **with a timezone**; an already-expired row is a `warning:`-prefixed entry, still in the returned list.

Every message names the file, the index or key, and what was expected, e.g.

```
conf/inventory.yaml: assets[0].criticality: 'crown_jewel' no longer exists — DEC-004 moved the
database onto the high | medium | low | unknown vocabulary; there is no mapping, choose one of those four
conf/identities.yaml: identities[0].is_privileged: expected a boolean written unquoted (true or false), got 'false'
warning: conf/iocs.csv: iocs[0] value '198.51.100.9': expires_at: '2020-01-01T00:00:00Z' is already in the
past, so the row is invisible to the lookup (... AND expires_at > now()); extend it or delete it
```

**DEC-007 implemented as ruled.** `INVENTORY_PATHS` is parsed with `json.loads` and must be a list of `str`; bad JSON, a non-list, a list holding a non-`str`, or an empty array each return one problem naming the key — only unset-or-empty falls back to the `conf/` defaults. Routing is by content: a CSV goes to `validate_iocs`, a YAML file to `validate_assets` or `validate_identities` by its top-level key, and a file matching none returns one problem naming the path and both keys. Reordering `INVENTORY_PATHS` or renaming a file changes nothing (test `test_routing_is_by_content_not_by_basename`, and the reordered-paths run in §5). The CSV reader drops blank lines and lines whose first non-space character is `#`; a `#` inside a quoted field is untouched. Both cases are tested.

## 3. Deviations

Four, all small, none touching a frozen contract.

1. **The IoC example rows expire in 2030, not `2026-12-31`.** The card's illustrative row is
   `203.0.113.10,malicious,2026-12-31T00:00:00Z,manual`. Shipped verbatim it turns acceptance
   #2 (`validate(the three examples)` → `[]`) into a time bomb: from 2027-01-01 the row is
   expired, `validate()` returns a `warning:` line, and both #2 and the shipped-examples test
   fail in a clean checkout for a reason that has nothing to do with the code. The rows keep
   the card's shape, addresses and columns; only the year moves.
2. **The CSV note block sits below the data rows, not above them.** Acceptance #5 reads the
   file with a plain `csv.DictReader`, which takes the **first** line as the header — so no
   comment can precede it. The header row is therefore line 1, the three data rows follow, and
   the note the card asks for (`not_found` ≠ `skipped`, the expiry semantics, the DEC-007
   comment rule) follows those, as real `#` lines. `docs/inventory-format.md` states the
   convention so the Owner's own `conf/iocs.csv` keeps it.
3. **`is_privileged` is optional, and means `false` when absent.** The column is
   `boolean NOT NULL DEFAULT false`, so an absent key is not a malformed file; the card's rule
   is about the *type* (`"false"` the string is rejected), which is enforced. The format
   document says an omitted value means `false` and asks for `true` to be written explicitly,
   because a privileged account is a hard G8′ block.
4. **One rule the card does not name: an empty `INVENTORY_PATHS` array is a configuration
   error.** `INVENTORY_PATHS=[]` is valid JSON and a list of `str`, so DEC-007's "never a
   silent fallback" leaves only two options: check nothing and return `[]` — which tells the
   Owner their files are fine when nothing was read — or report it. It reports it.

Not a deviation but worth recording: `git pull` failed (`could not read Username for
'https://github.com'` — the agent account has no credentials for the public remote), so the
branch was cut from the local `main` @ `e5f14de`, which is the newest commit on it.

## 4. Open questions / follow-ups

- **What P1 must deliver for this format to become real:** `013_assets_enrichment.sql` must
  drop `ck_assets_criticality` and re-add it over `('high','medium','low','unknown')`, and add
  `owner text NULL` and `role text NULL` to `assets` (DEC-004, "Carried by"). The same
  migration carries §6.1's `source`, `loaded_at`, `active` on `assets`, `identities` and
  `iocs`. Until it lands, a file written to this format validates but cannot be loaded: the
  database still CHECKs the v1 vocabulary and has no column for `owner`/`role`. **No `.sql`
  file was touched by this task.**
- **P2, when it writes the loader:** the CSV reader needs the same one condition this module
  has — skip blank lines and lines whose first non-space character is `#` (DEC-007). If the
  loader is written without it, the Owner's comments in `conf/iocs.csv` become phantom IoC
  rows, which is precisely the footgun the ruling closes. `_meaningful_lines()` here is the
  reference behaviour. P2 also owns `active` / `loaded_at` and
  `POST /api/admin/reload-inventory`, both described in the format document as future
  behaviour.
- **`warning:` is a contract with `make`-style checks:** `validate()` returns non-empty when a
  row has expired, and the docstring tells callers they may filter on the prefix. Whoever
  wires a check target in P2 should decide once whether a warning is fatal there.
- **Two DEC-004 follow-ups are still open and are not mine** (recorded so the trail is
  unbroken): the risk-score formula at `docs/phase-4-enrichment.md:170` still weights the two
  retired values and must be re-weighted before `soar/risk.py` in P2; `kb/playbooks/malware.md:36`
  and `kb/playbooks/ssh_brute_force.md:34` still branch on a value that no longer exists and
  are rewritten during the P3 playbook review.
- **Owner action now unblocked:** `STATE.md` carries "write `conf/inventory.yaml` …" behind
