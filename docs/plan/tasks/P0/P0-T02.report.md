- **D1 — `env_file` is written in the long form.** The card says `env_file: [.env]`; the file has

The shell-test form was written first and found broken: `exit 0` inside a recipe line ends that line's shell only, and the target ran on into `ruff --config … ` with no path and failed with exit 2. `LINT_PATHS := $(wildcard backend eval)` plus `ifeq ($(strip $(LINT_PATHS)),)` is correct in all three states and keeps make's command echo.

- **D5 — the six `NOTIFY_SMTP_*` lines are prefixed `# | `, not `# `.** The acceptance comparison's `have` regex is `^#?\s*([A-Z][A-Z0-9_]{2,})=`, which matches a plainly commented-out `# NOTIFY_SMTP_HOST=` — six plainly commented lines would have made `extra` seven entries long and failed acceptance 7, while `NOTIFY_SMTP_*` is not itself extractable from §6.3 (the `*` stops the pattern). The prefix keeps them commented out, keeps them documented as the alternative, and keeps the check honest. The reason is written into `.env.example` next to the block so a later editor does not "tidy" it back.

## 4. Open questions / follow-ups

1. **For P1 (`backend/app/infra/config.py`): the `.env` reader must strip trailing comments.** The three DSN lines carry the card's inline comments verbatim (`DATABASE_URL=postgresql://…/soc            # app runtime, role app_rw …`). Docker Compose's own `env_file` parser strips them — verified, `docker compose config` prints `DATABASE_URL: postgresql://soc:soc@127.0.0.1:55432/soc` — but a ten-line stdlib reader that only splits on the first `=` would keep the comment inside the value and produce an unusable DSN. Either strip ` #…` or drop the three inline comments when `.env` is written.
2. **Underscore-formatted integers.** `MAX_PAYLOAD_BYTES=2_097_152`, `RAW_LOG_MAX_BYTES=1_024_000`, `PROMPT_LOG_MAX_BYTES=32_768`, `PROMPT_TOTAL_BUDGET_TOKENS=40_000`, `CASE_PROMPT_BUDGET_TOKENS=60_000` are §6.3's documented defaults transcribed exactly. Python's `int()` accepts the underscores, so `config.py` needs nothing special — but any other consumer (a shell, a container entrypoint) would not.
3. **`make test-db` is unproven end to end** — INBOX `2026-09-05 · P0 / P1 · BLOCKER`, option A is one command (`sudo -u postgres psql -c 'ALTER ROLE user1 CREATEDB'`). Until it clears, the healthcheck-poll branch of that target, `scripts/migrate.sh` against a real database, and `scripts/backup.sh`'s `pg_dump` have never run. They should be re-verified at the first review point after the blocker is cleared, before P1 relies on `migrate`.
4. **Ruff runs on its default rule selection** (`E4`, `E7`, `E9`, `F`), which is what context pack §9 asks for ("black + ruff defaults"). If a later phase wants import-order or naming rules, that is a `[tool.ruff.lint]` addition and a separate decision — flagged because `backend/` is empty today and the first real code will be the first real test of the selection.
5. **`db` publishes 55432 on the host, and the three DSN defaults point at it.** If the Owner clears the DB blocker by granting `CREATEDB` on the *system* PostgreSQL (INBOX option A) rather than by fixing docker access (option B), the DSNs in `.env` must move to port 5432 and to the `user1` role. `.env.example` is a template and does not need editing for that; `.env` does.
