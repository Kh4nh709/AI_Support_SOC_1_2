- **Design notes:**

  **Do not run this against the live indexer.** There are no credentials (`soc_ro` was never created). Everything below is verifiable offline, and the acceptance list is written so it can be. The live run is an Owner action recorded in `STATE.md`.

  **Interface:**
  ```
  usage: indexer_probe.py [--env-file PATH] [--since YYYY-MM-DD] [--page N]
                          [--save-samples N] [--samples-dir DIR] [--json]
  ```
  **DEC-007 — `--json` is defined as:** print the same three sections the text report prints, as a single JSON object on stdout, and print nothing else there. Same data, same field names, one machine-readable shape; the text table stays the default. Exit codes are unchanged (`0` ok, `2` configuration error), diagnostics still go to stderr, and `INDEXER_PASSWORD` never appears in either form. It exists so P2's puller work and the Owner's retention answer can be scripted instead of re-typed from a table.
  There is **no** `--insecure`, no `--no-verify`, no `verify=False` anywhere in the file. Context pack §6.3 says `INDEXER_CA` is required and there is no insecure mode; a Reviewer greps for exactly that.

  **Configuration:** read `--env-file` (default `.env` at the repository root) with a ten-line stdlib parser — strip blank lines and `#` comments, split on the first `=`, strip surrounding quotes, and let a real environment variable win over the file. Do not add `python-dotenv`. Required keys — empty or missing means exit 2: `INDEXER_URL`, `INDEXER_USER`, `INDEXER_PASSWORD`, `INDEXER_CA`, `INDEXER_INDEX`, `PULL_START` (overridable by `--since`). Optional, never a cause of exit 2 because it has a default: `PULL_PAGE` (overridable by `--page`, default 500). Report **all** missing/empty required keys in one stderr message rather than stopping at the first, and check the `INDEXER_CA` file's readability last — acceptance 4 sets only `INDEXER_CA` and expects stderr to name it, which fails if an earlier empty key short-circuits first.

  **Exit codes — make them exact, the acceptance tests assert them:**
  - `0` success.
  - `2` configuration problem: a required key is empty, or `INDEXER_CA` does not point at a readable file. For empty credentials the stderr message must name `soc_ro` and `docs/plan/INBOX.md` so the Owner is sent to the blocker instead of guessing.
  - `3` transport or TLS failure (`httpx.TransportError`, including certificate errors) — print the exception class and the URL, never the password.
  - `4` the indexer answered with a non-2xx status — print the status and the first 300 characters of the body.

  **What it does, in order:**
  1. `GET {INDEXER_URL}/_cat/indices/{INDEXER_INDEX}?format=json&h=index,docs.count,store.size&s=index` → the per-day table. Index names are `wazuh-alerts-4.x-YYYY.MM.dd`; parse the date out of the suffix, keep only days `>= --since`, and print one line per day plus a total. Print the **earliest** index date present (before the `--since` filter) — that is the number that sizes the G1 gold set and the Owner has an open action to report it.
  2. `POST {INDEXER_URL}/{INDEXER_INDEX}/_search` with one `search_after` page, to prove the path the P2 puller will use:
     ```json
     {"size": <page>, "sort": [{"timestamp": "asc"}],
      "query": {"range": {"timestamp": {"gte": "<since>"}}}}
     ```
     Print how many hits came back, the first and last `sort` values, and the `_index` of the first hit. If a second page is wanted, `search_after: [<last sort value>]` — implement the parameter but issue at most two requests.
     **Assumption to flag:** the sort field is `timestamp`. The canonical document's `sort` value `1786903016130` is the epoch-millis of `fields.timestamp[0]`, and `source_cursor.last_sort` is a `bigint`, which fits. It can only be confirmed against the live index. Print the sort field in the header line of the output, and record in your report that P2's puller inherits this assumption and must re-check it on the first real pull.
  3. `--save-samples N`: from the returned hits, pick up to N documents with **distinct** `_source.rule.id`, and write each as `backend/tests/fixtures/indexer_sample_rule<rule_id>.json`, pretty-printed, byte-faithful to what the indexer returned (G9 habit). Default `--samples-dir backend/tests/fixtures`. Print each path written. **DEC-007 — this does not violate "Do not touch any other file":** that rule governs files *you author*, not files the delivered tool writes when someone runs it. `indexer_sample_rule<id>.json` files are runtime output, produced only with `--save-samples` and only once credentials exist, and the Owner commits them (see STATE.md's Owner actions), not you. Author exactly the four paths in "Files — create" and no others. **Note for the Reviewer (checklist item 8, Scope):** if the Owner has already run the probe against the live index, `backend/tests/fixtures/indexer_sample_rule<id>.json` files may appear in the diff. They are this tool's runtime output, committed by the Owner, and are **not** an out-of-scope file authored by the Coder — do not raise them under item 8. Anything else outside the four paths still is. This is the switch the Owner runs once credentials exist; the P0 deliverable asks for five documents of different rules.

  **Never** print, log or write `INDEXER_PASSWORD` — not in the header line, not in an error, not into a saved fixture. Use `httpx.BasicAuth`. Build the client as `httpx.Client(verify=<INDEXER_CA path>, timeout=30.0, auth=...)`.

  **Structure for testability:** put the logic in functions that take an `httpx.Client` — `fetch_index_table(client, base, index)`, `fetch_page(client, base, index, since, page, after=None)`, `format_day_table(rows, since)`, `pick_samples(hits, n)` — and keep `main(argv)` thin, returning the exit code rather than calling `sys.exit` internally.
