# P0-T07 — make test-db and the run targets stop requiring docker

No task card exists: DEC-011 ordered the re-plan, the Planner was never run, and the Owner
asked for the fix directly. Scope taken from DEC-011 plus the Director's later scope note
(`*.sw?`, `.env.example:20`, `DATABASE_URL` / `DATABASE_URL_OWNER`) and the Owner's decision
of 05/09 that no target may require docker.

## 1. Built

- `Makefile` — `COMPOSE` removed; zero references to docker remain in any recipe.
  - `test-db` takes `TEST_DATABASE_URL` from the environment, else the last assignment in
    `.env`; a trailing comment is stripped only when whitespace precedes the `#`, so a `#`
    inside a DSN survives. Unset and unreachable are two distinct errors, each naming the key
    and the fix. On success it echoes the DSN it used before running pytest.
  - `run-app` — `PYTHONPATH=backend python3 -m uvicorn app.web.main:app --host $(APP_HOST)
    --port $(APP_PORT)`, new `APP_HOST ?= 127.0.0.1` and `APP_PORT ?= 8000`. Loopback by
    default rather than compose's `0.0.0.0`, overridable when the advisor needs LAN access.
  - `run-worker` — `PYTHONPATH=backend python3 -m app.infra.worker`, matching the command
    docker-compose.yml carried.
  - `test`, `lint`, `migrate`, `backup` unchanged.
- `.env.example` — socket DSNs are the documented default (`soc_dev`, `soc_dev`, `soc_test`),
  the compose forms kept as a commented portable alternative. Notes why the socket form is
  passwordless here and that a worktree has no `.env`.
- `.gitignore` — `*.sw?`, `*~`, `.*.swp`.
- `docker-compose.yml` — header comment only; the file is now optional, not a dependency.
