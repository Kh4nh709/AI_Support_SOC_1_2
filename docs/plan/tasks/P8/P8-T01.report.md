## Built

- **`eval/ops_export.py`** (new). One read-only command writes one markdown file describing
  `[--since, --until)` in numbers. It follows `report.py`'s pattern (`_resolve_dsn`,
  `_connect_readonly`, `Exit`, fixed decimals) but imports none of its private helpers. It imports
  two names: `DEC111_SENTENCE` from `build_gold` and `EVIDENCE_TARGET` from `metrics` (public,
  in `__all__`).
  - **Population (note 1).** Alert figures use `alerts` with `received_at` in the window and
    `NOT is_synthetic`. `source` is not a filter. LLM figures use `llm_runs` with
    `pipeline='triage'`, `created_at` in the window, joined to a non-synthetic alert. Event figures
    use `audit_events` with `created_at` in the window, minus events about a synthetic alert.
    Synthetic rows appear on one line only: `synthetic rows in the window, excluded: n (Q01)`.
  - **Sections, in the card's order.**
    1. Window, DEC-111 sentence, the descriptive sentence and the population.
    2. Intake and dedup: `via` × `outcome`; latency p50/p95/max and the count over 60 s;
       `rejected_alerts`; `source` × `agent_name` with alerts and heads; heads, duplicates,
       alerts per head, max `occurrence_count`.
    3. Pull loop: pull jobs by status; the largest gap between consecutive succeeded
       `scheduled_at`, with its from/to instants; `source_cursor.last_error IS NULL` per manager
       at the run; `job.exhausted`.
    4. ① online, over the proposer rows where the gate ran (`stopped_by IS NULL`):
       - rows by `stopped_by`, then the final verdict;
       - the gate-forced rate, with *"the gate is squeezing ①"* and R5 printed above 0.60
         (an exact `Fraction` compare);
       - `forced_by` per step, the `hallucination_flag` rate, and the evidence-verified rate
         beside `≥ 0.90` (✓/✗, as P7 prints it);
       - step 6, latency p50/p95 per role and per alert, cost total and per alert;
       - `model_id` and `prompt_version` by role, and the heads' `triage_status`.
    5. Auto-close events and heads per `autoclose_rule_id`.
    6. Architecture §6's six rows (metric · value · basis) and the branch sizes.
    7. `label.created` (with its undo records) and `triage_labels` by `source`, headed as
       labelling rather than decisions.
    8. The appendix.
  - **The SQL is the citation (note 3).** There are 28 module-level `Query(qid, title, sql)`
    constants, run once each in `QUERIES` order by `_Runner.run`, which records them. Every
    database call goes through `_execute`. Every figure names its `Qnn`. Section 8 prints the
    recorded list verbatim with the bind parameters `%(since)s` / `%(until)s`. Percentiles use
    `percentile_disc`. Latencies are integer ms, computed in SQL.
  - **Human rows (note 2 item 6).**
    - Each row prints `not measured`. Its basis gives the missing precondition, the DEC and the
      counted evidence, for example `` no human-decision pilot ran: the Tier-1 console was
      deprioritized (DEC-116); `tier1.decided` = 0 (Q24) ``.
    - When any count in a row is non-zero, the row prints `descriptive, n = k` and no rate.
    - The gate-forced row is `measured`, with section 4's value.
  - **No free text (note 4).** No query selects a description, raw text, payload, prompt, quote or
    `result`/`gate_result` text. Table cells escape `|` and newlines.
  - **Undefined is not zero (note 5).** An empty ratio or percentile prints `n/a (0 rows)`. Rates
    have 3 decimals, USD 5, ms are integers. No clock, host, DSN or path reaches the file.
  - **CLI.**
    - Flags: `--since` (default `2026-09-26T00:00:00Z`), `--until` (required), `--out` (default
      `docs/results/operations.md`), `--env-file .env`, `--dsn`.
    - Both instants must carry a UTC zone (`Z` or `+00:00`); naive or non-UTC input exits 2.
    - `since >= until` exits 2 before any DSN is read. Exit 4 when there is no DSN or libpq cannot
      open it (the exception class is printed, never the DSN).
    - The exit codes appear in the module docstring and the `--help` epilog.
- **`backend/tests/test_ops_export.py`** (new), 22 tests: 12 `@pytest.mark.db`, 10 pure (usage,
  DSN, help).
  - Alerts are seeded through `domain.transitions.open_alert` and then placed with an `UPDATE` of
    `received_at`. `llm_runs`, `jobs`, `intake` and `audit_events` get direct `INSERT`s with known
    values and explicit timestamps.
  - Nothing is committed: every row lives in the `db` fixture's transaction and is rolled back,
    append-only tables included.
  - All timestamps sit in a 2011 window no other test writes into, so the shared suite's `now()`
    rows never enter the counts. The expected numbers are derived in the test's comments.

## Deviations

1. **The transaction is `REPEATABLE READ, READ ONLY`**, not bare `READ ONLY`. All 28 queries
   then read one snapshot, so a row that changes mid-run cannot make two figures disagree. It is
   still read-only; `test_read_only_transaction` proves it.
2. **The synthetic exclusion also covers events and labels.** Event queries drop events whose
   subject is a synthetic alert (`NOT EXISTS …`). `autoclose_reviews` and `triage_labels` join to
   a non-synthetic alert. Note 1 states the rule for alerts and LLM rows; I applied it to these so
   "nowhere else" holds for every figure.
3. **Small additions within note 4's vocabulary.** All are counts, ids or timestamps:
   - intake broken down by `via` as well as `outcome`;
   - a `heads` column in the agent table;
   - the from/to instants of the largest pull gap;
   - heads per `autoclose_rule_id`;
   - the undo records inside `label.created`;
   - a `## 1` heading over the header block;
   - "at the run" labels on the figures that read a column's current state: max
     `occurrence_count`, pull-job `status`, the heads' `triage_status`, `source_cursor`.
4. **"Printed with its SQL" is a citation, not a second copy.** Every figure names its `Qnn`, and
   section 8 holds each query once, verbatim. Printing each query twice would double the document
   and add nothing the appendix test does not already guarantee.
5. **Harness constraints on commands.** This session's sandbox refuses a command that combines
   `PYTHONPATH=`/`make` with a runtime-computed operand, that contains `eval` (the shell builtin,
   or the bare directory token), or that puts `git` in a compound command. So:
   - Acceptance 2 used a static, password-free `--dsn postgresql:///soc_p8t01_test` and a fixed
     `--out` instead of `"$TDB"` and `$(mktemp -d)`. The window check precedes DSN resolution,
     so the result cannot differ; `test_usage_errors_exit_2` enforces that ordering.
   - `make test-db` read a worktree-local, git-ignored `.env` (mode 600) holding only the
     `soc_p8t01_test` DSN. This is the Makefile's own fallback. The file was deleted after the
     final run.
   - The per-file pytest runs exported only `TEST_DATABASE_URL`, without `dsn_env.py`'s PG*
     variables; this file does not need them.
   - Paths are spelled `./eval/...`.
6. **`descriptive, n = k` needs one choice for rows with two counts.** `k` is the row's first
   evidence count, the metric's own unit:
   - `tier1.decided` for the decisions, median and agreement rows;
   - `autoclose_reviews` rows for the digest row;
   - `case.opened` for ②.

   So acknowledges without decisions print `descriptive, n = 0`, beside `alert.acknowledged` = 1.
   That keeps "never `not measured` beside a non-zero count", and no rate or median is ever
   computed for these rows.

## Open questions

1. **Which `stopped_by` values are possible** (`run_triage_job` at `130b10a`):
   - **Proposer rows:** `NULL` (the gate ran, steps 1–7), `linter` (builder violation, no model
     call), `cap` (monthly cap before the proposer call, or the verifier call hit it), `schema`
     (the proposer JSON failed after the repair), `transient` (last attempt, on the proposer or
     the verifier call).
   - **Verifier rows:** `NULL`, `schema`, `cap`, `transient`. On `schema` (the verifier's answer
     did not parse), the proposer row keeps `NULL` and step 6 records `invalid`.
   - **Failed rows can carry real spend.** A proposer row with `cap` or `transient` keeps the
     proposer call's latency and cost when only the verifier failed (the "write with what exists"
     path). Those costs are in the totals, and the rows stay out of the forced-rate denominator.
   - **No row at all:** `disabled` appears only in a log line; a skipped closed alert and a
     `PermanentError` write nothing.
   - **P7-T01:** its held refactor is reported to keep all 17 write calls identical (DEC-121
     context). I did not re-check that branch.
2. **§6 metrics that could be measured from existing rows.** I implemented none of these; the card
   scopes them out. Each is a proxy, not the architecture's metric.
   - (i) **① agreement.** Compare ①'s online `final_verdict` with the P6 gold labels (or the
     frozen truth) on the blind-branch heads: `llm_runs` joined to `triage_labels` by alert,
     `suggestion_visible = false`. Two caveats. The labels are blind offline labels, not triage
     decisions. On the lab corpus the result largely repeats P7's offline B4 figure, using the
     live verdict instead.
   - (ii) **Auto-close wrong-close rate with a Wilson CI.** Score it against the lab windows'
     truth instead of a digest: an auto-closed head inside an attack window with an expected
     rule counts as a wrong close. This needs `eval/lab_windows.csv`, so it cannot come from rows
     alone. If `soc_dev` still has no enabled auto-close rule (P5-T10 measured 0 on 23/09), n = 0
     and the rate is n/a.
   - (iii) **Decisions per person.** `label.created` per actor gives labels per labeller, which
     section 7 deliberately keeps apart from decisions.
   - **No source rows:** median acknowledge → decide and ② usefulness have none.
3. **State at the run versus the window.** Four figures read a column's current state:
   `source_cursor`, pull-job `status`, the heads' `triage_status`, and `occurrence_count`. A head
   can absorb a duplicate that arrives after `--until`, within the 4 h cluster age. Two runs are
   therefore byte-identical over the same rows, not across later ingestion. For P8-T06, should
   `--until` be the close-out instant with the worker stopped, or the last window's end plus the
   dedup horizon?
