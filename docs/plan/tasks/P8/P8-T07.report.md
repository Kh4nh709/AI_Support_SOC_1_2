## 1. Built

- **`Makefile` · `db-restore`** — still the real-recovery tool: it stops app and worker, drops and
  recreates the database `.env`'s `DATABASE_URL_OWNER` names, restores into it and restarts them. But
  first, **before `$(COMPOSE) stop` and before `drop database`**:
  1. `.env` must name a `DATABASE_URL_OWNER` (base: an empty DSN went on to `compose stop`);
  2. the server is asked its major version (`psql … -XtAc "select current_setting('server_version_num')::int / 10000"`);
  3. `pg_restore` and `psql` are taken from `PG_LIB/<major>/bin` (`PG_LIB ?= /usr/lib/postgresql`,
     restore.sh's and backup.sh's rule), else from PATH with a `warning` line;
  4. a `pg_restore` **newer than the server** is refused (Deviation 1);
  5. `pg_restore --list "$f"` with that binary must succeed.

  Any of these failing exits **2** with `… nothing was stopped or dropped`. A line
  `db-restore: server 16, /usr/lib/postgresql/16/bin/pg_restore` names the binary used. After the
  pre-flight, stop → drop/create → restore are chained with `&&`; the exit code is the failing step's
  and the message names the stage (base: each step ran whatever the previous did, success was echoed
  after a failed restore, and the exit code was `compose up`'s). App and worker are restarted in every
  outcome past the pre-flight, as before.
- **`Makefile` · `test-db`** — the DSN is shown only through `$(PY) scripts/dsn_env.py --redact "$dsn"`.
  The old `sed -E 's#://([^:/@]+):[^@]*@#…#'` stopped at the first `@` (DEC-123).
- **`scripts/dsn_env.py --redact <dsn>`** (additive) — the one redaction routine. A URI password is masked
  from `user:` to the **last** `@`; a key=value `password=…` (quoted or not) and a URI `?password=…` are
  masked too. `redact()` and `passwords()` share one parser (`_password_spans`). With no `--redact`, the
  script is unchanged: same export line, byte for byte (acceptance 2).
- **`backend/tests/conftest.py`**

    cannot disagree.
  - **`Dsn(str)`**: its `__repr__` is `repr(redact_dsn(self))`; it is still a `str`, so `psycopg.connect`,
    f-strings and subprocess arguments get the real value. `_test_database`, `require_test_dsn` (which
    wraps its argument first, so its own frame prints redacted when the `_test` rail fires) and
    `_maintenance_dsn` return it.
  - The migrate check (`conftest.py:126` on the base) is `pytest.fail` on plain values. Before, pytest
    rendered `CompletedProcess(args=[…, dsn])` to explain the `assert`.
  - **A second layer, `pytest_runtest_makereport`** (Deviation 3): in every report it masks the
    database passwords found in `TEST_DATABASE_URL`, `DATABASE_URL`, `DATABASE_URL_OWNER` and
    `PGPASSWORD`. That means each one as written, percent-decoded, repr- and conninfo-escaped, its
    pieces between URI delimiters, and a prefix or suffix left at a `...` where pytest cut a long repr.
    A report is re-rendered as plain text only when it held a password.
- **`backend/tests/test_credential_hygiene.py`** (new) — 40 tests: 35 need no server (so `make test` runs
  them too) and 5 are `db`-marked.
  - **Redaction:** 6 fake passwords (`@`, `:`, `/`, `#`, percent-escapes, all of them). Each goes through

  - **Export line:** 5 golden export lines, computed with the base script, and 4 usage errors.

## 3. Deviations

1. **`db-restore` refuses a `pg_restore` newer than the server** (exit 2, before anything is stopped). The
   card says "fall back to PATH's with a warning". The fallback still happens, with the warning, when
   PATH's client is not newer (`test_db_restore_falls_back_…`). But red (e) shows the literal fallback on
   this host (PATH 18, server 16): it passes `--list`, drops the database, then fails on
   `SET transaction_timeout`, which contradicts the card's title. The message says to install the
   server's client. Inside the `db` container, `pg_restore` is already 16.
2. **`dsn_env.redact` does not split with `urllib.parse`.** The card suggested it "reuses `urllib.parse`
   like `conftest.redact_dsn`", but that is the bug the card's own test list targets. Measured on the base
   with fake passwords: `conftest.redact_dsn` returned the DSN **whole** for a password containing a raw
   `/`, `#` or `?`, because `urlsplit` ends the authority there and finds no password. libpq accepts raw
   `#` and `?` in a password: `psql "postgresql://soc:Wq9Zk#Jx4Vm@127.0.0.1:9/x_test"` → `Connection
   refused`, meaning it parsed. So a *working* DSN would have been printed entire. The new routine is the
   card's first option (mask to the last `@`), written once and used by both `make test-db` and
   `conftest.redact_dsn`. Its outputs for the existing `test_conftest_helpers.py` cases are unchanged.
3. **A second layer in `conftest.py`, the report hook.** It is not in the card. The card's mechanism, a
   `str` with a redacted repr, cannot reach these routes, measured with the inner run and red (d):
   - **psycopg's own frame.** `Connection.connect` rebinds its `conninfo` argument to a plain
     `user=… password=… …` string before it raises, and pytest prints the last frame's arguments. So any
     failed connection, in the `db` fixture or in a test that connects with `_test_database` itself,
     printed the password. On this host, a restart of the lab's `db` container during a `make test-db`
     would do it on every test.
   - **`test_adversarial.py:935-969`** builds DSN strings from `parsed.netloc` (`:941`) and asserts on
     `CompletedProcess.returncode` (`:953`, `:969`), so pytest's explanation prints the DSN.
   - Also: `==` text diffs, captured output, and reprs pytest cuts in the middle of a password (DEC-122's
     leak was such a prefix).

   Those files are outside the card's Files list, so the fix is a hook in `conftest.py`. It leaves a
   report untouched unless a password is in it; a masked report is plain text, with no colour and no
   short-summary message. Passwords shorter than 4 characters are not masked, for example the documented
   default `soc`.
4. **`dsn_env.py --redact` with no DSN is a usage error** (exit 2). On the base, a lone `--redact` was read
   as a DSN and printed an empty export line. The export line for any DSN is unchanged.
5. **`db-restore` hardening beyond the pre-flight**, all inside the target: a missing `DATABASE_URL_OWNER`
   exits 2; the steps are chained; the exit code is honest; `psql -X`; a failed restart is reported. The
   target's meaning is kept, and the success test pins it.
6. **The real target is tested; no pre-flight function was extracted.** `COMPOSE` is a make variable and
   the pre-flight runs before its first use, so `make -C <scratch> -f Makefile db-restore
   COMPOSE=<recorder>` exercises the recipe itself. `docker` is also a recorder on PATH as a second net.
   The scratch `.env` holds the stand-in's DSN **without** its password; the password travels in
   `PGPASSWORD`, never in a file.
7. **The fixture inner run stubs the server.** A fake password cannot connect, and the real one must
   never be the probe. The inner conftest replaces `psycopg`, `subprocess` and `shutil` inside
   `tests.conftest`'s namespace, in the inner process only. The fixture's own code runs unchanged. A
   separate `db` test checks the real fixture on the real server.

## 4. Open questions

1. **Credentials in the process list** (not a failing test's output, so not fixed here). DSNs with their
   passwords travel in argv in these places:
   - `make test-db`'s `psql "${dsn%/*}/postgres"` and both `dsn_env.py` calls (under 1 s);
   - `conftest._test_database` → `bash scripts/migrate.sh <dsn>` → each `psql "$DSN"`, a few seconds on
     every `make test-db`;
   - `db-restore`'s `psql` and `pg_restore -d "$dsn"`: the **live** DSN, for the whole restore;
   - `test_adversarial.py`'s migrate and load calls.

   `ps aux` shows all of them. The auto-memory note `soc-test-shared-db-race` tells agents to run
   `ps aux | grep -iE 'pytest|migrate'`. During another session's `make test-db`, as happened twice
   today, that prints `bash scripts/migrate.sh postgresql://soc:<password>@…`. Suggested:
   - agents only count (`ps aux | grep -c "[m]ake test-db"`) and never list;
   - a follow-up card passes `migrate.sh` a password-less DSN with `PGPASSWORD`. `conftest.py` can do
     this in three lines. The memory note is the Owner's.
2. **`--list` proves the archive is readable, not that every entry restores.** The target's default
   `FILE`, the tracked `backups/latest.dump`, carries `DEFAULT ACL … FOR ROLE user1` entries that fail
   under `--exit-on-error` on this host (P5-T12, open question 4). ACLs restore last, so the data would
   be in, but the target now correctly reports `FAILED at restore`. For P8-T03's runbook:
   - rehearse with `scripts/restore.sh <dump> --into <scratch>` first;
   - then `make db-restore FILE=<that dump>`;
   - never rely on the default `latest.dump` until a fresh one is committed.
3. After a failure past the pre-flight, the target still restarts app and worker (base behaviour). The
   Director decides whether a failed restore should leave them stopped instead.
4. `test_backup_restore.py` keeps its own `_Dsn`/`_Env`, which are outside this card's files. It could now
   use `conftest.Dsn`.
5. Left on the server: `soc_p8t07_test`, the session database. The stand-ins were dropped by their fixture.
