  1. Pick `pg_restore`/`psql` of the server's major version, as `restore.sh` does; fall back to PATH's

     is then untouched.
  3. Keep the target's meaning: it is the real-recovery tool that replaces the live database. It is not a
     rehearsal (that is `restore.sh`).

  unreadable archive, and against a private `_test` database standing in for the live one (point
  `DATABASE_URL_OWNER` at it through a temporary `.env`-shaped file or the environment, whichever the
  target reads). Assert exit 2 and that the stand-in database still exists with its rows. **Never run
  `make db-restore` against the real `.env`**, and never stop the real compose services. If the target
  cannot be exercised without the compose services, extract its pre-flight into a function you can test,
  and test that; say which in the report.
- **Fix 2 · `test-db` masks the whole password.** The mask `s#://([^:/@]+):[^@]*@#…#` stops at the
  first `@`, so a password containing `@` prints its tail. Mask everything between `user:` and the
  **last** `@` before the host, or better, call one redaction routine: `scripts/dsn_env.py --redact
  <dsn>`, a new optional flag that reuses `urllib.parse` like `conftest.redact_dsn`, so there is one
  implementation. Test it with passwords containing `@`, `:`, `/`, `#` and percent-escapes, and assert no
  password fragment survives.
- **Fix 3 · No DSN reaches a failing test's output.** `_test_database` (and any fixture that returns a
  DSN string) returns a `str` subclass whose `__repr__` is `redact_dsn(self)`. It is still a `str`, so
  `psycopg.connect(dsn)` is unchanged. Find every other place a raw DSN can reach a traceback or an
  assertion message (`grep -rn "_test_database\|TEST_DATABASE_URL" backend/tests`) and route it through
  the same redaction. Test: a deliberately failing inner pytest run (`pytester` or a `subprocess` pytest
  on a temporary test file) that takes the DSN fixture, with a fake password; assert the password does
  not appear in its output.
