# Run card — P8-T02 · The restore drill: a real backup of `soc_dev`, restored into a separate empty database, verified by migrations, counts and an application-role read; `docs/restore-drill.md` written and signed

> **Run card, 26/09/2026 (Director, DEC-129).** `must`, **≈ 1 h**. **Executed by the Director; the Owner
> signs.** It needs `scripts/restore.sh` (P5-T12, DEC-128) merged. **Never during a lab window.** Run it
> after the last window of 27/09: on 28/09 after the freeze, or on 30/09. It reads `soc_dev` (one
> `pg_dump`) and creates one new database on the same server. It **writes nothing to `soc_dev`** and
> never runs `make db-restore` (that one replaces the live database).

Run every command from the **primary checkout** with `PY=.venv/bin/python`, in one shell that has
sourced `.env` (`set -a; . ./.env; set +a`). Never print a DSN. Mask anything pasted.

## Read first
1. `docs/plan/tasks/P5/P5-T12.prompt.md` + `.report.md` + `.review.md`: `restore.sh`'s interface, its
   guards (it refuses the live name and a non-empty target without `--force`), and its printed block.
2. `prompts/P8.md`, the restore-drill bullet. It names two expectations (DEC-023 item 6, DEC-024(a)):
   the dump carries `GRANT … TO app_rw` lines, and a cluster without that role would report each one as
   an error. **On this host the roles exist cluster-wide** (one server, `127.0.0.1:55432`), so the restore
   meets them. The drill records that fact instead of assuming it.
3. `docs/migration-runbook.md` §3.4: the 22/09 restore, the one precedent.

## Steps. Record each command's decisive output, with timestamps (`date -u +%FT%TZ`)
1. **Before.** Counts on `soc_dev`, read-only, at T0: `schema_migrations`, `alerts`, `intake`,
   `llm_runs`, `jobs`, `audit_events`, `triage_labels`, `eval_runs`.
2. **Backup.** `bash scripts/backup.sh` (DSN from the sourced `DATABASE_URL_OWNER`). Record the file name,
   its size and T1.
3. **After.** The same counts on `soc_dev` at T2. The pipeline keeps pulling during the drill, so the
   criterion for each table is **before ≤ restored ≤ after**. The dump is one consistent snapshot taken
   between T0 and T2.
4. **Guard, for real.** `bash scripts/restore.sh <dump> --into "<the soc_dev name>"` → **exit 2**, both
   names printed, nothing restored. This is the run against the real name that P5-T12 deferred to the drill
   (DEC-128 item 2).
5. **Restore.** `bash scripts/restore.sh <dump> --into soc_restore_drill` → exit 0 with the printed block:
   `schema_migrations` = 17 and the table counts. Record `pg_restore`'s own error lines, if any, verbatim
   (masked). The brief says to expect none for roles here (Read first 2); any that do appear are recorded,
   not hidden.
6. **Criterion.** For each table: before ≤ restored ≤ after, and migrations = 17. Any miss is a failed
   drill, and it is recorded as failed.
7. **The application role reads the restored copy.** `psql` connects as `app_rw` (its DSN from
   `DATABASE_URL`, with only the database name swapped to `soc_restore_drill`) and runs
   `select count(*) from alerts`. The count must equal step 5's. `permission denied` fails the drill: the
   grants did not survive.
8. **The code against the restored schema.** `make test` shows exactly the DEC-113 failure, on the commit
   the drill ran from (record `git rev-parse --short HEAD`). `make test-db` needs a `_test` database, so it
   is **not** pointed at `soc_restore_drill`. Record that the drill's database proof is steps 5–7, and do
   not claim more.
9. **Write `docs/restore-drill.md`**: date; commit; T0/T1/T2; the dump file (name and size, never
   committed); each step's command and decisive output; the criterion table (table · before · restored ·
   after · holds); the outcome (**PASS / FAIL**); a line `Signed: ________ (Owner) date ______`; and one
   paragraph of what the drill does **not** prove (no restore onto a *fresh* cluster, no application
   start against the copy, the RPO the schedule gives once the crontab is armed). Commit it with the
   scratch-index procedure; never switch HEAD in the shared checkout.
10. **Clean-up is the Owner's call.** Leave `soc_restore_drill` in place until the Owner signs, then
    `dropdb soc_restore_drill` (Owner, or the Director at the Owner's word). Record which.

## Stop conditions
- `restore.sh` restores anything in step 4: stop. It is a defect; reopen P5-T12. `soc_dev` has not been
  touched, because the guard runs before any `pg_restore`, but check the step 3 counts again.
- `pg_dump` fails, or any step 1–3 command writes to `soc_dev`: stop and record.

## Report
The drill document is the report. Set the `STATE.md` row to `done` once the Owner has signed. Until then
it stays `todo`, with the note "drill run <date>: PASS/FAIL; awaiting the Owner's signature". A run card
has no `task/` branch, so it never takes `review` or `in-progress`: `test_dispatch_state.py` invariant 2
would fail.
