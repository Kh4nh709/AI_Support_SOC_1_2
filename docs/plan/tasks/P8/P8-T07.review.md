## Correctness, read from the diff

- **`db-restore` can no longer destroy the live database.** Before `$(COMPOSE) stop` or `drop database`, it:
  - asks the server for its major version;
  - picks that version's `pg_restore`/`psql` (as `backup.sh`/`restore.sh` do);
  - **refuses a `pg_restore` newer than the server**;
  - refuses a dump that binary cannot read (`--list`).

  Each refusal exits 2 with "nothing was stopped or dropped". The stages are chained and the exit code is
  honest. Red step (b) reproduced DEC-130's loss on a private stand-in without the pre-flight. Red step
  (e) shows why the card's literal "fall back to PATH's" was not enough. The tests drive the real target,
  with recorders in place of `compose` and `docker`.
- **`test-db` masks the whole password** through `scripts/dsn_env.py --redact`, one routine shared with
  `conftest.redact_dsn`. Red step (a) printed DEC-123's `…:***@Jx4Vm@Pb7Ty@…` shape. The `export …` line
  is byte-identical to the base, pinned by five golden lines.
- **A failing test cannot print a password.** Two layers:
  - every DSN the fixtures hand out is a `Dsn`, whose `repr` is redacted (red step (c));
  - a report hook masks the environment's passwords in every report, for what a `repr` cannot reach
    (red step (d)).

  The hook rewrites report text only, never an outcome, and ignores anything shorter than 4 characters.
  `conftest.py:126`'s `assert` on the migrate result became `pytest.fail` with plain values.

## Rulings on the deviations (DEC-134)

1. **Refusing a newer `pg_restore`**: accepted. On this host the literal fallback drops the database and
   then fails.
2. **`--redact` masks from `user:` to the last `@` instead of using `urllib`**: accepted. The old
   `urllib` path returned a DSN whole when the password held a raw `/`, `#` or `?`, which libpq accepts.
   The existing `test_conftest_helpers.py` outputs are unchanged.
3. **The report hook, a second layer beyond the card**: accepted. psycopg rebinds its argument to a
   plain conninfo string before failing, which no `repr` can cover.
4. The smaller changes (usage error on `--redact` without a DSN, a missing `DATABASE_URL_OWNER` → exit
   2, the target tested directly): accepted.

## Rulings on the open questions

1. **DSNs travel in process arguments** (`psql`, `migrate.sh`, `pg_restore`). A `ps aux` during another
   session's run prints the password. The Director's memory note that told agents to `ps aux | grep …`
   is corrected to **count only** (`pgrep -fc`). Moving the DSNs to `PGPASSWORD` is recorded in
   `docs/limitations.md` (xxxiv) at close-out, not built now.
2. **`--list` proves readability, not restorability.** The tracked `latest.dump` carries `DEFAULT ACL …
   user1` entries that fail under `--exit-on-error`. P8-T03's runbook says to rehearse with `restore.sh`
   on a fresh `backup.sh` dump first (P8-T03 banner).
3. **A failure after the drop still restarts app and worker.** Not changed now: `db-restore` is
   disaster-only. P8-T03's runbook says to stop them at once and repair before restarting
   (`docker compose stop app worker`).
