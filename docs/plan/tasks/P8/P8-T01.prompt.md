## Design notes

**1 · Population.** Every alert-based figure is over `alerts` with `received_at >= since AND received_at <
until AND NOT is_synthetic`. G3's adversarial rows are loaded after the freeze with no job (P7-T08 step 1),
and ① never sees them online, so they are counted on one separate line ("synthetic rows in the window,
excluded: n") and nowhere else. `source` is **not** a filter: the lab-window heads are retagged
`source='lab'` by `eval/lab_tag.py` (DEC-085), and they *are* the online traffic. Break the intake table
down by `source` and by `agent_name` so the reader sees what is lab and what is the host's own background.
LLM figures are over `llm_runs` with `pipeline='triage'` and `created_at` in the window, joined to a
non-synthetic alert.

**2 · Sections and figures, in this order. Each figure is printed with its SQL (note 3).**
1. **Header.** The window, `DEC111_SENTENCE`, and one sentence: *"Descriptive: an operating record, not a
   controlled experiment (architecture §6)."* No run timestamp; the window is the identity.
2. **Intake and dedup.** `intake` rows in the window by `outcome`. Intake latency
   (`processed_at − received_at`): p50, p95 and max, plus the count over 60 s (G12's bound).
   `rejected_alerts` in the window. `alerts` by `source` × `agent_name`. Heads
   (`duplicate_of IS NULL`), duplicates merged, the ratio of alerts to heads, max `occurrence_count`.
3. **The pull loop.** `jobs` of type `pull` by `status`, and the largest gap between consecutive
   `succeeded` pull jobs' `scheduled_at` inside the window. `source_cursor.last_error IS NULL` at the run.
   `job.exhausted` events.
4. **① online.**
   - Proposer rows `n`, and `stopped_by` by class (`NULL` means the gate ran).
   - The final verdict distribution over the rows where the gate ran (`gate_result->>'final_verdict'`).
   - **The gate-forced rate**: `forced = true` over the rows where the gate ran. When it exceeds 0.60,
     print the architecture's sentence: *"the gate is squeezing ①"* (§6), and name R5 (§9).
   - `forced_by` counts per step, from the jsonb array; `hallucination_flag` rate.
   - The online evidence-verified rate: Σ surviving reasons ÷ Σ (surviving + dropped). Surviving is
     `jsonb_array_length(result->'reasons')` and dropped is `jsonb_array_length(gate_result->'dropped_reasons')`.
     Print it beside the 0.90 target, as P7 does.
   - Verifier step 6: `agree` / `disagree` / `invalid`.
   - Latency p50 and p95 per role and per alert (proposer + verifier summed by `subject_id`).
   - `cost_usd` total and per alert. `model_id` and `prompt_version` as distinct values with counts.
   - `triage_status` of the heads.

   Percentiles are `percentile_disc` in SQL: deterministic, and the SQL is then the citation.
5. **Auto-close.** `alert.auto_closed` and `alert.autoclose_blocked_critical` event counts; heads with
   `autoclose_rule_id IS NOT NULL`.
6. **Architecture §6's online metrics, one row each.** Columns: metric · value · basis.
   - Decisions by branch (blind / visible) and by person.
   - Median acknowledge → decide by branch.
   - ① agreement with human decisions on the blind branch.
   - The gate-forced `needs_review` rate: **measured**, the value from section 4.
   - The auto-close wrong-close rate from the digest, with its Wilson CI.
   - ② usefulness 1–5.

   Every row except the gate-forced one prints `not measured`, with a basis naming the missing
   precondition and its DEC. The basis also carries the counted evidence: `tier1.decided` n,
   `alert.acknowledged` n, `autoclose.reviewed` n, `autoclose_reviews` n, `case.opened` n. For example:
   *"not measured — no human-decision pilot ran: the Tier-1 console was deprioritized (DEC-116);
   `tier1.decided` = 0"*.
   **If any of those counts is non-zero, print the count and "descriptive, n = k" instead. Never
   "not measured" beside a non-zero count, and never a rate with n < 1.** Print the branch sizes
   too, as `suggestion_visible` true/false counts over the heads. The blind assignment happens at
   intake whether or not anyone decides.
7. **Labelling activity (P6), not triage decisions.** `label.created` events and `triage_labels` by
   `source`. This keeps the gold labelling from ever being read as pilot decisions.
8. **Appendix: SQL.** Every query, verbatim, in the order used, with its bind parameters shown as
   `%(since)s` / `%(until)s`. The brief's design note: the thesis must be able to cite it.

**3 · The SQL is the citation.** Keep each query in one module-level constant, and have both the run and
the appendix read that same constant: never two copies. One helper runs a query and records it for the
appendix.

**4 · No free text, ever.** The output contains counts, identifiers, enums, category and agent names, rule
ids and timestamps only. It never contains `description`, `raw_log`, `raw_text`, `raw_payload`,
`system_prompt`, `user_message`, a reason's `quote`, or `result`/`gate_result` text fields. This is
committed evidence (DEC-121 Q4's rule, applied here). A test seeds a unique marker string into every
free-text column and asserts it is absent from the output.

**5 · Undefined is not zero.** A ratio whose denominator is 0 prints `n/a (0 rows)`. Fixed decimals: 3
for rates, 5 for USD, integers for ms.

**6 · Tests (`backend/tests/test_ops_export.py`, `@pytest.mark.db`; private DB `soc_p8t01_test`).** Seed
through `domain.transitions.open_alert` where an alert is needed (as `test_triage_job.py` does), with
