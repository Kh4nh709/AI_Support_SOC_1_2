## 4. Open questions / follow-ups

1. **Note for the Reviewer, on acceptance 6.** The card's line is correct as written — a `bigserial` reads
   `is_identity|NO`. But the *sequence* is not the discriminator: measured on this cluster, `bigint GENERATED BY
   DEFAULT AS IDENTITY` and `bigserial` both create `intake_intake_id_seq`. My first draft of that test asserted
   the sequence was absent; it failed for the wrong reason, and was rewritten before the migration existed to
   assert the three things that do discriminate: `is_identity='YES'`, `identity_generation='BY DEFAULT'`,
   `column_default IS NULL`.

2. **For P2, not for this task.** `archive_line_5503.json` is the `_source` object, which is what the card
   specified and what DEC-019 calls the archive-line shape. Strictly, `_source` also carries Logstash/Filebeat
   additions (`@timestamp`, `@version`, `path`, `tags`, `host`, `event.original`) that a manager's own
   `alerts.json` line does not; the manager's line is available verbatim inside the same fixture as the string
   `_source.event.original`. When the real backfill path lands, whoever writes it should decide whether the
   replay fixture should become that line instead. It changes nothing here — both shapes are rewritten by `jsonb`
   and both exercise the same claim.

3. **Handover to P1-T06.** `intake` is created with its constraints and nothing else, as design note 6 requires:
   no GRANT, no REVOKE, no trigger, no index beyond the ones the three keys imply. 017 can apply
   `REVOKE UPDATE, DELETE, TRUNCATE` then `GRANT UPDATE (processed_at, outcome, error)` in that order without
   touching this file. `intake_id` is `IDENTITY`, so an `INSERT` as `app_rw` needs no sequence privilege.

4. **Cost, already accepted by DEC-023 item 5.** The received document is stored twice — `raw_text` and the
   STORED generated `raw_payload` — TOASTed and compressed, tens of MB at pilot volume. `GENERATED … VIRTUAL`
   would avoid it and is PG18; this cluster is 16.15.
