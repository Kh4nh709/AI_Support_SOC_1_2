## Method

starts from: the DEC-023 harness fixes (`Makefile` `TESTS`/`-rs`, `test_conftest_helpers.py`
counting migrations by glob) present, **no `.env`**, 12 migrations on disk. Migrations 013–017 do
not exist on `main` yet, so they were **constructed from the five sibling cards' own `sql` blocks**
(T02's block is complete; T03/T04/T05's were wrapped in `BEGIN;`/`COMMIT;` and their
`schema_migrations` line per the conventions; T06's is complete) and written into the worktree's
`docs/Schema/`. T07's acceptance lines were then executed there **verbatim, in card order**, and
every expected output now quoted in the card is what that run printed. The worktree was removed and
every database it created was dropped afterwards.

Every claimed defect below carries the command that demonstrated it and the command that
demonstrated the fix. Classification letters are the taxonomy the six sibling audits produced.

## Defects

**a1 · SILENT GREEN — acceptances 8 and 9 were bare `pytest … -q`.** No `TEST_DATABASE_URL`, and an
extra `-q` stacking on `addopts = "-q"`. Demonstrated in the worktree (no `.env`):
`python3 -m pytest -c backend/pyproject.toml backend/tests -m db -q; echo rc=$?` → `sss`, `rc=0`;
with `-rs` the reason shows: `TEST_DATABASE_URL unreachable: postgresql://soc:***@127.0.0.1:55432/soc_test`.
Fix: inline `TEST_DATABASE_URL=postgresql:///soc_p1t07_test`, `-rs`, `N passed` with `skipped`
absent (DEC-023's rule, which my own pass on 05/09 applied to T02–T06 and missed here on lines 8
and 9). Demonstrated: `TEST_DATABASE_URL=postgresql:///soc_p1t07_test python3 -m pytest -c
backend/pyproject.toml backend/tests -m db -rs` → `3 passed, 77 deselected`, and acceptance 9 now
also carries a `--collect-only -q | grep -E '^tests/test_schema_v3(_01[3-7])?\.py: [0-9]+$'` proof
so "every sibling file" is a count, not a belief.

**a2 · SILENT GREEN — acceptance 7's `diff … && echo IDENTICAL` passes on two empty files.**
Demonstrated: `: > /tmp/e1; : > /tmp/e2; diff /tmp/e1 /tmp/e2 && echo IDENTICAL` → `IDENTICAL`. A
mistyped database name sends `psql`'s error to stderr and leaves both files empty, and the line
goes green. Fix: `test -s` on the a-side files inside the `&&` chain, plus `wc -l` pasted
(measured 195 / 81 / 7 on the constructed case-A state). Demonstrated: the corrected chain printed
`IDENTICAL` with those counts.

**d1 · PROSE WHERE A COMMAND BELONGS — acceptance 7's "Do the same for `pg_constraint` … and for
non-internal triggers".** Nothing for a Reviewer to execute verbatim. Fix: the two `psql` queries
(`conrelid::regclass||' '||conname||' '||pg_get_constraintdef(oid)`, `tgrelid::regclass||' '||
tgname||' '||pg_get_triggerdef(oid)`, both `order by 1`) written out and run: `IDENTICAL`.

**c1 · SELF-CONTRADICTION — acceptance 13 dropped two of three databases under "leave no scratch
database behind".** Demonstrated: after running 10 and 13 as written, `psql -tAc "select datname
from pg_database where datname like 'soc_p1t07%'" postgres` → `soc_p1t07_test`. Fix: `dropdb
soc_p1t07a && dropdb soc_p1t07b && dropdb soc_p1t07_test` and a `count(*) … → 0` check; design
note 6 now names three databases. Demonstrated: `0`. (This is the handed-in defect 2, confirmed.)

**Handed-in defect 1 — `DROP DATABASE IF EXISTS` absent — does NOT reproduce as stated.** The
claim was that `createdb soc_p1t07a` fails on the first acceptance line because a stale
`soc_p1t07a` exists. A bare `createdb soc_p1t07a` does fail (`ERROR: database "soc_p1t07a" already
exists`, rc 1), but the card's acceptance 2 was never bare: it reads `dropdb --if-exists soc_p1t07a
&& createdb soc_p1t07a`, the CLI form of DEC-024 (e)'s pattern and the same idiom every sibling
card uses (`grep -n 'dropdb --if-exists' docs/plan/tasks/P1/P1-T0[2-7].prompt.md` → seven hits, T07
included). Executed as written it returned rc 0 and **cleared the leftover** — which is the
self-healing DEC-024 wanted. The Director's `grep -c 'DROP DATABASE IF EXISTS'` returning 0 on
every P1 card, not only T07, is a grep for the SQL spelling of an idiom the cards carry in shell
spelling. What was missing was narrower: acceptance 10 created `soc_p1t07_test` with a bare
`createdb … 2>/dev/null` (harmless — the fixture itself does `DROP DATABASE IF EXISTS`), and that
database was never dropped (c1). Fix: acceptance 10 and rule 3 now open with `dropdb --if-exists
soc_p1t07_test && createdb soc_p1t07_test`. Note for the Director: T02–T06 still use `createdb
soc_p1t0N_test 2>/dev/null;` on their `make test-db` lines — the same harmless gap, not corrected
here because those cards are outside this audit's scope.
