## Non-blocking notes

1. **Design note 3's stated reason is factually wrong about PostgreSQL — the DDL is not.**
   The card, the migration comment (`016…sql:60-63`) and the report all say a bare
   `role IN (…)` "would reject every insert that omits it". Measured false: a CHECK whose
   expression evaluates to NULL passes, so `CHECK (role IN (…))` already admits NULL.
   `CREATE TEMP TABLE t (v text CHECK (v IN ('a','b'))); INSERT INTO t VALUES (NULL);`
   → `INSERT 0 1`. Removing the `role IS NULL OR` prefix from 016 changes no test result
   (mutation G below: `3 passed`). The prefix is redundant, not wrong, and reads well as
   documentation — I would leave the SQL alone. But the **rationale** is worth correcting
   wherever it is recorded, because the same false premise would let a future author
   conclude that a bare CHECK enforces NOT NULL. **For the Director**, not for this Coder:
   the sentence originates in the card, and DEC-009 has the Coder transcribe the card.

2. **`docs/Schema/test_constraints.py:157,158,180,181` still inserts `job_type='enrich'`,**
   which the database refuses after 016. Nothing goes red: both gates collect
   `backend/tests` only (`TESTS ?= backend/tests`, `Makefile:14`; `make test` and
   `make test-db` each collect the same 288 items), and the file is a standalone v1 script,
   not a pytest module — pointing pytest at it raises `INTERNALERROR` because it executes
   at import. So it is stale, not broken, and it is outside T05's file list by rule.
   Flagging for whoever owns v1 script hygiene; a hand-run of it after 016 merges will fail.

3. `docs/Schema/schema.sql:344` and `003_jobs_audit_llm.sql:25` still show the 2-value
   `ck_jobs_job_type`. Correct and expected — acceptance 13 requires `schema.sql` untouched
   (P1-T07 regenerates it) and 003 is history.

4. **Three of the 21 tests pass pre-state; the report disclosed this rather than hiding it,**
   and each has a real failing case, which I made red rather than reasoned about (mutations
   A, B, C below). No action needed — recording it because a green pre-state test is the
   exact shape DEC-027 warns about, and here it survives the scrutiny.

5. Minor: several tests assert absolute counts (`count(*) FROM jobs == 6`;
   `SELECT source FROM alerts ORDER BY source`) and so assume an empty table at test start.
   Sound today — the `db` fixture rolls back per test — but they would break under any
   future change to that fixture's isolation.
