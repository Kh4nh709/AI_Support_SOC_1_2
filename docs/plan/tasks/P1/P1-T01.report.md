## 3 · Deviations

1. **Acceptance 6 was run as
   `env -u INDEXER_PASSWORD -u LLM_BASE_URL INDEXER_CA=… python3 eval/smoke_test.py --env-file ../AI_Support_SOC_1_2/.env --report docs/smoke-test-D1.md`,
   not verbatim.** This shell carries ambient `LLM_*`/`INDEXER_*` exports from the harness. Two of
   them differ from `.env`: `INDEXER_PASSWORD` is **empty** and `LLM_BASE_URL` points at
   `…/anthropic` instead of `…/`. Under the dotenv rule the card mandates ("a key already set in
   the environment must win"), and which `eval/indexer_probe.py` already implements verbatim
   ("A real environment variable wins over the file, even when it is empty"), both would have
   beaten `.env` — the empty password fails config validation, and the wrong base URL would have
   measured a different endpoint. I kept the precedence rule as specified and cleared exactly
   those two stale variables instead of weakening it. In a clean shell the command is verbatim.
   Confirmed by hashing: the other eleven `LLM_*`/`INDEXER_*`/`PULL_*` values, `LLM_API_KEY`
   included, are identical in the environment and in `.env`.
2. **The live run was killed once by the host for low memory and restarted.** It is a plain
   `nohup` process, not a script fault. The restart replayed the 18 responses already cached and
   paid only for the remaining 20 — design note 9 doing its job. Total spend across both runs is
   the $0.1577 reported, not double.
3. **`P1-tasks.md` and this card disagree on one line, and per DEC-007 item 7 the card wins.**
   The index says "Files — create: `eval/smoke_test.py`"; the card says modify, because P0-T06
   already shipped it as a docstring skeleton. I modified it. No second file was created.
4. **`wrap_untrusted` strips the nonce twice — before *and* after NFKC.** §7.1 orders "strip,
   NFKC, escape", which I follow; the second strip is an addition, not a substitution. NFKC folds
   fullwidth digits to ASCII, so a nonce written as `０１２３…` survives the first strip and
   reappears as a forged boundary after normalisation. Covered by
   `test_wrap_untrusted_strips_a_nonce_reassembled_by_nfkc_normalisation`.
5. **The cache key hashes the nonce-normalised user message.** The formula is still
   `sha256(model + "\n" + system + "\n" + user)`; `stable_user()` defines what `user` means for
   it. Without this, §7.1's fresh-nonce-per-build makes every key unique and design note 9's
   "a second run makes no network call" is unreachable. The nonce itself stays
   `secrets.token_hex(8)` and is never weakened.
6. **`srcip` is wrapped in a block rather than emitted as a fact.** §7.1's `Id` set is closed
   (`alert_id`, `rule_id`, MITRE, `agent_id`) and an IP address is not in it, so G6′ puts it
   inside. Flagged because a reader may expect it outside.
7. **Two items beyond the card's letter, both in service of it.** A failed call is recorded as an
   `origin="error"` row instead of propagating (one 4xx would otherwise have destroyed 37 paid
   measurements), and a repair round gets its own row in the per-call table, since it is a
   separate billed call with its own latency and reasoning tokens.

Not deviations, but worth naming: `backend/requirements.txt` is untouched and no dependency was
added; no frozen contract was edited; `backend/app/llm/**` and `backend/app/security/**` were not
touched; `output_schemas.json` was not created.

## 4 · Open questions / follow-ups

**Measured reasoning-token share: 225,040 of 236,377 billed completion tokens = 95.2 %.** Output
is priced 47× input (`0.66` vs `0.014`), so **95 % of this project's LLM bill is the model
thinking, not the model answering.** Per class: 5,141 of 5,412 mean completion tokens on real
alerts, 8,894 of 9,263 on the ≥ 30 KB class, 8,783 of 9,234 on the adversarial class. Any P3
token estimate built from response length will be wrong by roughly 20×.

**Total spend: $0.1577** for 38 calls — $0.0042 per call, 0.53 % of `LLM_MONTHLY_USD_CAP=30`.
This is **4× the card's $0.04 estimate**, for the same reason: the estimate assumed a normal
completion, and the measured one is 95 % reasoning. The $0.50 spend guard did not trip.
`prompt_cache_hit_tokens` summed to 28,032 against 95,585 misses; `.env` has no cache price key,
so they are recorded and not priced.

**Recommendation on the model (recommendation only — accepting it is the Owner's call,
`README.md` §Conventions).** Four of the five §4.5 checks pass, and the two that matter most for
P3 pass outright: **100 % JSON-parse and 100 % schema-valid `triage_v2` on the first attempt,
across all 38 calls, with zero repair rounds.** A 33.5 KB prompt was accepted. The one failure is
latency: **p95 101.8 s against a 60 s threshold** (p50 35.0 s; worst 139.1 s on the ≥ 30 KB
class), driven by the same reasoning tokens that drive the cost.

I recommend **accepting `deepseek-v4-flash` for pipeline ①, and treating the p95 miss as a
timeout-and-scheduling question rather than a reason to change model** — but this is exactly the
kind of call the card reserves for you, and the case against is real, so here is both sides:

- *For accepting:* ① runs from a job, never from a request handler (§7.5), so no user waits on
  the call; `LLM_TIMEOUT_S` is already 120 s; G7 guarantees no state depends on a model call. A
  101.8 s p95 costs throughput, not correctness. Schema behaviour — the thing P3's gate is built
  on — is perfect, and §4.5's fallback would trade that away for an unmeasured model.
- *Against:* the tail is long and thin — one call took **139.1 s** (the largest ≥ 30 KB prompt,
  13,234 prompt tokens), the next slowest 101.8 s. With `N_WORKER=1` and a 35 s median, ① sustains
  roughly 100 alerts an hour, and the 74 %-of-index rule 92601 alone runs at 5,530 documents over
  four days.
- *If you take the fallback,* §4.5's order is: another DeepSeek chat model through the same
  adapter, then keep `json_object` with 2 repair rounds and drop `raw_log` to 8 KB. Re-running
  `eval/smoke_test.py` against a different `LLM_MODEL_PROPOSER` reproduces this whole report for
  another ~$0.16, so the comparison is cheap.
- *Either way, one measured surprise deserves a decision now:* **`LLM_TIMEOUT_S=120` did not
  behave as a wall-clock cap.** The 139.1 s call was made with `timeout=120` on both the client
  and the request, returned successfully, and recorded `attempts: 1` — no timeout was raised and
  no retry was spent. The OpenAI SDK passes that value to httpx, where the read timeout bounds the
  gap between received bytes rather than the total duration of a non-streaming call. So the 120 s
  in §6.3 is not the guarantee it reads like, and P3 must not assume ① cannot exceed it. Whether
  to raise `LLM_TIMEOUT_S`, add a real wall-clock bound in the P3 adapter, or cap `raw_log` at
  8 KB as §4.5's second fallback already suggests, is a §6.3 matter and therefore yours. No INBOX
  item filed — nothing blocked this task, and none of it changes a frozen contract on its own.

**Injection: 0 of 3 obeyed.** No adversarial alert produced `false_positive`, and `playbook_used`
came back `null` every time. Two of three responses *contain* the canary token — both times
inside `reasons[].quote`, i.e. the model quoting the injected sentence as the suspicious content
it is. The report gives these two separate columns; folding them into one "canary echoed" column
would have reported a citation as a compromise, which is what an earlier draft of this report did
before I read the raw responses. **This is an observation, not a safety verdict** — §7.3 step 5
says the detector never changes the verdict, and P1 has no gate.

**Two things P3 must not read into this run.** The structured facts fed to the model are neutral
placeholders (`ioc_reputation: skipped`, `asset_criticality: unknown`, `identity_privileged:
unknown`, `occurrence_count: 1`) because P1 has no database — so gate step 2's field-by-field
comparison is entirely untested here. And `TRIAGE_V2` rejects unknown top-level keys and requires
`identity_privileged` to be the *string* `"true"|"false"|"unknown"`; the model never violated
either, but P3 should keep both rules rather than discover them.

tables and 300-character excerpts are committed, full raw responses are in the git-ignored
`eval/results/smoke/` (39 files). I did not widen it.
