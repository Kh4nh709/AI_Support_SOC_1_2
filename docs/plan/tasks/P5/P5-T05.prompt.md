- **Design notes:**

  **1 · The seam, from this side.** P5-T07's `case.html` contains exactly
  `{% include "_investigation.html" ignore missing %}` and passes the page's existing context (`case`,
  `alerts`, `user`). Your partial reads that context plus whatever your own routes add. **You do not edit
  `case.html`** — if you find you need a variable it does not pass, fetch it in your own route and render
  your own fragment; that is what HTMX is for and it is what keeps the cut clean.

  **2 · Three routes, all HTML fragments, all in your own router module.** `POST /cases/{case_id}/analyze`
  → calls the API's logic path and swaps in the *"đang phân tích…"* fragment carrying the `run_id` and an
  `hx-get` poll; `GET /cases/{case_id}/investigation` → the current state (no run → the button; running →
  the polling fragment; done → the result block); the poll target is that same GET with
  `hx-trigger="every 3s"`, which **stops itself** by swapping in a fragment without the trigger once the run
  is done. A 409 (already running) and a 429 (quota) render through `_flash.html` with the Vietnamese
  sentence, never a raw status code — *"Đang có một lượt phân tích chạy cho case này"* and
  *"Đã dùng hết N lượt phân tích hôm nay"*.

  **3 · What the result block must show, and the one thing it must never hide.** Summary and
  `attack_narrative` (escaped, inside `<pre>`, never `|safe`); `suggested_conclusion` and `confidence` as
  labelled values; **every hypothesis with its `evidence_against` rendered beside it** — a hypothesis whose
  `evidence_against` is empty is a schema violation upstream, and the template renders a visible warning
  rather than an empty list, because the empty list is the interesting case; each evidence item marked
  **verified** or **unverified** from `evidence_check.verified` / `.rejected`, with the rejection reason
  (`not_in_case` / `quote_not_found`) shown; `citation_warnings` listed; and, when
  `evidence_check.original_conclusion` is present, the sentence that **the model's conclusion was overruled
  to `need_more_data` and what it originally said**. Hiding the overrule would make the screen a worse record
  than the database.

  **4 · The label that stops an analyst distrusting the data (P7-2).** When the case's clusters are still
  absorbing duplicates, show *"đợt tấn công đang tiếp diễn — bộ đếm đang tăng"* with `last_seen_at` beside
  the snapshot the run recorded, so a number that changed between the run and the reading is explained rather
  than surprising. The snapshot is in the `llm_runs` row (P5-T04 design note 3c).

  **5 · Tests (`backend/tests/test_pages_investigation.py`).** `TestClient` with `get_conn` overridden and a
  real session cookie, the P4-T05 pattern. The three states render; the poll fragment carries `hx-trigger`
  while running and **does not** once done; 409 and 429 render as flashes; an unverified evidence item is
  visibly marked; an overruled conclusion shows both values; `raw_log`-derived text is escaped (assert a
  `<script>` in a quote appears escaped in the HTML). **And the seam, from this side:**
  `test_case_page_renders_the_partial_when_present` — render `case.html` through the real template
  environment and assert the ② block appears. (P5-T07 owns the mirror test, that the page renders **without**
  the partial; between the two, planning decision 2 is proven in both directions.)
  **Red steps (DEC-025):** (a) drop `ignore missing` from P5-T07's include **in a scratch copy of the template,
  never on the branch** → rendering without the partial raises `TemplateNotFound`, which is what the token
  prevents; restore the scratch copy and say so in the report; (b) render `attack_narrative` with `|safe` →
  the escaping test goes red; (c) remove the `evidence_check` marking → the unverified-item test goes red
  while the "result renders" test stays green.
