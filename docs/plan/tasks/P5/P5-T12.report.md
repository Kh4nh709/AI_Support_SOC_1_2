## 1. Built

- **`scripts/restore.sh <dump> --into <dbname> [--force]`** (new) — the rehearsal tool for P8's
  drill, deliberately not `make db-restore`. It refuses with **exit 2 before connecting to anything**
  when: `DATABASE_URL` is unset (read from the environment only — it never opens `.env`; the caller
  sources it), the target is the database `DATABASE_URL` **or** `DATABASE_URL_OWNER` names (both names
  printed), the target is `postgres`/`template0`/`template1` or not a plain lower-case name, `--force`
  is given for a name that does not end in `_test`, or the dump is missing or empty. It then connects
  as `DATABASE_URL_OWNER` (else `DATABASE_URL`) with the database name swapped, reads the archive,
  creates the target if absent, refuses a **non-empty** target (exit 2) unless `--force` (drop and
  recreate), runs `pg_restore --no-owner --exit-on-error`, and prints a pasteable record: date (the
  server's `now()`), dump path + size + sha256, source database / archive time / pg_dump version,
  target and its state, the live name(s), pg_restore exit and version, `schema_migrations`, the five
  table counts, elapsed. Exit 1 when pg_restore fails or `schema_migrations` is absent/0.
- **`scripts/backup.sh [--quiet] [DSN]`** (extended) — retention is now **the `BACKUP_KEEP` (default
  14) newest `soc-*.dump` by mtime**, pruned only after a dump succeeded; `latest.dump` does not match
  the pattern and is never counted or pruned. `--quiet` prints one summary line per run for the cron
  log. The dump is written to a hidden `.soc-<ts>.dump.partial`, read back with `pg_restore --list`,
  then renamed; `latest.dump` is refreshed through a temp file and `mv`. A failure leaves no file,
  prunes nothing and prints `backup: FAILED <UTC> at <stage> (exit N)`. `BACKUP_KEEP` that is `0`,
  negative, non-numeric or zero-padded is refused (exit 2) before anything is dumped.
- **Both scripts use the PostgreSQL client of the server's own major version** when it is installed
  (`/usr/lib/postgresql/<major>/bin`), else `PATH`'s, with a warning. See Deviations 3 for the
  measurements that forced this.
- **`conf/soc-backup.cron`** (new) — commented; `MAILTO=""`; one job line:
  `0 2 * * * { cd /project/project/AI_Support_SOC_1_2 && set -a && . ./.env && set +a && /bin/bash /project/project/AI_Support_SOC_1_2/scripts/backup.sh --quiet; } >> "$HOME/soc-backup.log" 2>&1`.

## 3. Deviations

1. **Acceptance 3 was run with `DATABASE_URL="$TDB"` in front.** DEC-128 item 3 makes `restore.sh`
   read `DATABASE_URL` from the environment only. With it unset the live database is unknown, so the
   script fails closed (exit 2, message above) rather than assume "no live database". The carded
   line was written before the amendment; in the drill the caller sources `.env` first.
2. **`--force` is allowed only on a name ending in `_test`.** It is the one destructive path
   (drop + recreate), and it carries the same rail `conftest.py` puts on every database it drops.
   Without it, a caller whose `DATABASE_URL` names a *test* database could `--into <live name>
   --force` and drop the live database on the same server. Unforced restores into an absent or empty
   database of any (non-system) name are unchanged. `restore.sh` also protects the name in
   `DATABASE_URL_OWNER`, not only `DATABASE_URL`, and refuses non-URI DSNs (fail closed).
3. **Both scripts pick the client binaries of the server's major version** (not in the card; forced
   by measurement on ATTT-M1, where `PATH` = `/usr/bin` wrappers → 18.6 and the server is 16.15):
   - `pg_dump` 18 writes archive **1.16**; `pg_restore` 16 answers
     `pg_restore: error: unsupported version (1.16) in file header`. The nightly job refreshes
     `backups/latest.dump`, which `db/init/02-restore.sh` restores **with the container's pg_restore 16**
     on a fresh volume, so a `PATH` `pg_dump` would have silently replaced a restorable file with an
     unrestorable one every night.
   - `pg_restore` 18 into the 16 server, `--no-owner --exit-on-error`, fails at the first statement
     for **both** a 1.15 and a 1.16 archive:
     `ERROR: unrecognized configuration parameter "transaction_timeout"` / `Command was: SET transaction_timeout = 0;`
     — so with the card's exact flags and `PATH`'s binary, the drill would restore nothing.
   - `/usr/lib/postgresql/16/bin/{pg_dump,pg_restore}` are installed on this host; with them the
     archive is 1.15 and the restore gives `schema_migrations` 17 and 7 triggers.
4. **`backup.sh` beyond "retention + `--quiet`"**: `--quiet` prints **one line per run, not
   silence** (with `MAILTO=""` a silent success and a job that never ran look the same in the log;
   the file stays the proof); the dump is atomic and read back before it counts; a `FAILED` line on
   any failure; `BACKUP_KEEP` validated (empty → the default 14). The old opt-in age prune is gone.
5. **Tests: 18 of the 23 need no server and carry no `db` mark**, so they also run in `make test` —
   the cron file's no-docker check and the live-database guard then run in the everyday suite. The
   5 that need a server are `db`-marked. Design note 4's (a)–(e) are all present; the extras are
   listed in Built.
6. **Red step (b) was demonstrated on a scratch copy of the worktree** (`tar` of the tree without
   `.git`, `backups/` and caches, the guard loop deleted there, the test file run there), not by
   editing the real `restore.sh`: the project's standing note is that the harness refuses edits that
   weaken a security check even for a revert-in-five-minutes demonstration, and it also means the
   real guard was never absent, even transiently. (a) and (c) edited the real files, with sha256
   before/after shown.
7. **Derived test database names** follow `test_auth.py`'s convention, `<session db>_<role>_test`
   (`soc_p5t12_test_restore_test`, `…_source_test`, `…_nonempty_test`), so the test never collides
   with the card's manual `soc_p5t12_restore_test`.
8. `P5-tasks.md` and this card: no disagreement found beyond what the DEC-128 banner itself amends.
