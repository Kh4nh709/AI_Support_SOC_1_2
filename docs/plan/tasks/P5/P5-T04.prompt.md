  **2 · `llm/investigate.py` is pure.** `build(dossier, *, nonce, cfg) -> tuple[str, str]` (system, user) and

  **3 · `tier2/investigate.py` — the job, and the four things that make it correct.**
  `run_investigate_job(conn, job, *, adapter=None)`; `job.subject_id` is the `case_id`.
  (a) **A new nonce per attempt** (§6.5) — `security.wrap.new_nonce()` inside the handler, never cached, so a
  retry cannot be steered by a boundary the previous attempt leaked.
  (b) **G7 is absolute:** this job writes `llm_runs`, `cases.last_analyzed_at` and nothing else. It does
  **not** touch `alerts.status` or `cases.status`; `grep -c "UPDATE alerts\|UPDATE cases SET status" backend/app/tier2/investigate.py` → `0` is acceptance 6.
  (c) **The `llm_runs` row**: `pipeline='investigate'`, `subject_type='case'`, `subject_id=case_id`,
  `role='investigator'`, the **verbatim** prompt in `system_prompt`/`user_message`, `result`,
  `evidence_check`, `citation_warnings`, `injection_findings`, `input_tokens`, `output_tokens`,
  `latency_ms`, `cost_usd`, `stopped_by`, `model_id`, `prompt_version`, and the P7-2 snapshot
  (`alert_count`, `total_occurrences`, `last_seen_at` from `Dossier.snapshot`) inside `result`'s envelope or
  `agent_trace` — **your choice, stated in the report**, but it must be readable back for P8.
  (d) **Errors**: `LLMTimeout` → transient (the job retries with backoff `[10, 60, 300]`);
  `LLMBudgetExceeded` and `LLMPermanent` → permanent; both paths still write an `llm_runs` row with
  `result IS NULL` and `stopped_by` set, because a run that was attempted and failed is evidence (①'s error
  table, `tier1/triage.py`).

  **4 · The evidence check — the point of ②, and the only place a model's claim is contradicted by data.**
  For each `evidence[i]`: `alert_id` must be in the case **or be a duplicate of one of its heads** (DEC-036's
  query shape: `alert_id IN (SELECT alert_id FROM case_alerts WHERE case_id = %s) OR duplicate_of IN (that
  subquery)`), **and** `quote` must be a **substring** of that alert's `raw_log` or `description` after
  `security.wrap.normalise` on both sides (NFKC — otherwise a look-alike Unicode quote fails for the wrong
  reason). Write the outcome per item into `evidence_check` as
  `{verified: [...], rejected: [{index, alert_id, reason: "not_in_case" | "quote_not_found"}]}`.
  **Zero verified items → `suggested_conclusion := need_more_data`**, rewritten in the stored `result` with
  the original recorded in `evidence_check.original_conclusion` — the model's answer is not deleted, it is
  overruled and the overrule is auditable. A rejected id also appends to `citation_warnings`
  (`docs/phase-7-tier2.md:277`: *"Model bịa ra id là chuyện có thật, và một bằng chứng bịa nguy hiểm hơn
  không có bằng chứng"*). **One more rule from the same page:** run `app.security.detector` over the dossier;
  a **high**-severity injection finding forbids `suggested_conclusion = 'false_positive'` — force
  `need_more_data` and record it in `evidence_check.forced_by`.

  **5 · `run_id` without a schema change — the mechanism, because the obvious one does not work.**
  `llm_runs` is append-only (migration 017 REVOKEs `UPDATE`/`DELETE` from `app_rw` and a trigger enforces it),
  so the route cannot insert a placeholder row and let the job fill it. And `jobs` has no payload column, so
  the route cannot hand the job a pre-generated id. **Derive it:** `RUN_NAMESPACE = uuid.UUID(<a constant in
  this module>)` and `run_id_for_job(job_id) = uuid5(RUN_NAMESPACE, f"investigate:{job_id}")`. `enqueue()`
  returns the `job_id`, so the route computes the same id it returns in the 202 and the job computes the same
  id when it writes the row. Deterministic, collision-free per job, no migration, and the single-flight index
  on `(job_type, subject_id)` keeps doing its job. State this in the report — it is the card's least obvious
  decision.

  **6 · The two routes (`web/routers/tier2_runs.py`, discovered — `git diff main -- backend/app/web/main.py` must be empty).**
