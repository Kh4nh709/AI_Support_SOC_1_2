- **Design notes:**

  **1 · `submit()` is a guard, a call and a translation — it is not a second implementation.**
  `submit(conn, case_id, actor, *, conclusion, reason)`: validate `conclusion ∈ {concluded_fp,
  concluded_policy_violation, confirmed_incident}` (anything else → `ValueError` → **422**); refuse an empty
  `reason` before any SQL (**422**); `SET LOCAL statement_timeout = '5s'` **first**; then
  `domain.transitions.conclude_case(...)`. Translate: `StaleState` → **409** with a body naming the case's
  current status and, when it is already concluded, who concluded it and when (read **inside** the
  transaction before raising, the way `tier1/decide.py`'s `DecisionConflict` carries its numbers — the
  rollback that follows is correct, nothing was meant to persist); `IllegalTransition` → **500**; a
  statement-timeout error → **503** with the whole transaction rolled back
  (`docs/phase-7-tier2.md` §Xử lý lỗi). **G2 holds because you never write a status yourself:**
  `grep -cE "UPDATE (alerts|cases) SET" backend/app/tier2/conclude.py` → `0` is acceptance 5.

  **2 · Notes.** `add_note(conn, case_id, author_id, body) -> note_id` — reject an empty or whitespace-only
  body (**422**), cap the body at a stated length, `INSERT INTO case_notes (case_id, author_id, body)` and let
  `note_id` come from the IDENTITY column (**do not supply it** — migration 015 note (4)).
  `list_notes(conn, case_id)` ordered `created_at, note_id` (the second key makes the order total, which is
  what P5-T03's determinism depends on when it reads notes into block 8). **No audit event** — `case.note_added`
  does not exist in the 27 names and adding it is a frozen-contract change; the note itself is the record, in
  an append-only-by-convention table. Say this in the report so it reads as a decision, not an omission.

  **3 · The four routes (`web/routers/tier2.py`, discovered).** All `require_role("tier2", "admin")`.
  `GET /api/tier2/cases` — OFFSET-paged, `investigating` first then by `created_at DESC, case_id` (a total
  order), each row carrying `case_id, title, status, severity, created_at, last_analyzed_at`, the cluster
  count from `case_alerts` and the **total `occurrence_count` including duplicates** (DEC-036's query shape,
  because the head count alone understates a case by orders of magnitude on this corpus — 99,920 of 100,526
  alerts are duplicates).
  `GET /api/tier2/cases/{case_id}` — the case, its heads with an **explicit column list** (G10), the notes,
  and `last_analyzed_at`; **404** when absent.
  `POST /api/tier2/cases/{case_id}/notes` — **201** with the note.
  `POST /api/tier2/cases/{case_id}/conclude` — **200** on success, and §1's codes otherwise.
  The ② result is **not** joined here — it is `GET /api/tier2/runs/{run_id}`'s (P5-T04) and this card must
  work with that card absent.

  **4 · Tests.** `test_conclude.py` (`db`): each of the three conclusions maps to the right `alerts.status`
  (`closed_fp`, `closed_benign`, `closed_confirmed`); **the fan-out reaches duplicates** — build a case with
  2 heads and 5 duplicates each and assert all 12 rows moved and `sealed_at` is set (this is
  `docs/phase-7-tier2.md` detail 1: *"Thiếu vế này, hàng nghìn bản sao ở lại trạng thái cũ"*); concluding a
  case that is not `investigating` → 409 with the current status in the body; empty `reason` → 422;
  an unknown `conclusion` → 422. `test_tier2_api.py` (`db`): the four routes, their codes, `require_role`
  refusing a `tier1` session with a **403 and an `authz.denied` row that survives the raise**, the list page's
  ordering and its duplicate-inclusive count, and a 404 for a case that does not exist.
  **Red steps (DEC-025):** (a) drop the `OR duplicate_of IN (…)` half of the count in `GET /cases` → the
  duplicate-inclusive count test goes red while the head count stays right, which is exactly the failure mode
  DEC-036 exists for; (b) remove the `SET LOCAL statement_timeout` → add a test that asserts it is set (query
  `current_setting('statement_timeout')` inside the route's transaction) and watch it go red; (c) supply
  `note_id` explicitly on the INSERT → the IDENTITY test goes red on the second note.
