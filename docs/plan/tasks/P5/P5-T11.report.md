## 1 · Built

- `backend/app/infra/health.py` — `check(conn, cfg, *, clock=None, backups_dir=None) -> HealthReport`:
  runs the ten §3.9 checks, writes one `system_health` row, and calls `notify.send` only on a state
  change plus the daily 08:05 summary. `CheckResult`/`HealthReport` dataclasses. Ten private check
  functions in §3.9's order (`_check_heartbeat`, `_check_intake_backlog`, `_check_job_backlog`,
  `_check_llm_null_ratio`, `_check_triage_unavailable`, `_check_monthly_cost`, `_check_backup_age`,
  `_check_inventory_empty`, `_check_digest_unreviewed`, `_check_disk_free`), each `{name, ok, value,
  threshold, detail}`. `_insert_report` catches a `checked_at` unique violation on a savepoint
  (`conn.transaction()`) and skips the tick. `_write_alarm_event` writes `health.alarm` with raw SQL.
  `_is_daily_summary_due` is the pure boundary function for the 08:05 rule.
- `backend/app/infra/notify.py` — `send(level, text, *, cfg=None, client_factory=None) -> bool`: Telegram
  when both `NOTIFY_TELEGRAM_BOT_TOKEN`/`NOTIFY_TELEGRAM_CHAT_ID` are set (one `httpx.post`), else the
  log sink (one JSON line + a counter). One `try/except Exception` wraps the whole dispatch — the "never
  raises" contract in one place. `counters()` returns a copy of the module's send counters.
- `backend/app/web/handlers/health.py` — the `health` handler module: `JOB_TYPE = "health"`,
  `handle(conn, job, *, cfg=None) -> Reschedule` (calls `infra.health.check`, reschedules itself every
  300 s). No `STATEMENT_TIMEOUT` (P5-tasks.md §5: only `investigate` declares one).
- `backend/app/web/routers/health.py` — `GET /health`: loopback (`127.0.0.1`/`::1`) → 200 with the
  newest `system_health` row unconditionally; everyone else → `current_user` (401 caught and re-raised
  as 403) then `require_role("admin")` (its own 403 on a wrong role) → 200 only for an admin session.
- `backend/tests/test_health.py` — 38 tests: the ten checks each fire/pass (24 cases across ten checks,
  some with an extra edge case), the state-change rule (first-run baseline, alarm→no-resend→recovery,
  previous-state-from-the-table), the daily-summary boundary (pure + wired), the `checked_at` collision,
  the exit-gate item, `health ∈ JOB_TYPES`, the handler module, and `GET /health`'s four session cases.
- `backend/tests/test_notify.py` — 11 pure tests: the Telegram arm's URL/payload, an httpx exception, a
  4xx, the token never in captured output, the log sink for all three empty-key combinations, `send`
  surviving a broken `config.load()`, and the counters.
- `backend/tests/test_worker_handlers.py` — one existing test extended (see §3): the discovered handler
  set now asserts four names, `health` included.

- **`infra.health.check()` gained two keyword-only test seams beyond the card's literal
  `check(conn, cfg) -> HealthReport`**: `clock: Callable[[Connection], datetime] | None` and
  `backups_dir: Path | None`. Both default to production behaviour (`_db_now` reads the database's own
  `now()`; `backups_dir` defaults to `Path("backups")`). Needed because (a) Postgres's `now()` cannot be
  frozen from a test without a server-side extension, and design note 7 explicitly requires "Check 9
  before and after 17:00" and "the 08:05 summary fires once" — both deterministic only with an injectable
  clock; (b) a test must never write into the tracked `backups/` directory. The production call form
  `check(conn, cfg)` is unchanged and is what the handler and `GET /health` both use.
- **`notify.send()` gained keyword-only `cfg`/`client_factory`** beyond the card's literal
  `send(level, text) -> bool`. `cfg` lets `infra.health.check` (and tests) pass a `Config` without a real
  `.env` read (DEC-047); `client_factory` is the fake-transport seam ("no real network sends"). The
  two-positional-argument call form `notify.send(level, text)` — acceptance 4's exact call — is
  unchanged and behaves identically (reads `config.load()` itself).
- **`GET /health`'s "no session" case is normalized to 403**, not the 401 `current_user` gives every
  other route. Design note 6 and its own test list both say "a non-loopback client without a session →
  403" — implemented by catching `current_user`'s `HTTPException(401)` and re-raising `403` at this one
  route only; `web/deps.py` itself is untouched and every other route's 401 behaviour is unchanged.
- **The `system_health` INSERT binds `checked_at` as a parameter** (from one `SELECT now()` at the top of
  `check()`) rather than the literal `now()` design note 3 spells in the INSERT text. Functionally
  identical — both are the database's own clock, and Postgres's `now()` is stable for the whole
  transaction so the two forms return the same value either way — but explicit rather than resting on
  that transactional-stability property implicitly, and it is the same value `_is_daily_summary_due` and
  check 9 need for their local-time decisions.

## 4 · Open questions / follow-ups

- **The three consequences of `infra → nothing` (design note 1), named explicitly:**
  (a) check 9 (`digest_unreviewed`) cannot call `tier1.digest.unreviewed_count` and is three lines of raw
  SQL in `_check_digest_unreviewed` instead — `alerts` with `status = 'auto_closed'` and `closed_at` in
  yesterday's local window, `LEFT JOIN autoclose_reviews`, count the misses — which is also why this card
  does not depend on P5-T08;
  (b) check 6 (`monthly_cost`) cannot call `audit.llm_runs.month_spend_usd` and sums `llm_runs.cost_usd`
  for the current month itself, in `_check_monthly_cost`;
  (c) `health.alarm` is written with raw SQL in `_write_alarm_event`, exactly as `infra/jobs.py:152`
  writes `job.exhausted`, never through `app.audit.events.write_event`.
- **`system_health.checked_at` as the primary key (migration 015 note 5) — a P8 limitation.** Two health
  ticks landing in the same microsecond collide on insert; `_insert_report` catches the `UniqueViolation`
  on a savepoint, logs it, and skips that tick's row and notification rather than retrying with a nudged
  timestamp. `test_checked_at_collision_is_caught_and_this_tick_is_skipped` proves the caller's
  transaction stays usable afterward. Fixing the collision itself (a surrogate key) is a §6.1 schema
  change, out of this card's scope (rule 4's stop condition).
- **`request.client.host` limitation (design note 6) — corrected in review round 1, S5.** `make run-app`
  binds `127.0.0.1:8000`, where the exemption is correct as originally written. Under
  `docker-compose.yml` the app container binds `0.0.0.0:8000` and publishes `8000:8000`; a request
  arriving via that published port is proxied by Docker's own `docker-proxy`, which is the peer this
  route then sees — never `127.0.0.1`. The exemption still correctly never applies to that request (it
  genuinely is not the app's own host loopback), but as a consequence it also never applies to an
  operator polling from the Docker host the way `make run-app` allowed — **only a request made *inside*
  the app container is loopback under compose**:
  `docker compose exec -T app python -c "import urllib.request as u; print(u.urlopen('http://127.0.0.1:8000/health').read().decode())"`
  (named here for P5-T13's runbook, which owns writing the operator-facing table). §5 of this report and
  `web/routers/health.py`'s own docstring are both corrected to say this.
- **Seeding — resolved in review round 1.** `web/worker.py:main()` now also runs
  `enqueue(conn, "health", "system")` (idempotent through the same partial unique index `pull`'s own seed
  uses), right after the `pull` seed, so a worker restart re-arms a dead `health` chain exactly as it
  already did for `pull`. The Director's ruling lifted acceptance 3's "no diff in `worker.py`" for this
  one line; `test_main_passes_timeouts_to_run_forever` (`test_worker_handlers.py`) now captures and
  asserts the enqueue calls, `[("pull", "indexer"), ("health", "system")]`.

### Blocker

**B1 — a Telegram send slower than 10 s killed the worker.** The Reviewer's probe traced
`infra.worker._run_claimed_job`: `infra/db.py`'s `transaction()` sets
`idle_in_transaction_session_timeout = '10s'` for every job; `notify.send`'s `httpx` call could sit the
connection idle past that ceiling, and Postgres killed the session mid-job — the next statement raised
`OperationalError`, which escaped and took the worker down; the row never committed, so the 300 s reclaim
re-triggered the same failure forever.
- **Fix:** `web/handlers/health.py` gained `_raise_idle_timeout(conn, cfg)` — the handler's first
  statement, `SET LOCAL idle_in_transaction_session_timeout = '<JOB_LOCK_TIMEOUT_S>s'` — mirroring
  `tier1/triage.py`'s function of the same name exactly. `infra/notify.py`'s client timeout is now
  `httpx.Timeout(10.0, connect=5.0)` (was a bare `10.0`), a second, independent bound.
- **Test:** `test_slow_notify_does_not_kill_the_connection_b1` (scratch DB `sdb`) — a wrapper compresses
  `idle_in_transaction_session_timeout` to `1s` (mimicking the worker's own wrapping transaction, just
  faster), `notify.send` is faked to `time.sleep(1.5)`, then the real `handle()` runs. Asserts `handle()`
  does not raise, the following `commit()` succeeds, and exactly one `system_health` row exists.
- **Red step:** removed the `_raise_idle_timeout` call → the test failed with
  `psycopg.errors.IdleInTransactionSessionTimeout: terminating connection due to idle-in-transaction
  timeout` — the exact mechanism the Reviewer's probe found. Restored; test passes again.
