## Correctness, read from the code

- **`restore.sh` refuses before it connects**, in this order:
  - a malformed or system target name;
  - an unset `DATABASE_URL` (the live name would be unknown);
  - a target equal to the database `DATABASE_URL` **or** `DATABASE_URL_OWNER` names, with both names
    printed and exit 2;
  - `--force` on a name not ending in `_test`;
  - a missing or empty dump.

  An existing target must be empty (relations + functions + own schemas = 0) unless `--force`. The target
  name is regex-validated before it is interpolated into SQL. Acceptance 4 ran the same-database refusal
  three times on a non-empty stand-in, `--force` included, with the database OID unchanged.
- **Version pinning is the important finding.** On ATTT-M1, PATH has PostgreSQL 18 tools against a
  16 server:
  - `pg_dump` 18 writes archive format 1.16, which the container's `pg_restore` 16 rejects;
  - `pg_restore` 18 into 16 fails on `SET transaction_timeout`.

  Both scripts now take the tools of the server's own major version (`/usr/lib/postgresql/<major>/bin`),
  and warn when they are absent.
- **`backup.sh`** keeps a count: the `BACKUP_KEEP` (default 14) newest `soc-*.dump` files, and prunes
  only after a dump has succeeded. `latest.dump` is never counted and never pruned. A dump is written
  under `.partial`, read back with `pg_restore --list`, then renamed. `RETENTION_DAYS` (the §6.3
  data-retention key, 365) no longer drives pruning. The report gives the reasoning.
- **The schedule** is a user crontab line (not a compose cron, DEC-018/021) that logs stdout and stderr
  with `MAILTO=""`. The report gives the reason a systemd user timer was rejected (`Linger=no`). **It is
  not armed.**
- The test file redacts every DSN in fixture reprs, so a failing test cannot print a password (the
  DEC-122 pattern).
