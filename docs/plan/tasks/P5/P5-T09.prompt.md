- **Design notes:**

  **1 · Size it for what this system actually produces.** Measured 23/09: **zero** auto-closed alerts,
  **zero** auto-close rules, and — because 523 of 606 heads are absent from the inventory and G8′ hard-blocks
  them — **at most 77 heads in the whole database could ever auto-close**. So the page is a **single scrollable
  list with no pager**, sized for tens of rows a day, and the empty state is the normal state until the Owner
  adds `Windows_Endpoint` to `conf/inventory.yaml` and creates a rule. **The empty state must say which of
  those two is missing** — *"chưa có rule tự đóng nào"* versus *"không có cụm nào bị tự đóng trong ngày"* —
  because on this deployment the reviewer's first question will be *why is this page empty*, and a blank page
  that cannot answer it is a page that gets mistrusted. `prompts/P5.md:31`'s *"auto-close can fire only on
  agent 001 (`user1-IA1803`)"* is stale: that agent stopped reporting (DEC-106).

  **2 · One click, one row, no page reload.** Each row: the cluster (rule, description, severity, category,
  agent, `occurrence_count`, the time span), ①'s verdict with a visible **disagreement marker** when the model
  would not have closed it, and three buttons `Đúng | Sai | Không chắc` posting to
  `POST /admin/digest/{alert_id}/review` with `hx-target` on the row and `hx-swap="outerHTML"`. The response
  is the same row re-rendered in its reviewed state — greyed, verdict shown, buttons gone — plus a flash
  through `_flash.html`. **`Sai` reopens the alert**, and the re-rendered row says so in words
  (*"đã mở lại về hàng đợi Tier 1"*), because a button that silently changes an alert's status is the kind of
  thing an operator learns to distrust.

  **3 · Role, and the link.** `require_role("admin")` on both routes — the digest is the admin's review loop
  (`prompts/P5.md:30`). `base.html` already carries an `admin` nav section (P4-T04); your page is reachable
  from it, and if the link is not there **say so in the report** rather than editing `base.html`, which is
  P4-T04's file.

  **4 · A 409 is a normal outcome here, not an error.** Two admins reviewing the same row, or an alert that
  left `auto_closed` between the page render and the click, must render as a flash naming what happened and
  re-render the row from the database — never a stack trace and never a silent no-op. P5-T08's `review`
  surfaces that case; your job is to show it.

  **5 · Tests (`backend/tests/test_pages_digest.py`, `db`).** `TestClient` with `get_conn` overridden and a
  real admin cookie. The page lists a day's clusters with disagreements first; each of the three buttons
  produces its effect through the page (`Sai` leaves the alert `queued_tier1` **and** the row says so); a
  second click on a reviewed row renders the conflict flash; a `tier1` session is refused with an
  `authz.denied` row that **survives the raise**; the two empty states render their two different sentences;
  `raw_log`-derived text is escaped and `|safe` appears nowhere. **Red steps (DEC-025):** (a) point the
  review POST at the wrong alert id (a constant) → the per-row test goes red while a "page renders" test
  stays green; (b) render the reviewed row without re-reading the database → the conflict test goes red;
  (c) drop the disagreement marker → the marker test goes red.
