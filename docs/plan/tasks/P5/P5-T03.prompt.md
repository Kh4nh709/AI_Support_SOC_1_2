- **Design notes:**

  **1 · The nine blocks, in this order, and the block boundary is where trust ends.** (1) **case header as
  facts** — title, `severity`, cluster count, total `occurrence_count`, the time span, who escalated and why;
  every value a closed-set enum, an int or an ISO datetime, rendered through `llm.builder.fact()` so it can
  stand **outside** a wrapper (G6′). (2) **every cluster**: the head alert in full with `raw_log` up to
  **8 KB**, its `occurrence_count` and the duplicates' time span. (3) **timeline**, ≤ **300** lines, one event
  per line, `time · rule · host · user`. (4) **entities** (design note 2). (5) **±2 h correlation per alert**
  as structured rows, clusters **not already in the case** (`domain.correlation.rows_query`). (6) **Tier-1
  decisions** on the case's alerts, read from `audit_events` (`alert.acknowledged`, `tier1.decided`,
  `tier1.escalated`, `alert.reopened`), oldest first. (7) **playbooks** for every `category` present in the
  case, through `kb.lookup.get_playbook` — a missing playbook is `SENTENCE_NO_PLAYBOOK`, never silence.
  (8) **analyst notes and the previous ② result** (`case_notes`, and the newest `llm_runs` row with
  `pipeline='investigate' AND subject_id = case_id`). (9) the out-of-block sentence, **verbatim**:
  *"Không có threat intel ngoài, dữ liệu gói tin, EDR. Thiếu thì trả need_more_data, không suy đoán."*
  **Blocks 2, 3, 5, 7 and 8 are free text and every one of them goes inside `security.wrap.untrusted_block`
  with the session nonce.** Blocks 8's two halves are the ones `docs/phase-7-tier2.md:250` warns are easiest
  to forget: an analyst note can quote a log verbatim, and a previous ② result that was injected carries the
  attacker's instructions into the next run — *injection accumulating across rounds*. There is a test for
  each.

  **2 · Entity extraction — the regexes, the cap, and one SQL per type.** From the case's `raw_log`s and
  `description`s: IPv4 and IPv6, `md5`/`sha1`/`sha256` (32/40/64 hex, word-bounded), domains validated against
  a **committed IANA TLD list** (a module-level frozenset in this file — not a network fetch, not a new data
  file). Usernames come from `data.dstuser` / `data.srcuser` in `raw_payload`, hosts from `agent.name` and
  `predecoder.hostname` — **from the structured columns, not from a regex over free text**. Each entity gets
  its inventory lookup (`lookup_asset`, `lookup_identity`, `lookup_ioc`) and a **7-day history: alert counts
  by category**, one SQL per entity *type* with the entity list as a parameter (`= ANY(%s)`), never one query
  per entity — `prompts/P5.md:53`. **Cap 50 entities total**, ordered deterministically (by type, then by
  descending 7-day count, then by the entity string) so the cap cuts the same entities every time; the cut is
  recorded like any other truncation. An entity that is absent from the inventory renders
  `llm.builder.SENTENCE_ABSENT` — *absence is not evidence of harmlessness* — never an empty field.

  **3 · Determinism is the acceptance, so build for it.** Nothing in this module reads `datetime.now()`,
  `random`, `uuid4`, a `set` iteration order or a dict whose insertion order depends on a query without
  `ORDER BY`. **Every** query is explicitly ordered to a total order (add the primary key as the last sort
  key), every read of `alerts` uses an **explicit column list** (G10), and the only non-deterministic input is
  the `nonce` parameter — which is why it is a parameter and not generated inside. The test builds twice with
  the same nonce and asserts byte equality of the rendered text, then twice with different nonces and asserts
  the two differ **only** where the nonce appears (`security.wrap.strip_nonce` makes that check exact).

  **4 · Budget and truncation, in §7.6's order and not in a different one.** Estimate tokens as `len(text) / 4`
  (the project's crude estimator — `eval/smoke_test.py`; name it in a comment so nobody mistakes it for a
  tokeniser). If the rendered dossier exceeds `cfg.CASE_PROMPT_BUDGET_TOKENS`, cut in exactly this order and
  stop as soon as it fits: **`raw_log` 8 KB → `raw_log` 4 KB → representatives down to 15 clusters → timeline**.
  Each cut appends a structured entry to `Dossier.truncations` (`{step, before, after}`) **and** leaves the
  truncation mark inside the block that lost content — `security.wrap.truncate_block` already returns
  `(text, truncated)`; use it rather than slicing. A dossier that still exceeds the budget after the timeline
  is gone is returned as-is with a final `truncations` entry saying so: **it is not an exception**, because a
  case that large is a real case and the job must still run on it.

  **5 · The snapshot P7-2 requires.** `Dossier.snapshot` = `{alert_count, total_occurrences, last_seen_at}`,
  read in the same transaction as the blocks. P5-T04 writes it into the `llm_runs` row, which is what makes
  two ② runs on the same case comparable when the cluster grew between them — *"Đây là **đúng**, không phải
  lỗi: dữ liệu đã đổi thật. Nhưng phải truy được."*

  **6 · Duplicates, and the one query shape that gets them right.** `case_alerts` holds **heads only**
  (DEC-036). The case's alerts are `SELECT … FROM alerts WHERE alert_id IN (SELECT alert_id FROM case_alerts
  WHERE case_id = %s)`; their duplicates are `… WHERE duplicate_of IN (that same subquery)`. Never
  `JOIN case_alerts USING (alert_id)` expecting duplicates to be in it — `docs/phase-7-tier2.md`'s v1 SQL does
  exactly that and DEC-036 annotated it rather than let it be transcribed.

  **7 · Tests (`backend/tests/test_dossier.py`, `db`-marked where they need rows).** The determinism pair
  (design note 3). A **20-cluster synthetic case** built by the test, with `raw_log`s sized to force every
  truncation step, asserting the steps fire **in order** and the result is within budget — and a control at
  half the budget asserting **no** step fires. Entity extraction on fixtures: each regex family matched and
  each near-miss rejected (31- and 33-hex strings, `999.1.1.1`, a bare `localhost`, a domain whose TLD is not
  in the list). The 50-entity cap cuts deterministically. Every free-text block is inside a nonce-carrying
  wrapper, **including the analyst note and the previous ② result** — and `app.security.linter.lint` returns
  no violation on the rendered dossier (G6′, the invariant this module can be checked against for free).
  A case whose duplicates outnumber its heads renders the duplicates' counts without listing them as clusters.
  **Red steps (DEC-025):** (a) remove `ORDER BY` from the entity query → the determinism test goes red (if it
  does not, the query is returning one row and the test is too small — enlarge it, that is the finding);
  (b) swap the truncation order to cut the timeline first → the ordered-steps test goes red while a
  "within budget" assertion alone would have stayed green, which is why the test asserts the sequence;
  (c) move the previous-② block outside its wrapper → the linter test goes red.
