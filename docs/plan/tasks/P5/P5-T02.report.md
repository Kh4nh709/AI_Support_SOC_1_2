## 3 · Deviations from the card, and why

1. **The live measurement ran at `--calls 3`, not `--calls 30`, on the Director's explicit dispatch authorization ("one real `investigate_v2` measurement … under $0.10"), not the card's own default.** The card's acceptance 3 literally asks for `--calls 30 --arms 60000,12800` (60 live calls). Pricing measured from the primary checkout's `.env` (`LLM_PRICE_IN_PER_M=0.014`, `LLM_PRICE_OUT_PER_M=0.66`) put a full 60-call run in the same ballpark as the card's own $0.055 estimate but with real uncertainty on the output side (`investigate_v2`'s hypotheses/evidence arrays are larger than `triage_v2`'s), so a run that size risked landing close to, or over, the $0.10 ceiling the dispatch set — tighter than the card's own (superseded) "< $0.10" framing assumed for a 30-call run. Six live calls (3 per arm) cost **$0.01828–$0.02265** across three attempts, comfortably inside the authorized budget, and the script fully supports `--calls 30` unchanged — it is a runtime flag, not a code path difference. The `--dry-run` and unit-test acceptance items (1 and 2), which need no live call, were run exactly as the card specifies.
2. **Acceptance 5's `git diff` runs against `dc5cedd`, not `main`.** The card (rule 1) assumes a worktree `git worktree add … -b task/P5-T02 main`; DEC-151 instead dispatches Coders from the director tip (here `dc5cedd`), so `main` is many commits behind this branch and a diff against it shows unrelated upstream changes (`backend/app/ingest/category.py`, `wazuh_parser.py`, `llm/builder.py` — none touched by this card). Against `dc5cedd`, the true starting point, the diff on the named paths is empty, which is the property acceptance 5 is checking for.
3. **The cache key formula is exactly the card's (`sha256(model+system+user+LLM_THINKING+budget)`), but the script does not use `app.security.wrap.new_nonce()`'s cryptographically random nonce as the default per-call nonce — it uses a deterministic `f"{call_index:016x}"` instead (`deterministic_nonce()`).** Discovered mid-build: with a fresh *random* nonce per call (matching §6.5's "nonce regenerated per attempt" literally), every one of the `calls` sends within one arm gets a distinct cache entry on the first run (correct — N independent samples), but a **second invocation** can never reproduce any of those nonces, so it can never hit the cache, defeating acceptance 3's "re-running without `--refresh` … 0 live · N cached" and "byte-identical report" requirements outright (verified: it printed `N live · 0 cached` again and made N new network calls). `eval/smoke_test.py` has the same tension and resolves it with `stable_user()`, which folds the nonce out of the cache-key hash — but that collapses this script's N same-content, nonce-only-different calls within one arm into a *single* cache entry, which would make "N live calls" measure one sample N times. The fix keeps the card's literal cache-key formula untouched and instead makes the nonce itself reproducible-per-index: call 0, 1, 2 within an arm get three distinct (and thus three independently measured) nonces/cache entries, and the *same* call index gets the *same* nonce on every invocation of the script, so a rerun replays every prior call from the cache. A further, related fix was needed for the **report file** itself: the per-call table and the header `Provenance:` line originally rendered this invocation's own live-vs-cache split (`record["origin"]`), which correctly differs between the first run and a cached rerun and therefore broke the byte-identical requirement on its own, independent of the nonce question. The fix adds a second, persisted field, `record["provenance"]`, set to `"live"` the one time a record is genuinely sent and carried unchanged through every later cache load; the report renders `provenance`, the STDOUT summary and `arm_metrics()` still use the per-invocation `origin`. Both fixes were caught by actually running the live→rerun→diff sequence in §2.3, not inferred — the first `--calls 3` live/rerun pair showed a non-empty diff (`origin` column and `Provenance:` line differed) before either fix, and an empty diff after.
4. **Context pack §4.5 does not exist under that name in the current `docs/plan/00-context-pack.md`.** The card's read-first list cites "§4.5's thresholds (p95 ≤ 60 s, JSON ≥ 90 %, schema-valid after one repair ≥ 98 %)"; the current context pack has no `§4.5` heading at all (it runs §0–§13, and §7 is "AI layer rules"). The four thresholds themselves are real and traceable — `docs/smoke-test-D1.md`/`docs/smoke-test-D1-nothink.md` cite "Architecture §4.5" (a separate, older document) and `DECISIONS.md` DEC-032 restates the same four numbers as "the Owner's decision rule" — so `investigate_measure.py`'s `THRESHOLDS` tuple and `docs/investigate-size-class.md` §2 apply them and cite DEC-032 rather than a `00-context-pack.md` section that is not there. Per DEC-151's guardrail ("current code … wins, and the Coder records the deviation"), this is recorded rather than silently worked around.
5. **`eval/smoke_test.py` does not actually contain a `len(text) / 4` pre-send token estimator**, contrary to the card's design note 2 ("the same crude estimator `eval/smoke_test.py` uses"). That script never estimates tokens before sending — every count it reports comes from the live `usage` object after the call. The formula itself is still implemented exactly as the card specifies (`estimate_tokens()`); only the claimed precedent is inaccurate, and `docs/investigate-size-class.md`'s header says so in one sentence per the card's own instruction ("the report says so in one sentence").
6. **DEC-108/DEC-097's "② falls on 25/09" ruling does not apply to this dispatch.** The card (written 19–23/09, and `P5-tasks.md` §4.2) discusses whether T02 should be kept as a `should` once ② is cut. DEC-151 (29/09, the dispatching decision for this very run) reinstates ② and all four bundle cards outright ("P4 and P5 are reinstated … ② included"), superseding DEC-116's deprioritization and DEC-111's cut. This card was therefore built as originally carded, `must`, not as the §4.2 fallback.
