## 3 · Deviations

1. **`llm_runs` is read directly**, not through `GET /api/tier2/runs/{id}`. That endpoint returns
   neither `agent_trace` (the P7-2 snapshot) nor `created_at`, and does not check that the run belongs
   to a case; the read here always filters `subject_id = <this case>`, so another case's run is never
   shown (`test_a_run_of_another_case_is_never_shown`).
2. **Shell mode.** The card describes a page that renders the block itself; `case.html` (not this
   card's to edit) passes no investigation data, so `_investigation.html` renders a shell that loads the
   real state on page load. The card's `test_case_page_renders_the_partial_when_present` therefore asserts
   the shell (`hx-trigger="load"`, one `id="investigation"`), and
   `test_the_shell_is_replaced_by_the_state_it_loads` asserts the loaded state carries no load trigger.
3. **The quota answers 200**, not 429 (Director's ruling): `case.html`'s `beforeSwap` listener swaps only
   409, 422 and 503, and no JS may be added. Already-running and concluded are 409, as the API.
4. **No out-of-band flash.** Every message (running conflict, quota, concluded) is inside the swapped
   `<section>`; `case.html` has no `#flash`, so an OOB `_flash.html` would be dropped by htmx 2.0.4.
   `test_a_refusal_is_a_bare_swappable_section_never_an_oob_flash` pins it.
5. **A plain (non-htmx) form POST redirects 303 to the case page**, as `cases_pages.add_note_page` does; a
   refused non-htmx POST still returns the fragment with the refusal status (the fragment is the message).
6. **`?run_id=` is a hint, not a lookup key**: it only turns an otherwise `idle` state into `failed`
   (the API's 404-after-202); a real running or finished state always wins, and a malformed value is ignored.
7. **`citation_warnings` is not displayed** — the per-item reason under each unverified evidence item says

8. **The button label is always "Phân tích"** (also after a result), as dispatched.

### S2 · a job stuck `pending` or `running` polled forever

- **Rule** (`case_analyze_pages.py`, `STALL_TIMEOUT_FACTOR = 2`): the case's newest `investigate` job,
  with no final `llm_runs` row behind it, is **stalled** when
  - `pending` and `now() - scheduled_at > 2 × JOB_LOCK_TIMEOUT_S`, or
  - `running` and `now() - locked_at > 2 × JOB_LOCK_TIMEOUT_S`.

  `scheduled_at` and not `created_at`, because the worker's backoff writes a retry's due time there.
  The clock is the database's `now()`; the age is computed in SQL (`extract(epoch FROM (now() - …))`)
  and only compared with the bound in Python; the bound is the existing `JOB_LOCK_TIMEOUT_S` (default
  300, so 600 s). No new config key and no schema change. Each poll re-reads it (stateless).
- **What the page shows**: `data-state="stalled"`, the section has **no** `hx-trigger` (polling stops)
  and **no** *Phân tích* button. It shows `Chưa được xử lý sau N phút — kiểm tra worker` (N = whole
  minutes actually elapsed, floored) in a warning flash, plus a *Kiểm tra lại* button
  (`data-field="analysis_recheck"`) that does an `hx-get` of the same
  `GET /cases/{id}/investigation?run_id=…` into `#investigation`. The text does not say the worker is
  dead: a triage backlog can legitimately hold an investigate job for a while. A previous good result
  is hidden while stalled, as it is while running. A final row still wins over the job's age.
- **Small choices to know about**: a `running` job whose `locked_at` is NULL (should not happen) is
  measured from `scheduled_at`; a `scheduled_at` in the future (backoff) gives a negative age and is
  never stalled.
- Tests (12 items): pending 11 min → stalled, no poll, no button; pending 1 min stays running; the
  parametrized 1 / 9 / 11 min cases; running with `locked_at` 11 min old → stalled; running is measured
  from `locked_at` and pending from `scheduled_at` (a pending job created long ago but rescheduled
  recently is not stalled; a future `scheduled_at` is not stalled); the bound follows
  `JOB_LOCK_TIMEOUT_S` (a config override to 60 s); a final row wins over an old job; the previous
  result is hidden; the recheck GET returns the result once the job has finished; a second POST while
  stalled answers 409 with the stalled fragment; the not-dead wording (25 min shows "25 phút").
- **Red (f)**: the rule disabled in memory (`STALL_TIMEOUT_FACTOR` set to `10**9` by the scratch plugin)
  → 7 tests go red: pending 11 min, the not-dead wording, `[11-stalled]`, running locked 11 min, the
