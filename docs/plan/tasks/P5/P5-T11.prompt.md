- **Design notes:**

  **1 · `infra/` imports nothing, and that decides three things.** The package map gives `infra/` no imports
  at all, so: (a) check 9 (*yesterday's digest unreviewed*) **cannot** call `tier1.digest.unreviewed_count`
  and is three lines of SQL here — `alerts` with `status = 'auto_closed'` and `closed_at` in yesterday's
  window, `LEFT JOIN autoclose_reviews USING (alert_id)`, count the misses — which is also why this card does
  **not** depend on P5-T08; (b) check 6 (*monthly cost*) cannot call `audit.llm_runs.month_spend_usd` and sums
  `llm_runs.cost_usd` for the current month itself; (c) `health.alarm` is written with **raw SQL**, exactly
  as `infra/jobs.py:152` writes `job.exhausted`, not through `audit.events.write_event`. All three are
  deliberate and all three go in your report, because each one looks like a missed reuse until you know the
  rule. `test_import_rules.py` is the guard and acceptance 5 runs it.

  **2 · The ten checks, each a named function returning the same small shape.** `{name, ok, value, threshold,
  detail}`, so the report, the row and the page all read one structure. In §3.9's order: (1) `heartbeat` —
  `now() - source_heartbeat.last_seen_at > HEARTBEAT_MAX_AGE_MIN` minutes; (2) `intake_backlog` — oldest row
  with `processed_at IS NULL AND error IS NULL` older than 5 min (**G12's alarm**); (3) `job_backlog` — oldest
  `pending` job with `scheduled_at <= now()` older than 10 min; (4) `llm_null_ratio` — `llm_runs` in the last
  hour with `result IS NULL` over the total, > 30 % (**zero rows in the window is `ok`, not a division by
  zero** — test it); (5) `triage_unavailable` — `alerts.triage_status = 'unavailable'` over 24 h, > 10 %;
  (6) `monthly_cost` — the month's `sum(cost_usd)` over `LLM_MONTHLY_USD_CAP`, > 80 %; (7) `backup_age` —
  the newest `backups/soc-*.dump` (falling back to `backups/latest.dump`) older than 36 h, **or no file at
  all**, which is `not ok` with a distinct `detail`; (8) `inventory_empty` — `assets` has no rows;
  (9) `digest_unreviewed` — design note 1(a), and **evaluated only when the local time is ≥ 17:00**, `ok`
  otherwise, so the alarm reads as *"nobody reviewed it today"* and not *"it is 09:00"*; (10) `disk_free` —
  `shutil.disk_usage` on the repository root, free fraction < 20 %. **Measured 23/09 for your fixtures, so
  you know which of these are true right now:** disk is 26 % used (check 10 `ok`), `backups/` holds exactly
  one file dated 22/09 20:06 — so **check 7 alarms from 24/09 08:06 (+07)** until P5-T12 lands a schedule,
  and that is the first genuine alarm this system will raise.

  **3 · One row per run, and the collision the contract chose.** `INSERT INTO system_health (checked_at,
  checks, ok) VALUES (now(), %s, %s)` — `checked_at` from the **database's** clock (§9) and it is the primary
  key. Two runs in the same microsecond collide; migration 015 note (5) says that is the contract's choice,
  so **catch the unique violation, log it and return** rather than retrying with a nudged timestamp — a
  health job that rewrites its own clock to fit a key is worse than a health job that occasionally skips a
  tick. Record it as a P8 limitation in your report; fixing it is a §6.1 change and rule 4's stop condition.

  **4 · Sending only on a state change.** Read the newest `system_health` row **before** inserting; send when
  `previous.ok != now.ok` (`ok → alarm` and `alarm → ok`), and once a day at **08:05** send a summary
  regardless. Nothing else sends. A worker restart must not re-alarm — the previous state comes from the
  table, not from process memory, and there is a test for exactly that. Every `ok → alarm` transition also
  writes `health.alarm` to `audit_events` (design note 1(c)); the event type exists, no new name.

  **5 · `infra/notify.py` — one function, one sink, and it never raises.** `send(level, text) -> bool`.
  Telegram when `NOTIFY_TELEGRAM_BOT_TOKEN` **and** `NOTIFY_TELEGRAM_CHAT_ID` are both non-empty: one
  `httpx.post` to the bot API with a short timeout. Otherwise a **structured-log sink**: one JSON line at the
  given level, and a module counter. *"`notify.send(level, text)` never raises into the caller; failures are
  logged and counted"* (`prompts/P5.md:54`) — so **every** exception is caught, including a timeout, a DNS
  failure and a 4xx, and the function returns `False`. **The log sink is not a stub**: on this host, today,
  `.env` has no `NOTIFY_TELEGRAM_*` value, so it is the only sink there is and the health job must be
  demonstrable without a bot token. **Never log the token** (it is in the URL — build the URL at the call
  site and keep it out of every log line; a test asserts the token does not appear in captured output).

  **6 · `GET /health` — the one unauthenticated route in this phase, and it is narrow.** §6.4 says *no auth
  from localhost*. Implement it as: `request.client.host in {"127.0.0.1", "::1"}` → **200** with the newest
  `system_health` row; otherwise the `require_role("admin")` dependency, so a remote caller with an admin
  session still gets it and a remote caller without one gets **403**. Two literals and a comment naming §6.4
  — **not** a config key, **not** a CIDR list, **not** a header check. Write the limitation in your report:
  behind a reverse proxy `request.client.host` would be the proxy, and this deployment has none (`make run-app`
  binds `127.0.0.1:8000`).

  **7 · Tests.** `test_health.py` (`db`) — **each threshold simulated on both sides**: build the rows that
  make it fire and the rows that make it pass, ten pairs, with `notify` faked (`monkeypatch` on
  `infra.notify.send`, capturing calls). The state-change rule: alarm → no second send while it stays an
  alarm → one send on recovery; and a *"previous state is read from the table"* test that constructs the
  previous row directly and asserts no re-send. The 08:05 summary fires once. Check 4 with **zero** `llm_runs`
  in the window is `ok`. Check 7 with an empty `backups/` directory is `not ok` with its own `detail`. Check 9
  before and after 17:00. The `system_health` unique violation is caught. `GET /health` from loopback without
  a session → 200; from a non-loopback client without a session → 403; with an admin session → 200.
  `test_notify.py` (pure) — the Telegram arm builds the right URL and posts once; **an exception from
  `httpx` returns `False` and does not propagate** (this is the card's most important test:
  a notifier that raises takes the health job down with it); the log arm fires when either key is empty; the
  token never appears in captured log output. **Red steps (DEC-025):** (a) let one `httpx` exception escape
  `send` → the never-raises test goes red **and** a health test goes red with it, which is the point;
  (b) send on every run instead of on change → the no-second-send test goes red while the first-send test
  stays green; (c) compare the free-disk fraction with `>` instead of `<` → check 10's pair inverts and both
  halves go red, which is why every threshold is tested on both sides.
