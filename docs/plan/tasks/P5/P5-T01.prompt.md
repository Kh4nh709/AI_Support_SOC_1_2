- **Design notes:**

  **1 · The package contract, in one paragraph.** `backend/app/web/handlers/__init__.py` exposes
  `iter_handlers() -> dict[str, Handler]` and `iter_timeouts() -> dict[str, str]`. Both walk
  `sorted(pkgutil.iter_modules(__path__), key=lambda i: i.name)` and `importlib.import_module` each module.
  **Every** module must expose `JOB_TYPE: str` and `handle` — a module that forgets either is an
  `AttributeError` at import time, and there is **no `try/except ImportError` and no `getattr` default**:
  a handler that silently fails to mount is the DEC-039 shape, and fail-fast is the point (the
  `routers/__init__.py` docstring says this about routers; say it about handlers). `STATEMENT_TIMEOUT: str`
  is **optional** and only appears in `iter_timeouts()`'s result when a module declares it. A `JOB_TYPE`
  that is not in `app.infra.jobs.JOB_TYPES` is a `PermanentError` naming the module and the value —
  the same guard `enqueue()` applies at `infra/jobs.py:68`, at import time instead of at insert time.
  **A duplicate `JOB_TYPE` across two modules is a `PermanentError` too**, not a silent last-wins: two cards
  each claiming `digest` must fail loudly at start-up, which is the whole reason this package exists.

  **2 · The three modules are re-exports, and nothing else.** Each is a docstring plus three lines:

        from app.infra.puller import pull_job
        JOB_TYPE = "pull"
        handle = pull_job

  the same for `pipeline` (`app.soar.pipeline.run_pipeline_job`) and `triage`
  (`app.tier1.triage.run_triage_job`). `run_triage_job` has a keyword-only `adapter` parameter with a
  default, so the bare function satisfies `Handler` unchanged — do **not** wrap it in a lambda or a
  `functools.partial`, which would change what `test_g7_llm_off.py` and `test_triage_job.py` can monkeypatch.
  **No tier file is opened.** Acceptance 3 is the proof and it is not a formality: moving a handler body into
  `web/` would break G1's package map and the import-rules test.

  **3 · `web/worker.py` after the rewrite.** `HANDLERS = iter_handlers()` stays a **module-level name** so
  `from app.web.worker import HANDLERS` keeps working for anything that does it; add
  `TIMEOUTS = iter_timeouts()`; `main()` passes `run_forever(lambda: conn, HANDLERS, once="--once" in argv, timeouts=TIMEOUTS)`.
  Everything else in `main()` — `config.load()` first, `db.connect()`, the single-flight `enqueue(conn, "pull", "indexer")`,
  the commit — is unchanged, line for line. The docstring paragraph that currently reads *"Only `pull` and
  `pipeline` are wired here"* is stale twice over (`triage` landed in P3-T10) and is replaced by a sentence
  naming the package and the `JOB_TYPE`/`handle`/`STATEMENT_TIMEOUT` contract.

  **4 · Tests (`backend/tests/test_worker_handlers.py`, pure — no `db` marker).**
  `test_iter_handlers_discovers_the_three_on_main`: keys are exactly `{"pipeline", "pull", "triage"}` and each
  value **is** the tier function (`iter_handlers()["pull"] is app.infra.puller.pull_job`, identity, not equality).
  `test_iter_timeouts_is_empty_until_a_module_declares_one`: `iter_timeouts() == {}` on this branch — the first
  entry arrives with P5-T04's `investigate`.
  `test_worker_module_exposes_both_mappings`: `app.web.worker.HANDLERS == iter_handlers()` and `TIMEOUTS == iter_timeouts()`.
  `test_a_module_without_JOB_TYPE_fails_loudly` and `test_a_module_without_handle_fails_loudly`: write a module
  into a `tmp_path` package, point the walk at it (parameterise the internal walk on a package object, or use
  `monkeypatch.setattr` on `__path__` — your choice, but the test must exercise the real function, not a copy of it)
  and assert `AttributeError`.
  `test_duplicate_job_type_is_permanent_error` and `test_unknown_job_type_is_permanent_error`: same technique,
  `pytest.raises(PermanentError)` with the module name in `str(exc.value)`.

  **5 · Red steps (DEC-025), each shown red once and restored.** (a) Replace the `AttributeError` with a
  `getattr(module, "handle", None)` skip → `test_a_module_without_handle_fails_loudly` goes red **and** the
  discovery test still passes, which is exactly why the loud test exists. (b) Make `iter_handlers()` return
  `{m.name: ...}` instead of `{module.JOB_TYPE: ...}` → the key set becomes the module names and
  `test_iter_handlers_discovers_the_three_on_main` goes red on `triage` vs `triage` looking identical while
  `pull` vs `pull` does too — so **name one module differently from its `JOB_TYPE`** when you break it, or the
  red step does not discriminate (this is the DEC-077 trap: a red step that cannot go red for the right reason).
  (c) Drop `timeouts=TIMEOUTS` from the `run_forever` call → `test_worker_module_exposes_both_mappings` stays
  green, so add the assertion that `main()` passes it (inspect with `monkeypatch` on
  `app.web.worker.run_forever`) and watch **that** go red.
