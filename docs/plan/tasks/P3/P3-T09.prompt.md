  **2 · The ① user message, section by section (architecture §4.1), through `PromptBuilder` only.**
  - `HEADING_ALERT`; line `alert_id: Id · rule_id: Id · rule_level: int · alert_time: datetime`; line `severity: Enum · category: Enum · occurrence_count: int · risk_band: Enum` (`risk_band(inp.risk_score)`; omit the part when `None`); line `ioc_reputation: Enum · asset_criticality: Enum · identity_privileged: Enum` (from `facts`); line `lookup_asset: Enum · lookup_identity: Enum · lookup_ioc: Enum` (`LookupStatus` from `lookup_status`); line `categories: Enum, …` only when `len(categories) > 1`; line `mitre: Id, …` only when non-empty (each `Id("mitre", …)`; an id that fails the regex is **omitted with a warning**, never placed); line `agent_id: Id` only when present and valid.
  - block `rule_description` = `inp.description`, attrs `alert_id=Id`; block `wazuh_raw_log` = `inp.raw_log`, attrs `alert_id=Id`, `limit_bytes=cfg.PROMPT_LOG_MAX_BYTES` (the wrapper puts `[truncated]` inside; if `inp.raw_log_truncated` is already `True` from ingestion, add warning `raw_log_truncated_at_ingest`).
  - `HEADING_CONTEXT`: for each of `asset`, `identity`, `ioc` whose `lookup_status` is `not_found` → `sentence("<label>:", SENTENCE_ABSENT)` **outside** any block (the legacy sentence 1, its placement rule kept); then, if `include_context` and at least one lookup is `found`, one block `context` whose text is `asset: hostname=<agent_name> origin_host=<origin_host> owner=<owner> role=<role>` / `identity: username=<alert_user>` / `ioc: <reputation>` for the found ones — **hostnames, owner, role, username are free text and live here and nowhere else**. A `skipped` lookup gets neither (nothing to say).
  - `HEADING_CORRELATION`: if `include_correlation` and `correlation.rows` is non-empty → one line per `CorrelationRow` (≤ 20): `rule_id: Id · category: Enum · status: Enum · clusters: int · alerts: int · src_ips: int · first_seen: datetime · last_seen: datetime`; then block `correlation_samples` containing the ≤ 5 samples rendered as `alert_id=… rule_id=… severity=… status=… occurrence=… alert_time=…` + `description` + `raw_log` (each sample's `raw_log` cut with `wrap.truncate_block(…, 2_048)` — marker inside); if `rows` is empty → `sentence(SENTENCE_NO_CORRELATION)` outside.
  - `HEADING_PLAYBOOK`: block `kb_playbook` = `playbook_text`, attrs `category=Enum`, when a playbook exists; else `sentence(SENTENCE_NO_PLAYBOOK)` outside (legacy sentence 2 — for `unknown` and for a missing file). `playbook_used_effective = inp.category` only when the playbook text exists **and** `table is not None and table.reviewed` (architecture §3.10: an unreviewed table means ① still runs but `playbook_used` is null and a warning is recorded); otherwise `None`, with warning `decision_table_unreviewed:<category>` (table present, unreviewed), `no_table:<category>` (playbook without a table) or `no_playbook` (`unknown` / missing file). The text block is sent in all three cases where it exists — the *prose* is authoritative regardless; only the *machine* table is gated on review.
  - `HEADING_REQUEST`; `sentence(SENTENCE_REQUEST_TRIAGE)`.
  `system = triage_system.txt + "\n\n## Schema triage_v2\n" + schemas.render("triage_v2")` (planning decision 14).

  **3 · The budget, checked before sending, cut in phase-5's order, one warning per cut.** `estimated = llm.adapter.estimate_tokens(system) + llm.adapter.estimate_tokens(user)` (P3-T04's module function — not a method on the adapter instance). If `estimated > cfg.PROMPT_TOTAL_BUDGET_TOKENS`, rebuild with, in order until it fits: (a) raw_log limit 32,768 → 8,192 (`warning: raw_log_cut_to_8192`); (b) samples 5 → 3 → 0 (`correlation_samples_cut_to_3`, `correlation_samples_dropped`); (c) correlation rows 20 → 10 (`correlation_rows_cut_to_10`). Never the alert facts, never the playbook. Still over after (c) → send anyway with `budget_exceeded_after_cuts` (phase-5: "vẫn gửi"). The warnings list becomes `llm_runs.citation_warnings` (P3-T10). Measured today the largest `raw_log` on the queue is 3,439 chars, so this path is exercised only by the test that feeds a 200 KB raw_log and 1,800 correlated alerts (T8 of phase-5).

  **4 · The verifier prompt (architecture §4.3) — facts and rules outside, the proposer inside.**
  - `HEADING_FACTS`; line `severity · category · rule_level · occurrence_count · ioc_reputation · asset_criticality · identity_privileged` (all `fact()`); line `correlated_clusters: int`; then one line per correlated category — `category: Enum · clusters: int` (architecture §4.3: "số cụm tương quan theo category"); line `first_seen: datetime · last_seen: datetime`. No hostnames, no usernames, no text.
  - `HEADING_TABLE`; if `table` is given **and reviewed**: one line per rule, entirely from `fact()` calls joined by the separator — `rule: Id("rule_ref", rule.id) · then: Verdict(rule.action) · <cond>: … ` where a list condition renders as `fact` name + comma-joined enum values (`severity: low, medium`) and a numeric condition as its own fact name (`occurrence_lt: 50`, `rule_level_gte: 12` — the four condition keys are in `FACT_NAMES` for exactly this). Every token is then a constant, an `Id`, an enum value, an int or a separator, and the linter passes without a block. If no table, or the table is unreviewed → `sentence(SENTENCE_NO_PLAYBOOK)` and `playbook_used_effective = None`.
  - `HEADING_PROPOSER`; `sentence(SENTENCE_PROPOSER_IS_DATA)` outside; one block `proposer` whose text is `json.dumps({"verdict": verdict, "reasons": reasons}, ensure_ascii=False)` — the surviving reasons after step 3, the verdict after step 4 (P3-T10 passes both).
  - `HEADING_REQUEST`; `sentence(SENTENCE_REQUEST_VERIFIER)`. `system = verifier_system.txt + "\n\n## Schema verifier_v1\n" + schemas.render("verifier_v1")`.
  A test asserts the verifier user message contains none of: `inp.raw_log`, `inp.description`, `agent_name`, `origin_host`, `alert_user`, `owner`, `role` — by value, on a fixture where each is a distinctive string.

  **5 · `propose()` / `verify()` — one call, validate, at most one repair, never a third call.** `result = adapter.complete(system=…, user=…, model=cfg.LLM_MODEL_PROPOSER|VERIFIER)`; `parsed = json.loads(result.content)` (a `JSONDecodeError` → `parsed=None`, errors `["<root>: expected a JSON object"]`); `errors = schemas.validate(name, parsed)`. If `errors` and not yet repaired: build the repair prompt = the same `system`, user = original user + `"\n\n" + HEADING_REPAIR + "\n" + SENTENCE_REPAIR + "\n" + "\n".join(BULLET + e for e in errors)` (planning decision 9: the messages carry paths and vocabularies only — they are template constants, field paths and enum words — **lint it before sending**, and a test proves the repair prompt lints clean), call again, `repaired=True`, `calls=2`. Still invalid → `parsed=None` with the second error list; P3-T10 turns that into `unavailable`/`stopped_by='schema'`. `usage` is the **sum** over the calls made; `latency_ms` the sum; `model` from the last call.

  **6 · `prompt_version`.** `subprocess.run(["git", "rev-parse", "--short", "HEAD"], …)` once per process (module-level cache keyed by template path), `+`, `hashlib.sha256(template.read_bytes()).hexdigest()`. Failure of `git` (no repository, no binary) → `"nogit"`. Tests compute the sha independently and assert the suffix.

  **7 · Everything built is linted in the tests.** `test_proposer_prompt_lints_clean` and `test_verifier_prompt_lints_clean` run P3-T03's `lint()` on the canonical alert's prompt with a distinctive injected description, and on a prompt where every lookup is `not_found` (no `context` block — exercising the three sentences outside), and on the repair prompt. `test_every_free_text_is_inside_a_block` asserts each of `description`, `raw_log`, `agent_name`, `origin_host`, `alert_user`, `owner`, `role`, the playbook text and each sample `raw_log` appears in the user message **only** between a boundary carrying the build's nonce (search the rendered blocks, then assert the string is absent from the message with all blocks removed).
