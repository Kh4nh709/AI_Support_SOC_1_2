- **Design notes:**

  **1 · The public surface, exactly.**
  ```python
  BLOCK_SOURCES = frozenset({"wazuh_raw_log", "rule_description", "correlation_samples", "kb_playbook", "context", "proposer"})
  TRUNCATION_MARKER = "[truncated]"          # §7.1 — replaces the legacy "[đã cắt]"
  NONCE_REMOVED = "[nonce-removed]"

  def new_nonce() -> str: ...                # secrets.token_hex(8) — 16 hex chars, one per build
  def normalise(text: str) -> str: ...       # unicodedata.normalize("NFKC", text)
  def strip_nonce(text: str, nonce: str) -> str: ...   # text.replace(nonce, NONCE_REMOVED) — after NFKC, before escaping
  def truncate_block(text: str, limit_bytes: int) -> tuple[str, bool]: ...
  def untrusted_block(text: str, source: str, *, nonce: str, limit_bytes: int | None = None, **attrs: str) -> Block: ...

  @dataclass(frozen=True)
  class Block:
      source: str            # ∈ BLOCK_SOURCES
      attrs: Mapping[str, str]
      plain: str             # NFKC-normalised, nonce-stripped, truncated — NOT escaped (the gate's quote check reads this)
      escaped: str           # html.escape(plain, quote=False) — what is placed between the tags
      truncated: bool
      dropped_bytes: int
      rendered: str          # the full '<untrusted_data nonce="…" source="…" …>\n{escaped}\n</untrusted_data nonce="…">'
  ```
  The first five of `BLOCK_SOURCES` are exactly `triage_v2.reasons[].source`'s enum (§6.2); `proposer` is the verifier prompt's one block (P3-T09). `untrusted_block` raises `ValueError` on any other `source` — the vocabulary is closed here, not in the builder.

  **2 · Order of operations inside `untrusted_block`, and why it is this order.** (i) `normalise` — NFKC folds the compatibility look-alikes (`＜` U+FF1C → `<`) *before* escaping so that escaping catches them; (ii) `strip_nonce` — on the normalised text, so a nonce hidden behind a compatibility character is still found; (iii) `truncate_block` if `limit_bytes` is given — the marker is appended to `plain` **inside** the content, so it is escaped with the content and cannot be forged from outside; (iv) `html.escape(plain, quote=False)` — `<`, `>`, `&` only; (v) render with `nonce` and `source` first, then `attrs` sorted by key, each value `html.escape(str(v), quote=True)`. Attribute *values* are the caller's responsibility to keep closed-set (P3-T02 restricts them to `Id`/`Enum`/`int`); this module escapes them and nothing more.

  **3 · `truncate_block` cuts on a UTF-8 byte budget without splitting a character.** `encoded = text.encode("utf-8")`; if `len(encoded) <= limit_bytes` → `(text, False)`. Otherwise `head = encoded[:limit_bytes].decode("utf-8", errors="ignore")` — `ignore` drops a trailing partial sequence rather than raising — then `head + "\n" + TRUNCATION_MARKER + f" {len(encoded) - len(head.encode('utf-8'))} bytes dropped"`, `True`. The marker line is *part of the returned text*, so whoever wraps it wraps the marker too. The legacy `cat_raw_log` sliced bytes and decoded with `ignore` as well; what it did not do is put the marker in the returned text — `boc_raw_log` appended it separately, which is the seam §7.4 closes.

  **4 · The rendered boundary is byte-exact and closes with the nonce too.** `<untrusted_data nonce="{n}" source="{s}"{attrs}>` + `\n` + escaped + `\n` + `</untrusted_data nonce="{n}">`. The closing tag carries the nonce (architecture §4.1's example, `triage_system.txt:11`): a look-alike closer without the nonce is content by the system prompt's own rule. `rendered` is what the builder concatenates; nothing else in the codebase writes those angle brackets — P3-T03's linter and P3-T07's detector both treat any other occurrence as data.

  **5 · Nothing here is randomised except `new_nonce`.** No module-level nonce, no default nonce parameter: `nonce` is keyword-only and required. The legacy builder's `or NONCE` fallback turned a forgotten argument into silence (`prompt_builder.py:49–54` records the incident); a missing `nonce` here is a `TypeError` at the call site.

  **6 · `plain` is what the gate compares quotes against, `escaped` is what the model reads.** Keep both on the `Block` — P3-T08's step 3 accepts a quote that matches either (the model may quote `&lt;` or `<`), P3-T07's detector scans `plain`. Do not add a third representation.
