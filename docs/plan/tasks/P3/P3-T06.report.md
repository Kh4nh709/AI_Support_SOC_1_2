# P3-T06 report — `kb/lookup.py` + decision tables

## 1 · Built

- `backend/app/kb/lookup.py` — rewritten from the P0-T06 docstring stub:
  - `KB_ROOT` — `Path(__file__).resolve().parents[3] / "kb"` (repo-root `kb/`, per planning decision 5).
  - `DecisionTableError(Exception)` — raised by the loader, naming the file, the rule id and the key.
  - `Rule` / `DecisionTable` (frozen dataclasses) — `DecisionTable.reviewed` is `bool(reviewed_by and reviewed_at)`.
  - `severity_for(rule_level) -> str` — DEC-053's band (`>=12 critical`, `>=8 high`, `>=5 medium`, else `low`).
  - `fact_grid() -> Iterator[dict]` — the 2,520-point consistency grid, `severity` derived from `rule_level`.
  - `rule_matches(rule, facts) -> bool` — every condition key ANDed; a fact the condition needs but `facts` lacks makes the rule not match, never raises.
  - `apply_table(table, facts) -> (action, rule_id) | None` — first match in file order; ignores `table.reviewed`.
  - `rule_holds(table, rule_id, facts) -> bool | None` — `None` when `rule_id` is not in the table.
  - `check_consistency(table) -> list[str]` — every `(rule_a, rule_b, point)` where both hold with a different `then`.
  - `get_playbook(category, *, root=KB_ROOT) -> str | None` — the playbook's raw markdown text (the future `kb_playbook` prompt-block source); `None` for `unknown` or a missing file.
  - `get_decision_table(category, *, root=KB_ROOT) -> DecisionTable | None` — loads, validates and parses the YAML; `None` for `unknown` or a missing file.
- `kb/decision_tables/{c2_beacon,data_exfiltration,malware,policy_violation,privilege_escalation,ransomware,recon,ssh_brute_force,suspicious_login,web_attack}.yaml` — ten skeletons, `reviewed_by`/`reviewed_at: null`, three example rules each (`<abbr>-1` false-positive, `<abbr>-2` IoC escalate, `<abbr>-3` rule-level escalate); `ssh_brute_force.yaml`'s `sbf-1`/`sbf-2`/`sbf-3` are verbatim from the card's design note 2 (= architecture §3.10's example, rendered in the new field names). `privilege_escalation.yaml`'s header additionally notes DEC-055 (rule `5402`/rootcheck `510`/`521`).
- `backend/tests/test_kb_lookup.py` — 29 tests (the 21 named in the card plus 8 edge-case additions: missing-file lookups, a well-formed-table acceptance case, a playbook-name-mismatch rejection, an AND-of-conditions check, a grid-size pin, and a same-action-overlap-is-fine check).

## 3 · Deviations from the card and why

- **Rule-id regex widened from `^[a-z]{2,6}-\d{1,2}$` (design note 2) to `^[a-z0-9]{2,6}-\d{1,2}$`.** Design note 5's own abbreviation list is `c2b, dex, mal, pol, pre, ran, rec, sbf, sul, web` — `c2b` (for `c2_beacon`) contains a digit, which the letters-only regex in note 2 cannot match. The two notes disagree with each other, not with a frozen contract, so I resolved it in favor of note 5's explicit abbreviation and widened the character class rather than inventing a different abbreviation. Everything else about the id (2–6 chars, one hyphen, a 1–2 digit suffix, unique per file, still outside any block) is unchanged. Flagging per the prompt's own rule ("this prompt wins... say so in your report").
- Everything else matches the card as written (none other).
