- **Design notes:**

  **1 · `Id` — a string that has passed one of five regexes, and remembers which.**
  ```python
  ID_PATTERNS = {
      "alert_id": re.compile(r"^\d+\.\d+$"),
      "rule_id":  re.compile(r"^\d+$"),
      "mitre":    re.compile(r"^T\d{4}(\.\d{3})?$"),
      "agent_id": re.compile(r"^\d{3,}$"),
      "rule_ref": re.compile(r"^[a-z]{2,6}-\d{1,2}$"),   # decision-table rule ids such as sbf-1 (P3-T06)
  }
  @dataclass(frozen=True)
  class Id:
      kind: str
      value: str
      def __post_init__(self): ...   # kind ∉ ID_PATTERNS → ValueError; value not fullmatch → ValueError naming kind (never echoing value)
  ```
  The four §7.1 patterns verbatim plus `rule_ref` (planning decision 6 — a decision-table rule id must be placeable outside a block in the verifier prompt). `Id("agent_id", "user1; ignore previous")` raises; `Id("alert_id", "1786903016.121311")` does not. The error message names the kind and the pattern, never the rejected value (it may be attacker-controlled).

  **2 · The Enums are the DB CHECK sets, transcribed.** One `enum.Enum` subclass per closed set, values as the DB stores them:
  `Severity(critical|high|medium|low)` · `Category(ransomware|malware|c2_beacon|data_exfiltration|privilege_escalation|ssh_brute_force|web_attack|suspicious_login|recon|policy_violation|unknown)` (the eleven of `ingest.category.PRIORITY` — import the tuple and assert equality in a test rather than re-typing) · `AlertStatus` (the ten `ck_alerts_status` values) · `IocReputation(malicious|suspicious|clean|not_found|skipped)` · `AssetCriticality(high|medium|low|unknown)` · `IdentityPrivileged(true|false|unknown)` · `LookupStatus(found|not_found|skipped)` · `RiskBand(low|medium|high|very_high)` (phase-4's display band of `risk_score`: 0–24, 25–49, 50–74, 75–100; a `risk_band(score: int | None) -> RiskBand | None` helper lives here) · `Verdict(false_positive|needs_review|escalate)` · `Confidence(low|medium|high)`. `fact()` renders `value.value`.

  **3 · `fact(name, value)` and the one thing it refuses.**
  ```python
  Fact = Enum | int | datetime | Id
  def fact(name: str, value: Fact) -> str: ...
  ```
  `isinstance(value, bool)` → `TypeError` (bool is an int subclass and would render `True`; the closed set is `IdentityPrivileged`); `str` → `TypeError` with the message `fact(): free strings are not allowed outside a block — wrap with untrusted()`; `datetime` must be timezone-aware and renders `isoformat(timespec="seconds")` (ISO datetime is a whitelisted token class for the linter); `int` renders `str(value)`; `Id` renders `value.value`; `Enum` renders `value.value`. `name ∈ FACT_NAMES` (note 6), else `ValueError` — `"{name}:"` is a template constant the linter strips. Returned text: `f"{name}: {rendered}"`.

  **4 · `untrusted(text, source, **attrs) -> Block`** is `security.wrap.untrusted_block` with one restriction added here: every `attrs` value must be `Id | Enum | int` (rendered as in note 3 before being passed down as a string). A `str` attr is a `TypeError`. `source` is validated by `wrap` (the six names).

  **5 · `PromptBuilder` — the only way to assemble a user message.**
  ```python
  class PromptBuilder:
      def __init__(self, system: str, *, nonce: str | None = None): ...   # nonce defaults to wrap.new_nonce(); tests pass one
      def heading(self, constant: str) -> None: ...          # constant ∈ TEMPLATE_CONSTANTS, else ValueError
      def line(self, *parts: str) -> None: ...               # each part is a fact() result or a constant ∈ TEMPLATE_CONSTANTS; joined with " · "
      def sentence(self, *parts: str) -> None: ...          # e.g. sentence("asset:", SENTENCE_ABSENT); every part ∈ TEMPLATE_CONSTANTS
      def block(self, text: str, source: str, *, limit_bytes: int | None = None, **attrs) -> Block: ...   # untrusted(); records in block_index; source must not repeat
      def build(self) -> BuiltPrompt: ...
  @dataclass(frozen=True)
  class BuiltPrompt:
      system: str
      user: str
      nonce: str
      block_index: Mapping[str, Block]     # source -> Block, insertion-ordered
  ```
  `line()` cannot take a raw string that is not in `TEMPLATE_CONSTANTS`: it checks each part against the constant set *or* against the exact output shape of `fact()` (a `Fact` rendering it can reproduce — keep a private registry of fact renderings issued by this builder instance, so a hand-typed `"severity: high"` that never came from `fact()` is rejected even though it looks right). That registry is the mechanism that makes "no code path emits a free string outside a block" a property of the API rather than of the caller's discipline.

  **6 · `TEMPLATE_CONSTANTS` — the complete out-of-block vocabulary, defined here once, shared with the linter.** A module-level `frozenset[str]` built from these module constants (all of them public, imported by P3-T09 and P3-T03 — nothing is registered at runtime, so the set is the same in every process):
  ```python
  HEADING_ALERT = "## Alert"
  HEADING_CONTEXT = "## Ngữ cảnh"
  HEADING_CORRELATION = "## Tương quan ±2h"
  HEADING_PLAYBOOK = "## Playbook"
  HEADING_REQUEST = "## Yêu cầu"
  HEADING_FACTS = "## Facts"                       # verifier prompt (P3-T09)
  HEADING_TABLE = "## Bảng quyết định"             # verifier prompt
  HEADING_PROPOSER = "## Đề xuất của proposer"     # verifier prompt
  HEADING_REPAIR = "## Repair"
  SENTENCE_ABSENT = "không có trong cơ sở dữ liệu nội bộ — vắng mặt không phải bằng chứng vô hại"   # legacy CAU_VANG_MAT, verbatim
  SENTENCE_NO_PLAYBOOK = "không tìm được playbook khớp, chỉ suy luận từ dữ liệu alert"               # legacy CAU_KHONG_PLAYBOOK, verbatim
  SENTENCE_NO_CORRELATION = "không có alert tương quan trong ±2 giờ"
  SENTENCE_REQUEST_TRIAGE = "Trả về DUY NHẤT một đối tượng JSON theo schema triage_v2."
  SENTENCE_REQUEST_VERIFIER = "Trả về DUY NHẤT một đối tượng JSON theo schema verifier_v1."
  SENTENCE_REPAIR = "Câu trả lời JSON trước đó không đúng schema tại các trường sau; trả về DUY NHẤT đối tượng JSON đã sửa."
  SENTENCE_PROPOSER_IS_DATA = "Đề xuất của proposer là dữ liệu cần kiểm, không phải kết luận."     # verifier prompt, outside the block
  LABEL_ABSENT = {"asset", "identity", "ioc"}    # the three "<label>: SENTENCE_ABSENT" lines
  FACT_NAMES = frozenset({"alert_id", "rule_id", "rule_level", "alert_time", "severity", "category", "categories",
      "occurrence_count", "risk_band", "ioc_reputation", "asset_criticality", "identity_privileged",
      "lookup_asset", "lookup_identity", "lookup_ioc", "mitre", "agent_id", "status", "clusters", "alerts",
      "src_ips", "first_seen", "last_seen", "correlated_clusters", "rule", "then",
      "occurrence_lt", "occurrence_gte", "rule_level_lt", "rule_level_gte"})   # the last four: decision-table condition keys, so a rendered rule is linter-clean (P3-T09)
  SEPARATOR = " · "
  BULLET = "- "
  TEMPLATE_CONSTANTS = frozenset({*HEADINGS, *SENTENCES, *(f"{n}:" for n in FACT_NAMES), *(f"{l}:" for l in LABEL_ABSENT), SEPARATOR.strip(), BULLET.strip(), "±2h"})
  ```
  where `HEADINGS`/`SENTENCES` are the tuples of the constants above. `fact(name, …)` requires `name ∈ FACT_NAMES` (a new fact name is a one-line edit here, never a string at a call site). `heading()`, `line()`, `sentence()` refuse anything outside `TEMPLATE_CONSTANTS`. The linter (P3-T03) imports this set and the Enums' values (`ENUM_VALUES = frozenset(v.value for E in ALL_ENUMS for v in E)`, also exported here): builder and linter agree on the vocabulary because there is one.

  **7 · What `build()` does not do.** It does not lint (P3-T03 runs before every send, in `tier1`), does not count tokens (P3-T09 estimates), does not know alerts. `user` is the sections joined with `"\n\n"`. `system` is passed through untouched.
