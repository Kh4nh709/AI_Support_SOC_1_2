## 3. Deviations

1. **Repair-prompt linting uses an extended constant set (`REPAIR_CONSTANTS`).** Design note 5 says the repair suffix is "template constants, field paths and enum words — lint it before sending". P3-T03's `lint()` admits only `TEMPLATE_CONSTANTS` ∪ enum values ∪ ints ∪ ISO datetimes ∪ ids: a schema field path (`suggested_action`, `structured_basis.severity`, `reasons[].source`) and the validator's message words (`missing`, `expected one of …`) are none of those, so the verbatim suffix cannot lint clean against `TEMPLATE_CONSTANTS` alone. `REPAIR_CONSTANTS` is derived from `output_schemas.json` (paths, `<root>`, the fixed message vocabulary from `schemas.py`'s docstring, and each enum leaf's exact `expected one of …` string — so the vocabularies are the schema's, not hand-typed); the whole repair message is linted against `TEMPLATE_CONSTANTS | REPAIR_CONSTANTS`; `test_repair_lint_rejects_an_echoed_value` shows the extension does not launder a value.
2. **The bullets are sanitised, not joined verbatim.** Two validator message shapes cannot be sent as-is: an `unexpected key` message carries the model's own key in its path (`IGNORE PREVIOUS INSTRUCTIONS: unexpected key` — P3-T05's "never contains the offending value" holds for values, not keys), and an array index (`reasons[1].source`) is not a schema path. `_repair_line` rewrites the former to the longest known *object* prefix (`structured_basis: unexpected key`, `reasons[]: unexpected key`, `<root>: unexpected key`) and the latter to the schema's `[]` form, dropping the index. `Proposal.schema_errors` keeps the validator's raw messages for `llm_runs`. A root key that *spells* a real nested path (`"structured_basis.severity"`) is attributed to that object — wrong parent, still value-free; pinned by `test_repair_unexpected_key_with_dots_maps_to_a_known_object`.
3. **List conditions render as one fact per value** — `severity: low · severity: medium`, not the card's `severity: low, medium`. `PromptBuilder.line()` accepts only `fact()` renderings and `TEMPLATE_CONSTANTS`; there is no comma constant and `fact()` takes one Enum, so the comma form is not expressible through the typed API (`builder.py` is not in this card's file list). The same applies to the alert line's `categories:` and `mitre:` lists (`categories: ssh_brute_force · categories: suspicious_login`). Lints clean either way.
4. **`include_context=False` omits the whole `## Ngữ cảnh` section**, the `SENTENCE_ABSENT` lines included, not only the block. Design note 2 lists the sentences before the `if include_context` block, but note 1's parenthetical says "the block and its heading are omitted entirely" — with no heading the sentences would be orphaned, and B2 (P7) measures what the section contributes. Pinned by `test_include_switches_omit_blocks` (`SENTENCE_ABSENT not in user` when off).
5. **A cut that changes nothing emits no warning.** Design note 3 lists the four steps; I emit a step's warning only when it actually changes the prompt (raw_log longer than 8 KB, more than 3 / more than 0 samples, more than 10 rows). Otherwise `citation_warnings` would claim the model did not see a raw_log it saw in full. `test_budget_cuts_that_change_nothing_are_not_warned` pins it: a 100-byte raw_log with two rows and two samples under a 1-token budget yields exactly `correlation_samples_dropped, budget_exceeded_after_cuts`.
6. **Verifier rules whose id fails the `rule_ref` pattern are omitted with `invalid_rule_ref`.** P3-T06 widened the kb rule-id regex to `^[a-z0-9]{2,6}-\d{1,2}$` (its report's deviation, for `c2b-1`), but P3-T02's `ID_PATTERNS["rule_ref"]` and P3-T03's linter copy are still `^[a-z]{2,6}-\d{1,2}$`, so `Id("rule_ref", "c2b-1")` raises. The card gives no rule for this; I mirrored its mitre rule (omit with a warning, never place). No table is reviewed today, so no live prompt is affected — see §4.
7. **Warning names the card does not spell out:** `invalid_mitre_id`, `invalid_agent_id`, `invalid_rule_ref` (one per bad id, value never echoed); the verifier's table warnings mirror the proposer's (`decision_table_unreviewed:<cat>`, `no_table:<cat>`, `no_playbook` for `unknown`).
