- **Design notes:**

  **1 · The gate, as the context pack states it (§7.3) — implement this, in this order, with these outcomes:**
  ```
  1 schema valid?            no → one repair attempt with the error message → still no → unavailable
  2 structured_basis == DB facts on every field?  no → hallucination_flag, verdict := needs_review
  3 every reasons[i].quote is a substring (NFKC, whitespace-collapsed) of the block named by source; drop invalid; 0 left → needs_review
  4 verdict == false_positive kept only if: severity ≠ critical ∧ ioc ∉ {malicious, suspicious} ∧ asset ∉ {high, unknown}
    ∧ identity_privileged ≠ true ∧ playbook_rule_applied ∈ decision table ∧ that rule's condition holds on DB facts; else needs_review
  5 detector (regex/heuristics) → injection_findings only; never changes the verdict
  6 verifier: prompt = DB facts + playbook decision table + {verdict, reasons} wrapped as untrusted; agree=false or differing verdict → needs_review
  7 output_guard: closed sets; write llm_runs (proposer + verifier) with gate_result, verifier_result, evidence_check; set triage_status
  ```
  Because `security` imports only `infra`, four things arrive as arguments rather than imports:
  ```python
  Validator = Callable[[str, Any], list[str]]                    # P3-T05 llm.schemas.validate
  RuleCheck = Callable[[str | None], tuple[bool, str | None]]    # P3-T10 builds it from kb.rule_holds + table.reviewed; returns (holds, why_not)
  Scanner   = Callable[[Iterable[Block]], list[Any]]             # P3-T07 detector.scan; findings are stored as given (detector.as_json)

  @dataclass
  class GateState:
      proposer_raw: dict            # the parsed model JSON, never mutated
      facts: Mapping[str, Any]      # planning decision 7
      blocks: Mapping[str, Block]   # BuiltPrompt.block_index
      proposed_verdict: str
      verdict: str                  # evolves through the steps
      reasons: list[dict]           # surviving reasons
      steps: dict[str, str]         # "1": "ok"|"repaired"|"failed", "2": "ok"|"mismatch", "3": "ok"|"dropped:<n>", "4": "ok"|"missing"|"n/a", "5": "findings:<n>", "6": "agree"|"disagree"|"invalid"|"skipped", "7": "ok"
      forced_by: list[str]; missing: list[str]; mismatched_fields: list[str]; dropped_reasons: list[dict]
      hallucination_flag: bool; warnings: list[str]; injection_findings: list[Any]; verifier_verdict: str | None

  def step1_schema(parsed: dict | None, validate: Validator, *, repaired: bool) -> tuple[str, list[str]]
      # returns ("ok" | "repair" | "failed", errors): parsed None (JSON did not parse) counts as invalid; first failure with repaired=False → "repair"; failure with repaired=True → "failed"
  def start(parsed: dict, facts, blocks, *, repaired: bool) -> GateState                      # after step 1 passed; steps["1"] = "repaired" if repaired else "ok"
  def step2_basis(state) -> None
  def step3_quotes(state) -> None
  def step4_fp_policy(state, rule_check: RuleCheck) -> None
  def step5_detector(state, scan: Scanner) -> None
  def run_steps_1_to_5(parsed, facts, blocks, *, repaired, rule_check, scan) -> GateState       # start + 2..5, in order
  def step6_verifier(state, verifier_parsed: dict | None) -> None                              # None = verifier invalid after repair, or skipped
  def step7_output_guard(state) -> dict                                                        # returns the final triage_v2 `result`; calls output_guard.enforce
  def gate_result(state, *, prompt_version: str, playbook_used_effective: str | None) -> dict
  ```
  Verdict transitions are monotone: a step may set `verdict = "needs_review"` and append its name to `forced_by`; nothing ever sets `false_positive` or `escalate` after `start`. `forced = proposed_verdict != verdict`.

  **2 · Step 2 — field by field, lower-cased strings, integer for the count.** Compare `structured_basis.{severity, ioc_reputation, asset_criticality, identity_privileged}` with `facts[...]` after `str.lower()` on both sides, and `int(structured_basis.occurrence_count) == facts["occurrence_count"]` (the build-time value, stored in `gate_result.facts`, so a cluster that grew during the call does not read as a hallucination). `playbook_rule_applied` is **not** compared here — it is step 4's. Any mismatch → `hallucination_flag = True`, `mismatched_fields = [...]`, verdict `needs_review`, `forced_by += ["step2"]`.

  **3 · Step 3 — the quote check.** `norm(s) = " ".join(unicodedata.normalize("NFKC", s).split())`. A reason survives iff `reason.source in state.blocks` and `norm(quote)` is non-empty and is a substring of `norm(block.plain)` **or** of `norm(block.escaped)` (the model may quote `<` or `&lt;`; both are the same evidence). Dropped reasons go to `dropped_reasons` as `{"index": i, "why": "unknown_source"|"not_substring"|"empty_quote"}` — the *claim* text is not copied there (it is model output; `proposer_raw` keeps it). Zero survivors → verdict `needs_review`, `forced_by += ["step3"]`, `steps["3"] = "dropped:<n>"`.

  **4 · Step 4 — the FP policy, and `missing` names every failed condition, not just the first.** Applies only when `verdict == "false_positive"` at this point (`steps["4"] = "n/a"` otherwise). Conditions, each appending to `missing` when it fails: `facts.severity != "critical"` (`"severity"`), `facts.ioc_reputation not in {"malicious", "suspicious"}` (`"ioc_reputation"`), `facts.asset_criticality not in {"high", "unknown"}` (`"asset_criticality"` — **`unknown` is not "not important"**, architecture §4.2), `facts.identity_privileged != "true"` (`"identity_privileged"`), and `rule_check(structured_basis.playbook_rule_applied)` → `(True, None)` (`"playbook_rule"` plus the `why_not` string into `warnings` — P3-T10's `rule_check` returns `why_not ∈ {"no_rule_cited", "unknown_rule", "table_unreviewed", "rule_does_not_hold", "rule_is_not_false_positive", "no_table"}`). Any `missing` → `needs_review`, `forced_by += ["step4"]`. **This is the only bold step in the diagram: no detector output feeds it.**

  **5 · Step 5 — record, never decide.** `state.injection_findings = scan(state.blocks.values())`; `steps["5"] = f"findings:{len(...)}"`. A test asserts that a `high`-level finding leaves `verdict` untouched (phase-5's v1 layer 3 is not implemented — planning decision 13 — and the test is the statement of that).

  **6 · Step 6 — compare against the current verdict, not the proposer's original.** `verifier_parsed` is the validated `verifier_v1` dict, or `None`. `None` → `steps["6"] = "invalid"`, `needs_review`, `forced_by += ["step6"]`. Otherwise `verifier_verdict = structured_only_verdict`; if `agree is False` **or** `structured_only_verdict != state.verdict` → `needs_review`, `forced_by += ["step6"]`, `steps["6"] = "disagree"`; else `"agree"`. The verifier is always run by P3-T10, even when steps 2–4 already forced (`verifier_result` is P7's measurement); the comparison is against the verdict *after* step 4, which is what the verifier prompt carried (P3-T09 passes `state.verdict` and `state.reasons`).

  **7 · Step 7 and `output_guard.enforce(result) -> dict`.** `result` = `proposer_raw` with `suggested_action` replaced by `state.verdict` and `reasons` replaced by the survivors, then passed through `enforce()`: every enum field re-checked against §6.2's closed sets (the same vocabularies as `schemas.py`, transcribed here — `security` cannot import `llm`), `occurrence_count` is an `int`, keys outside the schema dropped, `reasons[].source` re-checked; a violation raises `OutputGuardError` (it should be impossible after step 1, and a test proves the guard is live by feeding it a crafted object directly). `enforce` never adds an action, never rewrites text — ① has no actions to strip; the legacy `output_guard`'s "force `requires_human_approval`" has no counterpart in `triage_v2` and is not ported.

  **8 · `gate_result` (planning decision 1) — the document P4 displays and P7 re-gates from:**
  ```python
  {"version": 1, "proposed_verdict": …, "final_verdict": …, "forced": bool, "forced_by": [...], "steps": {...},
   "hallucination_flag": bool, "mismatched_fields": [...], "dropped_reasons": [...], "missing": [...],
   "facts": {...}, "warnings": [...], "verifier_verdict": …, "playbook_used_effective": … | None,
   "prompt_version": …, "proposer_raw": {...}}
  ```
  `forced` is the key P4's `tier1.decided` payload reads (`prompts/P4.md:29`). `proposer_raw` is the untouched parsed model output — P7's B2/B3 re-run `run_steps_1_to_5` on it with a restricted step set; keep the step functions individually importable for that reason.

  **9 · The crafted-JSON matrix, all from the fakes' payloads with one field changed each** (the brief's required list, plus the ones the steps above add): basis mismatch → `needs_review` + `hallucination_flag` + the field named · invalid quote → dropped, survivors kept · all quotes invalid → `needs_review` via step 3 · FP with no structured evidence (`playbook_rule_applied: null`) → `needs_review`, `missing` contains `playbook_rule` · FP with `asset_criticality = unknown` → `missing` contains `asset_criticality` · FP with every condition met and `rule_check → (True, None)` → **`false_positive` survives** (the positive control — without it the matrix proves nothing) · FP with `severity = critical` → `missing` contains `severity` · verifier disagree → `needs_review` · verifier `agree: true` but a different `structured_only_verdict` → `needs_review` · verifier `None` → `needs_review`, `steps["6"] == "invalid"` · step 1 first failure → `"repair"`, second → `"failed"` · detector `high` finding → verdict unchanged · `escalate` passes steps 2–4 untouched (`steps["4"] == "n/a"`) · `output_guard.enforce` raises on `suggested_action: "maybe"`.
