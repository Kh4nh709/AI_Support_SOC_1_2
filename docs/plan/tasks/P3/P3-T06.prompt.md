- **Design notes:**

  **1 · Where the files are (planning decision 5).** The ten playbooks live at the **repo root** `kb/playbooks/` and `test_category.py:32` pins that path; the tables go beside them at `kb/decision_tables/<category>.yaml`. In `lookup.py`: `KB_ROOT = Path(__file__).resolve().parents[3] / "kb"` (`backend/app/kb/lookup.py` → `kb` → `app` → `backend` → repo root), and every public function takes `root: Path = KB_ROOT` so tests point it at `tmp_path`. A test asserts `KB_ROOT / "playbooks"` is the same directory `test_category.py` uses.

  **2 · The format, and the loader that refuses anything else.**
  ```yaml
  # kb/decision_tables/ssh_brute_force.yaml — SKELETON. Content is the Owner's + advisor's (§11).
  # reviewed_by/reviewed_at stay null until that sitting; while null the gate treats the table as absent
  # (architecture §3.10) and records decision_table_unreviewed:<category> in gate_result.warnings.
  category: ssh_brute_force
  playbook: ssh_brute_force_v1          # the name in kb/playbooks/ssh_brute_force.md's title line
  reviewed_by: null                     # e.g. "Owner + advisor"
  reviewed_at: null                     # ISO date, e.g. 2026-09-17
  rules:
    - id: sbf-1                         # ^[a-z]{2,6}-\d{1,2}$ — an Id the verifier prompt may place outside a block
      if: {severity: [low, medium], ioc_reputation: [not_found, clean], asset_criticality: [low, medium],
           identity_privileged: ["false"], occurrence_lt: 50}
      then: false_positive
    - id: sbf-2
      if: {ioc_reputation: [malicious, suspicious]}
      then: escalate
    - id: sbf-3
      if: {rule_level_gte: 12}
      then: escalate
  ```
  `if` keys: `severity`, `ioc_reputation`, `asset_criticality`, `identity_privileged` — each a **list** of values from the §6.2 vocabulary of that field (`identity_privileged` over the strings `"true"|"false"|"unknown"` — quote them, YAML would otherwise read `true` as a boolean); `occurrence_lt`, `occurrence_gte`, `rule_level_lt`, `rule_level_gte` — ints. `then` ∈ `false_positive|needs_review|escalate`. `id` unique within the file. A key outside this set, a value outside its vocabulary, a non-list where a list is required, a `then` outside the three, a duplicate `id`, a `category` that does not match the file name, or a `playbook` name that is not in the playbook file's first line → `DecisionTableError` naming the file, the rule id and the key. **The YAML boolean trap is real:** a test writes `identity_privileged: [false]` unquoted and asserts the loader rejects it with a message that says to quote it.

  **3 · The dataclasses and the three evaluators — pure, no I/O, no `Config`.**
  ```python
  @dataclass(frozen=True)
  class Rule: id: str; condition: Mapping[str, Any]; action: str
  @dataclass(frozen=True)
  class DecisionTable:
      category: str; playbook: str; reviewed_by: str | None; reviewed_at: str | None; rules: tuple[Rule, ...]
      @property
      def reviewed(self) -> bool: return bool(self.reviewed_by and self.reviewed_at)
  def get_playbook(category: str, *, root: Path = KB_ROOT) -> str | None          # None for "unknown" or a missing file
  def get_decision_table(category: str, *, root: Path = KB_ROOT) -> DecisionTable | None
  def rule_matches(rule: Rule, facts: Mapping[str, Any]) -> bool                   # every key of `condition` holds
  def apply_table(table: DecisionTable, facts: Mapping[str, Any]) -> tuple[str, str] | None   # first match in file order → (action, rule_id); ignores `reviewed`
  def rule_holds(table: DecisionTable, rule_id: str, facts: Mapping[str, Any]) -> bool | None  # None when rule_id is not in the table
  def check_consistency(table: DecisionTable) -> list[str]                          # names every (rule_a, rule_b, fact point) with different actions both holding
  ```
  `facts` is P3-T09's dict (planning decision 7): `severity`, `ioc_reputation`, `asset_criticality`, `identity_privileged` (strings), `occurrence_count`, `rule_level` (ints); a missing key makes any rule needing it **not** match (never raises). `apply_table` ignores `reviewed` on purpose: it is P7's B1 baseline and must evaluate authored tables offline; the *gate* consults `table.reviewed` (P3-T10 wraps it). Say so in the docstring.

  **4 · The consistency grid — severity is derived, not an axis.** `alerts.severity` is `rule_level` banded (`docs/phase-1-tiep-nhan-chuan-hoa.md:148`, DEC-053: ≥ 12 critical, ≥ 8 high, ≥ 5 medium, else low), so a fact point with `severity=low` and `rule_level=12` cannot exist and must not be generated — on a free product every `severity`-conditioned FP rule would "contradict" every `rule_level_gte: 12` escalate rule at an impossible point. Grid: `rule_level ∈ {0, 3, 5, 8, 12, 15}` (→ severity `low, low, medium, high, critical, critical`) × `ioc_reputation` (5) × `asset_criticality` (4) × `identity_privileged` (3) × `occurrence_count ∈ {1, 10, 49, 50, 100, 999, 1000}` = **2,520 points**; expose `fact_grid() -> Iterator[dict]` and put the band in one function `severity_for(rule_level)` (a test pins the six band values). For every point, collect the rules that hold; if two hold with different `then`, report `f"{rule_a.id} ({rule_a.action}) and {rule_b.id} ({rule_b.action}) both hold at {point}"`. Same-action overlap is fine (rules are ordered; the first wins). The skeletons must all return `[]`; **the test also constructs a deliberately contradictory table** (`x-1: {severity: [low]} → false_positive`, `x-2: {rule_level_lt: 5} → escalate` — both hold at `rule_level=3`) and asserts `check_consistency` names both ids — the red half of the acceptance.

  **5 · The skeletons.** Ten files, one per `ingest.category.PRIORITY` entry except `unknown`, each with the header comment of note 2, `reviewed_by: null`, `reviewed_at: null`, and **two or three example rules in the §3.10 pattern** (`<abbr>-1` a false-positive rule on low/medium severity + clean/not_found IoC + low/medium asset + non-privileged identity + an occurrence bound; `<abbr>-2` escalate on `ioc_reputation ∈ [malicious, suspicious]`; `<abbr>-3` escalate on `rule_level_gte: 12`), using `ssh_brute_force`'s `sbf-1`/`sbf-3` verbatim from §3.10. Abbreviations: `c2b`, `dex`, `mal`, `pol`, `pre`, `ran`, `rec`, `sbf`, `sul`, `web`. The `privilege_escalation` header additionally notes DEC-055: rule `5402` (*successful sudo*, level 3, 57 clusters of G1) resolves to this category today and the Owner decides whether a rule names it. **None of this is policy** — it is the shape the Owner fills in; the header says so.

  **6 · Two-way test and the token bound.** `test_every_category_has_one_playbook_and_one_table` walks `PRIORITY` minus `unknown` and the two directories in both directions (a table without a playbook, a playbook without a table, a file whose stem is not a category — all red). `test_largest_playbook_under_3000_tokens` uses the 2.5-bytes-per-token estimate of P3-T04 (`llm.adapter.estimate_tokens` if merged; else inline `ceil(len(b)/2.5)` and say so) — measured today the largest playbook is 45 lines, far under; the test is the guard, not a finding.
