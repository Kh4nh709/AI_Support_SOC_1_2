# P3-T04 report — `llm/adapter.py`: DeepSeek adapter, wall-clock deadline, retries, cost, monthly cap

## 1. Built

- `backend/app/llm/adapter.py` (modified — was the P0-T06 docstring skeleton):
  - `LLMResult` — frozen dataclass, the same four fields as `backend/tests/fakes/llm.py`'s `LLMResult` (re-declared, not imported, per design note 1).
  - `LLMTimeout(TransientError)`, `LLMBudgetExceeded(PermanentError)`, `LLMPermanent(PermanentError)` — the three error classes.
  - `DeepSeekAdapter(cfg, *, client=None, spent_usd=lambda: 0.0, sleep=time.sleep, clock=time.monotonic, log=None)` — `client` defaults to a real `openai.OpenAI(..., max_retries=0)`; `log` is an extra keyword beyond design note 1's literal signature block, added because design note 8 requires an injectable `log: Callable[[dict], None] | None` and `complete()`'s signature has no room for it (see Deviations).
  - `DeepSeekAdapter.complete(*, system, user, response_format=None, timeout_s=None, model=None) -> LLMResult` — the public call: rejects a system prompt without `"JSON"`; checks `spent_usd() >= LLM_MONTHLY_USD_CAP` before every attempt; runs the SDK call on a daemon thread joined with the deadline; retries `1 + LLM_RETRY` attempts total on network/5xx with `sleep(2.0 * attempt)` backoff; a 4xx or exhausted-permanent path raises `LLMPermanent`; an exhausted connection/timeout error is wrapped in `TransientError` (a 5xx re-raises as itself — already deterministic under `infra.errors.classify`).
  - `cost_usd(usage, cfg) -> float` — `prompt_tokens/1e6*LLM_PRICE_IN_PER_M + completion_tokens/1e6*LLM_PRICE_OUT_PER_M`, rounded to 5 decimals.
  - `estimate_tokens(text) -> int` — `ceil(len(utf8 bytes) / 2.5)`.
  - Module-private helpers: `_as_dict`, `_usage_dict` (lifted from `eval/smoke_test.py`'s `usage_dict` rules), `_message_content` (never reads `reasoning_content`), `_classify_attempt`.
- `backend/tests/test_adapter.py` (created) — 25 tests across 9 classes: the 15 named acceptance tests plus 10 edge-case tests (caller-supplied overrides, empty content, model fallback, price-swap failing case, cap-checked-on-every-attempt, connection-error-exhausted wrapping, structured-log content and default-off).

## 3. Deviations

1. **`log: Callable[[dict], None] | None = None` added to `DeepSeekAdapter.__init__`, beyond design note 1's literal signature block.** Design note 8 requires "even that only through a `log: Callable[[dict], None] | None` the caller may inject (default: nothing)" for the one structured line per attempt (`{"llm": "attempt", "n": attempt, "outcome": ..., "ms": ...}`), but `complete()`'s own signature (also given verbatim in note 1) has no parameter for it — the only place it can live is the constructor. Added as an extra keyword-only parameter with a safe default (`None`, meaning no logging), so it does not change the `client`/`spent_usd`/`sleep`/`clock` surface the fake-compatibility contract cares about. Exercised by two of the added edge-case tests.
2. **The task's own worktree needed a fast-forward before its card could be read.** `../AI_Support_SOC_1_2-P3-T04` (branch `task/P3-T04`) was created at `c522d9c` (per DEC-081), one commit behind `main`'s dispatch commit `fa6b62d`, which is the commit that actually adds `docs/plan/tasks/P3/*.prompt.md`, this task's own card included. `git merge --ff-only main` (0 divergent commits, clean fast-forward) was required before `docs/plan/tasks/P3/P3-T04.prompt.md` existed in the worktree at all. Flagged under Open questions — the same gap applies to every other P3 worktree created in that same dispatch.
3. The module docstring inherited from the P0-T06 skeleton ("JSON mode, one repair round, and usage/cost recording") was rewritten — the repair round is explicitly out of this card's scope (P3-T09) and the original wording would have mis-described what the file now does.
