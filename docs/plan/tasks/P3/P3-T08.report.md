# P3-T08 report — `security/gate.py` steps 1–5, 7 (+ step 6 comparison) + `security/output_guard.py`

## 1. Built

- **`backend/app/security/gate.py`**:
  - `GateState` — the mutable dataclass carrying `proposer_raw`, `facts`, `blocks`, `proposed_verdict`, `verdict`, `reasons`, `steps`, `forced_by`, `missing`, `mismatched_fields`, `dropped_reasons`, `hallucination_flag`, `warnings`, `injection_findings`, `verifier_verdict` — exactly the field list in design note 1.
  - `step1_schema(parsed, validate, *, repaired) -> (status, errors)` — `"ok"|"repair"|"failed"`; `parsed=None` counts as invalid without calling `validate`.
  - `start(parsed, facts, blocks, *, repaired) -> GateState` — the post-step-1 constructor; `steps["1"]` = `"repaired"`/`"ok"`.
  - `step2_basis(state)` — structured_basis vs DB facts, lower-cased strings + integer-equal `occurrence_count`; `playbook_rule_applied` excluded (that's step 4's).
  - `step3_quotes(state)` — NFKC + whitespace-collapsed substring check against `block.plain` or `block.escaped`; drops classified as `unknown_source`/`empty_quote`/`not_substring`.
  - `step4_fp_policy(state, rule_check)` — the five-condition false_positive policy; `n/a` when verdict isn't already `false_positive`; `missing` names every failed condition.
  - `step5_detector(state, scan)` — records `injection_findings`, never touches `verdict`.
  - `run_steps_1_to_5(parsed, facts, blocks, *, repaired, rule_check, scan) -> GateState` — `start` + steps 2–5 in order.
  - `step6_verifier(state, verifier_parsed)` — compares against `state.verdict` (post-step-4), not `proposed_verdict`.
  - `step7_output_guard(state) -> dict` — builds `result` from `proposer_raw` + the gated `suggested_action`/`reasons`, passes it through `output_guard.enforce`.
  - `finish(state, verifier_parsed) -> dict` — step 6 then step 7, the counterpart to `run_steps_1_to_5` for the second half (design note "Scope in: … run_steps_1_to_5, finish …"); step 6/7 stay individually callable for P7's restricted re-run.
  - `gate_result(state, *, prompt_version, playbook_used_effective) -> dict` — the document shape from design note 8, `forced = proposed_verdict != verdict`.
- **`backend/app/security/output_guard.py`**:
  - `OutputGuardError(ValueError)`.
  - `enforce(result: dict) -> dict` — re-checks every §6.2 `triage_v2` closed set (transcribed here, not imported from `app.llm.schemas` — `security` may import only `infra`), requires `occurrence_count` to be a real `int`, drops unknown keys at both the top level and inside `structured_basis`/`reasons[]`, never adds an action or rewrites text.
- **`backend/tests/test_gate.py`** — 38 tests: the 22 named by the card plus 16 edge-case tests found while writing them (step 1 pass-through, step 2 case-insensitivity and the `playbook_rule_applied` exclusion, step 3 empty-quote, step 5 zero-findings, the `run_steps_1_to_5`/`finish` runners, three more `output_guard.enforce` closed-set checks, and a "forced is False" `gate_result` case).
