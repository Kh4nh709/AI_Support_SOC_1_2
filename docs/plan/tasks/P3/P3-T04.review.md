## The DEC-033 contract — verified directly, not trusted from the report

This card exists to stop one specific defect: an adapter that hands `LLM_TIMEOUT_S` to the
SDK's own `timeout=` kwarg and calls the deadline enforced, when httpx's timeout bounds only
the gap between received bytes (measured 05/09: 139.1 s completed under `timeout=120`,
`attempts: 1`). Read `backend/app/llm/adapter.py:209-247` (`_call_once`) myself: the SDK call
runs inside `threading.Thread(target=_run, daemon=True)`; the caller does
`thread.join(timeout=timeout_s)`; if `thread.is_alive()` after the join, it raises
`LLMTimeout` and abandons the thread. The SDK is still given `timeout=timeout_s` (design
note 2's httpx gap guard, kept, not relied on) — but the wall-clock bound comes from the
`join`, not from that kwarg.

**Reproduced the failing case myself** rather than accepting the report's paste. In the
scratch worktree (below), replaced `_call_once`'s thread+join with a direct, synchronous
`_run()` call (bypassing the deadline mechanism entirely) and re-ran
`-k deadline`: both tests failed —
```
Failed: DID NOT RAISE LLMTimeout
2 failed, 23 deselected in 7.28s
```
— i.e. with the thread/join removed, a client that ignores its `timeout` kwarg and just
blocks 3 s (`SlowClient`, `backend/tests/test_adapter.py:88-104`, using a real `time.sleep`,
not a fake exception) sails past a `LLM_TIMEOUT_S=1` deadline undetected, exactly the 05/09
shape. Restored the file (`git diff` empty afterward) and re-ran green (`25 passed`, deadline
tests `1.00s`/`1.01s`). The guard is real, not vacuous, and it is the guard DEC-033 asked for.

`LLM_THINKING` is sent as `extra_body` on every call regardless of value (design note 2);
`reasoning_content` is never read (`_message_content`, adapter.py:95-101, only reads
`.content`); the monthly cap is checked at the top of the attempt loop, before any attempt,
including retries (`test_cap_checked_before_every_attempt_not_only_the_first` mutates
`spent_usd` inside the injected `sleep` between attempt 1 and 2 and proves attempt 2 never
fires) — all read from source, not just from the report.

## Deviations (Coder's report, assessed)

1. **`log: Callable[[dict], None] | None = None` added to `__init__`, beyond design note 1's
   literal signature block.** The card contradicts itself here: note 1's literal code gives
   `__init__` and `complete()` signatures with no `log` parameter on either, while note 8
   requires an injectable `log` the caller may supply. Since `complete()`'s own signature is
   also given verbatim (no room to add it there without breaking the fake-compatible surface),
   the constructor is the only place left. Additive, keyword-only, defaults to `None`
   (no-op) — does not disturb `client`/`spent_usd`/`sleep`/`clock`. Accepted; the
   self-contradiction is the card's, not the Coder's, and it was flagged rather than silently
   resolved.
2. **Worktree fast-forward gap** (worktree created one commit before the dispatch commit that
   wrote its own card) — a dispatch-process note, not a code defect; already flagged to the
   Director/Planner in the report's Open questions.
3. **Module docstring rewritten** from the P0-T06 skeleton — accurate to what this card scopes
   in/out (repair round is P3-T09, not here). No concern.
