- **Design notes:**

  **1 · The surface.**
  ```python
  @dataclass(frozen=True)
  class Finding:
      category: str        # instruction_override | role_override | fake_role_marker | prompt_exfiltration |
                           # forbidden_action_request | delimiter_escape_attempt | obfuscation_hidden_chars |
                           # possible_obfuscation | delimiter_lookalike | nonce_shaped_token | fake_truncation_marker |
                           # role_marker_flood | imperative_density
      pattern: str         # the regex source or "heuristic:<name>"
      matched_text: str    # ≤ 80 chars of the match — this is attacker text; it is stored in llm_runs, never printed
      source: str          # the block source it was found in
      level: str           # "high" | "medium"
  def scan(blocks: Iterable[Block]) -> list[Finding]: ...
  def level(findings: Iterable[Finding]) -> str: ...   # "high" if any finding.level == "high"; "medium" if any; else "none"
  def as_json(findings) -> list[dict]: ...              # the shape written to llm_runs.injection_findings
  ```
  Input is P3-T01's `Block`s (`block_index.values()`); `scan` reads `block.plain` (normalised, unescaped) — the text the model effectively reads, minus escaping.

  **2 · The 20 patterns = the 19 ported + 1.** Port `_PATTERNS` from `prompt_guard.py:60–80` verbatim (same regex source, same category names, `re.IGNORECASE | re.MULTILINE`). Add the twentieth: a Vietnamese instruction-override pattern, `r"(bỏ qua|quên|phớt lờ)\s+(mọi|tất cả|các)?\s*(hướng dẫn|chỉ thị|lệnh)\s*(trước|ở trên|trên)"` → `instruction_override` — the phrase phase-5 itself uses as its example (`docs/phase-5-auto-triage.md:86`). Level: every regex category is `high` except `obfuscation_hidden_chars`, which is `medium` on its own (the source's `risk_level` rule).

  **3 · The 8 heuristics.** *Ported, `must`:* (1) `base64_run` — a contiguous `[A-Za-z0-9+/]{80,}={0,2}` run → `possible_obfuscation`, `medium` (a SHA-256 hex is 64 chars, deliberately under the threshold); (2) `proximity` — one of `block|delete|quarantine|resolve|approve` within 60 chars of one of `automatically|immediately|without review|without approval|no review|without waiting`, either order → `forbidden_action_request`, `high`; (3) `hidden_chars` — U+200B/U+200C/U+200D/U+FEFF present → `obfuscation_hidden_chars`, `medium`. *New, `should` — ship what fits in the estimate, list what you skipped in the report:* (4) `delimiter_lookalike` — after NFKC the text contains `<untrusted_data` or `</untrusted_data` (a boundary-shaped string inside content — it survived escaping as text, which is the point) → `delimiter_escape_attempt`, `high`; (5) `nonce_shaped_token` — a bare 16-hex token within 40 chars of the word `nonce` → `nonce_shaped_token`, `medium`; (6) `fake_truncation_marker` — `[truncated]` appears in `plain` *before* the position the wrapper's own marker would occupy (i.e. anywhere when `block.truncated` is `False`, or more than once when `True`) → `fake_truncation_marker`, `medium`; (7) `role_marker_flood` — ≥ 3 lines matching `^\s*(system|assistant|user|human)\s*:` → `role_marker_flood`, `high`; (8) `imperative_density` — ≥ 3 sentences in a block of ≤ 20 sentences starting with an English or Vietnamese imperative from a 20-word list (`ignore, disregard, forget, override, execute, classify, mark, set, bỏ qua, hãy, đánh dấu, phân loại, …`) → `imperative_density`, `medium`. Each heuristic is its own function; `scan` calls them in this order after the regexes.

  **4 · Never mutates, never decides.** `scan` takes blocks and returns a new list; it does not touch `Block`, does not raise on any input (empty block, `None` text, binary garbage), and has no notion of a verdict. A test asserts that every public function's return type is `list[Finding]` or `str` and that the module contains no string from `{"false_positive", "needs_review", "escalate"}` (`grep` in acceptance 6).

  **5 · The canonical alert is clean.** `alert_40112.json`'s `full_log` (`Accepted password for user1 from 127.0.0.1 port 48104 ssh2`) and its description produce **no** findings; P1-T01's three adversarial payloads (`eval/smoke_test.py:670–698` — `INJECTION_TEMPLATE` placed into `data.dstuser`, `full_log` and `rule.description` by `make_adversarial`; reproduce the template as a string in the test, once per target) each produce ≥ 1 `high` finding. A base64 blob of 100 chars alone → `medium` only; the same blob plus "ignore previous instructions" → `high`.

  **6 · One occurrence, one Finding (regex vs heuristic) — added 19/09, DEC-092, Reviewer round 1 non-blocking note, bucket (b): the card commanded this duplicate.** The 19th ported regex and the `hidden_chars` heuristic (note 3(3)) detect the same four code points on the same `block.plain` — the reference `prompt_guard.py:123-134` never had a separate hidden-chars heuristic; note 3(3) called "ported" something that lived only inside `_PATTERNS`. Both stay (note 2's verbatim port and note 3's eight functions are unchanged, `len(PATTERNS) == 20`, `len(HEURISTICS) == 8`), but `scan` records each occurrence once. **Rule, inside `scan`, per block:** collect the regex Findings first; then a heuristic tuple whose `(source, category, matched_text)` equals that of a regex Finding already collected **for the same block** is dropped — the regex Finding wins (its `pattern` is the regex source, not `heuristic:hidden_chars`). The comparison is on the capped `matched_text` (`[:_MATCH_CAP]`); regex Findings are never deduplicated against each other (two identical hidden characters are two occurrences and two Findings; two different regexes matching one span, e.g. `<<</untrusted_data>` hitting the 17th and 18th, stay two Findings). `level()` is unaffected (both hidden-char paths are `medium`). **Reach beyond hidden chars, disclosed so nobody "fixes" it:** the key also coincides — and the heuristic Finding is likewise dropped — when `delimiter_lookalike`'s slice equals the 18th regex's match, i.e. a bare lowercase ASCII `<untrusted_data>`/`</untrusted_data>` that ends the block (`scan([Block("</untrusted_data>")])` → 1 Finding, the regex one; with trailing text, an attrs-shaped or fullwidth tag, or uppercase, the two Findings differ and both are kept — that is the same occurrence counted once, not a lost detection). No other heuristic can coincide: `proximity`'s window always contains its verb and never equals a regex match, and base64_run / nonce_shaped_token / fake_truncation_marker / role_marker_flood / imperative_density emit categories no regex emits. **Known and deliberately not deduplicated:** regexes 15/16 vs `proximity` (both `forbidden_action_request`, matched_text never coincides) — inherited verbatim from the reference, which runs both with no dedupe; `nonce_shaped_token` reports one token once per `nonce` word within 40 chars. Both are measurement facts for P3-T10 and P8, not defects of this card.
