- **Design notes:**

  **1 · The edge table is data, and `_apply` is the only writer.** A module-level tuple of
  `Edge(id, table, from_states, to_state, sets, event_type, actor)` — A1…A17 as §5 and architecture
  §3.5 list them — and one private `_apply(conn, edge, row_id, *, sets, audit_payload, actor_id)`
  that: (a) `UPDATE <table> SET status = %s, <sets> WHERE <id> = %s AND status = ANY(%s) RETURNING
  status` — **the from-state check is in the `WHERE`**, not in a prior `SELECT`, so two concurrent
  callers cannot both pass a guard read from a stale row; (b) `rowcount == 0` → `StaleState` (the row
  exists in another state, or does not exist — one `SELECT status` afterwards to make the message
  say which); (c) `write_event(...)` in the same transaction; the caller owns `BEGIN`/`COMMIT`
  (P2-T10, P4). Asking for an `(from, to)` pair that is not an edge raises `IllegalTransition` before
  any SQL. Those two exceptions are the whole error surface.

  **2 · The database already enforces the shape of every edge; write what it demands.** Measured
  on the migrated database, the CHECKs your `sets` must satisfy or the transaction rolls back:
  - `ck_alerts_g3_terminal_phai_co_closed_at`: `duplicate`, `auto_closed`, `closed_fp`,
    `closed_benign`, `closed_confirmed` need `closed_at IS NOT NULL` (G3).
  - `ck_alerts_h2_dong_boi_nguoi_phai_seal`: `closed_fp|closed_benign|closed_confirmed` need
    `sealed_at IS NOT NULL` (H2 — a human decision seals the cluster).
  - `ck_alerts_h3_escalate_khong_seal`: `escalated_tier2` needs `sealed_at IS NULL` (H3 — an
    investigated cluster keeps absorbing).
  - `ck_alerts_ban_sao_phai_seal_va_tro_goc`: `duplicate` needs `duplicate_of`, `closed_at` **and**
    `sealed_at`.
  - `ck_alerts_khong_tu_tro`: `duplicate_of <> alert_id`.
  - `ck_cases_ket_luan_phai_co_moc`: a concluded case needs `concluded_at`, `concluded_by`,
    `conclusion_reason` in the same `UPDATE`.
  Every `now()` is the database's, inside the statement (§9 "Time").

  **3 · The eight functions.**
  - `open_alert(conn, alert: Alert, *, kind: Literal["received","duplicate","auto_closed"], source: str,
    suggestion_visible: bool, duplicate_of: str | None = None, rule: AutocloseMatch | None = None,
    context: AlertContext | None = None, risk_score: int | None = None, risk_components: dict | None =
    None) -> str`

    `alert.received` (`system`). `duplicate`: `status='duplicate'`, `duplicate_of`, `closed_at =
    now()`, `sealed_at = now()`, audit `alert.duplicate_merged` with `{"parent": …, "occurrence": …}`
    (phase-2 3a — the parent's counter is bumped by P2-T05's `bump_parent`, called by the pipeline
    **before** this). `auto_closed`: `status='auto_closed'`, `closed_at = now()`, **`sealed_at` left
    NULL** (M4: the noise cluster keeps absorbing for 30 min), `close_reason`, `autoclose_rule_id`, audit
    `alert.auto_closed` with `{"rule_id","rule_name","reason"}`, **written with the internal context
    and the risk score the pipeline computed before deciding** (`asset_context`, `identity_context`,
    `ioc_context`, `lookup_status`, `risk_score`, `risk_score_components` — phase-3 M1/M3: an
    auto-closed alert keeps its internal context, and writing those columns never changes `status`)
    — **and `enqueue(conn, "triage", alert_id)` in the same transaction**: D8, ① runs on 100 % of
    auto-closed alerts (DEC-012). For `kind="received"` the three context arguments are ignored:
