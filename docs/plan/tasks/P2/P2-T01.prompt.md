- **Design notes:**

  **1 · The key set is §6.3's, mechanically.** Do not type the list from memory. `scripts/gen_env_example.py`
  exposes `keys_from_pack()` — the same extractor that generates `.env.example` and that `make lint`
  checks — and your test asserts that every key it returns is a field of `Config` and vice versa. Measured
  today: it returns **54** keys (the 53 of DEC-003 plus `LLM_THINKING`, DEC-032). Importing a script from
  `scripts/` in a test is fine: `sys.path.insert(0, "scripts")` then `import gen_env_example`.

  **2 · Shape and precedence.** `Config` is a frozen `dataclass` whose fields are exactly the §6.3 keys (acceptance 2 relies on `dataclasses.fields`); derived values such as `llm_enabled` are `@property`s, not fields. `load(*, env_file: str | Path = ".env") -> Config` reads the environment first, then `.env`, then the §6.3 default — **the default is the value §6.3's text gives, not the value `.env.example` happens to carry** (the generator keeps host values there; `LLM_MODEL_PROPOSER` is empty by contract and `deepseek-v4-flash` only on this host). A worktree has no `.env`
  (git-ignored), so the loader must work with no file at all. The `.env` reader is the ten-line one
  `eval/indexer_probe.py` already uses (`KEY=value`, `#` comments, last assignment wins, a trailing
  ` # comment` stripped only when whitespace precedes the `#`) — copy it, do not import across
  `eval/`/`backend/app/` (context pack §4: `eval/` is never imported by `backend/app/`).

  **3 · Parse rules, by shape.**
  - integers: `int(value.replace("_", ""))` — §6.3 writes `2_097_152`; `int("2_097_152")` happens to
    work in Python 3.12 but be explicit.
  - floats: `EVAL_BLIND_FRACTION`.
  - JSON lists: `JOB_BACKOFF`, `INVENTORY_PATHS`, `NEVER_AUTOCLOSE_AGENTS` — parsed with `json.loads`
    per DEC-007 item 2: bad JSON, or JSON that is not a list of the right scalar type, is a
    `ConfigError` **naming the key**; never a silent fallback. Only unset-or-empty falls back to the
    default.
  - closed sets: `LLM_THINKING ∈ enabled|disabled` (default `enabled`); anything else is a
    `ConfigError` naming the key and the two allowed values.
  - strings and secrets: `INDEXER_PASSWORD`, `LLM_API_KEY`, `JWT_SECRET`, the two `NOTIFY_*`. Empty is
    allowed at load time — **which module needs which secret is that module's check**, made when it
    is used (the puller checks `INDEXER_*`, P3's adapter checks `LLM_API_KEY`). `Config.__repr__` and
    any `dump()` you add must redact them: acceptance 6.
  - `LLM_MODEL_PROPOSER` **may be empty** and that is not an error: G7 (P2-T10) runs with it unset to
    prove no state depends on a model. Expose `config.llm_enabled -> bool` = `bool(LLM_MODEL_PROPOSER)`.
    `LLM_MODEL_VERIFIER` defaults to the proposer when empty (§6.3).
  - `DATABASE_URL` may be empty in a worktree (its password lives only in the Owner's `.env`);
    `DATABASE_URL_OWNER` and `TEST_DATABASE_URL` default to `postgresql:///soc_dev` and
    `postgresql:///soc_test` per `.env.example`.

  **4 · One startup assertion §5 of phase-1 demands:** `MAX_PAYLOAD_BYTES > RAW_LOG_MAX_BYTES`, checked
  in the loader and raised as `ConfigError` naming both keys. (`assert` is stripped under `-O`; use an
  `if`.)

  **5 · `infra/errors.py`.** Three exception classes — `ConfigError`, `TransientError`,
  `PermanentError` — and `classify(exc: BaseException) -> Literal["transient", "permanent"]`. The
  table, from phase-4 P4-7 and §9: `TransientError`, `psycopg.OperationalError`, `httpx.TransportError`,
  `httpx.TimeoutException`, and an HTTP status ≥ 500 (when the exception carries one) → `transient`;
  `PermanentError`, `ValueError`/`KeyError`/`TypeError` raised by our own parsing, `psycopg.DataError`,
  `psycopg.IntegrityError`, an HTTP 4xx → `permanent`. **Anything unclassified is `transient`** and
  increments a module-level counter keyed `UNCLASSIFIED:<ExceptionClassName>` (§9) — `counters()`
  returns a copy so the worker's health line can read it. Transient means "the job retries"; permanent
  means "the job fails now" — the semantics are P2-T02's, the classification is yours.

  **6 · Nothing here talks to a database, the network or the clock.** Both modules are pure and
  their tests run under `make test` with no marker.
