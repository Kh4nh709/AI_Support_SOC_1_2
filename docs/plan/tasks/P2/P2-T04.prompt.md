- **Design notes:**

  **1 · Three document shapes, one parser, detected by structure.** Measured today on the live indexer:
  - **indexer hit**, what the puller stores: keys `_index, _id, _score, _source, sort` — and `fields`
    **only when the search body requested it** (`"fields": ["timestamp"]`, which P2-T11's puller does;
    the canonical fixture has it because it came from a dashboard export). `fields.timestamp[0]` is
    UTC ISO with `Z`; `sort[0]` equals the epoch-millis of `_source.timestamp` on every hit checked.
  - **bare document**: the `_source` object on its own — the webhook body, or a Logstash-shaped line
    such as `archive_line_5503.json` (`@timestamp`, `event.original`, `timestamp`, `rule`, `agent`…).
  - **raw archive line**: the manager's own object from `alerts.json` — exactly what
    `archive_line_5503.json` carries inside `event.original`: `timestamp` (`+0700`), `rule`, `agent`,
    `manager`, `id`, `full_log`, `decoder`, `data`, `location`; no `@timestamp`, no `fields`, no `sort`.
  Rule: if the object has a `_source` key, the alert is `_source` and the envelope is the rest;
  otherwise the object *is* the alert. `result.envelope` is `"indexer_hit"` or `"bare"` — P2-T10 uses
  it to derive `alerts.source` (planning decision 3). Phase-1 Khối 1's "hai dạng payload" test becomes
  three cases here.

  **2 · Field derivations — F3, F4, F5 and DEC-014, exactly.**
  - `alert_id` ← `id` (never the indexer's `_id`, phase-1 B5). Missing → **reject**.
  - `rule_id` ← `rule.id` as text; `description` ← `rule.description`. Missing either → **reject**.
  - `manager_id` ← `manager.name`, default `'default'` (F3).
  - `agent_name` ← `agent.name`; **when the `agent` object is absent, `agent_name ← manager.name`,
    `agent_id` and `agent_ip` stay `NULL`, and the alert proceeds** — never a rejection (DEC-014).
    This is defensive behaviour for a shape the manager can emit; **do not write any frequency for
    it** in code, comments or your report — the figure once quoted was withdrawn.
  - `origin_host` ← `predecoder.hostname`, fallback `agent.name` (F5), fallback `manager.name`.
  - `alert_time` ← `fields.timestamp[0]` when the envelope carries it; else `timestamp` with the
    `+0700 → +07:00` normalisation before `datetime.fromisoformat` (phase-1 Khối 3); **both paths are
    first-class** — the second is the replay path and the safety net, not an error branch (DEC-019).
    Neither parses → **reject** with the field named; never `now()`.
  - `event_time` ← **always `None`** in P2 (planning decision 5: F4 fills it only when the agent's
    timezone is declared in the inventory, and the inventory format has no such field). Leave
    `predecoder.timestamp` in `raw_payload`; write the reason as a one-line comment where a future
    reader will look for the derivation.
  - `srcip`/`dstip` ← `data.srcip`/`data.dstip`, missing → `''` (B1); `src_port`/`dst_port` via
    `_safe_int`, missing → `0` (C2); `alert_user` ← `data.dstuser`, fallback `data.srcuser`, missing →
    `None` — **never `''`** (`ck_alerts_alert_user_khong_rong`, measured: `CHECK (alert_user <> '')`);
    `decoder` ← `decoder.name` fallback `decoder.parent`; `mitre_ids` ← `rule.mitre.id[]`;
    `rule_groups` ← `rule.groups[]`; `rule_level` ← `rule.level` via `_safe_int`, missing → severity
    `low`; `severity` by Khối 4 (`≥12 critical, ≥8 high, ≥5 medium, else low`).
  - `category, categories, resolved_by, mapping_version` ← `ingest.category.resolve(mitre_ids,
    rule_groups, decoder, dst_port)` — all four signals, always (phase-1 Khối 5 constraint 1).
  - `srcip_is_private`/`dstip_is_private` via `_is_private` (C4, `ipaddress`, `''` → `None`).
  - `raw_log` ← `full_log`, missing → `''`; truncated at `RAW_LOG_MAX_BYTES` **by bytes, backing
    off to a UTF-8 boundary**, with `raw_log_truncated = True` (C3). The DB agrees:
    `ck_alerts_raw_log_tran_1000kb` is `octet_length(raw_log) <= 1024000`.
  - `event_bucket_hash` ← `compute_event_bucket_hash(rule_id, srcip, dstip, agent_name, alert_time)`
    = sha256 of `f"{rule_id}|{srcip}|{dstip}|{agent_name}|{floor(epoch_utc/300)}"` (C1/B6), on the
    canonical alert `76fcfceb90ed06f6be274be022445ff693254b73edbdb70180244328119b2a1a` — hard-coded
    in a test. The DB checks `^[0-9a-f]{64}$`.
  - `raw_payload` ← the **alert object** (the `_source` for a hit, the object itself otherwise) — that
    is what `alerts.raw_payload` holds, `NOT NULL`. The envelope (`_id`, `_index`, `sort`) is preserved
    on the `intake` row's `raw_text` (P2-T11/T13), not here.

  **3 · What the parser returns.** `parse_wazuh_alert(doc: Mapping) -> ParseResult`, a frozen dataclass
  with `alert: Alert | None`, `rejection: str | None` (the missing field's name — never an exception
  message, phase-1 §Xử lý lỗi), `envelope: Literal["indexer_hit","bare"]`. It is **total**: every test
  in phase-1's "Test bắt buộc" that says "không raise" is an assertion here. It reads no clock (R7 —
  acceptance 9 greps for it), touches no DB, imports only `domain`, `infra` (for `Config`'s
  `RAW_LOG_MAX_BYTES`) and `ingest.category`.

  **4 · `domain/alert.py`.** `Alert` — a frozen dataclass with exactly the parser's output fields
  above plus the lifecycle defaults phase-1's "Dữ liệu đầu ra kỳ vọng" lists (`status='received'`,
  `occurrence_count=1`, `triage_status='pending'`, …) so P2-T06/T10 have one shape to INSERT.
  `AlertContext` — `(asset_present: bool, asset_criticality: str, asset_owner: str | None, asset_role:
  str | None, identity_privileged: bool | None, ioc_reputation: str, lookup_status: dict[str, str])`,
  where `asset_criticality ∈ high|medium|low|unknown`, `ioc_reputation ∈
  malicious|suspicious|clean|not_found|skipped`, `lookup_status` values ∈ `found|not_found|skipped`
  (phase-4 "Ba trạng thái"). **You define it; P2-T08 fills a dict that P2-T10 turns into it; P2-T09
  reads it** (planning decision 4). `severity_from_level(level: int) -> str` and
  `compute_event_bucket_hash(...)` live here so `ingest` and `domain` share one definition. `domain`
  imports only `infra`/`audit` — nothing from `ingest`.

  **5 · The no-`fields` fixture, and the five real ones you already have.** Measured today: the
  five `indexer_sample_rule*.json` written by P0-T04's probe carry keys `_id, _index, _score,
  _source, sort` and **no `fields`** — the probe never requested it — so they are five real examples
  of the live no-`fields` shape and the fallback path. The canonical `alert_40112.json` and the hits
  in `indexer_search_page.json` **do** carry `fields`. To compare the two paths on **one** alert,
  create `backend/tests/fixtures/indexer_hit_no_fields.json` by copying `alert_40112.json` and
