- **Design notes:**

  **1 · The entry point and its result.** `evaluate(conn, alert: Alert, ctx: AlertContext, *, rules:
  Sequence[Rule] | None = None) -> AutocloseDecision`, a frozen dataclass `(blocked_by: str | None,
  match: AutocloseMatch | None)` where `AutocloseMatch` is **imported from `app.domain.transitions`**
  (P2-T06 defines it there so `domain` never imports `ingest`). `match is None and blocked_by is None`
  means "no rule matched — proceed to the queue"; `blocked_by` names the hard block that fired
  (`critical | never_autoclose_agent | asset_high | asset_not_in_inventory | identity_privileged |
  ioc_bad`) and is what the pipeline logs. `rules` defaults to the cache (note 4) — tests pass an
  explicit list.

  **2 · Hard blocks, in this order, before any rule is read** (`prompts/P2.md`; G8′):
  1. `alert.severity == "critical"`;
  2. `alert.agent_name in Config.NEVER_AUTOCLOSE_AGENTS`;
  3. `ctx.asset_criticality == "high"`;
  4. **`not ctx.asset_present`** — the host is absent from the inventory (distinct from present-with-`unknown`, which does **not** block — `inventory-format.md` §1);
  5. `ctx.identity_privileged is True`;
  6. `ctx.ioc_reputation in ("malicious", "suspicious")`.
  A blocked alert is never matched for closing — but for block 1 the spec wants a signal: when
  `severity == "critical"` **and** a rule would have matched, write the audit row
  `alert.autoclose_blocked_critical` with `{"rule_id": …}` (phase-3 §Xử lý lỗi — "tín hiệu rule cần
  xem lại"). The other five blocks return silently (structured log line, no audit — there is no event
  type for them in §6.1, and inventing one is a contract change).

  **3 · The whitelist and the operators — transcribe, do not widen.** Phase-3's table plus the three
  v3 internal fields: `rule_id` (`eq`,`in`), `category` (`eq`,`in`), `srcip`/`dstip`
  (`eq`,`in`,`cidr`), `agent_name`/`agent_id` (`eq`,`in`,`prefix`), `alert_user` (`eq`,`in`),
  `decoder` (`eq`,`in`), `dst_port`/`src_port` (`eq`,`in` — remember `0` means "no data", C2),
  `rule_level` (`eq`,`lte`), **`asset_criticality`** (`eq`,`in`), **`identity_privileged`** (`eq`),
  **`ioc_reputation`** (`eq`,`in`). `cidr` is evaluated with `ipaddress` in Python (`ip in
  ip_network(value, strict=False)`), deterministic and index-free. **Three things stay out, on
  purpose** (phase-3): any other enrichment field (`risk_score`, owner, role), `srcip_is_private`
  (an address property, not a security conclusion — a rule that wants a private range writes
  `cidr`), and `regex` as an operator (ReDoS). A rule whose `match` names a field or operator outside
  the whitelist, or whose `match` is not a list of `{field, op, value}` objects, is **skipped whole**
  with a warning log — never "minus the bad condition", which would widen it (phase-3 §Xử lý lỗi).

  **4 · Loading and caching rules.** `load_rules(conn) -> list[Rule]`: `SELECT autoclose_rule_id, name, match,
  reason FROM autoclose_rules WHERE enabled ORDER BY created_at ASC, autoclose_rule_id ASC` — the `ORDER BY` is
  what makes two identical alerts close by the same rule (A3). The column is `autoclose_rule_id`:
  migration 006 renamed it, and the earlier draft's `rule_id` fails on a migrated database with
  `column "rule_id" does not exist` (measured 06/09). `ix_autoclose_rules_enabled` is
  `(created_at, autoclose_rule_id) WHERE enabled = true`, i.e. exactly this `ORDER BY`. `Rule` is a frozen dataclass; parsing
  `match` happens at load, so a broken rule is skipped once, not per alert. Cache: a module-level
  `(monotonic_loaded_at, rules)` with a **60 s TTL** (phase-3 AC-C4; not a §6.3 key, so a module
  constant `RULE_CACHE_TTL_S = 60`, and `reload_rules(conn)` busts it — P5's admin route will call
  it). The pipeline (P2-T10) loads rules **before** taking the advisory lock; you make that easy by
  keeping `load_rules` separate from `evaluate`. A load failure → empty list → nothing closes
  (fail-open, A8).

  **5 · `simulate(conn, match: list[dict]) -> SimulateStats`.** Over the last 30 days of **clusters**
  (`duplicate_of IS NULL AND status <> 'duplicate' AND NOT is_synthetic AND received_at >= now() -
  interval '30 days'`), apply the same matcher — hard blocks included, using each alert's stored
  `asset_context`/`identity_context`/`ioc_context` jsonb columns to rebuild its `AlertContext` — and
  return `{"clusters": n, "alerts": sum(occurrence_count), "by_severity": {...}, "by_asset_criticality":
  {...}, "samples": [≤ 20 alert_ids]}`. Same code path as `evaluate` — a rule the simulator says would
  close 40 clusters must close exactly those 40 when enabled. Explicit column list (G10).

  **6 · Layer 2 — the width report.** `rule_width_report(conn, days: int = 7) -> list[dict]`: phase-3's
  query with `AUTOCLOSE_RULE_WIDTH_PCT` from `Config` — `sum(occurrence_count)` per
  `autoclose_rule_id` over the window against `count(*)` of all alerts in the window, rows over the
  threshold. **Sum, not count** (M4: after clustering, a rule that closed 5,000 alerts is one row).
  P5's health job calls it; you ship it with one test whose data makes the difference visible (one
  `auto_closed` row with `occurrence_count = 5000` must show as 5000, not 1).

  **7 · No control sample.** Phase-3's 5 % sample, its per-rule-per-day cap and the sample flag in
  the audit payload are v1; D8 replaced them with "① runs on 100 % of auto-closed alerts" and the
  digest (planning decision 7). Do not implement any of the three; `open_alert("auto_closed")`
  enqueues `triage` for every auto-closed alert.

  **8 · Tests are the owner; rules need a creator.** `autoclose_rules.created_by` is `uuid NOT
  NULL` **with a foreign key to `users(user_id)`** — `fk_autoclose_created_by`, migration 007; measured
  06/09: a random uuid fails with `violates foreign key constraint "fk_autoclose_created_by"`. So
  every test, and the shell lines in acceptances 4 and 5, first insert one user:
  `INSERT INTO users(user_id,username,display_name,role,password_hash) VALUES
  ('00000000-0000-0000-0000-00000000aaaa','t09','t09','admin','x')` (`role` is CHECKed to
  `tier1|tier2|admin`; the five columns are the ones `NOT NULL` without a default). The match-everything rule is `match = []` (an empty
  AND is true) — that is the G8′ test: with it enabled, the six blocked alerts still return
  `blocked_by`, and the seventh (non-critical, listed agent absent, asset `medium`, present,
  non-privileged, IoC `not_found`) returns a match. Encode DEC-012's facts: `IA1803` (`high`) is
  blocked by `asset_high`; `user1-IA1803` (`medium`, `user1` non-privileged) is closable.

  **9 · Your own database, DSN inline.** `TEST_DATABASE_URL=postgresql:///soc_p2t09_test` on every
  pytest line (DEC-023 item 8).
