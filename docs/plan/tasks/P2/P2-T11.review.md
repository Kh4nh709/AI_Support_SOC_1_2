## Non-blocking notes

1. **`is_heartbeat` reads the class attribute `Config.HEARTBEAT_RULE_ID`, not an instance value —
   verified to silently ignore a configured override.** `Config(HEARTBEAT_RULE_ID="999999")` still
   makes `is_heartbeat` match only `"100999"` (measured: `is_heartbeat({"_source": {"rule": {"id":
   "999999"}}})` on that instance → `False`; `id: "100999"` → `True`). This is design note 5's
   own literal formula (`doc["_source"]["rule"]["id"] == Config.HEARTBEAT_RULE_ID`, no `cfg`
   parameter in the prescribed signature) — the Coder transcribed it verbatim and disclosed the
   class/instance subtlety as Deviation 2, so under DEC-009 this is not chargeable here. But §6.3
   documents every constant in it, `HEARTBEAT_RULE_ID` included, as "overridable by env," and this
   function silently defeats that for the one key it reads. No acceptance item exercises an
   override, so nothing here fails today (the deployed value is `100999`); flagging for the
   Director as a likely card defect (design note 5 should probably read `cfg.HEARTBEAT_RULE_ID`
   with `cfg` added to `is_heartbeat`'s signature) before it bites a future environment.
2. **`P2-T11.report.md`, acceptance 4's evidence is mislabeled.** The pasted request-1 body
   (`gte=1785542400000`) is the *no-prior-cursor* (`PULL_START`) arm; the report's own sentence
   claims it is `"a pre-seeded cursor 1786903000000 − PULL_OVERLAP_S(60)×1000"`, which computes to
   `1786902940000`, not `1785542400000`. I independently ran the actual pre-seeded-cursor arm
   myself (item 4 above) and it is correct — `gte == cursor − 60000` exactly, and the permanent
   test `test_request_bodies_carry_fields_size_gte_and_search_after` asserts and passes this same
   thing. The underlying behaviour is right; only this one transcript/explanation in the report is
   self-inconsistent. Worth a one-line fix to the report, not worth a round.

Neither note changes the verdict: both are either not chargeable to this Coder (DEC-009) or do not
affect a currently-shipping behaviour, and both are surfaced here rather than silently passed over.
