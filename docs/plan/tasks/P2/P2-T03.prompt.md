- **Design notes:**

  **1 · The canonical category set is the playbook directory, not the `Final-Project` map.** Measured
  today: `kb/playbooks/` holds exactly ten files — `c2_beacon`, `data_exfiltration`, `malware`,
  `policy_violation`, `privilege_escalation`, `ransomware`, `recon`, `ssh_brute_force`,
  `suspicious_login`, `web_attack` — and they are, one for one, the eleven names of phase-1's
  priority table minus `unknown`. Phase-1 R5 is a hard rule: **every category a map can produce must
  have a real playbook**, enforced by a test that scans the directory. So the `Final-Project` tables
  are ported **by value**, with this rename table applied to every map:

  | `Final-Project` value | v3 value | why |
  |---|---|---|
  | `malware_detection` | `malware` | same thing, playbook name |
  | `command_and_control` | `c2_beacon` | same thing, playbook name |
  | `web_attack_sqli`, `web_attack_xss`, `web_attack_webshell` | `web_attack` | one playbook covers the class |
  | `port_scan` | `recon` | same thing, playbook name |
  | `rdp_brute_force`, `phishing`, `persistence`, `suspicious_execution` | **dropped from the maps** | no playbook exists; R5 forbids mapping to a category without one |

  A signal whose only mapping was dropped simply does not match at that tier — resolution falls through
  to the next tier and ends at `unknown` if nothing else matches (phase-1: `unknown` is a *health*
  metric, and an alert with `category='unknown'` proceeds normally). **List the four dropped keys and
  the `rule.groups` / MITRE ids that used to reach them in your report** — the P3 playbook review
  decides whether any of them gets a playbook, and that review needs the list.

  **2 · The priority table, verbatim from phase-1 §Khối 5, declared as a tuple in code:**
  `ransomware > malware > c2_beacon > data_exfiltration > privilege_escalation > ssh_brute_force >
  web_attack > suspicious_login > recon > policy_violation > unknown`. Sorting is by this table,
  **never** by the order the SIEM sent the array (R4). The canonical alert is the proof: `mitre.id =
  ["T1078","T1110"]` resolves to `category = "ssh_brute_force"`, `categories = ["ssh_brute_force",
  "suspicious_login"]`, and reversing the array changes nothing.

  **3 · The signature and the five tiers.**
  `resolve(mitre_ids: Sequence[str], groups: Sequence[str], decoder: str | None, dst_port: int)
  -> Resolution` where `Resolution` is a frozen dataclass `(category: str, categories: tuple[str, ...],
  resolved_by: str, mapping_version: str)`. Tiers, each consulted only when the ones above produced
  nothing: 1 exact MITRE technique (`T1110.001` as-is) → `resolved_by='mitre'`; 2 parent technique
  (`T1543.003` → `T1543`) → `'mitre_parent'`; 3 `rule.groups` → `'rule_groups'`; 4 decoder substring
  match (`"sshd"` in `decoder.name`) → `'decoder'`; 5 destination port → `'dst_port'`; nothing →
  `category='unknown'`, `categories=()`, `resolved_by='none'`. Those six strings are the DB's
  `ck_alerts_resolved_by` set — measured: `('mitre','mitre_parent','rule_groups','decoder','dst_port','none')`.
  Note the parent-technique tier is **separate** from tier 1 in v3 (the `Final-Project` code folds
  them into one function): `resolved_by` must say which one fired.

  **4 · `MAPPING_VERSION = "v3.1"`** — a module constant, stored on every alert (`alerts.mapping_version`
  is `NOT NULL`, no default — measured), so a later change to the tables tells you which alerts need
  re-classifying. Bump it in the same commit as any table edit; the test that hashes the tables and
  pins the version is your reminder.

  **5 · The `Final-Project` constraint the port fixes.** Its ingest path called the resolver with
  `decoder=""` and `dst_port=0`, so tiers 4–5 never ran there and the RAG path got different answers
  for the same alert (phase-1 §Khối 5 constraint 1). v3 has **one** caller — the parser — and it passes
  all four signals. Your test proves tiers 4 and 5 are reachable.

  **6 · Pure.** No I/O, no clock, no DB. Total: nothing on this path may raise on any input — an empty
  list, `None`, a non-string in the array, a port that is not an int — R2 says return `unknown`
  instead. Use `str(x).strip()` defensively as the original does.
