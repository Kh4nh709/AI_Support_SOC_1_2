## Non-blocking notes

1. **`category.py:32` overstates totality.** The module docstring says "`resolve()` never
   raises on any input". Measured false — an object whose `__str__` raises propagates out of
   all three string-coercing tiers:
   `resolve([Hostile()],[],None,0)`, `resolve([],[Hostile()],None,0)` and
   `resolve([],[],Hostile(),0)` each raise `ValueError`. The behaviour is **correct against
   the card**: design note 6 enumerates the inputs it means (empty list, `None`, a non-string
   in the array, a port that is not an int — all four handled, acceptance 5 green) and tells
   the Coder to "use `str(x).strip()` defensively as the original does", and the original has
   no `try`. `_safe_str`'s own docstring states the real bound correctly — every signal comes
   from JSON, whose value types cannot make `str()` raise — so the module docstring
   contradicts its own helper. One clause fixes it ("on any JSON-derived input"). Worth doing
   because P2-T04 is the caller and its author may read line 32 as licence to skip boundary
   validation.

2. **Card design note 3's worked example is dead — for the Director, not the Coder.** It
   gives `T1543.003 → T1543` as the parent-tier illustration, but design note 1 drops `T1543`
   (it mapped to `persistence`, which has no playbook). Measured: `resolve(["T1543.003"],…)`
   → `unknown`/`none`. Anyone transcribing design note 3 literally writes a test that fails.
   The Coder used a live example instead (`T1071.999 → T1071` → `c2_beacon`/`mitre_parent`)
   and did not flag the collision; the card is where it should be fixed.

3. **Deviation 1 is sound, and acceptance 6 is what caused it.** Verified at the source:
   `Final-Project/…/category_resolver.py:73` is `"command_and_control": "command_and_control"`
   — the string is a legitimate Wazuh `rule.groups` **key** as well as the old category
   **value** the rename table retires. Acceptance 6's grep is textual over the whole file and
   admits no exception for "key, not value", so keeping it fails acceptance 6 and splitting
   the literal to dodge the grep would be precisely the green-while-proving-nothing shape
   DEC-025 exists to catch. Dropping it was the right call and the Coder reported it. Cost,
   measured: an alert whose *only* signal is that group no longer resolves at tier 3;
   `c2_beacon` remains reachable at tier 1 (`T1071`, `T1071.004`) and tier 4 (`suricata`).
   **For the Director:** acceptance 6 should probably have been scoped to values, not to the
   whole file text. `port_scan` carries the same latent conflict but is not a group key in the
   source, so nothing was lost there.

4. **No separate RED commit.** Tests and implementation landed together in `cab1614`; the
   report does not claim otherwise and checklist item 3 is satisfied. I substituted mutation
   testing for the missing red evidence — nine mutations, all caught (below) — which is
   stronger evidence than commit order.

5. Minor: `_safe_str(None)` returns `"None"`, so `decoder=None` is looked up as the string
   `"none"` rather than being skipped. Harmless today — no `DECODER_TO_CATEGORY` key is a
   substring of `"none"` — but a future short key (`"on"`, `"one"`) would make a null decoder
   match it silently.
