- **Design notes:**

  **1 · Three functions, and what each may not do.**
  - `cluster_lock(conn, rule_id, srcip, dstip, agent_name) -> None`:
    `SELECT pg_advisory_xact_lock(hashtext(%s || '|' || %s || '|' || %s || '|' || %s))` with the four
    values as parameters — the **string is concatenated in SQL** so two application versions running
    side by side compute one key (phase-2 step 1, D4). It is `xact`-scoped: it dies with the caller's
    transaction, and the caller (P2-T10) takes it **before** any read. Never `hashtext(event_bucket_hash)`
    — that is the trap phase-2 names: two alerts of one key in different 5-minute buckets would not
    serialise.
  - `find_open_cluster(conn, alert) -> ClusterHead | None` — the phase-2 step-2 query **verbatim**, six
    predicates: the four key columns with plain `=` (B1: `srcip`/`dstip` are `NOT NULL DEFAULT ''`, so
    no `IS NOT DISTINCT FROM`, measured 38× the buffers); `(closed_at IS NULL OR sealed_at IS NULL)`;
    `status <> 'duplicate'`; `last_seen_at >= now() - IDLE_GAP`; `first_seen_at >= now() - (30 min if
    status = 'auto_closed' else 4 h)`; `occurrence_count < MAX_CLUSTER_SIZE`; `ORDER BY last_seen_at
    DESC LIMIT 1 FOR UPDATE`. The four constants come from `Config`, passed as parameters — never
    interpolated. `ClusterHead` is a frozen dataclass `(alert_id, occurrence_count, triaged_count,
    status)`. Explicit column list — G10 forbids `SELECT *` on `alerts`.
  - `bump_parent(conn, parent_id) -> int`: `UPDATE alerts SET occurrence_count = occurrence_count + 1,
    last_seen_at = now() WHERE alert_id = %s RETURNING occurrence_count`. **`now()` in SQL, never a
    Python timestamp and never the alert's `alert_time`** (B2/D9 — the agent-clock case is measured to
    kill dedup entirely). `ck_alerts_last_seen_khong_lui` (`last_seen_at >= first_seen_at`) is the DB's
    own guard.

  **2 · The index is already there; prove it is used.** Measured today on the migrated database:
  `ix_alerts_dedup ON alerts (rule_id, srcip, agent_name, dstip, last_seen_at DESC) WHERE ((closed_at IS
  NULL) OR (sealed_at IS NULL)) AND (status <> 'duplicate')` — the predicate matches phase-2's query
  **syntactically**, which is D7's condition. Your `EXPLAIN` test must see `Index Scan using
  ix_alerts_dedup`. Two things about that test, so it is not flaky and not vacuous: (a) on a nearly
  empty table the planner prefers a sequential scan whatever the index — run the `EXPLAIN` under
  `SET LOCAL enable_seqscan = off`, which answers the real question ("is the index *usable* for this
  predicate?"); (b) `FOR UPDATE` makes PostgreSQL repeat the partial predicate in a `Filter` line even
  when the index is used (phase-2 D7 note) — assert on the index name in `Index Scan`, not on the
  absence of `Filter`. **Failing case:** change `status <> 'duplicate'` in your query to
  `status != 'dup'` → the partial index no longer matches and the plan falls back; the test must go red.

  **3 · Tests are the owner and may set clocks; the product code may not.** To exercise `IDLE_GAP`,
  `MAX_AGE` and the auto-closed 30-minute cap without sleeping, the **test fixture** inserts alert rows
  with explicit `first_seen_at` / `last_seen_at` in the past (`now() - interval '16 minutes'`, etc.).
  That is allowed in a test as the owner; it is forbidden in `bump_parent` (D9), and acceptance 7
  greps for it. Rows you insert need the twelve `NOT NULL`-without-default columns — measured:
  `alert_id, rule_id, rule_level, severity, description, agent_name, alert_time, category,
  resolved_by, mapping_version, event_bucket_hash, raw_payload` (`event_bucket_hash` must match
  `^[0-9a-f]{64}$`; `resolved_by ∈ mitre|mitre_parent|rule_groups|decoder|dst_port|none`;
  `alert_user` is never `''`). Build one `_insert_alert(conn, **overrides)` helper.

  **4 · Two sessions on one cluster — a real concurrency test, not a mock.** Two connections
  (`psycopg.connect(TEST_DATABASE_URL)` each, the fixture's DSN). Session A: `BEGIN`, `cluster_lock`,
  `pg_sleep(1.5)`, `COMMIT`. Session B, started 0.2 s later in a thread: `BEGIN`, `cluster_lock` on the
  **same** key, record the wall-clock it waited. Assert B waited ≥ 1 s. Then repeat with a **different**
  `srcip` and assert B did not wait. And the phase-2 trap: the same key with two `alert_time`s in
  different 5-minute buckets **still** serialises (the lock is on the key, not the hash). Measure the
  wait with `time.perf_counter()` around the lock call — that clock measures the test, not the data.

  **5 · Which predicate is which, in the test names.** Phase-2's mandatory list is the map:
  `test_hai_alert_cach_2_phut_thi_gop` … `test_cum_cham_1000_alert_thi_mo_cum_moi`,
  `test_goc_auto_closed_THI_GOP`, `test_goc_closed_fp_thi_khong_gop_mo_cum_moi`,
  `test_goc_escalated_tier2_van_gop`, `test_ban_sao_khong_the_lam_goc`, `test_alert_srcip_rong_van_gop_duoc_voi_nhau`.
  Use those names (or their English equivalents with the Vietnamese in the docstring) so the
  Reviewer can map card → spec → test without reading the bodies.

  **6 · Your own database, DSN inline.** `TEST_DATABASE_URL=postgresql:///soc_p2t05_test` on every
  pytest line (DEC-023 item 8). The fixture drops, recreates and migrates it — with 016/017 merged it
  carries `ix_alerts_dedup` and the v3 columns.
