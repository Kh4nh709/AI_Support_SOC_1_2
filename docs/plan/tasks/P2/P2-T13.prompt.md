- **Design notes:**

  **1 · The entry point.** `python3 -m app.infra.puller <subcommand> [--env-file PATH]` with
  `argparse` (`if __name__ == "__main__": raise SystemExit(main())`). Two subcommands:
  - `backfill --since YYYY-MM-DD [--until YYYY-MM-DD]`: the P2-T11 page loop from `since` at
    00:00:00Z (epoch-millis), **without** reading or writing `source_cursor` — the live puller's
    cursor is not moved backwards by a backfill, and the UNIQUE makes re-reading harmless. Prints
    `hits/new/duplicates/heartbeats` per page and a total. `--since 2026-09-02` is the live-source
    half of the P2 gate; a run from any date before 02/09 (including `PULL_START`'s default) returns
    nothing before 02/09 and is **not** a failure (DEC-017 — say so in the summary line when `new == 0`).
  - `replay --archive-file PATH [--batch 500]`: read the file **as bytes**, split on `\n`, skip blank
    lines; for each line: `manager_id = manager.name` (default `'default'`), `source_alert_id = id`,
    `sort_key` = epoch-millis of the line's `timestamp` (`+0700 → +07:00`, then `fromisoformat`;
    DEC-019's one new derivation), `raw_text` = **the line's bytes decoded as UTF-8, newline stripped,
    nothing else** (G9), `via = 'pull'`; heartbeat lines (`rule.id == HEARTBEAT_RULE_ID`) as
    P2-T11 does; everything else `INSERT … ON CONFLICT (manager_id, source_alert_id) DO NOTHING
    RETURNING intake_id` and `enqueue("pipeline", …)` for each new id; commit every `--batch` lines
    so a crash loses at most one batch and a re-run skips what is there. A line that is not JSON, or
    has no `id`, is counted as `bad` and **written to `rejected_alerts`** (`raw_payload` = `{"line":
    <text>}`, `reason`), never silently dropped. Summary: `lines/new/duplicates/heartbeats/bad`.

  **2 · Both archive shapes ingest, and `alerts.source` follows.** `archive_line_5503.json` is a
  **Logstash-shaped** line (`@timestamp`, `event.original`, `host`, `tags` …) whose `event.original`
  is the raw manager line — the Owner's export may be either shape depending on which file they read
  (`/data/wazuh/logs/alerts/alerts.json` — `/var/ossec/logs/alerts/` until 14/09 — and the rotated dailies are raw manager lines; anything that
  went through Logstash carries the extras). Both have `timestamp`, `id`, `manager.name`, `rule.id`
  at top level, so the same code handles both; the parser (P2-T04) handles both downstream, and the
  pipeline derives `alerts.source = 'replay'` from `via = 'pull'` + no `_source` envelope (planning
  decision 3). Your test ingests the fixture **and** its `event.original` as two lines with different
  ids and asserts two intake rows, two jobs, and `raw_text` equal to each line's bytes.

  **3 · Refuse what the application cannot read, and say what to do instead.** If `--archive-file`
  resolves under `/var/ossec/` **or `/data/wazuh/`** (the manager's live tree — D3 stays cut, DEC-060:
  the puller is the only live path *by choice*, G9/G12), or is unreadable, exit `2` with the Owner
  procedure below on stderr — by path prefix, before any `stat`, so a path that happens to be
  readable (14/09: `/data/wazuh/logs/alerts/alerts.json` is mode 777) is refused all the same. Host
  history behind this rule: 07/09 (DEC-051) `user1` was in group `wazuh` (gid 124) and `sg wazuh`
  could read `/var/ossec/logs/alerts/`; **14/09 (measured 22:15): `/var/ossec` no longer exists,
  group `wazuh` no longer exists (`sg wazuh` fails), the manager's tree is `/data/wazuh/`, and its
  `logs/alerts/2026/` and `logs/archives/` are `drwxr-x---` gid 999 (no local name) — not readable
  by `user1` at all; only `alerts.json` itself is.** `sudo` needs a password. So the application
  will never read it; the CLI must not pretend otherwise. **The Owner procedure, printed by `--help`
  and by that error, verbatim:**
  ```
  # RUN AS user1. Only the read of the manager's dailies needs root (14/09: the directory is
  # gid 999 and no `wazuh` group exists any more, so the 07/09 `sg wazuh` form cannot work).
  # The globs are expanded by root inside `sh -c`; the redirect stays OUTSIDE the quotes so the
  # output file is created by user1's shell and belongs to user1 — no chown, no chmod.
  mkdir -p /home/user1/archive
  sudo sh -c 'zcat -f /data/wazuh/logs/alerts/2026/*/ossec-alerts-*.json.gz \
                      /data/wazuh/logs/alerts/2026/*/ossec-alerts-*.json' \
      > /home/user1/archive/alerts-<first-day>_<last-day>.jsonl
  wc -l /home/user1/archive/alerts-<first-day>_<last-day>.jsonl
  # What `2026/` holds on the new manager is NOT visible from user1 (measured 14/09) — the Owner
  # sees it with `sudo ls /data/wazuh/logs/alerts/2026/`. The 08/08–07/09 export already exists:
  # /home/user1/archive/alerts-2026-08-08_09-07.jsonl, 92,030 lines, 113,379,904 bytes, intact on
  # 14/09 — that file IS the G1 corpus (DEC-053, 3,070 clusters). A second export is only for
  # days after 07/09 the Owner decides to add to G1; it is a decision, not a default.
  # Why `zcat -f` and two explicit globs — three failures the first attempt actually hit:
  #  * `zcat -f` reads BOTH shapes; a bare `cat` of `Sep/ossec-alerts-0[1-6].json` matched
  #    nothing, because September's dailies are `.gz`. It silently lost the whole month.
  #  * that non-zero `cat` broke the `&&` chain, so `chown` and `chmod` never ran — one bug,
  #    two symptoms. The second accidentally saved the first: `chmod 600` on a root-owned
  #    file would have locked user1 out of the export entirely.
  #  * the two explicit globs exclude the `.sum` checksum files that a `*` would sweep in.
  # `sudo mkdir` would leave /home/user1/archive root-owned inside user1's own home; `mkdir`
  # runs as user1 here. Expect one gap in the old export: 2026-09-02's source file is 0 bytes.
  # Then, as user1, from the repository root with .env present:
  PYTHONPATH=backend python3 -m app.infra.puller replay --archive-file /home/user1/archive/alerts-2026-08-08_09-07.jsonl
  make run-worker                                                 # processes the pipeline jobs; stop it when `select count(*) from intake where processed_at is null` reaches 0
  ```
  The path `/home/user1/archive/` is outside the repository on purpose (nothing under a public
  remote); `eval/dedup_verify.py` (P2-T15) reads the same file.

  **3b · Report every agent the archive contains that the inventory does not (DEC-051).**
  `replay` counts alerts per `agent.name` and prints, before ingesting, any name absent from
  `conf/inventory.yaml` — name, alert count, first and last date. It ingests them anyway; this
  is a report, not a filter. Why it is required: the inventory is a point-in-time snapshot of
  the estate and the archive spans thirty days, so **any host that existed at any point in the
  window can appear in replay and is invisible until something looks.** Measured 07/09 on the
  real export: `DESKTOP-MIRSO17` (agent 002, a Windows 10 host) contributed 2,472 alerts, all
  on 05/09, and is in neither the inventory nor `agent_control -l`. `inventory.validate()`
  returns `[]` and always would — it checks the file's internal consistency and has no notion
  of the estate. Under G8′ an unlisted host is a hard auto-close block, so these rows pin to
  `needs_review`; that is G8′ working, not a defect, and the report is what makes it visible.

  **4 · Tests: no network, no root.** `backfill`'s page loop is exercised with `httpx.MockTransport`

  (`SystemExit(2)`, the procedure on stderr). Rows written as `via='pull'` with the envelope absent
