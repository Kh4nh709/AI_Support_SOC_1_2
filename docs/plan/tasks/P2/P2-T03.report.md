## 3. Deviations

**1 · One `Final-Project` `rule.groups` key is dropped for a reason outside the rename table.** `GROUP_TO_CATEGORY` carried a key whose text is byte-for-byte identical to the *old category value* for the c2 class (the same string used both as a Wazuh group name and, elsewhere in the same source file, as the pre-port category value that design note 1's rename table retires in favour of `c2_beacon`). Acceptance 6 forbids that exact string from appearing anywhere in `category.py`, in code or in comments, with no exception for "used as a key, not a value" — the grep is textual over the whole file. Keeping the key as a literal would fail acceptance 6 outright; encoding it as a split/concatenated string literal to dodge the grep would satisfy the letter of the check while hiding the real identifier from anyone who greps for it later, which is the same failure shape DEC-025 exists to catch, just inverted (a check made to read green while the condition it exists to catch is still present, only obfuscated). I dropped the key. Consequence: an alert whose *only* signal is that one `rule.groups` value now falls through tier 3 instead of resolving there — but `c2_beacon` stays reachable at tier 1 (`T1071`/`T1071.004`) and tier 4 (the `suricata` decoder substring), so the category is not orphaned, only this one specific rule-groups signal for it. Recorded here rather than reconciled silently, per rule 1.
