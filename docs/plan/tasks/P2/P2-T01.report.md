## 4. Open questions / follow-ups

- `DATABASE_URL` / `DATABASE_URL_OWNER` can carry an embedded password in TCP form (`.env.example`'s own comment: "its password goes after the colon, in .env only"). Neither `__repr__` nor `dump()` redacts it — the design note's explicit secrets list doesn't include these two keys, and both default to the passwordless socket form on this host, so it isn't a live leak today, but it is a gap in "never log secrets" (rule 11) if an operator ever sets the TCP form with a password. Flagging rather than fixing: redacting a DSN correctly needs URL parsing, which is scope this card didn't ask for and no acceptance exercises.
- `eval/indexer_probe.py`'s `read_env_file` (the function design note 2 points at as "the ten-line one … already uses") does not actually strip a trailing ` # comment` — it only skips whole-line comments. That exact "whitespace-before-`#`" behavior does exist in this repo, but in the `Makefile`'s `test-db` target (shell/`sed`), not in that Python function. I implemented the behavior design note 2 describes (matching the `Makefile`'s documented semantics, which is unambiguous and deliberate: "a `#` inside a DSN password survives") rather than byte-for-byte copying `indexer_probe.py`'s function, which appears to predate that refinement. Non-blocking; noted so nobody goes looking for a discrepancy between the two `.env` readers and assumes it's a bug in this one.
