## Non-blocking notes

1. `backend/app/infra/db.py:44` — `conn.execute("BEGIN")` is redundant. psycopg 3 with
   `autocommit=False` has already begun the transaction implicitly by the time this runs (measured:
   `conn.info.transaction_status` is `0`/IDLE before any statement and `2`/INTRANS after a bare
   `SELECT 1`), so every `transaction()` call makes the server emit
   `WARNING: there is already a transaction in progress`. It is invisible to the application —
   psycopg discards notices when no handler is registered, and a plain run prints nothing — but it
   lands in the PostgreSQL server log once per job, forever. **The card asked for it literally**
   (design note 2: "`BEGIN`, `SET LOCAL …`"), so this is card-faithful, not a Coder defect.
   Second-order consequence worth stating: `transaction()` therefore does not open an independent
   transaction — handed a connection with uncommitted work it silently joins and commits that work
   too. Every call site in this diff commits first, so nothing is wrong today.
2. Acceptance 9's `grep` scans `infra/jobs.py` and `infra/worker.py` but **not** `infra/db.py` — the
   only file in the task that actually issues `SET LOCAL`. The invariant holds in fact (verified by
   reading `db.py:45-46`: both statements are `SET LOCAL`, and `test_db.py:101` proves the timeout
   does not survive the commit), but the card's guard does not cover the file it most protects.
3. `backend/app/infra/jobs.py:158` — `cfg.JOB_BACKOFF[job.attempts - 1]` raises `IndexError` when
   `JOB_MAX_ATTEMPTS` exceeds `len(JOB_BACKOFF)`. Both are env-overridable per §6.3, and the raise
   happens inside `finish_job`, which the loop calls from its own `except` block — so it would
   escape `run_forever` and kill the worker, the one thing design note 4 forbids. Measured with
   `JOB_MAX_ATTEMPTS=5` and the default `JOB_BACKOFF=[10,60,300]`: attempts 1–3 back off correctly,
   attempt 4 → `IndexError: list index out of range`. Unreachable on §6.3's defaults
   (`JOB_MAX_ATTEMPTS=3`, three backoff entries), outside every acceptance item, and config
   validation belongs to P2-T01, so it does not block — but it is a real latent worker-killer and
   worth one line in whoever owns `Config` validation next.
4. Design note 2 specifies `SET LOCAL statement_timeout = %s`, a bind parameter Postgres rejects.
   The Coder used `psycopg.sql.Literal` instead and explained it in report §1 and the `db.py`
   docstring — correct, but it is a deviation from a card instruction and belongs in report §3
   rather than §1.
