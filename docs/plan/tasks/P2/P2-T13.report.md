# P2-T13 report — backfill CLI

## 1. Built

`backend/app/infra/puller.py` (all additions; `pull_once` and everything P2-T11 shipped are untouched except two additive, backward-compatible keyword params):

- `_post_search(..., *, lt_ms=None)` / `_fetch_page_with_raw(..., *, lt_ms=None)` — optional upper bound on the search range, unused by `pull_once` (default `None` reproduces its exact request body).
- `_is_forbidden_archive_path(path) -> bool` — pure string prefix check against `/var/ossec` and `/data/wazuh`, no `stat`/`open`.
- `_print_refusal(path, reason)` — the refusal message plus `OWNER_PROCEDURE` on stderr.
- `OWNER_PROCEDURE` — design note 3's Owner procedure, verbatim.
- `_backfill_loop(conn, client, cfg, gte_ms, until_ms=None, *, on_page=None) -> PullResult` — the `backfill` page walk; never reads or writes `source_cursor`/`source_heartbeat`.
- `_cmd_backfill(args) -> int` — `config.load()`, DSN from `DATABASE_URL_OWNER`/`DATABASE_URL`, prints per-page and total summary lines, notes `new=0` is expected before 02/09.
- `ReplayResult` — `lines/new/duplicates/heartbeats/bad` dataclass.
- `_parse_replay_line`, `_replay_sort_key`, `_insert_rejected` — one archive line's JSON parse, DEC-019's `sort_key` derivation (`+0700 → +07:00`, `fromisoformat`), and the `rejected_alerts` write.
- `replay_lines(conn, data, *, batch=500) -> ReplayResult` — the `replay` core: split on `\n`, one `intake`/`rejected_alerts` row per line, `conn.commit()` every `batch` lines and once at the end.
- `_AgentStats`, `_known_hostnames(cfg)`, `_unknown_agents(data, cfg)` — design note 3b's report; reads `conf/inventory.yaml` via `cfg.INVENTORY_PATHS` directly (PyYAML), never imports `app.enrichment`.
- `_cmd_replay(args) -> int` — prefix check → file read → unknown-agent report → DSN → `replay_lines` → summary.
- `_build_parser()`, `main(argv=None) -> int` — `argparse` with `backfill`/`replay` subcommands, `--env-file` on each, `OWNER_PROCEDURE` as epilog on both the top-level parser and `replay`.
- `if __name__ == "__main__": raise SystemExit(main())`.

`backend/tests/test_backfill_cli.py` (new, 33 tests) — path-prefix checks, CLI-level refusal (no DB touched), both archive shapes (design note 2), G9 byte-identity + jsonb control, bad/missing-id lines, re-run idempotency, batching/crash recovery (1,001 lines, `--batch 500`), heartbeat handling, `_replay_sort_key`, design note 3b's unknown-agent report, and the full `backfill` page-loop behavior against `httpx.MockTransport` (cursor untouched, `--until`, idempotency, heartbeats, per-page callback).

## 3. Deviations from the card and why

1. **`intake` is append-only (migration 017 — DEC-023/024), so the crash/batch tests and every other test that calls `replay_lines` (which commits by design) cannot share `soc_p2t13_test` with the rest of the suite.** Measured: a first attempt that committed ~2,001 rows via the 1,001-line batch tests into `soc_p2t13_test` made `test_schema_v3_017.py`'s `count(db, 'intake') == 1` assertions fail (`2008 == 1`) for the rest of that `make test-db` session, and the row could not be deleted afterward — `DELETE`/`TRUNCATE` on `intake` raises `append-only table: intake is immutable` even for the owner role (confirmed against `test_the_row_trigger_stops_the_owner_deleting`). Fix: every test in `test_backfill_cli.py` that needs `replay_lines` to actually commit uses a `replay_db` fixture that creates, migrates, and drops its **own** database (`soc_p2t13_replay_test`) within this module alone; it never touches `TEST_DATABASE_URL`. Tests that only exercise `_backfill_loop` (which never commits, matching `pull_once`'s "caller owns the transaction" design) keep using the standard `db` fixture and its rollback-based isolation, unchanged from P2-T11's convention. Verified clean: after a full `test_backfill_cli.py` run, `soc_p2t13_replay_test` no longer exists and `soc_p2t13_test`'s `intake` table has 0 rows.
2. **`make test` shows 2 pre-existing failures unrelated to P2-T13.** `test_dispatch_state.py::test_approved_task_has_something_left_to_merge[P2-T09]` and `[P2-T11]` fail because `docs/plan/STATE.md` at this branch's base (`main` @ `ea7656a`, which this worktree is deliberately still on per dispatch instructions) still marks those two rows `approved` while their branches are already ancestors of `main`.
