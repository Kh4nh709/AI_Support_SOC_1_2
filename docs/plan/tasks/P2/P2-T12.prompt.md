## Task
- **Goal:** a second way into `intake` with identical downstream behaviour: authenticated, size-capped before parsing, byte-identical storage, `201` with the intake id, `409` on a repeat, and a `pipeline` job in the same transaction.
- **Scope in:** `infra/intake.py` (`receive`), the route, the tests.
- **Scope out:** anything after `intake` (the pipeline does not know which door a row came through); rate limiting (C8 cut it); the JWT analyst auth (P4 — this route authenticates a machine with a shared key, not a person).
- **Files — create:** `backend/app/infra/intake.py`, `backend/tests/test_webhook.py`
- **Files — modify:** `backend/app/web/main.py` (add the route; touch nothing P2-T08 wrote)
- **Do not touch** any other file. If you believe you must, stop and report (rule 4).
- **Depends on:** **P2-T02**, **P2-T08** (the app exists), **P2-T11** (the intake INSERT helper), **and the DEC answering the INBOX item** — verify all four.
- **Design notes:**

  **1 · `receive(conn, body: bytes, source_ip: str, cfg) -> int`.** In this order, and nothing
  earlier than the size check reads the body: (a) `len(body) > MAX_PAYLOAD_BYTES` → `PayloadTooLarge`
  (`413`), before any parse; (b) `json.loads(body)` failure, or no `id` / no `rule.id` → `INSERT INTO
  rejected_alerts (raw_payload, reason, source_ip)` with `raw_payload = {"body": <text>}` if it was
  not JSON, and `Rejected` (`400`); (c) heartbeat → the P2-T11 heartbeat handling, `201`; (d) `INSERT
  INTO intake (manager_id, source_alert_id, raw_text, sort_key, via) VALUES (…, 'webhook')` with
  `raw_text = body.decode("utf-8")` **unchanged** (G9), `sort_key` = epoch-millis of the document's
  `timestamp` (the same derivation the replay path uses — DEC-019), `ON CONFLICT … DO NOTHING RETURNING
  intake_id`; `None` → `Duplicate` (`409`); else `enqueue("pipeline", …)` in the same transaction and
  return the id. `is_synthetic` is never set from the outside: the webhook cannot produce a row the
  pipeline would mark synthetic (phase-1 B5 — there is no such field in the body contract).

  **2 · The route.** `POST /webhook/alerts` on `web/main.py`: read `X-API-Key`; missing or wrong →
  `401` **writing nothing** (phase-1: an attacker must not be able to grow the database without a
  key); source IP not in `⟨KEY⟩` allowlist → `403` (log at warning); then `receive(...)` and map its
  exceptions: `413`, `400` (with the missing field's name, never an exception message), `409`, `201
  {"intake_id": n}`. Compare the key in constant time (`hmac.compare_digest`). The `get_conn`
  dependency P2-T08 wrote is reused; tests override it exactly as `test_reload_inventory.py` does.

  **3 · The two keys — filled from the DEC.** `⟨KEY⟩` #1: the shared secret (`WEBHOOK_API_KEY`
  proposed; empty → the route answers `503` "webhook disabled", never "no auth"); `⟨KEY⟩` #2: the
  allowlist (`WEBHOOK_IP_ALLOWLIST` proposed, a JSON list of CIDRs, empty → deny all). Both enter
  `Config` (P2-T01's parse rules) — **the Coder does not add them to §6.3 or `.env.example`**: the
  DEC does, and `scripts/gen_env_example.py` regenerates the block.
