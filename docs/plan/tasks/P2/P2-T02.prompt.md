- **Design notes:**

  **1 · Why `infra/worker.py` knows no handler (G1, planning decision 1).** The pipeline handler lives
  in `soar/`, a tier; `infra` may not import it, and `test_import_rules.py` rejects the import on
  sight. So the loop is `run_forever(conn_factory, handlers: Mapping[str, Handler], *, once: bool =
  False, sleep_s: float = 1.0)` with `Handler = Callable[[psycopg.Connection, Job], None]`, and
  `python3 -m app.infra.worker` **no longer runs a worker** — P2-T10 creates `web/worker.py` (a
  composition root, allowed to import everything) that builds `{"pull": …, "pipeline": …}` and calls
  you, and changes the Makefile line. Your tests exercise the loop with fake handlers. `once=True` runs
  one claim-dispatch-finish cycle and returns — that is what every test and the G7 test use.

  **2 · `infra/db.py`.** `connect(dsn: str | None = None) -> psycopg.Connection` (autocommit off;
  `dsn` defaults to `Config.DATABASE_URL`, and an empty `DATABASE_URL` is a `ConfigError` naming the
  key — a worktree has none, so tests always pass the `db` fixture's connection explicitly);
  `transaction(conn, *, statement_timeout: str = "3s")` as a context manager: `BEGIN`, `SET LOCAL
  statement_timeout = %s`, `SET LOCAL idle_in_transaction_session_timeout = '10s'`, commit on exit,
  rollback on exception, re-raise. `SET LOCAL` is per-transaction and dies with it — that is the point;
  never `SET` without `LOCAL`. **No `psycopg_pool`**: it is importable on this host and not in
  `backend/requirements.txt`; acceptance 8 greps for it.

  **3 · `infra/jobs.py` — the queue, and the index that makes it single-flight.** Measured today:
  `ux_jobs_mot_job_song_moi_subject` is `UNIQUE (job_type, subject_id) WHERE status IN ('pending','running')`.
  - `enqueue(conn, job_type, subject_id, *, scheduled_at=None) -> int | None`:
    `INSERT … ON CONFLICT (job_type, subject_id) WHERE status IN ('pending','running') DO NOTHING
    RETURNING job_id` — a partial unique index **is** inferrable by `ON CONFLICT` when the `WHERE`
    matches the index predicate. Returns `None` when a live job already exists. This is what makes
    `jobs('triage')` and the self-scheduled `pull` idempotent without any Python-side check.
    `job_type` is validated against §6.5's six values *in Python too* (a clear `PermanentError`
    naming the value beats `ck_jobs_job_type`'s message).
  - `claim_job(conn, job_types: Sequence[str]) -> Job | None`: phase-4's two statements in one
    transaction — `SELECT … WHERE status='pending' AND scheduled_at <= now() AND job_type = ANY(%s)
    ORDER BY scheduled_at FOR UPDATE SKIP LOCKED LIMIT 1`, then `UPDATE jobs SET status='running',
    locked_at=now(), attempts=attempts+1`. **The `job_type = ANY(%s)` filter is load-bearing**: a P2
    worker must leave `triage` rows untouched for P3's handler (hand-off item 1), not claim and fail them.
  - `finish_job(conn, job, *, outcome: Literal["succeeded","transient","permanent"], error: str | None
    = None)`: `succeeded` → `status='succeeded'`; `permanent` → `status='failed'`, `last_error`;
    `transient` → if `attempts >= JOB_MAX_ATTEMPTS` → `status='failed'` **and** an audit row
    `job.exhausted` (`subject_id` = the job's subject, `actor_role='system'`), else `status='pending'`,
    `scheduled_at = now() + JOB_BACKOFF[attempts-1] seconds`, `last_error`. With the defaults that is
    10 s after the first failure, 60 s after the second, `failed` after the third — phase-4 P4-7's table.
    `now()` is the database's, in SQL — never a Python timestamp (§9 "Time").
  - `reclaim_stale(conn) -> int`: `UPDATE jobs SET status='pending', locked_at=NULL WHERE
    status='running' AND locked_at < now() - JOB_LOCK_TIMEOUT_S`. Returns the count. **Its test is a
    real reclaim, not a clock mock:** insert a `running` row with `locked_at = now() - interval '301
    seconds'` as the owner (tests are the owner), call `reclaim_stale`, see `1`, see the row `pending`.
  - `Job` is a frozen dataclass `(job_id, job_type, subject_id, attempts)`.

  **4 · The loop.** Per iteration: `reclaim_stale`; `claim_job` in its own short transaction; if a job:
  open `transaction(conn, statement_timeout=…)` (3 s default; P5's `conclude` asks for 5 s — take the
  timeout from the handler table entry if you make entries `(handler, timeout)`, or a second mapping;
  either is fine, say which); call the handler; on success `finish_job(…, "succeeded")`; on exception
  `classify(exc)` → `finish_job(…, "transient"|"permanent", error=str(exc)[:1000])`, **never
  re-raise out of the loop** — a bad job must not kill the worker. Structured JSON log lines to
  stdout per §9 (`{"job_id":…, "job_type":…, "outcome":…, "ms":…}`), never a payload, never a secret.
  **A handler may ask to be run again:** if it returns `Reschedule(delay_s: float)` (a tiny frozen
  dataclass you define in `infra/jobs.py`), the loop — **after** `finish_job(…, "succeeded")` has
  committed — calls `enqueue(job_type, subject_id, scheduled_at = now() + delay_s)` in a fresh
  transaction. That is how the `pull` job re-arms itself every `PULL_INTERVAL_S` (P2-T11) without
  the loop knowing what `pull` is, and why the order matters: while the current job is still
  `running`, a new `pending` row for the same `(job_type, subject_id)` would collide with
  `ux_jobs_mot_job_song_moi_subject`; after it is `succeeded` the index admits it. The loop stays
  generic — it never names a job type.

  **5 · `audit/events.py`.** `write_event(conn, event_type: str, subject_id: str, actor_role: str, *,
  actor_id: str | None = None, payload: dict | None = None) -> int`. `EVENT_TYPES` is a frozenset of
  the **27** names §6.1 fixes (the 21 v1 names + the 6 v3 names — take the list from
  `docs/plan/tasks/P1/P1-T05.prompt.md` design note 2, where it is pasted verbatim from the live
  constraint) and an unknown name is a `PermanentError` before SQL runs. Two DB CHECKs you must
  respect, measured: `ck_audit_actor_role` — `actor_role IN ('system','llm','analyst')`; and
  `ck_audit_actor_id_theo_role` — `actor_role='system'` requires `actor_id IS NULL`, `'analyst'`
  requires it `NOT NULL`. `payload` is passed as `psycopg.types.json.Jsonb`. `created_at` is the DB
  default. This module never updates or deletes: `audit_events` is append-only (017), and the test
  proves an `UPDATE` through your connection raises.

  **6 · Import direction, stated so no one "tidies" it.** `infra/*` imports nothing from
  `backend/app` but `infra`; `audit/events.py` imports `infra` only (`errors`, and `db` if you want
  the transaction helper). No `domain`, no `ingest`, no `soar`.

  **7 · Test as the owner on your own database.** Every db-marked test runs with
