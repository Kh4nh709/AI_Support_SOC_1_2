- **Design notes:**

  **1 · Why a fold over `alert_time`, stated in the script's docstring.** The product's
  `find_open_cluster` anchors `IDLE_GAP` on `last_seen_at >= now() − 15 min` and `MAX_AGE` on
  `first_seen_at` — **database clock**, by design (phase-2 B2/D9: the agent clock is measured to kill
  dedup). Replaying 29 days in an afternoon puts every alert of a key inside one wall-clock window
  and would report a handful of clusters, measuring nothing about the data. The Owner's 2,778 came
  from applying the same predicates over the alerts' own timestamps; this script does that with the
  product code for everything that is not the clock: `parse_wazuh_alert` for the fields, the four-column
  key `(rule_id, srcip, dstip, agent_name)` with `''` for missing IPs (B1), and the constants from
  `Config`. What it verifies: **the key derivation and the predicate arithmetic**. What it does not:
  the DB path — that is P2-T05's job on a real database.

  **2 · The fold.** Sort all parsed alerts by `alert_time` (stable, then by `alert_id`). Per key keep
  the open cluster `(first_seen, last_seen, count)`. For each alert: open a **new** cluster when there
  is none, or `alert_time − last_seen > DEDUP_IDLE_GAP_MINUTES`, or `alert_time − first_seen >
  MAX_CLUSTER_AGE_HOURS`, or `count >= MAX_CLUSTER_SIZE`; else join it (`count += 1`, `last_seen =
  alert_time`). Three predicates of the six do not apply offline and you say so: "still absorbing"
  and "not a duplicate" are structural (every archive alert is a fresh arrival), and the 30-minute
  auto-closed cap needs a rule set the archive did not have — the Owner's measurement applied
  `IDLE_GAP`, `MAX_AGE`, `MAX_SIZE` only (DEC-032), so the fold applies exactly those three. Rejected
  lines (`ParseResult.rejection`) are counted and excluded, never guessed.

  **3 · Output.** A table to stdout: `lines, parsed, rejected, clusters, ratio (parsed ÷ clusters)`,
  then `clusters per day` (by `alert_time` in `Asia/Ho_Chi_Minh`, the archive's day boundary),
  then the storm day `2026-08-16` alone (`alerts, clusters, largest cluster size, clusters that hit
  MAX_CLUSTER_SIZE, clusters that hit MAX_CLUSTER_AGE`) — that day is where `MAX_CLUSTER_SIZE=1000`
  and `MAX_CLUSTER_AGE_HOURS=4` actually bind (DEC-014). `--json` prints the same as one object.
  Verdict: `--expect 2778 --tolerance-pct 1.0` → exit `0` within tolerance, `1` outside, and the
  line `VERDICT: <clusters> vs <expect> (<±pct>) — <PASS|FAIL>`. Missing or unreadable
  `--archive-file` → exit `2` with the Owner procedure from P2-T13's `--help` on stderr. Never
  print a raw line (hostnames, users, IPs — the report may be pasted into a public repository).

  **4 · Tolerance, honestly.** The Owner's run processed **83,957** lines; the DEC-014 count of the
  same archive by another glob was 84,376 (a 0.5 % difference in the file set). `--tolerance-pct 1.0`

  wrong key column, a `>=` for a `>`, a timezone slip), not a new fact; **do not tune a constant to
