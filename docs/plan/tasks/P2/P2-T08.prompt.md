- **Design notes:**

  **1 · `load(conn, paths: Sequence[str | Path] | None = None) -> LoadReport`.** Validate first with the
  existing `validate(paths)`: any problem that is not a `warning:` line aborts the load with
  `PermanentError` listing the problems — a half-loaded inventory is worse than the old one. Then, per
  file, in one transaction the caller owns:
  - `assets`: `INSERT … ON CONFLICT (hostname) DO UPDATE SET criticality, owner, role, source, loaded_at
    = now(), active = true, updated_at = now()` with `source` = the file's **basename**
    (`inventory-format.md` §4: "`source` (tên tệp)"); then `UPDATE assets SET active = false WHERE source
    = %s AND active AND hostname <> ALL(%s)` — rows that vanished from the file become inactive and
    keep their history. `identities` the same on `username` with `is_privileged`.
  - `iocs` differ: the CSV carries its **own** `source` column (free text, default `'internal'` when
    empty — measured, `006_chot_hop_dong.sql:54`), and `(value, source)` is the primary key. Upsert on
    that pair with `reputation`, `expires_at`, `loaded_at = now()`, `active = true`; deactivate every
    `iocs` row whose `(value, source)` is not in the file. Do not write the file name into `iocs.source`
    — it is the indicator's provenance, not the loader's.
  - `LoadReport(assets: int, identities: int, iocs: int, deactivated: int, warnings: list[str])` — the
    numbers the route returns. Never `DELETE`.
  - The real files are git-ignored; tests write their own three files into `tmp_path` in the `.example`
    shape and pass `paths=` explicitly — never read `conf/*.yaml` from a test (a worktree does not have
    them either).

  **2 · `lookups.py` — three functions, three states, dicts only.** `enrichment` may import only
  `infra` (§4), so these return plain dicts and **do not import `app.domain`**; `soar/pipeline.py`
  turns them into an `AlertContext` (planning decision 4). Every dict carries `"status"` ∈
  `found | not_found | skipped` (phase-4: `not_found` is a security signal, `skipped` is not).
  - `lookup_asset(conn, agent_name: str, origin_host: str | None) -> dict`: `SELECT hostname,
    criticality, owner, role FROM assets WHERE hostname = %s AND active` for `agent_name`, then for
    `origin_host` if different (F5: "tra kiểm kê cả hai"). `found` → the row's values; `not_found` →
    `{"status":"not_found","present":False,"criticality":"unknown","owner":None,"role":None}`. **The
    `present` flag is G8′'s "asset not in inventory"** and is distinct from a present row whose
    criticality is `unknown` (`inventory-format.md` §1 explains why they differ).
  - `lookup_identity(conn, username: str | None) -> dict`: `None` → `skipped` (phase-4: "alert không
    có trường để tra"); else `SELECT is_privileged FROM identities WHERE username = %s AND active` →
    `found` with `is_privileged`, or `not_found` with `is_privileged: None`.
  - `lookup_ioc(conn, srcip: str, dstip: str, *, srcip_is_private: bool | None, dstip_is_private:
    bool | None) -> dict`: candidates are the non-empty IPs whose private flag is **not** `True`
    (C4: private → `skipped`, and `''` → nothing to look up); none → `skipped`; else `SELECT value,
    reputation FROM iocs WHERE value = ANY(%s) AND active AND expires_at > now()`; the worst reputation
    wins (`malicious > suspicious > clean`); no row → `not_found`. Returns `reputation ∈ malicious |
    suspicious | clean | not_found | skipped` — §6.2's `ioc_reputation` vocabulary exactly, so gate step
    2 (P3) compares strings without a mapping.
  - Every lookup is deterministic and read-only (E1: always run, never model-decided; the pipeline
    calls all three for every alert, auto-closed ones included — M1).

  **3 · `web/main.py`.** `app = FastAPI()`, a `get_conn()` dependency yielding a `psycopg` connection
  from `infra.db.connect()` (committed on success, rolled back on error, closed always), and
  `POST /api/admin/reload-inventory` → `load(conn)` → `LoadReport` as JSON, `200`; a `PermanentError`
  from validation → `422` with the problem list. **No authentication in P2** — `infra/auth.py` is
  P4's; P4 wraps this route with the `admin` dependency (hand-off). Say so in a comment on the route,
  with the hand-off item's number. `make run-app` already points at `app.web.main:app`.

  **4 · Testing the route without a password.** `DATABASE_URL` (the `app_rw` DSN) exists only in the
  Owner's `.env`; a worktree has none. Tests override `get_conn` with the `db` fixture's connection
  (`app.dependency_overrides[get_conn] = lambda: conn`) and use `fastapi.testclient.TestClient`
  (FastAPI's own, pinned). One test additionally `SET ROLE app_rw` on the fixture connection before the
  reload and asserts it succeeds — 017 grants `app_rw` `INSERT/UPDATE` on the three tables and
  `ALTER DEFAULT PRIVILEGES` covers them; that is the proof the real application role can reload.

  **5 · Real inventory facts to encode as tests (DEC-012).** `IA1803` at `criticality: high` and
  `user1-IA1803` at `medium`; `user1` `is_privileged: false`; `root` privileged. A lookup for a host in
  the file with `criticality: unknown` returns `present: True, criticality: "unknown"`; a host absent
  from the file returns `present: False` — two different dicts, and the G8′ tests in P2-T09 depend on
  the difference.

  **6 · Your own database, DSN inline.** `TEST_DATABASE_URL=postgresql:///soc_p2t08_test` on every
  pytest line (DEC-023 item 8).
