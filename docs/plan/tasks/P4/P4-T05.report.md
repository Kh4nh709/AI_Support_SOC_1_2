### Shoulds

- **S2 — the `HX-Redirect` success flash was dead code.** htmx navigates on
  `HX-Redirect` before it processes any swap, so the flash fragment `decide`/
  `escalate` used to send in that same response body was never seen (this matches
  what this report's own §4 already flagged as untested and possibly broken — the
  Reviewer's jsdom harness confirmed it). Fixed: `post_decide` now sends
  `HX-Redirect: /queue?flash=closed&n=<closed_count>` with an **empty** body;

  `queue_page` takes `flash`/`n`/`case`/`cut` as query parameters and a new
  `_queue_flash` helper builds the message from a fixed two-entry table — a
  digits-only `n` and an 8-hex `case` are the only values ever interpolated; anything
  else (an unrecognised `flash` kind, or a malformed `n`/`case`) drops the whole flash
  rather than rendering something broken or attacker-controlled. Six new tests
  (`test_queue_flash_closed_shows_message`, `..._unknown_kind_shows_nothing`,
  `..._bad_n_shows_nothing`, `..._escalated_with_cut_shows_case_and_truncation`,
  `..._bad_case_shows_nothing`) plus the two existing redirect tests changed from
  `== "/queue"` to `.startswith("/queue")`.

  `_decision_form.html` now takes `user` and renders the Tiếp nhận/decide/escalate/
