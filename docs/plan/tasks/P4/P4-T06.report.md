## 3. Deviations from the card

1. **The Director's design change (dispatch, not a deviation from it):** a private scratch
   database (`<TEST_DATABASE_URL's dbname>_e2e_test`, created/migrated/dropped by this module,
   `test_auth.py`'s `scratch_dsn`/`sdb` shape) with a real-shape `get_conn` override
   (`try: yield conn; conn.commit()` / `except BaseException: conn.rollback(); raise`), instead
   of the 19/09 card's `app.dependency_overrides[deps.get_conn] = lambda: db`. `PGHOST`/
   `PGPORT`/`PGUSER`/`PGPASSWORD` are derived from `TEST_DATABASE_URL` and passed explicitly to
   the `createdb`/`dropdb` subprocess calls (`test_health.py`'s pattern), never relied on from
   the ambient environment.
2. **Page assertions as merged, not as the 19/09 card describes** (per `P4-T05.review.md`):
   decide's success redirect is `/queue?flash=closed&n=<N>`, never bare `/queue`; escalate
   answers `201`, not `200`; the decision controls render for `tier1` only, tier2/admin see "Chỉ
   Tier 1 thao tác được"; a 409/422/503 is a `#flash` fragment sitting outside `#decision`
   (never dropped by htmx); an unknown alert is an HTML 404 page.
3. **`occurrence_count` for the fan-out head is set by an explicit `UPDATE`, not by
   `open_alert(kind="duplicate")` alone.** Read `domain/transitions.py:open_alert`: the
   `"duplicate"` branch inserts the duplicate row (status `duplicate`, `closed_at`/`sealed_at`
   `now()`) and writes `alert.duplicate_merged`; it never increments the *parent's*
   `occurrence_count` — that increment is `ingest/dedup.py`'s job in the real pipeline, not
   exercised here. `test_decide.py`, `test_tier1_api.py` and `test_pages_alerts.py` all set
   `occurrence_count` directly via `UPDATE alerts SET occurrence_count = …` for exactly this
   reason; this file does the same (`UPDATE … = 4` after three `open_alert(kind="duplicate")`
   calls, and the `+ 21` optimistic-lock bump).
4. **Each flow's alerts sit at a distinct multi-hour offset from the canonical fixture's
