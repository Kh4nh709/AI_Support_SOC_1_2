# P4-T08 report — `infra/intake.py` + `POST /webhook/alerts`

## 1. Built

- `backend/app/infra/intake.py` — `receive(conn, body, source_ip, cfg) -> Receipt`: size cap before any parse (413), JSON/object validation and `id`/`rule.id` presence (400, one `rejected_alerts` row each), heartbeat recognition reusing `puller.is_heartbeat` (201, no job, `puller._update_heartbeat` touched), else an `intake` INSERT with `via='webhook'` + `enqueue(conn, "pipeline", ...)` in the same statement sequence (201) or `Duplicate` (409) on the `ON CONFLICT`. Exception classes `PayloadTooLarge`, `Rejected(reason)`, `Duplicate`; dataclass `Receipt(kind, intake_id)`.
- `backend/app/web/routers/webhook.py` — `POST /webhook/alerts`: empty `WEBHOOK_API_KEY` → 503; missing/wrong key (constant-time `hmac.compare_digest`) → 401 before the body is ever read; source IP outside `WEBHOOK_IP_ALLOWLIST` → 403 (logged at `warning`, IP only); reads the body and maps `intake.receive`'s outcomes to 413/400/409/201, committing before the 400 so its `rejected_alerts` row survives `Conn`'s rollback-on-`HTTPException`.
- `backend/tests/test_webhook.py` — 16 tests (`@pytest.mark.db`), against a dedicated scratch database (`<TEST_DATABASE_URL db>_webhook_test`) built and dropped once per module, the same pattern `test_auth.py` uses and for the same reason: the shared `db` fixture's isolation depends on nothing ever being committed, and the 400/`commit-before-raise` case needs real commit semantics to be a discriminating test at all.

## 3. Deviations

1. **Case (b)'s red demonstration was not run against the real route file.** Claude Code's own auto-mode safety classifier declined the edit that would have replaced `hmac.compare_digest` with `==` in `webhook.py`, tagging it a security weakening (correctly — it is, even as a five-minute revert). Rather than argue with or route around that guard, I demonstrated the same grep discriminator on a throwaway copy under the scratchpad directory: the mutated copy matches the forbidden pattern (red), the real file — never touched — stays silent (green). This proves the grep is not vacuous (DEC-039's standard) without ever putting insecure code in the deployed route, even transiently.
2. **The card's acceptance 1 doesn't specify the shape of `test_missing_key_is_401_and_writes_nothing`/`test_wrong_key_is_401_and_writes_nothing` beyond the name.** My first draft checked only `intake` row count, which is silent to defect (c) (a `rejected_alerts` write on a 401) since that table was never queried. Caught while producing case (c)'s red demonstration, before this report was written; both tests now also assert a `rejected_alerts` count delta of zero across the request. No card text needed to change.
3. Two extra tests beyond the 14 named ones: `test_archive_line_bare_body_is_accepted` (exercises design note 3's `archive_line_5503.json`'s `event.original` body, which the 14 named tests don't individually cover) and `test_intake_module_has_no_forbidden_imports` (acceptance 4's import grep, restated as a test so a future edit to `intake.py` fails locally, not just at acceptance time).
4. Everything else matches the card's design notes 1–3 as written; no scope, file-list, or contract deviation.
