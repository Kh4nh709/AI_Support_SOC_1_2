  `VerificationError`) **and on `InvalidHashError`**, which in argon2-cffi 25.1.0 is a `ValueError`,

- `Claims(user_id, username, role, iat: float, exp: float)` — frozen dataclass.
- `LoginFailed(reason ∈ unknown_user|bad_password|inactive)`, `AccountLocked(locked_until)`,
  `Unauthorized(reason ∈ missing|malformed|expired|unknown_user|inactive|logged_out)`,

- `login(conn, username, password, cfg) -> Claims` — in the card's order: empty secret →
  `AuthDisabled` before any SQL (the test passes `conn=None`); `SELECT … FOR UPDATE` with
  `locked_until > now()` computed in SQL; locked → `AccountLocked` without a password check;
  inactive → `LoginFailed("inactive")`; wrong → the card's `UPDATE … RETURNING` (fifth wrong locks

  `iat = time.time()`, `exp = iat + JWT_TTL_HOURS·3600`. Never commits: the caller does (note 4).

- `create_user(conn, *, username, display_name, role, password) -> str` — role validated in Python
  against `ROLES`, `INSERT … gen_random_uuid() … RETURNING user_id`, then the `admin.user_created`

  (`actor_role='system'`, `actor_id NULL`, payload `{username, role}`).
- `set_password(conn, username, password) -> bool`, `deactivate(conn, username) -> bool`
  (`is_active = false, sessions_invalid_before = now()` in one statement).
- CLI — `build_parser()`, `main(argv) -> int`, `python3 -m app.infra.auth`:

## 3 · Deviations

1. **Acceptance 4's literal one-liner is a card defect on `fastapi==0.141.1`** (measured; §2 item 4).
   I kept `app.include_router` as the card requires — flattening `router.routes` into `app.routes`
   by hand would bypass `dependency_overrides_provider` and break every test override — and used
   `app.openapi()["paths"]` in `test_routers_are_discovered_sorted_and_auth_routes_exist`. The same
   expression appears in **P4-T03 acceptance 5** (`contains all six /api/tier1/... paths`); the
   Director may want to swap it for the `openapi()` form there before dispatch.
2. **`test_reload_inventory.py` changed in two lines beyond the card's fixture + one test:**
   `monkeypatch.setattr(main.db, …)` → `deps.db` in the two `get_conn` tests. `get_conn` now reads
   `db` from `deps`' namespace and `main.py` no longer imports `db` (the card: "nothing else lives
   in `main.py`"), so `main.db` does not exist. The alternative — an unused `from app.infra import db`
   in `main.py` purely so a test can patch it — is the worse change. (I had also relaxed
   `test_only_the_reload_inventory_route_exists_under_api`; the review showed that was unnecessary —
   on 0.141.1 `app.routes` never lists an included router's paths, so `main`'s exact assertion
   passes verbatim and is the guard for design note 5 — and it is restored verbatim.)
3. **`verify_password` also catches `argon2.exceptions.InvalidHashError`.** The card names
   `VerifyMismatchError` and "any other `Argon2Error`"; on argon2-cffi 25.1.0 `InvalidHashError`
   is a `ValueError` (MRO measured: `InvalidHashError → ValueError → Exception`), so a garbage
   hash would have escaped as a 500. `test_malformed_hash_is_false_not_error` covers `"garbage"`,
   `""` and the 011 backfill value.
4. **`Conn = Annotated[psycopg.Connection, Depends(get_conn, scope="function")]`** instead of the
   card's `Depends(get_conn)`. Measured at the ASGI level on 0.141.1: with the default scope the
   yield-dependency's exit code — `get_conn`'s commit — runs *after* the response has been sent
   (`send 204`, then `commit`), so `POST /api/auth/logout` answered 204 while the old token still
   verified on a second connection. `scope="function"` (FastAPI ≥ 0.121) runs the exit code after
   the path operation and before the response, for every route that takes `Conn` — P4-T02/T03/T08
   and P6-T02 inherit it. `get_conn` itself is unchanged; a route's exception still reaches its
   `except` first, so the commit-before-raise pattern is untouched (red steps (a)/(b)
   re-demonstrated under the new scope). Guarded by `test_api_logout_commits_before_the_204_is_sent`.
5. **Committing tests run on a scratch database `test_auth.py` builds and drops**, not the session
   database. `audit_events` is append-only to the owner too (migration 017's triggers), so the
   `admin.user_created` / `authz.denied` rows a committing test leaves cannot be cleaned up, and
   `test_schema_v3_017.py` counts that table from zero — `make test-db` was 6 red until this. The
   name is `<session dbname>_auth_test` (`soc_test` → `soc_test_auth_test`), so two runs on different
   DSNs cannot collide; rollback-only tests stay on `db`; an autouse guard fails any test that
   takes the scratch fixtures without `@pytest.mark.db`.
6. **Hardening from the adversarial review, beyond the card's letter** (each with a test and a
   red step): the inactive-user branch runs the dummy argon2 verify (same 401 body *and* the same
   cost as an unknown user — measured 4.6 ms vs 145.8 ms before); a DSN psycopg cannot parse is
   exit 2 with a fixed message (psycopg's `ProgrammingError` text quotes the DSN, and it is not an
   `OperationalError`); `--dsn`/`--env-file` are accepted before the subcommand (argparse would
   otherwise echo the DSN in `invalid choice: '<dsn>'`); `getpass` at EOF is the "empty password"
   exit 1, not a traceback; two `--user`s whose names map to one `SEED_PASSWORD_` key
   (`a-b`/`a_b`, or a case pair — the Owner holds two accounts) are refused before connecting; a
   blank cookie or bearer is `401 not authenticated` rather than `malformed`.
7. **Two helpers the card did not name:** `deps.set_session_cookie` / `deps.clear_session_cookie`
   (so P4-T04 reuses the call instead of the five attributes) and `deps.ROLE_TO_ACTOR` is used via
   `.get(role, "analyst")` — the card's `"admin" if … else "analyst"` in one lookup.

Not deviations, stated so nobody looks: the card's `(%s || ' minutes')::interval` is used as
written (an `int || text` concatenation is valid in PostgreSQL 16 — measured); the 423 is a
`JSONResponse` after `conn.commit()` because the card's flat `{"detail": "locked", "locked_until"}`
body cannot come out of `HTTPException`; the 22 card-named tests exist under their exact names.
