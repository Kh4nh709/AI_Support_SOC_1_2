## 3 · Deviations

1. **P4-T01's CLI was on `main` when quoted.** It was not at dispatch (`auth.py` = 1 line at `761b85d`); `main` gained the merge (`348c199`) while I was reading, so I fast-forwarded to `6e377c8` before the first commit and quoted the real `--help` (`seed-users --user USERNAME ROLE DISPLAY_NAME`, repeatable; `--env-file`/`--dsn`; passwords from `SEED_PASSWORD_<USERNAME>` or a prompt). The command in block 1f is P4-T01's report §4 verbatim with the four placeholders.
2. **Nine numbered subsections, not eight.** Design note 10 says "the eight `###` subsections" but enumerates `0 …` … `8 …`, and acceptance 2 counts `^### ` ≥ 9; the Goal lists (0)–(8). The test pins the enumeration 0–8 in order (nine headings) under the card's test name `test_pilot_section_and_eight_subsections_in_order`. Card slip (index-side count), not a scope change.
3. **Row f is split in two + a block.** The card's (f) is one row with the seed command; written that way the four `--user` sit on one line and `grep -c -- '--user'` (a line count) gives `1`, not `≥ 4`. Row **f** now proves the CLI is present (`seed-users --help`), block **1f** below the table carries the command on five lines, row **f′** verifies the four `users` rows. The test finds the block by its `--user`, so a `--help` probe is not mistaken for the seed command.
4. **Rows the card did not list, added:** **h′** (a login probe with a non-existent username → `401`, proving the running app loaded `JWT_SECRET`; `503` = started before row a); the DB-side heartbeat checks in §5 (`intake` rows with `outcome='heartbeat'`, `source_heartbeat.last_seen_at`) next to the card's `_count`. **Aligned with DEC-102 (landed on `main` during the task):** row **d1** carries the Owner Assist's detached start form and the pidfile stop (`kill -- -$(cat /home/user1/soc-logs/worker.pid)`), row **g** says the worker must be **restarted after P3-T10 merges** (option A — a running process never picks up the `triage` handler), §8 says the same for any merge touching `worker.py`/`soar/`/`infra/puller.py`.
5. **§5's `unavailable` remedy** reads `llm_runs.stopped_by` and `jobs.last_error` — `llm_runs` has no `error` column (schema 003/016).
6. **The adversarial review I ran on the draft covered 1 of 6 lenses.** A Workflow (6 lenses → 2 refuters each) lost five lenses to the session limit; only `test-robustness` completed (6 findings: 1 upheld and applied — section-scoping of the positive checks; 5 refuted as hardening beyond the card, two of which I applied anyway: fence masking, wider secret regex).
