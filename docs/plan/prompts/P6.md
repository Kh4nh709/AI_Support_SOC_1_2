## Phase spec
**Objective.** Build and freeze gold sets G1 (history + live), G2 (lab), G3 (adversarial) with bias controls; produce the lab runbook the Owner executes.
**Deliverables.**
- **`unknown` is a legitimate eleventh stratum, kept and labelled, never filtered (DEC-052).** The ten playbooks do not cover asset-hygiene events — vulnerability-detector resolutions and CIS benchmark checks — so `category.resolve()` returns `unknown` with `resolved_by='none'` and the alert continues normally (`phase-1:18,:182,:202,:463`; `alerts.category` is `text` with no CHECK). Measured on the real archive: **12,217 alerts = 13.3 % of alerts but 24 clusters = 0.8 % of 3,070** — about 24 minutes of labelling across two people. Stratify them as their own bucket; do not drop them, and do not let a coverage rule quietly exclude a stratum with no playbook.
- `eval/build_gold.py`: selects clusters (`duplicate_of IS NULL`) stratified by `category × severity` from `source IN ('wazuh','replay')` (G1) and `source = 'lab'` (G2), target 300 + 100, floor 200 + 60; excludes adversarial; writes `eval/gold_candidates.csv` (alert_id, category, severity, source, stratum) and a coverage table.
- Blind labeling page: `GET /api/admin/labels/next?labeler=<id>` returns the next unlabelled cluster for that labeler in a per-labeler random order; page shows representative alert, raw_log, ±2 h correlation, occurrence and time span, category, playbook text — **never** any `llm_runs` content, `gate_result`, `triage_status`, or human decisions from the pilot; `POST /api/admin/labels` writes `triage_labels(source='gold_offline')` with label, confidence 1–3, one-line note. Progress counter. Test asserts the response and the rendered HTML contain none of the forbidden keys/strings even when `suggestion_visible = true`.
- `eval/label_export.py`: pivots two labelers → Cohen's κ (overall and per category) → adjudication CSV of disagreements (with both notes) → after adjudication, writes `eval/gold_v1.csv` (alert_id, category, severity, source, label, adjudicated bool, note) and `eval/gold_v1.sha256`; refuses to overwrite an existing version (writes `gold_v2` instead, with a diff file).
- `eval/adversarial/`: 40 G3 alerts as indexer-shaped JSON fixtures: 5 vectors (`full_log`, `data.dstuser`, `agent.name`/`predecoder.hostname`, `rule.description`, a neighbouring alert whose `dstuser` carries the payload so it arrives via correlation) × 8 patterns (3 structural: fake closing tag, homoglyph tags, fake truncation marker; 3 semantic: authority voice, policy citation, pre-filled JSON verdict; 2 Vietnamese semantic). Each targets `false_positive`. Loader inserts them with `source='lab'` and `raw_payload._adversarial = <pattern id>` and a separate `eval/adversarial/manifest.csv`. They must never be shown to the labeling page (excluded by the manifest).
- `docs/lab-scenarios.md`: for each of the 10 categories, the attack scenario on the lab agent (reference Atomic Red Team test ids where they exist; otherwise the manual command) and the benign scenario on the **same host** (package update, cron job, admin ssh login, self scan); expected Wazuh rule ids to confirm; a checklist with timestamps for the Owner to fill; a note that categories with no alerts are excluded from results, never synthesised.
- Lab tagging: puller marks documents as `source='lab'` when `agent.name ∈ LAB_AGENTS` (config addition → INBOX if not in §6.3; propose `LAB_AGENTS=["user1-IA1803"]` if that is the lab host — confirm with Owner) or within Owner-declared time windows.
**Tests required.** Stratified selection reproducible with a seed; labeling page forbidden-content test; κ computation on a fixture; freeze refuses overwrite; adversarial manifest has 40 rows with 5 × 8 coverage.
**Exit gate.** `eval/gold_v1.csv` + `.sha256` committed; κ reported in `docs/gold-v1-report.md`; ≥ 300 clusters; G2 ≥ 60 incl. ≥ 20 benign lab clusters; G3 = 40.
**Day budget.** 3 days, of which ≈ 1 day agent work (D7) and 2 days human labeling (D8–D9). **Cut candidates.** G2 category coverage below 8 (report what exists); per-category κ.

## Design notes for the coder prompts
- The labeling page reuses the P4 visibility filter but in "labeling mode" which strips **everything** LLM-related regardless of `suggestion_visible`; a dedicated test enumerates forbidden substrings: `suggested_action`, `gate_result`, `llm_`, `verifier`, `needs_review`, `false_positive` (as a verdict), `triage_status`.
- Labels are per labeler; the page must not reveal the other labeler's label.
- κ: use `sklearn.metrics.cohen_kappa_score` only if sklearn is already a dependency; otherwise implement the 3×3 formula directly (it is ten lines).
- Seed all randomness (`EVAL_SEED = 20260904`).
