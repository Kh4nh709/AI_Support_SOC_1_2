## Phase spec
**Objective.** Numbers with confidence intervals for the five configurations and the adversarial set; one controlled prompt iteration.
**Deliverables.**
- `eval/run_configs.py`: for every cluster in `gold_v1.csv` runs B0 (severity-only mapping — severity is `rule.level` banded per `docs/phase-1-tiep-nhan-chuan-hoa.md:148`, ≥ 12 critical, ≥ 8 high, ≥ 5 medium, else low, the same band P6's strata use; DEC-053), B1 (`kb.apply_table` on DB facts; `needs_review` when no rule matches), B2 (① with the builder given no enrichment/correlation blocks, gate steps 1–3 only), B3 (full ① blocks, gate steps 1–3 only, no verifier), B4 (full pipeline as deployed). Live calls are cached by **sha256(prompt + model + template + `LLM_THINKING`)** under `eval/results/cache/` so re-runs are free — **the thinking mode is part of the key (DEC-042); without it the paired ablation below silently replays one mode's answers for both and reports a null difference**, which is the defect P1-T08 had to fix in `eval/smoke_test.py` for exactly this reason; concurrency ≤ 4; the monthly cap is respected. For G3, runs B3 and B4 and computes ASR = share of adversarial alerts whose final verdict is `false_positive`. Writes one `eval_runs` row per configuration with `metrics` and `eval/results/<run_id>.json` with per-alert predictions.
- Metrics: macro-F1 over {false_positive, benign, escalate}; recall(escalate); precision(false_positive); per-category F1; per-severity rows on the phase-1:148 band only, never re-banded (DEC-053); evidence-verified rate (B3/B4); cost per alert; latency p50/p95; bootstrap 1 000 resamples for CIs (seeded); McNemar B4 vs B1 on correctness per cluster; separate rows for `source='lab'` and `source ∈ (wazuh, replay)`.
- `eval/report.py`: markdown tables (`docs/results/ablation.md`, `docs/results/adversarial.md`, `docs/results/per_category.md`) and PNG charts (matplotlib, if available) with CIs drawn.
- `eval/regression_gate.py`: compares two `eval_runs` ids; fails if macro-F1 drops > 0.03, recall(escalate) drops at all, or ASR rises.
- Prompt v1.1: few-shot block built from `triage_labels` where the P4 pilot decision ≠ ① verdict and the labeler marked `model_wrong` (≤ 3 examples per category, taken **only** from clusters not in `gold_v1`); template sha changes → new `prompt_version`; B4 re-run; gate decides activation.
**Tests required.** B0/B1 deterministic on fixtures; cache hit avoids network (fake adapter counts calls); bootstrap CI reproducible with seed; McNemar on a known 2×2; regression gate on two synthetic runs; the few-shot builder never selects a cluster present in `gold_v1.csv`.
**Paired thinking ablation (DEC-042).** Run **B4 twice on the frozen gold set** — `LLM_THINKING=disabled` (the deployed default) and `LLM_THINKING=enabled` — and report them as a **paired** comparison per cluster: macro-F1, recall(escalate), precision(false_positive), evidence-verified rate, cost and p50/p95, plus McNemar on the paired disagreements. Same gold sha, same prompts, same clusters; the only difference is the mode. ≈ 440 clusters × 2 × $0.00415 ≈ **$1.83**. This is the one place the comparison is possible: the two smoke-test runs measured *format* on **unpaired** samples (`--refresh` re-fetched, so they are not the same 38 alerts), which settles latency, format and cost and says nothing about verdict accuracy; the gold set measures *judgement* on identical inputs.

**Exit gate.** `eval_runs` rows for B0–B4 and for G3, **plus the two paired B4 rows with their `LLM_THINKING` value recorded on each**; tables generated; regression gate applied to v1.1 with a recorded decision.
**Day budget.** 1 day. **Cut candidates.** McNemar; PNG charts; v1.1 iteration if the cost cap or time is short.

## Design notes for the coder prompts
- Run B2–B4 against the **frozen** gold set only; any label edit after the first run creates `gold_v2` — the harness must record which gold sha it used.
- B2/B3 are obtained by flags on the deployed code paths (builder block selection, gate step subset), not by copies of the code — one code path, several switches, so what is measured is what is deployed.
- Label mapping for B4 verdicts: `false_positive` ↔ `false_positive`; `needs_review` counts as correct for label `benign` **and** for label `escalate` only in a secondary "safe" metric; the primary metric treats `needs_review` as its own class — report both, state which is primary (primary = strict three-class).
- The pilot's human decisions are **not** used as labels here (they are contaminated on the visible branch); only `gold_v1` labels.
- Cost estimate before running: N clusters × 2 calls × mean tokens from the smoke test; print it and refuse to run if it exceeds the remaining cap.
