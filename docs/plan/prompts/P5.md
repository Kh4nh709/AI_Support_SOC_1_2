## Phase spec
**Objective.** Cases with ②, the digest loop, health alarms, backup.
**Deliverables.**
- `tier2/dossier.py`: deterministic nine-block dossier (context pack §7.6): case header as facts; every cluster with raw_log ≤ 8 KB in blocks; timeline ≤ 300 lines in a block; extracted entities (regex for IPv4/IPv6, md5/sha1/sha256, domains with IANA TLD list; usernames from `data.dstuser/srcuser`; hosts from `agent.name` and `predecoder.hostname`) with inventory lookups and a 7-day per-entity history (alert counts by category); ±2 h correlation per alert as structured rows; Tier-1 decisions from `audit_events`; playbooks for every category in the case; notes and previous ② result; the out-of-block "not available" sentence. Budget 60 k tokens with the truncation order raw_log 8 KB → 4 KB → representatives 15 → timeline.
- `llm/investigate.py` (single shot, `investigate_v2`), `tier2/investigate.py` job (`POST /analyze` → 202 with quota `ANALYZE_QUOTA_PER_USER_DAY` and one-running-per-case 409; nonce per attempt; evidence check: `alert_id ∈ case ∪ duplicates` and `quote` substring of that alert's raw_log or description; zero valid → `need_more_data`; `llm_runs` role `investigator` with `evidence_check`, `cost_usd`, `stopped_by`), `GET /runs/{run_id}`.
- `tier2/conclude.py` (`domain.conclude_case`, 5 s statement timeout, fan-out incl. duplicates, 409 on stale), `case_notes` REST, web screens: case list, case detail (② result with verified/unverified evidence marked, hypotheses with `evidence_against`, notes, conclude form), "analysing…" polling partial.
- `tier1/digest.py` job (08:00 daily; all clusters auto-closed in the last 24 h with their ① verdict; disagreements first) + admin digest page (one-click `correct | wrong | unsure` → `autoclose_reviews` + `triage_labels(source='digest')`; `wrong` → `domain.reopen` A17 with reason `digest`) + `rule.suspected_wrong` when a rule collects ≥ 2 `wrong` in 7 days + 17:00 reminder if unreviewed.
- Admin rules screen: create with simulate preview (counts by severity and criticality + 20 samples), toggle enabled; audit `admin.autoclose_rule_toggled` with before/after.
- `infra/health.py` job (every 5 min; thresholds from context pack: heartbeat > 30 min, unprocessed intake > 5 min, oldest pending job > 10 min, LLM null-result ratio 1 h > 30 %, `unavailable` 24 h > 10 %, monthly cost > 80 %, disk < 20 %, backup age > 36 h, inventory empty, digest unreviewed at 17:00) writing `system_health` and calling `infra/notify.py` (Telegram bot or SMTP; one adapter, env-selected); `GET /health` (no auth from localhost).
- `scripts/backup.sh` (`pg_dump -Fc` to `backups/`, keep 14) + compose cron entry; `scripts/restore.sh`.
**Tests required.** Dossier deterministic (two builds equal except nonce) and within budget on a 20-cluster synthetic case; entity extraction on fixtures; evidence check (id outside case, quote not found, zero valid → `need_more_data`); analyze quota and 409; conclude fan-out includes duplicates and is refused when stale; digest review path incl. reopen; `rule.suspected_wrong` trigger; health thresholds simulated per check with the notifier faked; backup script produces a file in CI (against the compose db).
**Exit gate.** ② runs on a real case with evidence check; digest reviews an auto-closed cluster and reopens it; health alarm fires with the indexer unreachable; a backup file is produced.
**Day budget.** 1 day (≈ 8 h; overbooked by design). **Cut candidates, in order:** ② (T01–T04) → digest UI (keep job + CSV) → health job (cron + grep). The Director decides at the evening gate; plan so that cutting ② removes whole tasks, not halves.

## Design notes for the coder prompts
- ② prompt: system template `investigate_system.txt` containing the word "JSON", the untrusted-data rule for every block, and "you have no tools; if data is missing answer need_more_data".
- The 7-day entity history is a single SQL per entity type using the correlation indexes; cap 50 entities.
- Digest job must be idempotent per day (re-running does not duplicate notifications).
- `notify.send(level, text)` never raises into the caller; failures are logged and counted.
- Health job writes one `system_health` row per run and sends only on state change (ok → alarm, alarm → ok) plus a daily 08:05 summary.
