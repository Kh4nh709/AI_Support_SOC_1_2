## Design notes the coders must receive (put them in the prompts)
- Cluster key hashed **in SQL**: `pg_advisory_xact_lock(hashtext(rule_id || '|' || srcip || '|' || dstip || '|' || agent_name))`.
- `alert_time` ← `fields.timestamp[0]` if present else `_source.timestamp` normalised (`+0700` → `+07:00`); `event_time` ← NULL unless the agent's timezone is declared in inventory (field `tz`); keep `predecoder.timestamp` raw in `raw_payload` only. `manager_id` ← `_source.manager.name` (default `'default'`). `origin_host` ← `predecoder.hostname` (fallback `agent.name`).
- Puller query: `POST {INDEXER_URL}/{INDEXER_INDEX}/_search` with `query.range.timestamp.gte = cursor − PULL_OVERLAP_S`, `sort: [{"timestamp":"asc"}]`, `size: PULL_PAGE`, `search_after` from the last hit's `sort`; `sort_key` = first sort value; duplicates are dropped by the UNIQUE constraint (`ON CONFLICT DO NOTHING`); cursor advances only after COMMIT. Auth: basic; TLS: always verified against `INDEXER_CA` (the OpenSearch root CA copied into `conf/root-ca.pem`; see context pack §6.3); there is no insecure mode — a missing or invalid CA is a startup error reported as an Owner action.
- Pipeline job runs everything for one intake in one transaction except the advisory-lock region, which stays as short as in v1 (one SELECT, one or two writes). Outcome written to `intake.outcome` and `processed_at`.
- Auto-close runs **after** internal enrichment; rule match fields = phase-3 whitelist + `asset_criticality`, `identity_privileged`, `ioc_reputation`. Hard blocks before rules, in this order: critical, never-agents, asset high, **asset not in inventory (lookup returned None)**, privileged identity, ioc malicious/suspicious.
- Every auto-closed alert also gets `jobs('triage')` (①  runs on 100 % of them).
- `suggestion_visible` is set at INSERT: `hash(alert_id) % 2 == 0` when `EVAL_BLIND_FRACTION == 0.5` (use a stable hash such as `hashlib.sha256`, not Python's `hash`).
- `correlation.summarize_for_prompt` returns structured rows `(rule_id, category, status, count, first_seen, last_seen)` plus up to 5 sample alerts as dicts; `correlated_cluster_ids` filters `status IN ('queued_tier1','tier1_active')`, LIMIT 200.
- Worker: single loop over all job types with a dispatch table; `pull` is a job scheduled every 60 s by the worker itself; `SET LOCAL statement_timeout = '3s'` per transaction, 5 s for conclude.
