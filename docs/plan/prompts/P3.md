## Design notes for the coder prompts
- The system prompt must contain the literal word "JSON" (DeepSeek `json_object` requirement). Keep the three mandatory sentences from the legacy builder and their placement rule (two outside blocks, the truncation marker inside).
- Facts outside blocks come from DB values with CHECK sets; never from the alert payload directly. Block sources are exactly the enum in `triage_v2.reasons[].source`.
- Quote check: normalise both sides with NFKC and collapse whitespace; substring test against the block named by `source`; keep the block index from `build()`.
- `structured_basis` comparison: string-equal per field after lowercasing; `occurrence_count` integer-equal against the value at build time (stored in `llm_runs.gate_result.facts`).
- Verifier prompt input: facts dict, the decision table rows for the category, and `{verdict, reasons}` wrapped as one untrusted block with `source="proposer"`; output schema `verifier_v1`.
- `prompt_version` = `git rev-parse --short HEAD` at process start, plus the sha256 of the template file, joined with `+`.
- Cost: `cost_usd = usage.prompt_tokens/1e6*LLM_PRICE_IN_PER_M + usage.completion_tokens/1e6*LLM_PRICE_OUT_PER_M`; monthly sum from `llm_runs` checked before each call.
- Errors: timeout/5xx → transient (job retry); schema fail after repair → `triage_status = unavailable`, `llm_runs.result = NULL`, `stopped_by = 'schema'`.
