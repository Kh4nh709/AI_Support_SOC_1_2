## Phase spec
**Objective.** Two analysts can work Tier-1 in a browser; the blind branch is enforced at the API; the pilot starts today.
**Deliverables.**
- `infra/auth.py`: argon2id password hashing, JWT HS256 with 8 h TTL, per-request DB read of `is_active`, `role`, `sessions_invalid_before`; lockout after `LOGIN_MAX_FAILS` for `LOCKOUT_MINUTES`; `POST /api/auth/login`, `POST /api/auth/logout` (sets `sessions_invalid_before = now()`); CLI `seed_users` creating two users (tier1+tier2 combined role is not allowed — create one `tier1`, one `tier2`, one `admin`; the Owner may hold two accounts).
- `tier1/queue.py` (`list_queue` with `LEFT JOIN llm_runs`, ordering `needs_retriage DESC, risk_score DESC NULLS LAST, first_seen_at ASC`, OFFSET pagination, risk shown as band), `tier1/decide.py` (`acknowledge` idempotent, `decide` with optimistic lock returning N and M on 409 and fan-out, `escalate` creating the case, `reopen` from `auto_closed` only) + REST routes.
- Suggestion stripping: a single response filter that removes the ① suggestion (and `llm_runs`-derived fields) from **every** response while `suggestion_visible = false` and status ∉ closed/escalated, for every role including admin; the labeling page in P6 will reuse it.
- `web/`: login, queue, alert detail (raw_log, correlation ±2 h, targeted accounts, playbook, ① verdict + reasons with quotes + `gate_result` summary when visible, decision form with reason and `seen_occurrence_count`), HTMX partials for decide/escalate/reopen, flash messages for 409 with N and M.
**Tests required.** Auth: wrong password ×5 → 423; logout invalidates the token; inactive user → 401. Queue: ordering; blind alert detail contains no `suggestion` key for tier1/tier2/admin until decided; after decision the suggestion appears in the detail (for analysis) and in `tier1.decided` audit payload. Decide: 409 with N and M when delta > 20; fan-out closes duplicates. Escalate: creates case and `case_alerts`, correlated clusters leave the queue. Reopen: only from `auto_closed`. E2E with the test client through the HTML routes.
**Exit gate.** Login, queue, detail, decide/escalate/reopen work end-to-end; blind alerts return no suggestion at the API for any role; pilot started (Owner action).
**Day budget.** 1 day. **Cut candidates.** Queue filters; pagination beyond OFFSET; flash-message polish.

## Design notes for the coder prompts
- JWT payload: `sub`, `role`, `iat`, `exp`; the DB check on every request is mandatory (one SELECT on `users` by PK).
- Templates: Jinja2 with autoescape on; HTMX from cdnjs pinned; no build step; one base layout; Vietnamese labels are fine in templates (the analysts are Vietnamese) — code stays English.
- The suggestion filter lives in one place (`tier1/visibility.py`) and is unit-tested with role × status × visibility matrix.
- `tier1.decided` audit payload must include `llm_suggestion`, `llm_confidence`, `gate_result.forced`, `suggestion_visible` — this is the evaluation join.
- Pilot start = Owner logs in as tier1 and decides real alerts; nothing else.
