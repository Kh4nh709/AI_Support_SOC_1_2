## Planning rules
- Tasks ≤ 4 h each, one branch each, explicit and disjoint file lists; ≤ 3 in parallel.
- Every task has acceptance commands a Reviewer can run. "Works" is not acceptance.
- Priority `must` tasks alone must satisfy the exit gate.
- Frozen contracts (context pack §6) are not changed by tasks; if needed, write a `DECISION_REQUEST` to INBOX.md and plan the rest.
- Human-only items become "Owner actions" rows in STATE.md.
- Reuse first: do not plan rewrites of anything that already exists and works.
- If the sum of `must` estimates exceeds the day budget by > 30 %, say so at the top of the task file and propose what to move to P1.
